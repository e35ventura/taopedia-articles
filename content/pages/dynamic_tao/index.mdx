# Dynamic TAO (dTAO)

Dynamic TAO, often shortened to dTAO, is Bittensor's subnet tokenomics model. It connects
network-level TAO with subnet-specific alpha tokens, subnet pools, stake context, and emission
allocation ([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

The useful article-level boundary is scope. Dynamic TAO is the broad system frame; alpha tokens,
reserves, stake weight, and emissions are more specific terms inside that frame.

## Subnet Tokenomics Scope

Dynamic TAO gives each subnet its own tokenomics context. The
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets) documentation
describes subnets with TAO reserves, subnet alpha reserves, alpha outstanding, and validator stake
weight.

That means Dynamic TAO should not be read as a separate token. It is the model that organizes TAO
and subnet alpha inside Bittensor's subnet economy.

## TAO and Alpha Context

TAO remains the network asset, while alpha tokens are subnet-specific assets. The
[Emission](https://docs.learnbittensor.org/learn/emissions) documentation describes both TAO and
subnet alpha in the emission system.

Dynamic TAO is the framing that keeps those asset scopes distinct. A claim about TAO, a claim about
alpha reserve, and a claim about alpha outstanding may all belong to Dynamic TAO while describing
different parts of the system.

## Pool Context

Subnets use paired pool sides. The
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets#liquidity-pools)
documentation describes subnet liquidity pools with TAO and subnet-alpha sides.

Dynamic TAO uses that pool context to connect network TAO with subnet alpha. The pool is not the
whole system, but it is one of the places where the TAO-and-alpha relationship appears.

## Emission Context

The [Emission](https://docs.learnbittensor.org/learn/emissions) documentation frames emissions as a
process involving TAO, alpha reserve injection, alpha outstanding injection, and distribution across
subnets.

Dynamic TAO is therefore not only a supply label. It is the broader model that describes how emitted
value is routed through subnet-specific tokenomics.

## Stake Weight Context

Validator stake weight is one Dynamic TAO-specific reading point. The
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets#validator-stake-weight)
documentation explains validator stake weight in the subnet context.

This keeps Dynamic TAO tied to subnet-level allocation rather than a single flat stake concept. The
same TAO can matter differently depending on subnet context and the related alpha position.

## Consensus Boundary

Dynamic TAO and Yuma Consensus are related but not interchangeable. Dynamic TAO is the tokenomics
frame; [Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus) is the consensus
process that turns validator weight signals into subnet reward outcomes.

This boundary prevents the article from collapsing mechanism layers. Dynamic TAO describes the
tokenomics environment, while Yuma Consensus describes an allocation process inside that
environment.

## Reading Boundaries

Dynamic TAO is the right term when the topic is Bittensor's subnet-aware tokenomics model
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)). More
specific terms should be used when the topic is only alpha reserve, alpha outstanding, validator
stake weight, or emission distribution.

The page should therefore stay conceptual. It should not become a staking guide, a subnet launch
guide, or a calculation guide for any specific subnet.
