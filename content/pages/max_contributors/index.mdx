# Max Contributors

Max contributors is a crowdloan pallet runtime constant, listed in the chain's constants metadata as
maxContributors, with the value 500, described as the maximum number of crowdloan contributors
([Subtensor API Constants: maxContributors](https://docs.learnbittensor.org/subtensor-api/constants#maxcontributors-u32)).
It caps how many distinct accounts may contribute to a single crowdloan.

## What It Means

A crowdloan pools TAO from many contributors toward a shared funding goal
([Crowdloans](https://docs.learnbittensor.org/subnets/crowdloans)). Max contributors sets the
ceiling on how many separate accounts one crowdloan may take on: up to 500. Once a crowdloan already
has 500 contributors, it cannot accept another new contributor
([Subtensor API Constants: maxContributors](https://docs.learnbittensor.org/subtensor-api/constants#maxcontributors-u32)).
The cap counts distinct contributors to one crowdloan, not the total across every crowdloan on the
network. Each crowdloan is measured against the same limit on its own, so one crowdloan filling its
contributor slots has no bearing on how many contributors another crowdloan may take.

## Distinction from the Contribution Minimum

Max contributors and the contribution minimum limit different things. Max contributors caps how many
accounts may join a crowdloan, while the absolute minimum contribution, valued at 100000000 rao, or
0.1 TAO, sets the smallest amount each account may add
([Subtensor API Constants: absoluteMinimumContribution](https://docs.learnbittensor.org/subtensor-api/constants#absoluteminimumcontribution-u64)).
One bounds the number of participants; the other bounds the size of each participant's contribution.
A crowdloan can reach its contributor cap regardless of how large or small the individual
contributions are.

## Distinction from the Refund Limit

Max contributors is also separate from the refund limit. The refund contributors limit, valued at
50, caps how many contributors can be refunded in a single refund operation, not how many a
crowdloan may hold in total
([Subtensor API Constants: refundContributorsLimit](https://docs.learnbittensor.org/subtensor-api/constants#refundcontributorslimit-u32)).
A crowdloan that reached 500 contributors would have its refunds processed in several operations,
since each one handles at most 50.

## Why a Contributor Cap Exists

Fixing a ceiling on contributors means a crowdloan tracks a bounded set of participants rather than
an open-ended one. With the cap at 500, the largest number of separate contributor records a single
crowdloan can accumulate is known in advance
([Subtensor API Constants: maxContributors](https://docs.learnbittensor.org/subtensor-api/constants#maxcontributors-u32)).
A prospective contributor to a crowdloan that has already reached the cap would need to join a
different crowdloan instead, since the full one can take no more participants.

## Reader Boundary

Max contributors is a single network-wide constant, not a per-subnet value, and it reflects the
current runtime configuration rather than a fixed protocol rule; the value could change in a future
runtime upgrade. It caps the count of contributors to one crowdloan and does not describe how much
the crowdloan raises or how contributions are returned
([Subtensor API Constants: maxContributors](https://docs.learnbittensor.org/subtensor-api/constants#maxcontributors-u32)).
