# Recycle

Recycle describes how the cost a neuron pays to register is returned to a subnet's economy rather
than permanently destroyed. The
[Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register) entry states that
when a hotkey registers, alpha worth the current swap value of the registration fee is taken from
the subnet's alpha liquidity pool and recycled, which keeps the value inside the subnet rather than
removing it from supply.

## What Recycling Does

Registration on a subnet requires paying a dynamic
[burn cost](https://docs.learnbittensor.org/resources/glossary#burn-cost). Recycling is the
accounting step that moves the alpha equivalent of that cost back into the subnet's liquidity pool
context when a registration succeeds, so the registrant pays to enter while the subnet's alpha is
not simply destroyed
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

This matters because it separates the registrant's payment from a net reduction in token supply. The
registrant still spends to register, but the subnet-side effect is a movement of alpha within the
pool rather than a one-way removal.

## Distinction from Burning

Burning removes tokens from circulation permanently, while recycling returns the alpha value of the
registration cost to the subnet's pool. The two are easy to conflate because both describe what
happens to a registration payment, but only burning reduces supply
([Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register)).

- **Burning** — permanent removal of tokens from supply.
- **Recycling** — returning the registration cost's alpha value to the subnet pool.

## Distinction from the Burn Hyperparameters

The min burn and max burn hyperparameters bound how large the registration cost can be, while
recycling describes what happens to that cost afterward. One sets the price range; the other handles
where the paid value goes
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Why Recycling Matters

Recycling keeps registration economically meaningful without draining a subnet's alpha. A registrant
must still pay the current cost to claim a slot, which preserves the anti-spam function of
registration, while the recycled alpha stays available to the subnet's pool rather than leaving the
system ([Emission](https://docs.learnbittensor.org/learn/emissions)).

For readers, the practical point is that "registration cost" should not be read as "burned forever."
The cost gates entry, but the subnet-side treatment of that cost is a recycling movement within the
alpha pool ([Glossary: Burn Cost](https://docs.learnbittensor.org/resources/glossary#burn-cost)).
