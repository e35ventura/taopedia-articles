# Non Zero Ref Count

`NonZeroRefCount` is a system pallet error raised when an account cannot be purged because its
reference count is still non-zero. The API docs describe it as "There is a non-zero reference count
preventing the account from being purged"
([Subtensor API Errors: NonZeroRefCount](https://docs.learnbittensor.org/subtensor-api/errors#nonzerorefcount)).

## What It Means

Pallets that depend on an account increment its reference count to signal that the account should
not be removed. When any of those dependencies remain, the count stays above zero and the system
pallet blocks account removal. This is a reference-count guard, not a balance check or a
composite-data check
([Subtensor API Errors: NonZeroRefCount](https://docs.learnbittensor.org/subtensor-api/errors#nonzerorefcount)).

## Distinction from Non Default Composite

`NonZeroRefCount` and `NonDefaultComposite` are both system pallet errors that block account
removal, but they guard different conditions. `NonDefaultComposite` fires when the account still
holds non-default composite data. `NonZeroRefCount` fires when the account's reference count is
non-zero
([Subtensor API Errors: NonDefaultComposite](https://docs.learnbittensor.org/subtensor-api/errors#nondefaultcomposite),
[Subtensor API Errors: NonZeroRefCount](https://docs.learnbittensor.org/subtensor-api/errors#nonzerorefcount)).

- **NonDefaultComposite** — account holds non-default composite data.
- **NonZeroRefCount** — account's reference count is non-zero.

## Reader Boundary

This page defines the error label and the reference-count guard on the account-removal path. It does
not report an account's current reference count or list which pallets increment it
([Subtensor API Errors: NonZeroRefCount](https://docs.learnbittensor.org/subtensor-api/errors#nonzerorefcount)).
