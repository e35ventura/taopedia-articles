# Initial Min Allowed Uids

Initial Min Allowed Uids is a subtensorModule runtime constant, listed in the chain's constants
metadata as initialMinAllowedUids, with the value 64 and the summary "Initial minimum allowed
network UIDs"
([Subtensor API Constants: initialMinAllowedUids](https://docs.learnbittensor.org/subtensor-api/constants#initialminalloweduids-u16)).
It supplies the default value a subnet's MinAllowedUids uses.

## What It Means

MinAllowedUids is held per subnet and sets the minimum number of UIDs a subnet may be reduced to.
Initial Min Allowed Uids is the default this per-subnet value falls back to before a different value
applies for a subnet
([Subtensor API Constants: initialMinAllowedUids](https://docs.learnbittensor.org/subtensor-api/constants#initialminalloweduids-u16)).
The MinAllowedUids in force on a subnet such as netuid 1 is that subnet's own chain state and can
differ from this default.

## Distinction from Max Allowed UIDs and Validators

Initial Min Allowed Uids is the default minimum UID count, while initialMaxAllowedUids, valued at
256, is the maximum number of UIDs a subnet may hold; initialMaxAllowedValidators, valued at 128, is
the maximum validators a subnet may have
([Subtensor API Constants: initialMaxAllowedUids](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxalloweduids-u16),
[Subtensor API Constants: initialMaxAllowedValidators](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxallowedvalidators-u16)).

## Reader Boundary

Initial Min Allowed Uids is a default constant, not the live per-subnet MinAllowedUids, and it
reflects the current runtime configuration rather than a fixed protocol rule
([Subtensor API Constants: initialMinAllowedUids](https://docs.learnbittensor.org/subtensor-api/constants#initialminalloweduids-u16)).
