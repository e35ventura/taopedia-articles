# Consensus Score

A consensus score is the per-miner agreement benchmark Yuma Consensus derives when validator weights
are combined into final rank results. For each miner column, documentation describes the benchmark
as the maximum weight level that still has at least the subnet's
[kappa](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#kappa) stake fraction
supporting it across validators
([Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

The term matters because validator signals can disagree. Consensus score names the per-miner
benchmark used to cap outlier weights before the filtered result contributes to rank.

In plain language, consensus score answers: for this miner, what weight level still has enough
stake-weighted validator support to become the clipping ceiling? Weights above that benchmark are
trimmed before they contribute to final rank
([Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

For a reader, consensus score differs from a single validator's view. One validator might rate a
miner highly, but if stake-weighted support does not back that level at the kappa threshold, that
signal is capped before it enters rank aggregation
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

That benchmark belongs inside the Yuma process. It is calculated from validator-submitted weights
for each miner column, then used to clip individual weights before final rank results are produced
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Glossary: Weight Vector](https://docs.learnbittensor.org/resources/glossary#weight-vector)).

## The Per-Miner Clipping Benchmark

For each miner column in the
[weight matrix](https://docs.learnbittensor.org/resources/glossary#weight-matrix), Yuma derives a
consensus benchmark `W̄_j` from validator-submitted weights. Documentation describes the benchmark as
the maximum weight level `w` that still has at least a configured fraction `κ` of total validator
stake supporting it across validators who assigned at least that level to miner `j`
([Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

That stake-majority fraction comes from the subnet's
[kappa](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#kappa) hyperparameter. Kappa
names the input stake fraction; consensus score names the resulting per-miner benchmark used when
individual weights are compared during clipping
([Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

## How Individual Weights Are Clipped

After `W̄_j` is derived for miner `j`, each validator's submitted weight is capped to the benchmark:

`W̄_ij = min(W_ij, W̄_j)`

Documentation states that weights above the benchmark are clipped, and neither the miner nor the
submitting validator receives emissions for the excess portion
([Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

Those clipped values are what downstream metrics read. Pre-rank sums use submitted weights before
this cap; final [rank](https://docs.learnbittensor.org/resources/glossary#rank) and
[trust](https://docs.learnbittensor.org/resources/glossary#trust) read the post-clip values
([Glossary: Trust](https://docs.learnbittensor.org/resources/glossary#trust)).

[Rank](https://docs.learnbittensor.org/resources/glossary#rank) aggregates clipped weights with
stake into `R_j = Σ_i S_i · W̄_ij`, while
[validator trust](https://docs.learnbittensor.org/resources/glossary#validator-trust) sums each
validator's clipped contributions across miners
([Yuma Consensus: Miner emissions](https://docs.learnbittensor.org/learn/yuma-consensus#miner-emissions),
[Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust)).

## Scoring Model Versus Consensus Benchmark

A subnet's [scoring model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)
is the upstream rule a validator uses to judge miner work. Consensus score is the downstream,
protocol-level benchmark Yuma computes from the submitted
[weight vectors](https://docs.learnbittensor.org/resources/glossary#weight-vector) after validators
disagree
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism),
[Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score)).

Evaluation vocabulary names how one validator forms scores. Consensus-score vocabulary names the
shared clipping reference the validator set produces once those scores are assembled into matrix
input ([Glossary: Weight Matrix](https://docs.learnbittensor.org/resources/glossary#weight-matrix)).

## Distinction from Kappa

Kappa is the subnet hyperparameter that sets the stake fraction used when deriving each miner's
clipping benchmark. Consensus score names that resulting per-miner benchmark `W̄_j`—the agreement
level individual weights are capped to during clipping
([Subnet Hyperparameters: Kappa](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#kappa),
[Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

- **Kappa** — configured stake fraction input to the clipping ceiling.
- **Consensus score** — resulting per-miner benchmark used during clipping.

## Distinction from Validator Trust

Consensus score is the per-miner clipping benchmark `W̄_j` derived from stake-weighted agreement.
Validator trust sums one validator's clipped weights across miners after that benchmark is applied
([Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

- **Consensus score** — per-miner agreement benchmark inside the clipping step.
- **Validator trust** — validator-side clipped influence summed across miners.

## Distinction from Rank

Consensus score is the per-miner benchmark used when clipping outlier weights. Rank is the
miner-side standing read after those clipped values are stake-weighted and aggregated
([Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Glossary: Rank](https://docs.learnbittensor.org/resources/glossary#rank),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

- **Consensus score** — per-miner agreement benchmark inside the clipping step.
- **Rank** — miner-side outcome after filtered weights are combined.

## Distinction from Trust

Consensus score is the per-miner clipping benchmark `W̄_j` that caps individual validator weights.
Trust compares each miner's final rank to its pre-rank support to show how much survived that
filtering in the same pass
([Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Glossary: Trust](https://docs.learnbittensor.org/resources/glossary#trust),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

- **Consensus score** — per-miner agreement benchmark inside the clipping step.
- **Trust** — miner-side clipping survival ratio comparing final rank to pre-rank support.

## Distinction from Weight Vector

A weight vector is one validator's submitted miner scores. Consensus score is the per-miner clipping
benchmark Yuma derives from many such submissions on the selected subnet
([Glossary: Weight Vector](https://docs.learnbittensor.org/resources/glossary#weight-vector),
[Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

Weight vectors are inputs; consensus score is the per-miner benchmark those inputs produce before
rank aggregation.

## Distinction from Weight Matrix

A weight matrix stacks validator vectors into subnet-wide consensus input. Consensus score is read
from that grouped input when clipping filters individual weight values on the selected subnet
([Glossary: Weight Matrix](https://docs.learnbittensor.org/resources/glossary#weight-matrix),
[Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Weight matrix** — assembled validator input.
- **Consensus score** — clipping benchmark derived from that input.

## Distinction from Incentives

- **Consensus score** — clipping benchmark inside Yuma.
- **Incentives** — miner-facing credited results after rank is normalized.

## Distinction from Dividends

Consensus score is the per-miner clipping benchmark Yuma derives from submitted weights. Dividends
are the validator-side emission share credited from smoothed bonds multiplied by miner incentives
(`D_i = Σ_j B_ij · I_j`) in the same pass
([Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Consensus-based Weights](https://docs.learnbittensor.org/concepts/consensus-based-weights),
[Yuma Consensus: Validator emissions](https://docs.learnbittensor.org/learn/yuma-consensus#validator-emissions)).

- **Consensus score** — clipping benchmark inside Yuma.
- **Dividends** — validator-side share credited from bonds and miner incentives.

Benchmark vocabulary sits upstream of payout vocabulary
([Glossary: Validator-Miner Bonds](https://docs.learnbittensor.org/resources/glossary#validator-miner-bonds)).

## Distinction from Weight Copying

Weight copying is when a validator reuses visible weight signals instead of independently evaluating
miners. Consensus score is the per-miner clipping benchmark Yuma derives from submitted weights—the
same benchmark copiers may try to forecast from visible submissions
([Weight Copying Problem](https://docs.learnbittensor.org/concepts/weight-copying-in-bittensor),
[Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

- **Weight copying** — dependence on another validator's published scores.
- **Consensus score** — clipping benchmark derived from validator submissions.

## Distinction from Subnet Scoring Model

- **Subnet scoring model** — upstream per-validator evaluation rule.
- **Consensus score** — downstream clipping benchmark from submitted weights.

## Distinction from Self Weighting

Self-weighting inflates weights toward entities a validator controls. Consensus score is the
per-miner agreement benchmark Yuma uses to cap weights that exceed stake-weighted support at the
kappa threshold
([Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

- **Self-weighting** — inflated weights toward entities the validator controls.
- **Consensus score** — clipping benchmark derived from validator submissions.

Exploit vocabulary names self-preference; consensus-score vocabulary names the clipping benchmark
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

## Distinction from Yuma Consensus

- **Consensus score** — per-miner agreement benchmark used when clipping weights.
- **Yuma Consensus** — tempo step that turns submitted weights into emission shares.

## Reader Boundary

Consensus score should not be read as a payout amount, a validator trust score by itself, or proof
that a miner received a specific reward. It names the per-miner clipping benchmark Yuma uses when
filtering validator weight signals before rank and emission outcomes are assigned
([Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Glossary: Rank](https://docs.learnbittensor.org/resources/glossary#rank),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).
