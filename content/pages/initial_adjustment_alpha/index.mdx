# Initial Adjustment Alpha

Initial Adjustment Alpha is a subtensorModule runtime constant, listed in the chain's constants
metadata as initialAdjustmentAlpha, with the value 0 and the summary "Initial adjustment alpha on
burn and pow"
([Subtensor API Constants: initialAdjustmentAlpha](https://docs.learnbittensor.org/subtensor-api/constants#initialadjustmentalpha-u64)).
It supplies the default value a subnet's AdjustmentAlpha uses.

## What It Means

AdjustmentAlpha is held per subnet and sets the smoothing weight a subnet applies when it adjusts
its registration difficulty and burn between adjustment intervals. Initial Adjustment Alpha is the
default this per-subnet value falls back to before a different value applies for a subnet
([Subtensor API Constants: initialAdjustmentAlpha](https://docs.learnbittensor.org/subtensor-api/constants#initialadjustmentalpha-u64)).
The AdjustmentAlpha in force on a subnet such as netuid 1 is that subnet's own chain state and can
differ from this default.

## Distinction from Adjustment Interval and Target

Initial Adjustment Alpha is the default adjustment smoothing weight, while
initialAdjustmentInterval, valued at 100, is the number of blocks between those adjustments;
initialTargetRegistrationsPerInterval, valued at 2, is the target number of registrations per
interval the adjustment aims for
([Subtensor API Constants: initialAdjustmentInterval](https://docs.learnbittensor.org/subtensor-api/constants#initialadjustmentinterval-u16),
[Subtensor API Constants: initialTargetRegistrationsPerInterval](https://docs.learnbittensor.org/subtensor-api/constants#initialtargetregistrationsperinterval-u16)).

## Reader Boundary

Initial Adjustment Alpha is a default constant, not the live per-subnet AdjustmentAlpha, and it
reflects the current runtime configuration rather than a fixed protocol rule
([Subtensor API Constants: initialAdjustmentAlpha](https://docs.learnbittensor.org/subtensor-api/constants#initialadjustmentalpha-u64)).
