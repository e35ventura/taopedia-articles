Chunking is Bittensor Subnet 40. Its on-chain identity lists
[VectorChat/chunking_subnet](https://github.com/VectorChat/chunking_subnet) as the subnet's GitHub
repository and VectorChat as the operating team. The subnet's goal is to produce high-quality
document splits for retrieval-augmented generation (RAG) pipelines, where the quality of
segmentation directly affects downstream retrieval accuracy.

## How the Mechanism Works

Validators send miners a text passage along with a set of constraints: a maximum chunk size (in
tokens or characters), a target chunk count, and a response timeout. Miners must split the document
into the requested number of chunks, each staying within the size limit, and return the result
before the deadline.

The validator then scores the returned chunks using a semantic embedding model. Two properties drive
the score: intra-chunk similarity and inter-chunk dissimilarity. For intra-chunk similarity, the
validator samples sentence pairs from within each chunk and measures their cosine similarity using a
sentence-embedding model — higher similarity signals that the chunk is topically tight. For
inter-chunk dissimilarity, the validator samples sentence pairs drawn from different chunks and
measures cosine similarity — lower similarity signals that the chunks cover distinct topics without
overlap. The final score is proportional to the difference between these two values.

Miners are ranked against each other on the same input in a tournament structure, so emissions
follow relative performance rather than absolute thresholds. When scores are comparable, faster
valid responses receive a higher ranking.

Hard constraint violations zero out or heavily penalize a response. Chunks that exceed the size
limit, chunks with excessive cross-chunk content duplication, and responses that time out all
receive a score of zero. Trivially splitting the document without respecting semantic boundaries
produces high inter-chunk similarity and a near-zero or negative score. Persistent low ranking in
the tournament erodes miner emissions over time.

## Participating as a Miner

A successful chunking miner must return responses that satisfy the hard constraints — correct count,
no chunk over the size cap — while maximizing semantic coherence within each chunk and minimizing
overlap between chunks. Approaches that split on sentence-embedding distance to find true topic
boundaries tend to outperform fixed-window or character-count splitters. The subnet rewards miners
that split on meaningful conceptual shifts in the source text rather than on arbitrary length.

Operators should treat the
[VectorChat/chunking_subnet](https://github.com/VectorChat/chunking_subnet) repository as the source
of truth for current request and response formats, registered endpoints, and any scoring updates
made after the subnet launched in July 2024.

## Participating as a Validator

Validators source or generate text passages, attach constraints, and submit queries to registered
miners. They then run the embedding-based scoring routine over the returned chunks, produce
per-miner scores, and publish the resulting weights on-chain to feed [[Yuma Consensus]]. The
tournament ranking means that a validator's job is comparison rather than absolute grading: each
miner's chunks are evaluated relative to the other miners that responded to the same query.

## On-Chain Identity

Live SN40 data, including metagraph state and alpha token pool information, is available on
[TaoStats](https://taostats.io/subnets/40). Readers can reproduce the subnet's registered identity
fields with the Bittensor CLI command documented in the
[btcli reference](https://docs.learnbittensor.org/btcli/#btcli-subnets-get-identity):
`btcli subnets get-identity --netuid 40 --network finney`.

The Finney subnet identity for netuid 40 reports the subnet name as Chunking, the operator as
VectorChat, and the GitHub repository as VectorChat/chunking_subnet. The subnet was registered on
the Bittensor network in July 2024 and runs with 256 registered neurons.
