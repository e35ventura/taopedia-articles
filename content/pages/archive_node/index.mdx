# Archive Node

An archive node is a type of public Subtensor node that downloads and validates every Bittensor
block from genesis onward, rather than only the most recently finalized blocks
([Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)).

## Lite Node Stores Less History

A lite node is the other public Subtensor node type. It performs warp synchronization, mainly
syncing with already-finalized blocks rather than the full chain from genesis
([Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)).

The two node types answer different questions. A lite node is enough for current chain state and
ordinary read access; an archive node is what a reader needs when the question concerns historical
state from an earlier block.

## Archive Nodes Are Not Neurons

A Subtensor node, archive or lite, is distinct from a Bittensor neuron. A neuron is either a subnet
validator or a subnet miner and exists inside a subnet; it does not itself hold a blockchain
database ([Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes),
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron)).

Running an archive node does not make an operator a validator or a miner, and registering as a
neuron does not require running an archive node. The two roles sit on separate layers of the
Bittensor stack.

## What Full History Enables

Storing every block gives an archive node full state access for tasks that need historical data,
such as analytics, audits, block explorers, and indexers that query older blocks rather than only
current state
([Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node)).

That makes archive node language useful when a claim depends on past chain state. A current balance
or current subnet parameter can be read from a lite node; a historical sequence of those same values
needs an archive node or an indexer built on one.

## Public Subtensor Access Can Use Either Node Type

Public Subtensor access names publicly reachable connections to the Subtensor chain layer in
general, while archive node names one specific node configuration within that public access, the one
that retains complete history ([Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)).

A public Subtensor connection can be backed by either node type. Which one is in use determines
whether historical queries beyond recently finalized blocks are available.

## Reader Boundary

This page describes the archive-node concept and how it differs from a lite node and from a neuron.
It is not setup or operations guidance, and it makes no claim about any specific node's current sync
status or storage capacity, which are details of the deployment in question
([Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)).
