# Archive Node

An archive node is a type of public Subtensor node that stores the entire Bittensor blockchain
history. The official
[Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node) describes
it as a public Subtensor node that retains the full blockchain history, allowing complete data
access and querying across past chain state.

## Why Full History Matters

Subtensor is the blockchain layer that records Bittensor transactions, stake, and emissions over
time. An archive node keeps every historical block rather than a recent window, so it can answer
queries about chain state at any past point. The
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes) documentation frames archive
nodes as the option for workloads that need deep historical lookups.

For readers, archive node names a node configuration choice about how much history is retained, not
a separate network or a validator role.

## Public Node Context

An archive node is one kind of
[public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor) access
point. Public Subtensor refers to publicly reachable chain access, and archive node describes the
full-history variant of that access. Both sit on the connection side of Bittensor vocabulary rather
than the staking or consensus side.

This article does not describe node installation steps, hardware sizing, or endpoint URLs. Those
details belong in official node-operation references and live infrastructure data.

References:
[Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)

## Relationship to Lite Node

An archive node and a lite node are related but describe different storage profiles for public
Subtensor nodes. An archive node stores the full blockchain history, while the
[Glossary: Lite Node](https://docs.learnbittensor.org/resources/glossary#lite-node) describes a node
that stores limited blockchain data and relies on archive nodes for full historical queries.

For readers, archive node names the full-history option, while lite node names the lightweight
option that depends on archive nodes when deeper history is needed.

References:
[Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node),
[Glossary: Lite Node](https://docs.learnbittensor.org/resources/glossary#lite-node)

## Relationship to Subtensor

An archive node and Subtensor are related but different scopes in Bittensor vocabulary. The
[Glossary: Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor) describes
Subtensor as Bittensor's blockchain layer and system of record, while an archive node is a node
configuration that serves that chain's full history to clients.

For readers, Subtensor names the blockchain itself, while archive node names a way of running and
exposing a complete copy of that chain.

References: [Glossary: Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)

## Relationship to Mainchain

An archive node and the mainchain are related but different parts of network vocabulary. The
[Glossary: Mainchain](https://docs.learnbittensor.org/resources/glossary#mainchain) describes the
primary production Bittensor network, while an archive node is a node type that can serve the full
history of that network to readers and tools.

For readers, mainchain names which network is being served, while archive node names how a complete
copy of that network's history is stored and queried.

References: [Glossary: Mainchain](https://docs.learnbittensor.org/resources/glossary#mainchain),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)

## Reader Boundary

Archive node should not be read as a recommendation to run any particular node, as a hardware guide,
or as a public endpoint list. It is the concept term for a public Subtensor node that stores the
full Bittensor blockchain history for complete data access and querying.
