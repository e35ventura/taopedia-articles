# Archive Node

An archive node is a public Subtensor node type that keeps the full Bittensor blockchain history.
The official
[Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node) describes
it as a public Subtensor node that stores the entire blockchain history and allows full data access
across that history.

For Taopedia readers, the key idea is historical coverage. Archive node vocabulary answers how much
chain history a node keeps available, not whether the node is a validator, subnet participant, or
wallet authority.

Reference: [Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node)

## Historical Coverage

Bittensor's chain records build over time. A full-history node preserves that older context instead
of focusing only on recent state. This matters when a reader needs to understand past blocks,
historical account state, or long-running changes in network activity.

The official [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes) page
distinguishes archive nodes from lite nodes by the amount of history they retain. In that source,
archive nodes are the full-history side of the public Subtensor node distinction.

References:
[Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node),
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Relationship to Public Subtensor

Archive nodes belong under public Subtensor vocabulary. The
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)
describes public Subtensor as publicly accessible Bittensor chain access that can be lite or
archive.

This means archive node is not a separate Bittensor network. It is a full-history form of public
access to a Subtensor network.

References:
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node)

## Relationship to Lite Node

Archive node and lite node describe different history scopes. The
[Glossary: Lite Node](https://docs.learnbittensor.org/resources/glossary#lite-node) describes a lite
node as a public Subtensor node that stores limited blockchain data and relies on archive nodes for
full historical data.

For readers, archive node names the full-history side of that pair. Lite node names the limited-data
side. Both are public Subtensor node concepts, but they answer different needs around chain history.

References:
[Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node),
[Glossary: Lite Node](https://docs.learnbittensor.org/resources/glossary#lite-node)

## Network Context

An archive node's historical record belongs to the network it follows. The
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks) page separates
mainnet, testnet, and localnet contexts, and a full-history record from one context should not be
treated as the history of another.

This matters when comparing information across sources. A complete record can still be complete only
for its own network context.

Reference: [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)

## Reader Boundary

Archive node is a term about historical chain availability. It should not be confused with a
subnet-level validator role, wallet authority, staking status, or a recommendation about any
particular public service.

This article defines the concept for readers. Current operational details belong in the official
node documentation and in whatever network context is being inspected.
