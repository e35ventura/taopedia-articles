# Archive Node

An archive node is a type of public Subtensor node that stores the entire blockchain history,
allowing for full data access and querying. Subtensor is Bittensor's layer 1 blockchain and serves
as the system of record for transactions and rankings, so a node that retains every past block holds
a complete copy of that record rather than only its present state.

References: [Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node),
[Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor)

## Archive Node Versus Lite Node

A public Subtensor is a publicly reachable node, and it comes in two kinds. A lite node stores only
limited blockchain data and depends on archive nodes for full historical data, while an archive node
holds the complete history itself. The difference is the amount of history each keeps: a lite node
carries a narrow slice of the chain, and an archive node carries all of it, so the two differ in how
far back their data reaches rather than in the network they belong to.

References: [Lite Node](https://docs.learnbittensor.org/resources/glossary#lite-node),
[Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)

## What Full History Enables

The Bittensor chain is built from blocks, where each block is a unit of data holding a collection of
transactions and a unique identifier, and a new block is added about every twelve seconds. Those
blocks accumulate into the chain's history. Because an archive node retains all of them, the data
for past state remains available from it and not only the latest values, which is the property that
chain-inspection reads of earlier blocks depend on.

References: [Block](https://docs.learnbittensor.org/resources/glossary#block),
[Inspecting the Chain](https://docs.learnbittensor.org/concepts/inspecting-the-chain)

## Network Independence

The archive-versus-lite distinction is about stored history, not about which network a node joins. A
public Subtensor can be synchronized with either the mainchain or the testchain, and either form can
be a lite node or an archive node. The mainchain is the primary production network, so an archive
node there holds production history, while an archive node on the testchain holds the test network's
history.

References: [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Mainchain](https://docs.learnbittensor.org/resources/glossary#mainchain)

## Reader Boundary

This page defines the concept and does not describe hardware, storage size, or synchronization time,
which depend on the chain's current length and change over time. The durable distinction is the one
in the definitions: an archive node keeps the entire blockchain history for full data access, while
a lite node keeps limited data and depends on archive nodes for the rest.

References: [Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node)
