# Archive Node

Archive node is Bittensor vocabulary for a public Subtensor node that keeps the full blockchain
history available. The official
[Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node) defines it
as a public Subtensor node that stores the entire blockchain history and allows full access to
historical chain data.

The important idea is history depth. An archive node term tells a reader that the node is associated
with full historical coverage, not merely recent state.

Reference: [Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node)

## Full-History Meaning

Bittensor chain records accumulate block by block. Some questions only need current or recent state,
while other questions depend on older records. Archive node names the full-history side of that
distinction.

For readers, this is a vocabulary boundary. Archive node does not by itself name a wallet, a subnet,
a validator role, or a governance authority. It names a public Subtensor node form in relation to
how much chain history is available.

Reference: [Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node)

## Public Subtensor Context

The
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)
entry describes public Subtensor as publicly accessible Bittensor network access that can be lite or
archive. Archive node sits inside that public Subtensor vocabulary.

This means the word "archive" is about the public node's history coverage. It is not a separate
Bittensor token, chain, subnet, or participant class.

References:
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node)

## Contrast With Lite Node

Archive node is easiest to read beside lite node. The
[Glossary: Lite Node](https://docs.learnbittensor.org/resources/glossary#lite-node) describes a lite
node as a public Subtensor node that stores limited blockchain data and relies on archive nodes for
full historical data.

The contrast is therefore about retained history. Archive node points to full historical coverage;
lite node points to limited retained data.

References:
[Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node),
[Glossary: Lite Node](https://docs.learnbittensor.org/resources/glossary#lite-node)

## Interpretation Boundary

Archive node should not be read as a claim about who controls a wallet, who validates a subnet, or
who receives emissions. Those are separate Bittensor concepts.

It also should not be read as a live-service claim. A Taopedia article can define what the term
means, but any particular public access point still has to be evaluated in its own current context.

## Relationship to Chain History

The value of the term comes from chain history. Bittensor activity leaves records over time, and a
full-history node is relevant when a reader needs historical context rather than only the current
view.

This makes archive node adjacent to articles about blocks, public chain inspection, and historical
state. It is still narrower than those broader topics because it names the node form, not every way
a reader might interpret chain records.

Reference: [Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node)
