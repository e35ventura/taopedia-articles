# Archive Node

An archive node is a type of public Subtensor node that stores the entire blockchain history,
allowing for full data access and querying. Subtensor is Bittensor's layer 1 blockchain and acts as
the system of record for transactions and rankings, so a node that keeps every past block can answer
questions about any earlier point in that record, not just the present one.

References: [Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)

## Archive Node Versus Lite Node

A public Subtensor is a publicly reachable node that can be run either as a lite node or as an
archive node. A lite node stores only limited blockchain data and relies on archive nodes for full
historical data, while an archive node holds the complete history itself. The trade-off is scope of
data: a lite node is lighter to run but can answer only a narrower set of queries, and an archive
node carries the whole history so that nothing historical has to be fetched from somewhere else.

References: [Lite Node](https://docs.learnbittensor.org/resources/glossary#lite-node),
[Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)

## What Full History Enables

The Bittensor chain is built from blocks, where each block is a unit of data holding a collection of
transactions and a unique identifier, and a new block is processed about every twelve seconds. Those
blocks accumulate into the chain's history. Because an archive node retains all of them, it can
serve reads of past state and not only the latest values, which is what tools that inspect the chain
rely on when they need to look back rather than only at the current block.

References: [Block](https://docs.learnbittensor.org/resources/glossary#block),
[Inspecting the Chain](https://docs.learnbittensor.org/concepts/inspecting-the-chain)

## Choosing Between Them

The choice follows from what you need to read. Work that only touches recent or current state can
use a lite node and lean on archive nodes for anything older, while work that must query arbitrary
past blocks needs an archive node so the full history is available locally. Either kind of public
Subtensor can be synchronized with the mainchain or the testchain, so the same archive-versus-lite
decision applies on production and on test networks.

References: [Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)

## Reader Boundary

This page defines the concept and is not a setup or operations guide. It does not specify hardware,
storage size, or sync time, all of which depend on the chain's current length and change over time.
The durable distinction is the one in the definitions: an archive node keeps the entire blockchain
history for full data access, while a lite node keeps limited data and depends on archive nodes for
the rest.

References: [Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node)
