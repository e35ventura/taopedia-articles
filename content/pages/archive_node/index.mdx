# Archive Node

An archive node is a type of Subtensor node that keeps the complete history of the Bittensor
blockchain, from the genesis block up to the latest one. Because it retains every past block, it can
answer questions about historical chain state rather than only the present.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Archive Node and Lite Node

The archive node is best understood next to its counterpart, the lite node. The documentation
describes a lite node as keeping only a recent window of finalized blocks, on the order of the last
few hundred, while an archive node validates and retains all blocks back to genesis. Both are kinds
of public Subtensor node; the difference is how much history each one holds.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Why Full History Matters

The point of keeping all of it is access to the past. The documentation notes that applications
which need blockchain data older than the recent window, such as block explorers and indexers, rely
on an archive node, because a lite node simply does not have the older blocks to serve. When the
question is about historical state, the archive node is the source that can answer it.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## The Cost of Completeness

Completeness is not free. Holding the entire chain means an archive node processes every block from
genesis, which the documentation notes is considerably slower than the lighter synchronization a
lite node performs, and it requires substantially more storage to hold the full historical data. So
the choice between the two reflects a trade-off between historical reach and resource use, not a
difference in correctness.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Reader Boundary

This page defines the concept at a high level. It does not give settings, requirements, or steps for
running a node, and exact storage sizes and sync behavior change as the chain grows. The lasting
idea is the role an archive node plays: the full-history source that serves data the recent window
cannot.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)
