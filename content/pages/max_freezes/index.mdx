# Max Freezes

Max freezes is a balances pallet runtime constant, listed in the chain's constants metadata as
maxFreezes, with the value 50 and the summary "The maximum number of individual freeze locks that
can exist on an account at any time"
([Subtensor API Constants: maxFreezes](https://docs.learnbittensor.org/subtensor-api/constants#maxfreezes-u32)).
The runtime sets this bound directly: it configures the balances pallet's freeze limit to 50
([runtime/src/lib.rs](https://github.com/opentensor/subtensor/blob/14bc6f9f964b9cc362e9635dd110a487fa5d15a0/runtime/src/lib.rs#L494)).

## What It Means

Each account can hold up to 50 individual freeze locks at the same time. The official errors
reference ties the limit directly to the error a reader would actually hit: it defines the
TooManyFreezes error as firing when the number of freezes on an account exceeds this constant
([Subtensor API Errors: TooManyFreezes](https://docs.learnbittensor.org/subtensor-api/errors#toomanyfreezes)).

The value applies uniformly across accounts; it is not a per-subnet or configurable-per-account
setting.

## Distinction from Max Reserves

A separate constant, maxReserves, shares the same value of 50 and the same strict-cap treatment, but
it bounds a different per-account list. maxReserves bounds the number of named reserves an account
can hold, and exceeding it raises TooManyReserves rather than TooManyFreezes
([Subtensor API Constants: maxReserves](https://docs.learnbittensor.org/subtensor-api/constants#maxreserves-u32),
[Subtensor API Errors: TooManyReserves](https://docs.learnbittensor.org/subtensor-api/errors#toomanyreserves)).

- **maxFreezes** — 50; exceeding it raises TooManyFreezes.
- **maxReserves** — 50; exceeding it raises TooManyReserves.

## Reader Boundary

This page defines the constant and its value. It does not report how many freeze locks any specific
account currently holds; that is live chain state
([Subtensor API Constants: maxFreezes](https://docs.learnbittensor.org/subtensor-api/constants#maxfreezes-u32)).
