# SS58 Encoded

SS58 encoded values are compact representations used for Bittensor wallet addresses. The
[SS58 Encoded glossary](https://docs.learnbittensor.org/resources/glossary#ss58-encoded) places the
term in wallet-address context, where public-key-derived address strings identify TAO destinations.

## What It Represents

An SS58 encoded value is not a separate asset, account role, or balance. It is the compact display
format for a public-key-derived
[wallet address](https://docs.learnbittensor.org/resources/glossary#wallet-address) on the Substrate
side of Bittensor wallet activity
([Glossary: SS58 Encoded](https://docs.learnbittensor.org/resources/glossary#ss58-encoded)).

Readers should separate four address ideas that sound similar:

- **SS58 encoded** — compact string format derived from public-key material.
- **Wallet address** — public TAO destination the string identifies.
- **Public key** — shareable keypair material used for verification and account reference.
- **H160 address** — EVM account format used in bridging and contract contexts, not interchangeable
  with SS58 labels on the same operation path
  ([Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials),
  [Token Bridging](https://docs.learnbittensor.org/evm-tutorials/bridge-vtao)).

An SS58 string identifies where TAO can be sent. It does not by itself show a balance, a staking
position, subnet role status, or proof that the holder controls the corresponding signing material
([Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key)).

Publishing an SS58 address for receiving TAO is normal. Publishing recovery phrases, mnemonics, or
private keys is not. SS58 vocabulary names destination addresses; seed phrase and workstation
security documentation names custody secrets
([Handle your Seed Phrase Securely](https://docs.learnbittensor.org/keys/handle-seed-phrase)).

Conversion between SS58 and H160 views is documented in EVM tutorials. Conversion changes how an
identity is displayed or parsed for a given action; it does not produce the corresponding private
key or move signing authority by itself
([Convert Ethereum H160 Address to Substrate SS58](https://docs.learnbittensor.org/evm-tutorials/convert-h160-to-ss58)).

Readers evaluating a transfer or wallet action should confirm which address format that operation
expects before submission.

## Distinction from Wallet Address

- **Wallet address** — public TAO destination.
- **SS58 encoded** — compact format used to display that destination.

## Distinction from Public Key

- **Public key** — shareable keypair material.
- **SS58 encoded** — address format derived from that material.

## Distinction from EdDSA Cryptographic Keypairs

- **EdDSA keypair** — cryptographic pair behind signing material.
- **SS58 encoded** — display format for the public side as a destination string.

## Distinction from Transfer

- **Transfer** — action of sending TAO to a destination address.
- **SS58 encoded** — address format that identifies that destination.

## Distinction from Coldkey

- **SS58 encoding** — public-key-derived address representation for a destination.
- **Coldkey** — wallet component that secures funds and authorizes sensitive operations.

## Distinction from Hotkey

- **SS58 encoding** — public-key-derived address representation for an on-chain identity.
- **Hotkey** — operational wallet component used for subnet work.

## Reader Boundary

SS58 encoded should be read as native wallet address-format vocabulary. It identifies
public-key-derived destinations on Bittensor; it does not by itself prove signing authority or
subnet role status
([Glossary: SS58 Encoded](https://docs.learnbittensor.org/resources/glossary#ss58-encoded)).
