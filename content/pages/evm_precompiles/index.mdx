# EVM Precompiles

EVM precompiles are built-in contracts that expose native Subtensor functions to Ethereum-style
smart contracts on Bittensor EVM. They let Solidity code reach chain operations, such as staking or
reading the metagraph, that ordinary EVM bytecode cannot perform on its own
([Bittensor EVM Precompiles](https://docs.learnbittensor.org/evm-tutorials/examples)).

A precompile is part of the chain's EVM environment rather than a contract a user deploys, so it is
available to any contract that calls it.

## Standard and Bittensor-Specific Precompiles

The precompiles reference groups them into two families. One family is the standard Ethereum
precompiles, such as ECRecover and the SHA-256 hash function, that EVM contracts expect on any
Ethereum-compatible chain. The other family is the Bittensor-specific precompiles that connect
contracts to Subtensor's own functions
([Bittensor EVM Precompiles](https://docs.learnbittensor.org/evm-tutorials/examples)).

This split lets familiar Ethereum tooling work unchanged while adding access to Bittensor operations
that have no equivalent on Ethereum mainnet.

## What the Bittensor Precompiles Provide

The Bittensor-specific precompiles cover several areas of native functionality. A balance-transfer
precompile moves TAO between accounts, and a staking precompile manages staking operations including
adding, removing, and moving stake along with delegation proxy management
([Bittensor EVM Precompiles](https://docs.learnbittensor.org/evm-tutorials/examples),
[Staking Precompile](https://docs.learnbittensor.org/evm-tutorials/staking-precompile)).

Other precompiles expose protocol structure and identity. Subnet and metagraph precompiles let
contracts manage subnet operations and read metagraph state, a neuron precompile handles neuron
operations, and an Ed25519 verify precompile checks Ed25519 signatures inside the EVM
([Bittensor EVM Precompiles](https://docs.learnbittensor.org/evm-tutorials/examples),
[Ed25519 Verify Precompile](https://docs.learnbittensor.org/evm-tutorials/ed25519-verify-precompile)).

## Distinction from Bittensor EVM Smart Contracts

A Bittensor EVM smart contract is a program a user deploys to the chain, while a precompile is a
built-in interface the EVM environment already provides for a native Subtensor function
([Bittensor EVM Precompiles](https://docs.learnbittensor.org/evm-tutorials/examples)).

- **Smart contract** — a user-deployed program running in Bittensor EVM.
- **Precompile** — a built-in interface to a native Subtensor function.

## Reader Boundary

This article defines the concept at a high level. It does not list precompile addresses, function
signatures, or current behavior, which belong to the EVM tutorials and to live chain state at the
time of use ([Bittensor EVM Precompiles](https://docs.learnbittensor.org/evm-tutorials/examples)).
