# Subnet Scoring Model

A subnet scoring model is the evaluation method validators use when judging miner responses inside a
Bittensor subnet
([Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

The term belongs to incentive-mechanism vocabulary. It names how returned work becomes an evaluation
result, separate from the task definition, validator-miner interaction pattern, and final consensus
aggregation.

## Evaluation Role

The scoring model explains how returned work is judged. The subnet task describes what miners are
asked to produce, while the scoring model describes how validators evaluate the responses they
receive
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism),
[Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)).

This keeps task vocabulary separate from scoring vocabulary. The task asks for work; the scoring
model evaluates returned work.

That order is the first interpretation boundary. A subnet can ask for a particular digital
commodity, but the scoring model explains how validators turn returned work into judgment inside
that subnet's incentive mechanism
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

## Protocol Boundary

Subnet protocol and subnet scoring model are adjacent but different. The protocol describes the
request-and-response pattern between validators and miners, while the scoring model describes how
returned responses are judged
([Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol),
[Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)).

The protocol creates the interaction surface. The scoring model explains the evaluation method
applied to that surface. A request-and-response pattern can exist without saying enough about how
the response is scored.

## Scores Before Weights

A scoring model sits earlier in the evaluation path than final weight signals. Weight vectors are
structured signals formed after validator evaluation and sent onward for consensus context
([Glossary: Weight Vector](https://docs.learnbittensor.org/resources/glossary#weight-vector),
[Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)).

This distinction keeps scoring formulas and weight vocabulary separate. The scoring model produces
evaluation scores; weight vocabulary describes the signals that later carry evaluation into
consensus.

The weight vector is therefore downstream of the scoring model. It can carry validator preference
toward consensus, but the scoring model is where the validator decides how miner responses compare
inside the subnet context
([Glossary: Weight Vector](https://docs.learnbittensor.org/resources/glossary#weight-vector)).

## Role Context

Miners produce responses for the subnet, and validators evaluate those responses under subnet
standards. Subnet documentation describes miners as producing a digital commodity and validators as
measuring miner work
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)).

The scoring model is the method validators apply to that work. It links miner responses to validator
evaluation without replacing either role.

Miner names the production side, validator names the evaluation side, and scoring model names the
method used during evaluation
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

## Multiple-Mechanism Boundary

When a subnet uses multiple incentive mechanisms, each mechanism can have its own scoring context.
The multiple-mechanism documentation describes separate mechanism contexts inside one subnet
([Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets),
[Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)).

The mechanism context matters in that case. A scoring standard for one mechanism belongs to that
mechanism's work-and-evaluation path, while another mechanism in the same subnet can require a
different scoring context.

## Consensus Boundary

Yuma Consensus is downstream of validator evaluation. A scoring model can shape the evidence a
validator uses, while consensus aggregates validator signals into incentive and dividend outcomes
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

This boundary keeps evaluation methods separate from final consensus outputs. Scoring is part of how
work is judged; consensus is the protocol process that aggregates validator signals.

That means a scoring-model article can explain evaluation logic without becoming a Yuma Consensus
article. The scoring model shapes validator evidence, while consensus combines submitted signals
after that evidence has already been formed.

## Reading the Term

Subnet scoring model is concept vocabulary for evaluation inside a subnet incentive mechanism. It
identifies the method validators use to compare returned work in a specific subnet context
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

The stable article-level point is the evaluation path: a subnet task requests work, miners return
responses, validators score those responses, and weight signals carry the resulting judgment toward
consensus.

## Network Context

The
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction#subnet-development)
describes subnet development as moving from localnet to testnet and then mainnet. A scoring-model
example belongs to the environment where the task, returned work, validator evaluation, and weight
signals were observed.

The [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks) reference
separates mainnet, testnet, and localnet. Localnet examples are isolated, testnet examples are
shared non-production examples, and mainnet examples belong to the production network context.
