# Subnet Scoring Model

A subnet scoring model is the evaluation logic a subnet uses to score miner work. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model) defines it as
the scoring method used by validators, while
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)
places scoring inside the broader incentive mechanism.

The term is about evaluation, not the entire subnet. A subnet can have a task, miners, validators,
and rewards, but the scoring model is the part that turns miner work into a score.

## Evaluation Role

Subnet scoring models sit between miner work and validator weight signals. The
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)
documentation describes incentive mechanisms as connecting miner behavior, validator evaluation, and
rewards.

In that process, the scoring model gives validators a way to compare miner outputs before those
evaluations become weight signals.

## Task Versus Scoring

A subnet task describes what kind of work a subnet asks for. A scoring model describes how that work
is evaluated. The
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets) documentation
describes subnets as markets for digital commodities, while the scoring-model glossary focuses on
the evaluation method.

That distinction matters because two subnets can ask for similar work while scoring it differently,
or a subnet can adjust its evaluation method without changing the broad work category.

## Weight Signal Handoff

Scores are not the final reward calculation by themselves. They feed the weight signals validators
produce for miner evaluation. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#weight-vector) describes a weight
vector as validator-provided weights for miners.

The scoring model therefore belongs before the weight-vector stage. It explains how a validator
arrives at scores, while the weight vector records the resulting signal.

## Consensus Handoff

After validator signals exist, Yuma Consensus combines them into subnet reward outcomes. The
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus) documentation describes the
aggregation process that uses validator weights.

This places the scoring model upstream of consensus. It influences the inputs validators produce,
while Yuma Consensus handles the aggregation of those inputs.

## Multiple Mechanism Use

Subnets with multiple incentive mechanisms can have separate evaluation paths. The
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)
documentation describes multiple mechanisms operating inside one subnet.

In that setting, each mechanism can use its own scoring logic and bond-pool context. The term subnet
scoring model still names the evaluation method, but the relevant method must be read within the
specific mechanism being discussed.

## Related Terms

Subnet scoring model is narrower than incentive mechanism and broader than a single score. The
incentive mechanism is the larger design connecting work, scoring, and rewards. The scoring model is
the evaluation method inside that design
([Glossary](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)).

Weight vectors and Yuma Consensus come later in the flow: they use validator outputs after scoring
has already taken place.
