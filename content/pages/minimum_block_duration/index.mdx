# Minimum Block Duration

Minimum block duration is a crowdloan pallet runtime constant, listed in the chain's constants
metadata as minimumBlockDuration, with the value 50400 and the summary "The minimum block duration
for a crowdloan"
([Subtensor API Constants: minimumBlockDuration](https://docs.learnbittensor.org/subtensor-api/constants#minimumblockduration-u32)).
It sets the shortest span, measured in blocks, that a single crowdloan may run.

## What It Means

A crowdloan collects contributions over a fixed window before it ends
([Crowdloans](https://docs.learnbittensor.org/subnets/crowdloans)). Minimum block duration sets the
floor on how long that window may be: a crowdloan cannot be configured to run for fewer than 50400
blocks
([Subtensor API Constants: minimumBlockDuration](https://docs.learnbittensor.org/subtensor-api/constants#minimumblockduration-u32)).
Because the span is counted in blocks, its length in calendar time depends on block speed; at twelve
seconds per block, 50400 blocks is about seven days. The floor applies to each crowdloan's own
configured duration, so no crowdloan can set a run window shorter than this value.

## Distinction from the Maximum Duration

Minimum block duration works together with the maximum block duration, which is valued at 432000
blocks, or about sixty days at twelve seconds per block
([Subtensor API Constants: maximumBlockDuration](https://docs.learnbittensor.org/subtensor-api/constants#maximumblockduration-u32)).
The minimum is the shortest a crowdloan may run and the maximum is the longest, so together the two
constants bound a crowdloan's run window to roughly seven to sixty days. A crowdloan's chosen
duration must fall inside that band, and this constant fixes its lower end.

## Why the Duration Has a Floor

Setting a floor on the duration means a crowdloan stays open long enough for contributors to take
part rather than closing almost immediately. A minimum run length gives the collection period a
guaranteed span, so a crowdloan cannot open and close within a handful of blocks
([Crowdloans](https://docs.learnbittensor.org/subnets/crowdloans)). The floor shapes the timing of a
crowdloan, not the amount it raises.

## Distinction from the Creation Deposit

Minimum block duration governs how long a crowdloan runs, while a separate threshold governs the
cost of opening one. The minimum deposit, valued at 10000000000 rao, or 10 TAO, is what the creator
must put up to start a crowdloan
([Subtensor API Constants: minimumDeposit](https://docs.learnbittensor.org/subtensor-api/constants#minimumdeposit-u64)).
One constant is about time; the other is about the up-front deposit. They constrain different
aspects of the same crowdloan.

## Reader Boundary

Minimum block duration is a single network-wide constant, not a per-subnet value, and it reflects
the current runtime configuration rather than a fixed protocol rule; the value could change in a
future runtime upgrade. It sets a crowdloan's shortest run length in blocks and does not describe
how much a crowdloan raises or whether it meets its goal
([Subtensor API Constants: minimumBlockDuration](https://docs.learnbittensor.org/subtensor-api/constants#minimumblockduration-u32)).
