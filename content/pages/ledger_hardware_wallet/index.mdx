# Ledger Hardware Wallet

A Ledger hardware wallet is a hardware signing device that can be used with Bittensor-compatible
wallet applications to manage TAO while keeping the private key inside the device. The official
[Using Ledger Hardware Wallet](https://docs.learnbittensor.org/staking-and-delegation/using-ledger-hw-wallet)
guide describes Ledger use for managing TAO on the Bittensor network, and the official
[Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)
guide frames Ledger as one of the hardware-wallet options for primary coldkey custody.

In Taopedia terms, the important concept is the signing boundary. A Ledger does not make a wallet
permissionless, and it does not remove the need to review transactions. It changes where the private
key lives and where signing occurs.

## What It Represents

Bittensor wallet documentation distinguishes the cryptographic wallet, the wallet application, and
the hardware wallet. The cryptographic wallet is the key-pair identity. The application prepares and
submits operations. The Ledger holds the private key and signs across a device boundary so the
coldkey private key does not load directly into the host operating system
([Wallets, Coldkeys and Hotkeys in Bittensor](https://docs.learnbittensor.org/keys/wallets)).

The primary coldkey is the highest-authority key for balances, stake, governance-sensitive actions,
and hotkey management. Ledger belongs in that custody tier when a user wants sensitive coldkey
actions authorized without keeping private key material in ordinary internet-connected software
([Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

Compatible wallet applications handle the interface, network context, transaction construction, and
submission flow while the Ledger signs what the user approves on the device. The official guidance
describes Ledger use for TAO transfers, staking, unstaking, and proxy creation through supported
wallet apps — not as a promise that every BTCLI, SDK, or Subtensor workflow is available through
every Ledger-connected interface
([Using Ledger Hardware Wallet](https://docs.learnbittensor.org/staking-and-delegation/using-ledger-hw-wallet),
[Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

The guidance also names which device app is required. Because Bittensor keys follow the Substrate
scheme, using a Ledger with Bittensor requires installing the Polkadot (DOT) app from Ledger Live
rather than a TAO-specific app
([Using Ledger Hardware Wallet](https://docs.learnbittensor.org/staking-and-delegation/using-ledger-hw-wallet)).

Ledger reduces private-key exposure on the host, but it does not make the surrounding system
trustworthy. Users still must verify recipient, amount, network context, and transaction meaning
before approving signatures, including against address-poisoning guidance on copied or abbreviated
addresses ([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

The safer pattern keeps the primary coldkey in hardware custody, uses compatible applications from
official sources, prefers scoped proxies for routine work, and treats every signature request as a
high-value decision ([Proxies overview](https://docs.learnbittensor.org/keys/proxies)).

## Development Stage Context

The
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction#subnet-development)
describes subnet development as moving from localnet to testnet and then mainnet. Ledger signing
examples should be read against that network boundary rather than as proof of production custody
behavior on another network
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from External Wallet

Ledger hardware wallet and external wallet are related but different wallet-security ideas. A Ledger
hardware wallet names a hardware signing device that keeps the private key on the device during
supported wallet-app operations, while an external wallet names custody or wallet software managed
outside the local Bittensor wallet path
([Glossary: External Wallet](https://docs.learnbittensor.org/resources/glossary#external-wallet),
[Using Ledger Hardware Wallet](https://docs.learnbittensor.org/staking-and-delegation/using-ledger-hw-wallet)).

Signing-hardware vocabulary and custody-location vocabulary answer different wallet questions.

- **Ledger hardware wallet** — hardware that holds the key and signs on-device.
- **External wallet** — custody or wallet software managed outside the local Bittensor wallet path.

## Distinction from Proxies

Ledger fits naturally with Bittensor proxy practice. The workstation-security guide says the primary
coldkey should remain in hardware custody and that, after the initial proxy relationship exists,
scoped proxies can handle subsequent operational work. It also states that Ledger can support proxy
creation when used through compatible wallet apps
([Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

Hardware-custody vocabulary and scoped-delegation vocabulary answer different control questions.

- **Ledger hardware wallet** — hardware custody for the primary coldkey.
- **Proxies** — scoped delegation that limits routine signing authority.

## Distinction from Hotkeys

Ledger custody is mainly about protecting the coldkey. Hotkeys have a different Bittensor role: they
identify miners and validators for operational activity. The wallet documentation explains that a
coldkey can own or manage hotkeys, while hotkeys are used for subnet mining and validation
operations
([Wallets, Coldkeys and Hotkeys in Bittensor](https://docs.learnbittensor.org/keys/wallets)).

Coldkey-custody vocabulary and operational-key vocabulary answer different signing roles.

- **Ledger hardware wallet** — coldkey custody and signing boundary.
- **Hotkey** — operational key for subnet mining and validation.

## Distinction from Seed Phrase

A Ledger hardware wallet and a seed phrase sit on opposite sides of key custody. The Ledger is the
device that holds the private key and signs on-device, while the seed phrase is the recovery
material documentation treats as key-equivalent because it can regenerate the wallet's keys
([Glossary: Seed Phrase](https://docs.learnbittensor.org/resources/glossary#seed-phrase),
[Handle your Seed Phrase Securely](https://docs.learnbittensor.org/keys/handle-seed-phrase)).

This is why hardware custody does not remove seed-phrase risk: an exposed recovery phrase lets an
attacker restore the keys elsewhere regardless of the device that normally signs.

- **Ledger hardware wallet** — the device that holds the key and signs across a device boundary.
- **Seed phrase** — the recovery words that can regenerate the wallet's keys.

## Distinction from Private Key

A Ledger hardware wallet and a private key are a container and the secret it protects. The private
key is the cryptographic signing material itself, while the Ledger is the hardware that keeps that
key on the device and signs without exposing it to the host
([Glossary: Private Key](https://docs.learnbittensor.org/resources/glossary#private-key),
[Wallets, Coldkeys and Hotkeys](https://docs.learnbittensor.org/keys/wallets)).

- **Private key** — the secret signing material.
- **Ledger hardware wallet** — the device that stores and signs with that key on-device.

## Distinction from Coldkey and Hotkey Workstation Security

Workstation security and a Ledger hardware wallet are a model and a tool that supports it.
Workstation security is the practice of matching each operation to the right device and key
authority, while a Ledger is one hardware device used to keep the primary coldkey in offline signing
custody within that model
([Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security),
[Using Ledger Hardware Wallet](https://docs.learnbittensor.org/staking-and-delegation/using-ledger-hw-wallet)).

- **Workstation security** — the model of which authority belongs on which device.
- **Ledger hardware wallet** — one hardware device for offline coldkey custody.

## Distinction from Yuma Consensus

A Ledger hardware wallet keeps coldkey signing material on a hardware device separate from the host.
Yuma Consensus is the on-chain process that converts submitted validator weights into emission
shares
([Using Ledger Hardware Wallet](https://docs.learnbittensor.org/staking-and-delegation/using-ledger-hw-wallet),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Ledger hardware wallet** — hardware device that keeps coldkey material offline.
- **Yuma Consensus** — on-chain weight aggregation that settles emissions.

## Distinction from Address Verification

Ledger does not remove address-verification risk. Hardware signing can keep the private key off the
host machine, but the user still must confirm the intended recipient, amount, and transaction
meaning before approving a signature
([Using Ledger Hardware Wallet](https://docs.learnbittensor.org/staking-and-delegation/using-ledger-hw-wallet),
[Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

- **Ledger hardware wallet** — hardware custody and signing boundary.
- **Address verification** — deliberate review of destination and transaction details before
  signing.

## Reader Boundary

A Ledger hardware wallet should not be read as a general endorsement of any particular wallet-app
workflow, a guarantee that every operation is supported, or a substitute for transaction review. It
is the concept term for a hardware signing device used to keep Bittensor coldkey material inside
dedicated hardware while compatible software prepares supported chain interactions.

Specific setup steps, app compatibility details, and interface screens can change over time. Those
details should be checked against the current official Ledger and Bittensor wallet documentation
before moving funds or approving signatures.
