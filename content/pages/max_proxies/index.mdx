# Max Proxies

Max proxies is a proxy pallet runtime constant, listed in the chain's constants metadata as
maxProxies, with the value 20 and the summary "The maximum amount of proxies allowed for a single
account"
([Subtensor API Constants: maxProxies](https://docs.learnbittensor.org/subtensor-api/constants#maxproxies-u32)).
It sets the largest number of proxy delegates one account may register at the same time.

## What It Means

A proxy is an account that an owner authorizes to submit a defined class of calls on the owner's
behalf without holding the owner's keys. Max proxies caps how many such delegates a single account
can hold at once: no more than 20. Once an account already has 20 proxies, it must remove one before
adding another
([Subtensor API Constants: maxProxies](https://docs.learnbittensor.org/subtensor-api/constants#maxproxies-u32)).
The cap is a per-account limit rather than a network total.

## The Deposit Grows With Each Proxy

Registering proxies is not free of reserve. The proxy pallet reserves a deposit computed from two
constants: proxyDepositBase, valued at 60000000, plus proxyDepositFactor, valued at 33000000,
charged for each proxy the account adds
([Subtensor API Constants: proxyDepositBase](https://docs.learnbittensor.org/subtensor-api/constants#proxydepositbase-u64),
[Subtensor API Constants: proxyDepositFactor](https://docs.learnbittensor.org/subtensor-api/constants#proxydepositfactor-u64)).
These values are denominated in rao, the base unit where one TAO is 1,000,000,000 rao, so the base
is 0.06 TAO and each added proxy adds 0.033 TAO to the reserved amount. Because the factor applies
per proxy, holding closer to the 20-proxy cap reserves a larger deposit than holding just one.

## Distinction from Max Pending

Max proxies and max pending limit different parts of the proxy system. Max proxies caps the number
of standing proxy delegates an account may hold, while max pending, valued at 75, caps how many
time-delayed proxy announcements may be pending at once
([Subtensor API Constants: maxPending](https://docs.learnbittensor.org/subtensor-api/constants#maxpending-u32)).
One bounds the roster of delegates; the other bounds the queue of announced-but-not-yet-executed
calls. An account can reach one limit without being near the other.

## Announcement Deposits Are Separate

The pending announcement queue carries its own reserve, distinct from the proxy deposit. The proxy
pallet reserves an announcement deposit built from a base of 36000000 rao, or 0.036 TAO, plus a
per-announcement amount of 68000000 rao, or 0.068 TAO
([Subtensor API Constants: announcement deposit base](https://docs.learnbittensor.org/subtensor-api/constants#announcementdepositbase-u64),
[Subtensor API Constants: announcement deposit factor](https://docs.learnbittensor.org/subtensor-api/constants#announcementdepositfactor-u64)).
Adding a proxy and announcing a time-delayed call therefore draw on two separate reserves, and max
proxies bounds only the roster of delegates.

## Reader Boundary

Max proxies is a single network-wide constant, not a per-subnet value, and it reflects the current
runtime configuration rather than a fixed protocol rule; the value could change in a future runtime
upgrade. It caps the count of proxies per account and does not by itself describe which call types a
proxy may make or the delay a time-delayed proxy enforces
([Subtensor API Constants: maxProxies](https://docs.learnbittensor.org/subtensor-api/constants#maxproxies-u32)).
