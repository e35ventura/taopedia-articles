# Child Hotkeys

Child hotkeys are a Bittensor feature that lets a parent hotkey re-delegate a proportion of its
stake weight to one or more child hotkeys, which then validate on the parent's behalf. The official
[Child Hotkeys](https://docs.learnbittensor.org/validators/child-hotkeys) documentation describes
them as a way for a subnet validator to use a separate delegate hotkey per subnet instead of
exposing one hotkey across every subnet it validates in.

The relationship moves stake _weight_, not ownership. Stake stays with the parent's [[Coldkeys]] and
stakers; the child hotkey only borrows the consensus weight needed to validate. This makes child
hotkeys distinct from [[Delegation]], where TAO holders delegate to a validator, and from
[[Staking]], which adds stake to a hotkey.

## Parent and Child Relationship

A parent allocates weight to children using decimal proportions. According to the official
[Child Hotkeys](https://docs.learnbittensor.org/validators/child-hotkeys#features) documentation,
the proportions assigned to children must sum to at most `1.0`, and any remainder stays with the
parent. A parent can therefore split its [[Stake Weight]] across several children, or move it
entirely to one child while retaining none for itself.

Once children are set, the child hotkey performs validation work and is the hotkey that needs a
[[Validator Permit]] on that subnet. The parent does not have to run validation directly on a subnet
it has delegated away through a child.

## Security Benefit

The documented motivation is operational security. The
[Benefits of child hotkeys](https://docs.learnbittensor.org/validators/child-hotkeys#benefits-of-child-hotkeys)
section explains that if an attacker compromises a child hotkey, only the subnets that use that
child are exposed, rather than every subnet the parent validates in. A validator can run each child
on a different machine, keeping the high-value parent key off the validation hosts.

## Childkey Take

A child hotkey can keep a share of the dividends it earns while validating for the parent. The
official
[Get and set child hotkey take](https://docs.learnbittensor.org/validators/child-hotkeys#get-and-set-child-hotkey-take)
documentation states that this childkey take is configured per subnet and must be between `0` and
`18%`. This is separate from [[Validator Take]]: validator take is the parent validator's fee on
delegated-stake emissions, while childkey take is the child's share of the [[Dividends]] it produces
on the subnet it validates.

## Requirements and Rate Limits

The official documentation lists several constraints that bound how child hotkeys can be used:

- **Minimum stake**: the parent must hold a minimum total stake, measured as the TAO-equivalent
  value of its alpha across all subnets, before it can set children
  ([Minimum stake requirement](https://docs.learnbittensor.org/validators/child-hotkeys#minimum-stake-requirement)).
- **Children per subnet**: a parent can set a limited number of children per netuid.
- **Rate limits**: setting or revoking children, and changing childkey take, are
  [rate limited](https://docs.learnbittensor.org/validators/child-hotkeys#rate-limits) so they
  cannot be changed every block.

Exact thresholds, child counts, and cooldown windows are chain parameters that can change, so the
current values should be read from the official documentation or queried from the chain rather than
assumed from this page.

## Managing Child Hotkeys

Child hotkeys are managed through the [Bittensor CLI](https://docs.learnbittensor.org/btcli) under
the `btcli stake child` command group, which the reference documents with subcommands to set, get,
revoke, and adjust the take:

- `btcli stake child set` — assign children and their proportions.
- `btcli stake child get` — list the current children for a hotkey.
- `btcli stake child revoke` — remove existing children.
- `btcli stake child take` — get or set the childkey take on a subnet.

## Reader Boundary

Child hotkeys are an operational tool for [[Subnet Validator]] key management, not a staking
recommendation or a yield product. They do not increase total emissions; they redistribute who does
the validation work and who keeps a share of the resulting dividends. Specific proportions, take
percentages, stake minimums, and rate limits depend on current chain state and should be verified
directly.
