# Alpha Halving

An alpha halving is a subnet-scoped emission-rate reduction for a subnet's alpha token. It applies
halving terminology to subnet alpha supply rather than to network-wide TAO supply. The key question
is which subnet's alpha-token emission rate is being reduced.

References: [Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving),
[Glossary: Alpha Tokens](https://docs.learnbittensor.org/resources/glossary#alpha-tokens),
[Glossary: Alpha Halving](https://docs.learnbittensor.org/resources/glossary#alpha-halving)

## Subnet Scope

Each subnet has its own alpha token, so alpha halving is read in relation to one subnet's
alpha-token supply. It is a subnet-level tokenomics event rather than a network-wide event affecting
every subnet in the same way.

Because alpha tokens are subnet-specific, an alpha-halving reference needs the subnet attached. The
same halving vocabulary can describe a supply schedule, but the affected asset is the selected
subnet's alpha token rather than TAO or another subnet's alpha token.

References: [Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Glossary: Alpha Tokens](https://docs.learnbittensor.org/resources/glossary#alpha-tokens)

## Emission Reduction

A halving reduces the rate at which new tokens are emitted after a supply milestone is reached. For
alpha halving, the reduced emission is the alpha-token emission for the relevant subnet.

The useful point is narrow: alpha halving slows future alpha creation for that subnet. It describes
a supply-schedule change, not a transfer action, validator evaluation, or reward-quality score.

The supply-milestone framing also keeps the term tied to emission rate rather than to a one-time
user action. The event is about how quickly new alpha is produced after the milestone, not about
moving existing alpha between accounts.

References: [Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving),
[Emission](https://docs.learnbittensor.org/learn/emissions)

## Alpha Token Context

Alpha tokens are subnet-specific assets used inside subnet tokenomics. Alpha halving matters because
it changes the emission rate of that subnet-specific asset.

This keeps the terminology separate: alpha token identifies the asset, while alpha halving refers to
an emission-rate reduction for that asset.

That distinction is useful in Dynamic TAO discussions because alpha tokens and TAO can appear
together in subnet tokenomics. Alpha halving concerns the alpha-token side of that setting; it does
not rename the network token or the TAO reserve side.

References:
[Glossary: Alpha Tokens](https://docs.learnbittensor.org/resources/glossary#alpha-tokens),
[Emission](https://docs.learnbittensor.org/learn/emissions),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)

## TAO Halving Contrast

Alpha halving and TAO halving use the same broad supply-milestone idea, but they apply at different
scopes. One belongs to a subnet's alpha-token supply, and the other belongs to the network's TAO
supply.

Keeping that distinction avoids reading a subnet-level alpha event as a network-level TAO event. The
shared word is halving; the asset and scope are different.

Issuance is also different from alpha halving. Issuance is the circulating TAO supply measure used
around network-level TAO halving, while alpha halving concerns the selected subnet's alpha-token
emission rate.

References: [Glossary: Halving](https://docs.learnbittensor.org/resources/glossary#halving),
[Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving),
[Glossary: Issuance](https://docs.learnbittensor.org/resources/glossary#issuance),
[Glossary: Alpha Halving](https://docs.learnbittensor.org/resources/glossary#alpha-halving)

## Incentives and Rewards

Alpha halving changes an emission-rate input. Miner evaluation, validator rewards, and subnet
incentive design come from the subnet's mechanisms and consensus process. Alpha halving names the
supply-rate change for the subnet alpha token.

That means alpha halving can change the emission setting without explaining how miners are evaluated
inside the subnet. Incentive mechanisms define useful work, and consensus organizes validator
evaluation.

References: [Emission](https://docs.learnbittensor.org/learn/emissions),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)

## Reading Alpha Halving

Alpha halving names subnet tokenomics terminology for a reduction in alpha-token emission rate. The
central point is that alpha-token emission can be reduced at the subnet level while remaining
distinct from broader TAO halving. Timing examples and observed values need the same subnet scope
because alpha halving is not a network-wide TAO event.

References: [Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving),
[Glossary: Alpha Halving](https://docs.learnbittensor.org/resources/glossary#alpha-halving),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)

## Network Examples

Bittensor separates mainnet, testnet, and localnet environments. Alpha-halving examples from one
environment belong to that environment because subnet state, alpha supply, and tokenomics conditions
can differ.

Localnet examples are isolated development examples. Testnet examples are shared non-production
examples. Mainnet alpha-halving interpretation concerns production subnet tokenomics behavior.

Specific numbers or milestone examples need the network, subnet, and source that produced them. The
concept travels across environments; the measured state belongs to one environment.

References: [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Introduction to Bittensor: Subnet development](https://docs.learnbittensor.org/learn/introduction#subnet-development)

## Participant Alpha Halves Uniformly Per Block

Official [Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving) documentation states
that during an [alpha halving](https://docs.learnbittensor.org/resources/glossary#alpha-halving),
the amount of [alpha](https://docs.learnbittensor.org/resources/glossary#alpha-tokens) distributed
to miners, validators, and the subnet owner each block is reduced by half. That cut applies
uniformly to every participant role inside the affected subnet.

That uniform per-block reduction is a different reading boundary from how rewards are ranked inside
the subnet. [Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus) still decides how
the reduced per-block alpha pool is split among miners and validators, and
[Emission](https://docs.learnbittensor.org/learn/emissions) still describes the broader distribution
stages. Alpha halving names the supply-rate step that shrinks the shared per-block alpha budget
before those allocation paths run.

The halving therefore changes how much new alpha enters the participant distribution path each
block, not which evaluation rules decide relative shares within that smaller pool.

References: [Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving),
[Emission](https://docs.learnbittensor.org/learn/emissions)

## TAO Halving Keeps Participant Alpha Steady

[Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving) splits alpha emissions into
two components that respond differently when a network-level
[TAO halving](https://docs.learnbittensor.org/resources/glossary#halving) occurs. Alpha injected
into a subnet pool alongside TAO reserve activity is cut in half because it tracks TAO injection to
preserve the pool price relationship. Alpha rewards distributed to miners, validators, and the
subnet owner stay at their prior level during that same TAO halving event.

An alpha halving moves the opposite path. It reduces the participant-facing alpha distribution rate
for one subnet when that subnet's own alpha issuance reaches its threshold, rather than leaving
participant alpha steady while only the pool-injection side changes.

That split helps when the word halving appears without an asset label. A TAO halving statement can
still change subnet pool injection without halving participant alpha rewards. An alpha halving
statement names a participant-side rate cut inside one subnet's tokenomics schedule.

References: [Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)

## Alpha Outstanding Matches the Emission Rate

[Emission](https://docs.learnbittensor.org/learn/emissions) documentation describes alpha
outstanding as alpha set aside to be distributed to subnet participants, and it ties the per-block
quantity to the subnet's alpha emission rate. Each block, the amount routed toward that outside-pool
participant path equals that rate for the selected subnet.

When an alpha halving reduces the subnet's alpha emission rate, the per-block alpha outstanding
accumulation step falls with it. The event therefore changes how quickly new alpha builds in the
participant distribution queue, not how existing alpha already held in reserves or hotkeys is
labeled.

That connection keeps alpha halving tied to the outstanding-side emission path described in
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets), separate
from alpha reserve injection that adds pool-side liquidity alongside TAO reserve activity. Halving
vocabulary on the outstanding path names a slower per-block build rate; reserve injection names a
different alpha movement inside the subnet market.

References:
[Emission: Alpha outstanding injection](https://docs.learnbittensor.org/learn/emissions#alpha-outstanding-injection),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)
