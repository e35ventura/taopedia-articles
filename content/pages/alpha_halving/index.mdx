# Alpha Halving

An alpha halving is a subnet-scoped emission-rate reduction for a subnet's alpha token. It applies
halving terminology to subnet alpha supply rather than to network-wide TAO supply. The key question
is which subnet's alpha-token emission rate is being reduced
([Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving),
[Glossary: Alpha Tokens](https://docs.learnbittensor.org/resources/glossary#alpha-tokens),
[Glossary: Alpha Halving](https://docs.learnbittensor.org/resources/glossary#alpha-halving)).

## Subnet Scope

Each subnet has its own alpha token, so alpha halving is read in relation to one subnet's
alpha-token supply. It is a subnet-level tokenomics event rather than a network-wide event affecting
every subnet in the same way
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

Because alpha tokens are subnet-specific, an alpha-halving reference needs the subnet attached. The
same halving vocabulary can describe a supply schedule, but the affected asset is the selected
subnet's alpha token rather than TAO or another subnet's alpha token.

## Emission Reduction

A halving reduces the rate at which new tokens are emitted after a supply milestone is reached. For
alpha halving, the reduced emission is the alpha-token emission for the relevant subnet
([Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving),
[Emission](https://docs.learnbittensor.org/learn/emissions)).

The useful point is narrow: alpha halving slows future alpha creation for that subnet. It describes
a supply-schedule change, not a transfer action, validator evaluation, or reward-quality score.

The supply-milestone framing also keeps the term tied to emission rate rather than to a one-time
user action. The event is about how quickly new alpha is produced after the milestone, not about
moving existing alpha between accounts.

## Alpha Token Context

Alpha tokens are subnet-specific assets used inside subnet tokenomics. Alpha halving matters because
it changes the emission rate of that subnet-specific asset
([Glossary: Alpha Tokens](https://docs.learnbittensor.org/resources/glossary#alpha-tokens),
[Emission](https://docs.learnbittensor.org/learn/emissions)).

This keeps the terminology separate: alpha token identifies the asset, while alpha halving refers to
an emission-rate reduction for that asset.

That distinction is useful in Dynamic TAO discussions because alpha tokens and TAO can appear
together in subnet tokenomics. Alpha halving concerns the alpha-token side of that setting; it does
not rename the network token or the TAO reserve side.

## TAO Halving Contrast

Alpha halving and TAO halving use the same broad supply-milestone idea, but they apply at different
scopes. One belongs to a subnet's alpha-token supply, and the other belongs to the network's TAO
supply ([Glossary: Halving](https://docs.learnbittensor.org/resources/glossary#halving),
[Glossary: Issuance](https://docs.learnbittensor.org/resources/glossary#issuance),
[Glossary: Alpha Halving](https://docs.learnbittensor.org/resources/glossary#alpha-halving)).

Keeping that distinction avoids reading a subnet-level alpha event as a network-level TAO event. The
shared word is halving; the asset and scope are different.

Issuance is also different from alpha halving. Issuance is the circulating TAO supply measure used
around network-level TAO halving, while alpha halving concerns the selected subnet's alpha-token
emission rate.

## Incentives and Rewards

Alpha halving changes an emission-rate input. Miner evaluation, validator rewards, and subnet
incentive design come from the subnet's mechanisms and consensus process. Alpha halving names the
supply-rate change for the subnet alpha token
([Emission](https://docs.learnbittensor.org/learn/emissions),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

That means alpha halving can change the emission setting without explaining how miners are evaluated
inside the subnet. Incentive mechanisms define useful work, and consensus organizes validator
evaluation.

## Alpha Emission, Subnet Pools, and Yuma Reward Pipeline

Alpha halving sits upstream of the reward path that subnet participants experience each tempo.
[Emission](https://docs.learnbittensor.org/learn/emissions) documentation separates injection and
distribution: every block, TAO and subnet alpha enter each subnet's pools, and every tempo the
accumulated value is extracted through
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)
([Emission: Injection and distribution](https://docs.learnbittensor.org/learn/emissions#injection-and-distribution-two-stages-of-the-emissions-process)).

Alpha halving changes how quickly new alpha enters that injection stage for one subnet. It does not
replace validator evaluation or the consensus aggregation step that turns weight signals into miner
incentives and validator dividends
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

For readers on a subnet such as netuid 1, the pipeline order is: alpha halving lowers the subnet's
alpha emission rate, injection adds liquidity to subnet pools each block, validators submit weight
signals from off-chain evaluation, and Yuma resolves those signals into tempo-bound reward outcomes.

## TAO Halving and Alpha Halving Watch Different Supply Totals

[Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving) documentation separates
network TAO halving from subnet alpha halving. TAO halvings activate at network-level supply
thresholds, while alpha halvings use subnet-level alpha issuance thresholds
([Halving Mechanisms: Alpha Halvings](https://docs.learnbittensor.org/concepts/halving#alpha-halvings)).

For readers, the relevant distinction is what each halving measures and when it activates on its own
supply total. The merged [Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving) and
[[Halving]] articles now carry both scopes in one reference path rather than treating alpha halving
as a side note.

## Alpha Halving Index Feeds the Distribution Ratio

A subnet's alpha halving progress is tracked as an index, separate from the network's TAO halving
index. The
[Glossary: ADR](https://docs.learnbittensor.org/resources/glossary#adr-alpha-distribution-ratio)
entry defines Alpha Distribution Ratio as two raised to the power of the gap between the global TAO
halving index and a subnet's own alpha halving index, so a subnet's count of alpha halvings is a
direct input to that ratio rather than a side note
([Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving)).

A subnet that has gone through more alpha halvings relative to the network's TAO halving progress
shifts that ratio compared with a subnet that has gone through fewer. Alpha halving count is
therefore one of the two index values readers need before citing an ADR figure for a specific
subnet.

## Development Stage Context

The
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction#subnet-development)
describes subnet development as moving from localnet to testnet and then mainnet. For alpha halving
on a subnet such as netuid 1, that sequence changes how readers should interpret supply totals,
subnet pool injection, and alpha halving index examples.

In localnet, alpha halving thresholds and subnet alpha totals can be tested in an isolated
environment. Localnet alpha issuance and halving examples on netuid 1 reflect local chain
configuration rather than production subnet tokenomics.

On testnet, alpha halving behavior can be observed in a shared non-production network. Testnet alpha
supply and halving index values on a selected netuid are separate from mainnet chain state
([Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

On mainnet, alpha halving describes live production subnet tokenomics behavior on the connected
Bittensor network. Observed milestone timing or index values depend on current alpha supply and
halving history on the active netuid.

The [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks) reference
separates mainnet, testnet, and localnet. An alpha-halving example from one environment should not
be read as representing production tokenomics behavior in another environment.

## Reader Boundary

Alpha halving names subnet tokenomics terminology for a reduction in alpha-token emission rate. The
central point is that alpha-token emission can be reduced at the subnet level while remaining
distinct from broader TAO halving. Timing examples and observed values need the same subnet scope
because alpha halving is not a network-wide TAO event
([Halving Mechanisms](https://docs.learnbittensor.org/concepts/halving),
[Glossary: Alpha Halving](https://docs.learnbittensor.org/resources/glossary#alpha-halving)).
