# Max Fee Rate

Max fee rate is a swap pallet runtime constant, listed in the chain's constants metadata as
maxFeeRate, with the value 10000 and the summary "The maximum fee rate that can be set"
([Subtensor API Constants: maxFeeRate](https://docs.learnbittensor.org/subtensor-api/constants#maxfeerate-u16)).
The runtime sets this bound directly, with the source itself annotating the value as about 15.26%
([runtime/src/lib.rs](https://github.com/opentensor/subtensor/blob/14bc6f9f964b9cc362e9635dd110a487fa5d15a0/runtime/src/lib.rs#L1132)).

## What It Means

The swap pallet's fee rate is a normalized value rather than a plain percentage, so the constant's
own value of 10000 is not itself "10000%"; it is a fraction of the value type's full range, which
the runtime comment states works out to about 15.26%. This ceiling is a single network-wide value,
not a per-subnet setting.

The set_fee_rate call is root-only. Before it will store a submitted fee rate, the pallet source
first checks that the caller is root, then that the target subnet exists, and only then compares the
submitted rate against this constant, rejecting the call with FeeRateTooHigh if the submitted rate
is higher
([swap/mod.rs](https://github.com/opentensor/subtensor/blob/14bc6f9f964b9cc362e9635dd110a487fa5d15a0/pallets/swap/src/pallet/mod.rs#L185-L196),
[Subtensor API Errors: FeeRateTooHigh](https://docs.learnbittensor.org/subtensor-api/errors#feeratetoohigh)).

This is the same ceiling the fee_rate_too_high error page describes only as "the runtime maximum"
without stating the value.

## Reader Boundary

This page defines the constant, its value, and the root-only check that enforces it. It does not
report any subnet's currently configured fee rate, since that value is separate per-subnet chain
state set by individual set_fee_rate calls, nor the full mapping from the normalized rate to a
percentage across every possible value
([Subtensor API Constants: maxFeeRate](https://docs.learnbittensor.org/subtensor-api/constants#maxfeerate-u16)).
