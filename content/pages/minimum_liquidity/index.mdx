# Minimum Liquidity

Minimum liquidity is a swap pallet runtime constant, listed in the chain's constants metadata as
minimumLiquidity, with the value 1000 and the summary "Minimum liquidity that is safe for rounding
and integer math"
([Subtensor API Constants: minimumLiquidity](https://docs.learnbittensor.org/subtensor-api/constants#minimumliquidity-u64)).
It names a small floor of liquidity that keeps the pool's integer arithmetic well-behaved.

## What It Means

Swap pools work with whole-number amounts, and very small liquidity can make integer math round in
unhelpful ways. Minimum liquidity is the floor the swap pallet documents as safe for that rounding
and integer math, set at 1000
([Subtensor API Constants: minimumLiquidity](https://docs.learnbittensor.org/subtensor-api/constants#minimumliquidity-u64)).
It is a small fixed value that applies network-wide rather than being configured per subnet. Because
it is expressed as a plain number, it is the same low floor for every pool regardless of the assets
involved.

## Distinction from Minimum Reserve

Minimum liquidity and minimum reserve are both swap pallet floors, but they differ in size and role.
Minimum reserve, valued at 1000000, is the reserve floor a trade's output side is checked against
before a swap proceeds, and a swap is rejected with the ReservesTooLow error when the reserve is too
thin
([Subtensor API Constants: minimumReserve](https://docs.learnbittensor.org/subtensor-api/constants#minimumreserve-u64),
[Subtensor API Errors: ReservesTooLow](https://docs.learnbittensor.org/subtensor-api/errors#reservestoolow)).
Minimum liquidity, at 1000, is the far smaller rounding-safety floor. One guards the reserve size a
swap needs; the other guards the arithmetic.

## Distinction from Max Fee Rate

Minimum liquidity also differs from max fee rate, another swap pallet constant. Max fee rate, valued
at 10000, bounds the highest fee rate that can be set for a pool
([Subtensor API Constants: maxFeeRate](https://docs.learnbittensor.org/subtensor-api/constants#maxfeerate-u16)).
Minimum liquidity concerns the liquidity floor for safe math, while max fee rate concerns the
pricing of swaps. The two constants bound unrelated aspects of the same pallet.

## A Floor for Arithmetic, Not Trade Size

Minimum liquidity is set to keep the pool's integer arithmetic well-behaved, and at 1000 it is far
smaller than the reserve floor of 1000000 that governs whether a swap can proceed
([Subtensor API Constants: minimumReserve](https://docs.learnbittensor.org/subtensor-api/constants#minimumreserve-u64)).
It is a low-level guard on rounding rather than a threshold that gates meaningful trade size, and
because it is fixed network-wide the same small floor applies to every subnet's swap pool
([Subtensor API Constants: minimumLiquidity](https://docs.learnbittensor.org/subtensor-api/constants#minimumliquidity-u64)).

## Reader Boundary

Minimum liquidity is a single network-wide constant, not a per-subnet value, and it reflects the
current runtime configuration rather than a fixed protocol rule; the value could change in a future
runtime upgrade. It names the rounding-safe liquidity floor and does not describe a pool's live
liquidity or the price of any swap
([Subtensor API Constants: minimumLiquidity](https://docs.learnbittensor.org/subtensor-api/constants#minimumliquidity-u64)).
