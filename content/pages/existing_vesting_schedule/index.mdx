# Existing Vesting Schedule

`ExistingVestingSchedule` is a balances pallet error raised when a new vesting schedule is submitted
for an account that already has one. The API errors reference documents this error on the
vesting-schedule creation path
([Subtensor API Errors: ExistingVestingSchedule](https://docs.learnbittensor.org/subtensor-api/errors#existingvestingschedule)).

## What It Means

A vesting schedule locks a portion of an account's balance for a period of time. The balances pallet
rejects a second vesting schedule when one is already in place. `ExistingVestingSchedule` fires when
a new vesting schedule is submitted for an account that already has an active schedule
([Subtensor API Errors: ExistingVestingSchedule](https://docs.learnbittensor.org/subtensor-api/errors#existingvestingschedule)).

This is a no-existing-schedule rejection, not proof that the account lacked balance, that the
vesting amount was invalid, or that the schedule had already completed.

## Why It Appears

This error appears when a vesting schedule creation is submitted for an account that already has a
vesting schedule and the pallet rejects the duplicate
([Subtensor API Errors: ExistingVestingSchedule](https://docs.learnbittensor.org/subtensor-api/errors#existingvestingschedule)).

## Distinction from Vesting Balance

`ExistingVestingSchedule` and `VestingBalance` are both balances-pallet errors that involve vesting,
but they fire at different checks. `ExistingVestingSchedule` fires when a new schedule is submitted
for an account that already has one. `VestingBalance` fires when an account's vesting balance is too
high to allow a transfer
([Subtensor API Errors: ExistingVestingSchedule](https://docs.learnbittensor.org/subtensor-api/errors#existingvestingschedule),
[Subtensor API Errors: VestingBalance](https://docs.learnbittensor.org/subtensor-api/errors#vestingbalance)).

- **ExistingVestingSchedule** — the account already has a vesting schedule.
- **VestingBalance** — the vesting balance is too high to send value.

## Distinction from Delta Zero

`ExistingVestingSchedule` and `DeltaZero` are both balances-pallet errors that block a balances
operation, but they fire at different checks. `ExistingVestingSchedule` fires when a new vesting
schedule is submitted for an account that already has one. `DeltaZero` fires when the submitted
delta amount is zero
([Subtensor API Errors: ExistingVestingSchedule](https://docs.learnbittensor.org/subtensor-api/errors#existingvestingschedule),
[Subtensor API Errors: DeltaZero](https://docs.learnbittensor.org/subtensor-api/errors#deltazero)).

- **ExistingVestingSchedule** — the account already has a vesting schedule.
- **DeltaZero** — the submitted delta amount is zero.

## Reader Boundary

This page defines the meaning of the error label and the no-existing-schedule guard it represents on
the vesting creation path. It does not report which accounts currently have vesting schedules,
describe the vesting schedule parameters, or list the extrinsics that create schedules
([Subtensor API Errors: ExistingVestingSchedule](https://docs.learnbittensor.org/subtensor-api/errors#existingvestingschedule)).
