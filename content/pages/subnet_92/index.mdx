TensorClaw is Bittensor Subnet 92, a decentralized large-language-model inference subnet. Its
on-chain description explains the goal: to aggregate high-quality LLM serving nodes globally through
Bittensor's incentive mechanism and expose them as a single, highly available, load-balanced API.
The codebase for the subnet is the `tensorclaw/tensorclaw` repository.

## What TensorClaw Rewards

The subnet's product is a unified inference endpoint. Instead of an application talking to one model
provider, TensorClaw pools many independent serving nodes behind a common, compatible API and
spreads requests across them, so the service stays available even when individual nodes fail. If a
node drops mid-request, the traffic is rerouted to another node in the pool.

What makes the incentive notable is that it is tied to real usage. Rather than rewarding nodes
simply for being online, the subnet weights rewards heavily toward the volume of genuine requests a
miner serves well, with a smaller portion coming from health and responsiveness checks. The guiding
principle, stated in the project's documentation, is that whoever processes more real requests with
high quality earns more — which points the incentive at actually serving users rather than at idle
capacity.

## Miner and Validator Roles

Miners operate the inference backends. A miner runs a model-serving endpoint and connects it to the
network to answer inference requests; the routing layer reaches miners as clients, so they do not
need to expose a public address. A miner earns mainly by reliably serving a high volume of real
requests with good quality and low latency.

Validators check that miners are genuinely serving and decide how reward is distributed. They send
real test prompts to confirm a node actually produces responses rather than faking availability, and
they track responsiveness and uptime. Combined with how much real request traffic a miner has
handled well, these signals determine the scores from which validators set weights on the network,
which is how reward flows through [[Yuma Consensus]]. At the article level the split is
straightforward: miners serve model inference, while validators verify and measure that service and
weight the network accordingly.

## On-Chain Identity

Live SN92 subnet data is available on [TaoStats](https://taostats.io/subnets/92), which identifies
the subnet as TensorClaw. Readers can reproduce the subnet identity fields directly with the
Bittensor CLI command documented in the
[btcli reference](https://docs.learnbittensor.org/btcli/#btcli-subnets-get-identity):
`btcli subnets get-identity --netuid 92 --network finney`. That Finney identity is the source of
truth for the subnet name and the GitHub repository associated with the subnet.
