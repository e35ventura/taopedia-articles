# Call Disabled

`CallDisabled` is a documented Subtensor standard error raised when an extrinsic call is attempted
while that call has been disabled on the runtime. The standard-errors reference describes it as
"Call is disabled"
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#calldisabled),
[Subtensor API Errors: CallDisabled](https://docs.learnbittensor.org/subtensor-api/errors#calldisabled)).

## What It Means

Subtensor can disable specific extrinsic calls administratively, preventing them from being executed
on the chain regardless of who signs the transaction or whether all other preconditions would pass.
`CallDisabled` is returned when such a disabled call is submitted
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#calldisabled)).

This is a runtime gating rejection, not proof that the caller lacks permission, that submitted
arguments are invalid, or that a related feature flag is toggled off. The call itself has been
disabled at the administrative level.

## Why It Appears

This error appears when a client, automation, or wallet submits an extrinsic that the runtime
currently has disabled. That can happen when a call is temporarily gated during a migration or
upgrade, when the feature the call belongs to is paused, or when the extrinsic is deprecated and no
longer available for execution
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#calldisabled)).

The practical meaning is narrow: the specific extrinsic being called is not currently available. The
caller should check whether an alternative call, a different path, or a later network state
addresses the same need.

## Distinction from Not Permitted On Root Subnet

`CallDisabled` and `NotPermittedOnRootSubnet` both block calls that cannot proceed, but for
different reasons. `NotPermittedOnRootSubnet` means the specific operation is not allowed on the
root subnet by design. `CallDisabled` means the extrinsic itself has been administratively disabled
across the runtime, regardless of which subnet is targeted
([Subtensor Standard Errors: NotPermittedOnRootSubnet](https://docs.learnbittensor.org/errors/subtensor#notpermittedonrootsubnet)).

- **CallDisabled** — the extrinsic is administratively disabled on the runtime.
- **NotPermittedOnRootSubnet** — the operation is not allowed on the root subnet by design.

## Reader Boundary

This page defines the meaning of the error label and the administrative gate that raises it. It does
not describe which specific calls can be disabled or how runtime call gating is configured; those
depend on the current network state and are not reported through hyperparameter reads
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
