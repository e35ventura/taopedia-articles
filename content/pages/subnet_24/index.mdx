# Subnet 24: Quasar

Quasar is Bittensor Subnet 24, a subnet focused on long-context language-model training and
evaluation. Miners publish Quasar-compatible model revisions, and validators compare those public
models under Quasar's evaluation rules
([Quasar repository](https://github.com/SILX-LABS/QUASAR-SUBNET),
[Subnet 24 on TaoStats](https://taostats.io/subnets/24)).

## What the Subnet Provides

Quasar turns model improvement into a Bittensor subnet task. The project centers on small,
Quasar-compatible language models, with miners publishing model artifacts and validators scoring the
submitted revisions
([Quasar README](https://raw.githubusercontent.com/SILX-LABS/QUASAR-SUBNET/main/README.md)).

This makes Subnet 24 different from an inference-serving subnet. The durable object being compared
is the model revision itself, not a single answer from a hosted service.

## Model Family Context

The Quasar model card presents Quasar foundation models as long-context reasoning models for agentic
systems and persistent memory-based intelligence. The preview model is a base pretraining model for
distributed knowledge distillation on Bittensor SN24, not a finished benchmark model
([Quasar model card](https://huggingface.co/silx-ai/Quasar-3B-A1B-Preview/raw/main/README.md)).

That context helps explain why the subnet emphasizes iterative model improvement. The subnet's task
is not simply to rank arbitrary models; it is to improve a shared Quasar-compatible model family
through repeated public submissions and validator evaluation.

## Evaluation Model

Quasar validator scoring combines paired KL duels with a composite evaluator. A challenger needs
both direct comparison evidence and broader quality coverage before it can become the leading model
under the subnet's rules
([Quasar README](https://raw.githubusercontent.com/SILX-LABS/QUASAR-SUBNET/main/README.md)).

The composite evaluator covers dimensions such as distribution match, capability, conversational
quality, generation discipline, and robustness. This keeps the evaluation from collapsing into a
single narrow score and gives the subnet a broader quality filter for long-context models.

## Commitment and Public Model Boundary

Quasar depends on public model revisions. Miners publish model repositories and commit pinned model
revisions, while validators retrieve and evaluate those committed artifacts
([Quasar README](https://raw.githubusercontent.com/SILX-LABS/QUASAR-SUBNET/main/README.md)).

That public-revision boundary is important because validators need a stable artifact to compare. The
model commitment is the reference point for evaluation, while private training details and
unsubmitted experiments sit outside the subnet's scoring path.

## Relationship to Yuma Consensus

Subnet 24 still uses the ordinary Bittensor incentive path. Validators turn Quasar evaluation
results into weights, and those weights feed into Yuma Consensus. Yuma aggregates validator weight
submissions, and the emission system uses the resulting consensus weights to distribute subnet
emissions ([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Emission](https://docs.learnbittensor.org/learn/emissions)).

For Quasar, this connects model-evaluation results to Bittensor incentives. The subnet-specific work
is model submission and validator comparison; the protocol relationship to rewards still runs
through validator weights and Yuma Consensus.

## Environment Context

Quasar examples can belong to localnet, testnet, or mainnet contexts, and those environments should
not be mixed. A local example can help explain model evaluation behavior, while testnet and mainnet
are separate Bittensor network environments with separate histories
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Introduction to Bittensor: Subnet development](https://docs.learnbittensor.org/learn/introduction#subnet-development)).

Keeping the environment attached prevents overreading examples. A model score, validator comparison,
or emission outcome from one environment should not be treated as proof of behavior in another.

## Concept Boundaries

Subnet 24 should be read as a Quasar overview rather than a miner guide, validator guide, or model
architecture dump. The stable concept is public long-context model evaluation: miners publish
Quasar-compatible revisions, validators compare them, and Yuma Consensus turns weights into emission
allocation
([Quasar README](https://raw.githubusercontent.com/SILX-LABS/QUASAR-SUBNET/main/README.md),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

Exact model requirements, training recipes, validator settings, and leaderboard details belong in
Quasar's own materials. The stable distinction is that Quasar is a model-evaluation subnet, not a
general model card article.
