# Target Registrations Per Interval

Target registrations per interval is a per-subnet hyperparameter, listed in the documentation as
`TargetRegistrationsPerInterval`, that once named the reference registration count for
interval-based burn recalibration. The reference now states it is not used for neuron registration;
live admission is governed by continuous burn pricing through burn half life and burn increase mult
instead ([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## What It Controlled

Under the legacy interval model, the hyperparameter set how many registrations the mechanism aimed
for during each
[adjustment interval](https://docs.learnbittensor.org/subnets/subnet-hyperparameters) window. Actual
registrations during that window were compared to this target to decide whether the dynamic burn
moved up, down, or held
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Glossary: Burn Cost](https://docs.learnbittensor.org/resources/glossary#burn-cost)).

It did not set the burn band floor or ceiling, the interval length, or who could register. It only
supplied the reference count inside the older demand-comparison recalibration model.

## Removed From Current Registration Economics

The canonical hyperparameter API no longer relies on interval-based demand comparison for neuron
admission. Official documentation lists target registrations per interval among parameters not used
for neuron registration, alongside adjustment interval and related legacy pricing vocabulary. Live
subnet registration economics are instead set through burn half life and burn increase mult
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Readers encountering this term in older material should treat it as legacy registration-pricing
vocabulary. Current burn behavior should be verified through the live burn hyperparameters on the
relevant netuid.

## Documented Type and Default

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `TargetRegistrationsPerInterval` as a `u16` with a default of one. The permission
required to set it is root rather than subnet owner, reflecting its place in older global tuning
rather than ordinary per-subnet owner configuration
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Distinction from Burn Increase Mult

Burn increase mult steps the live registration burn up after each successful slot claim in the
current model. Target registrations per interval supplied the reference registration count for
legacy interval-based recalibration windows instead
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register)).

- **Burn increase mult** — per-registration step-up in the current burn model.
- **Target registrations per interval** — legacy reference count for interval recalibration.
