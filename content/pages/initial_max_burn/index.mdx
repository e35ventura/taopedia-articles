# Initial Max Burn

Initial Max Burn is a subtensorModule runtime constant, listed in the chain's constants metadata as
initialMaxBurn, with the value 100000000000 and the summary "Initial Max Burn"
([Subtensor API Constants: initialMaxBurn](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxburn-u64)).
It supplies the default value a subnet's MaxBurn uses.

## What It Means

MaxBurn is held per subnet and sets the ceiling on the TAO registration burn a subnet may charge.
Initial Max Burn is the default this per-subnet value falls back to before a different value applies
for a subnet
([Subtensor API Constants: initialMaxBurn](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxburn-u64)).
The MaxBurn in force on a subnet such as netuid 1 is that subnet's own chain state and can differ
from this default.

## Distinction from Burn and Min Burn

Initial Max Burn is the default maximum registration burn, while initialBurn, valued at 100000000,
is the starting registration burn; initialMinBurn, valued at 500000, is the floor on the
registration burn
([Subtensor API Constants: initialBurn](https://docs.learnbittensor.org/subtensor-api/constants#initialburn-u64),
[Subtensor API Constants: initialMinBurn](https://docs.learnbittensor.org/subtensor-api/constants#initialminburn-u64)).

## Reader Boundary

Initial Max Burn is a default constant, not the live per-subnet MaxBurn, and it reflects the current
runtime configuration rather than a fixed protocol rule
([Subtensor API Constants: initialMaxBurn](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxburn-u64)).
