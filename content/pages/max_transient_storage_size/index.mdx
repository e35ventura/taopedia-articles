# Max Transient Storage Size

Max transient storage size is a contracts pallet runtime constant, listed in the chain's constants
metadata as maxTransientStorageSize, with the value 1048576 and the summary "The maximum size of the
transient storage in bytes"
([Subtensor API Constants: maxTransientStorageSize](https://docs.learnbittensor.org/subtensor-api/constants#maxtransientstoragesize-u32)).
It caps how large a contract's transient storage may be, measured in bytes.

## What It Means

Transient storage is a storage area a contract can use, distinct from its persistent storage. Max
transient storage size sets the ceiling on how large that area may be: at most 1048576 bytes, which
is one mebibyte
([Subtensor API Constants: maxTransientStorageSize](https://docs.learnbittensor.org/subtensor-api/constants#maxtransientstoragesize-u32)).
The limit is a total size in bytes for the transient area, not a limit on the number of items placed
in it.

## Distinction from Max Storage Key Len

Max transient storage size and max storage key len are both byte limits in the contracts pallet, but
they measure different things. Max transient storage size caps the overall size of the transient
storage area at 1048576 bytes, while max storage key len caps the length of a single storage key at
128 bytes
([Subtensor API Constants: maxStorageKeyLen](https://docs.learnbittensor.org/subtensor-api/constants#maxstoragekeylen-u32)).
One bounds a whole storage area; the other bounds the length of an individual key. They apply to
different parts of a contract's use of storage.

## Distinction from Max Code Len

Max transient storage size also differs from max code len. Max transient storage size bounds a
storage area used while a contract runs, while max code len bounds the length of the contract's code
at 131072 bytes
([Subtensor API Constants: maxCodeLen](https://docs.learnbittensor.org/subtensor-api/constants#maxcodelen-u32)).
One is about a storage area associated with the contract; the other is about the size of the
contract program itself. The two are separate byte limits set on their own.

## Why a Size Limit Exists

Fixing a maximum transient storage size means the area stays within a known bound rather than being
of unlimited size. With the cap at 1048576 bytes, the largest the transient area can be is fixed in
advance
([Subtensor API Constants: maxTransientStorageSize](https://docs.learnbittensor.org/subtensor-api/constants#maxtransientstoragesize-u32)).
The limit describes the size of the area, and is one of several fixed size limits the contracts
pallet defines. Keeping the ceiling as a constant means the maximum is the same for every contract
rather than varying from one contract to another.

## Reader Boundary

Max transient storage size is a single network-wide constant, not a per-subnet value, and it
reflects the current runtime configuration rather than a fixed protocol rule; the value could change
in a future runtime upgrade. It caps the byte size of the transient storage area and does not
describe how that area is used
([Subtensor API Constants: maxTransientStorageSize](https://docs.learnbittensor.org/subtensor-api/constants#maxtransientstoragesize-u32)).
