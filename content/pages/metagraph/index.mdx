# Metagraph

The metagraph is Bittensor's structured view of neuron state for a subnet. The official glossary
describes it as a data structure containing comprehensive information about a subnet's neurons,
including validator stake and subnet weights, and says that it aids emission calculation.

References: [Glossary: Metagraph](https://docs.learnbittensor.org/resources/glossary#metagraph),
[The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph)

## Subnet-Scoped State

A metagraph is selected by a subnet identifier, or netuid. The Bittensor subnet metagraph
documentation explains this relationship using `netuid = 1` as an example, then describes the
metagraph as a snapshot of that subnet's state at a particular block. The same hotkey can therefore
appear in different subnet contexts, but each metagraph is read for one subnet at a time.

Reference: [The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph)

## What It Contains

The metagraph exposes aligned fields for the neurons in the selected subnet. Official references
list fields such as hotkeys, coldkeys, axon information, stake, rank, trust, consensus, incentive,
dividends, emission, validator trust, activity state, last update, validator permit, weights, and
bonds. These fields make the metagraph useful for reading both identity context and consensus
outputs without treating either as a recommendation or ranking guarantee.

References: [The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph),
[Understanding Neurons](https://docs.learnbittensor.org/learn/neurons),
[bittensor.core.metagraph](https://docs.learnbittensor.org/python-api/html/autoapi/bittensor/core/metagraph/)

## Snapshot Behavior

A metagraph is a snapshot, not a live stream. The subnet metagraph documentation describes sync as
the step that retrieves current chain data for the selected subnet. After more blocks are produced,
an older local view can be stale until it is synced again.

References: [The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph),
[bittensor.core.metagraph](https://docs.learnbittensor.org/python-api/html/autoapi/bittensor/core/metagraph/)

## Consensus and Emissions Context

Metagraph fields sit close to Bittensor's incentive layer. Validator weights, rank, trust,
consensus, incentive, dividends, and emission values are the kinds of state that readers encounter
when studying Yuma Consensus and Bittensor emissions. The metagraph does not define every formula by
itself; it is the structured subnet state that those mechanisms and tools read from or update
around.

References: [Glossary: Metagraph](https://docs.learnbittensor.org/resources/glossary#metagraph),
[Yuma Consensus](https://docs.learnbittensor.org/yuma-consensus/),
[Emission](https://docs.bittensor.com/emissions)

## Reader Boundary

This article defines the term at a high level. It does not list live subnet membership, current
stakes, current emissions, or wallet-specific data. Those values change with chain state, so readers
should use official tooling or chain queries when they need current values for a specific netuid.
