# Subnet Metagraph

A subnet metagraph is a Bittensor data view that represents the state of one subnet at a specific
block. It describes the subnet's participants, stake-related values, weight and bond data,
performance metrics, and selected subnet configuration fields, so it is usually the first place to
look when inspecting how a subnet is currently represented to clients and consensus tooling.

References: [The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph),
[Subtensor metagraph RPC source](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/rpc_info/metagraph.rs)

## What it contains

The metagraph includes participant-level fields such as UIDs, hotkeys, activity status, validator
permits, stake values, ranks, trust, consensus, incentives, dividends, emissions, weights, bonds,
axons, and update blocks. It also includes subnet-level fields such as the subnet identifier, name,
symbol, tempo, registration settings, weight settings, Commit Reveal settings, and selected Dynamic
TAO pool and emission values.

References: [The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph),
[Subtensor metagraph RPC source](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/rpc_info/metagraph.rs)

## How readers use it

Readers use metagraph data to inspect which participants are present on a subnet, compare validator
and miner metrics, understand which weight and bond data is available, and debug subnet state at a
particular block. The metagraph is a snapshot-style view, not the incentive mechanism itself:
[[yuma_consensus|Yuma Consensus]] uses validator-submitted weights and consensus calculations to
derive miner and validator emission vectors.

References: [The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)

## Access paths

Bittensor exposes metagraph data through several interfaces. BTCLI can inspect a subnet metagraph
and output an abridged view or JSON. The Python SDK can sync a `Metagraph` object in lite mode or
full mode, where full mode includes weight and bond matrices. Subtensor also exposes RPC functions
for complete, all-subnet, and selective metagraph queries.

References: [The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph),
[BTCLI reference](https://docs.learnbittensor.org/btcli),
[Subtensor metagraph RPC source](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/rpc_info/metagraph.rs)

## Lite and full views

The official metagraph docs distinguish lite and full sync modes. Lite mode is faster and excludes
weights and bonds; it corresponds to the subset shown by BTCLI. Full mode includes the weight and
bond matrices needed for deeper validator, miner, and consensus analysis.

Reference: [The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph)

## Relationship to consensus

Metagraph fields help explain the data around consensus, but the metagraph does not replace
consensus. Validators submit weight vectors for miners, Yuma Consensus clips and aggregates those
weights, and the resulting ranks, incentives, bonds, dividends, and emissions are reflected through
metagraph-facing data.

References: [The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)

## Practical cautions

Metagraph data is block-specific, so readers should treat it as a snapshot rather than a permanent
claim about a subnet. Exact values can differ by network, subnet, block, and sync mode. For
operational decisions, query current data directly and use the official docs or implementation code
to interpret field meaning.

References: [The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph),
[Subtensor metagraph RPC source](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/rpc_info/metagraph.rs)
