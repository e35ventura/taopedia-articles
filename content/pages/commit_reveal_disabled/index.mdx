# Commit Reveal Disabled

`CommitRevealDisabled` is a documented Subtensor standard error raised on the concealed weight path.
The standard-errors reference describes it as "Attempting to commit/reveal weights when disabled"
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#commitrevealdisabled)).

## What It Means

When `CommitRevealWeightsEnabled` is off for a subnet, validators submit weights through the plain
`set_weights` path instead of the commit-then-reveal flow. Commit and reveal extrinsics therefore
begin by confirming that the scheme is active on the targeted network. `CommitRevealDisabled` is the
rejection when that hyperparameter check fails, before registration, rate-limit, or commit-queue
logic runs
([Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs),
[Commit Reveal Weights Enabled](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#commitrevealweightsenabled),
[Commit-Reveal](https://docs.learnbittensor.org/concepts/commit-reveal)).

The same label appears on legacy commit extrinsics, timelocked commit extrinsics, and reveal paths
that all gate on the same enabled flag early in their handlers
([Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs)).

## Why It Appears

This error appears when automation or a client still sends commit or reveal calls to a subnet that
has not switched to concealed submission, or after a subnet turns commit-reveal off while older
clients keep using the concealed API. The rejection is about which extrinsic family the subnet
accepts, not about whether a stored commit exists or whether a reveal hash matches
([Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs),
[Subtensor Standard Errors: NoWeightsCommitFound](https://docs.learnbittensor.org/errors/subtensor#noweightscommitfound)).

For a reader, the practical meaning is narrow: that subnet entry must use plain weight submission
instead of commit-reveal calls. The problem is not that commit-reveal is required where plain
weights were sent, that the commit-reveal version tag is wrong, or that batch vector lengths
mismatch
([Subtensor Standard Errors: CommitRevealEnabled](https://docs.learnbittensor.org/errors/subtensor#commitrevealenabled),
[Subtensor Standard Errors: IncorrectCommitRevealVersion](https://docs.learnbittensor.org/errors/subtensor#incorrectcommitrevealversion)).

## Distinction from Commit Reveal Enabled

`CommitRevealDisabled` and `CommitRevealEnabled` are paired rejections on opposite weight paths.
`CommitRevealDisabled` means a commit or reveal submission was sent to a network where the concealed
scheme is off. `CommitRevealEnabled` means a plain batch weight entry was sent to a network where
commit-reveal is on
([Commit Reveal Enabled](https://docs.learnbittensor.org/errors/subtensor#commitrevealenabled),
[Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs)).

- **CommitRevealDisabled** — commit-reveal calls are not accepted because the scheme is off.
- **CommitRevealEnabled** — plain weight calls are not accepted because commit-reveal is on.

## Reader Boundary

This page defines the meaning of the error label and the disabled-scheme gate on commit-reveal
extrinsics. It does not describe reveal timing, commit queue limits, or how the hyperparameter is
configured; those are separate topics
([Commit-Reveal](https://docs.learnbittensor.org/concepts/commit-reveal),
[Commit Reveal Weights Enabled](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#commitrevealweightsenabled)).
