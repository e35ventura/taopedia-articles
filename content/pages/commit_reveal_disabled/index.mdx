# Commit Reveal Disabled

`CommitRevealDisabled` is a documented Subtensor standard error raised by commit-reveal weight
extrinsics. The standard-errors reference describes it as "Attempting to commit/reveal weights when
disabled"
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#commitrevealdisabled)).

## What It Means

When the `CommitRevealWeightsEnabled` hyperparameter is off for a network, validator weights must
use the direct weight path rather than concealed commit-then-reveal submission.
`CommitRevealDisabled` means a commit or reveal weight call targeted such a network, so the
extrinsic is rejected before registration, version-key, rate-limit, or commit-queue checks run
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#commitrevealdisabled),
[Commit Reveal Weights Enabled](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#commitrevealweightsenabled),
[Commit-Reveal](https://docs.learnbittensor.org/concepts/commit-reveal),
[Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs)).

In `weights.rs`, the commit and reveal paths check whether commit-reveal is enabled for the target
network at the start of the extrinsic and return `CommitRevealDisabled` when it is not
([Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs)).

## Why It Appears

This error appears on the commit-reveal path, not on plain weight extrinsics. It fires when
automation or a client still uses commit or reveal calls on a network that has not enabled concealed
submission. The rejection is about which extrinsic family is allowed, not about whether a stored
commit exists or whether a reveal arrived on time
([Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs),
[Subtensor Standard Errors: NoWeightsCommitFound](https://docs.learnbittensor.org/errors/subtensor#noweightscommitfound),
[Subtensor Standard Errors: RevealTooEarly](https://docs.learnbittensor.org/errors/subtensor#revealtooearly)).

For a reader, the practical meaning is narrow: that network entry must use plain weight submission
instead of commit and reveal extrinsics. The problem is not a missing stored commit, an enabled
scheme on the wrong path, or a mismatched batch vector length
([Subtensor Standard Errors: CommitRevealEnabled](https://docs.learnbittensor.org/errors/subtensor#commitrevealenabled),
[Subtensor Standard Errors: InputLengthsUnequal](https://docs.learnbittensor.org/errors/subtensor#inputlengthsunequal)).

## Distinction from Commit Reveal Enabled

`CommitRevealDisabled` and `CommitRevealEnabled` are paired rejections on opposite weight paths.
`CommitRevealDisabled` means a commit or reveal submission was sent to a network where the scheme is
off. `CommitRevealEnabled` means a plain weight submission was sent to a network where commit-reveal
is on
([Commit Reveal Enabled](https://docs.learnbittensor.org/errors/subtensor#commitrevealenabled),
[Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs)).

- **CommitRevealDisabled** — commit-reveal calls are not accepted because the scheme is off.
- **CommitRevealEnabled** — plain weight calls are not accepted because commit-reveal is on.

## Distinction from No Weights Commit Found

`CommitRevealDisabled` and `NoWeightsCommitFound` both appear in commit-reveal troubleshooting, but
they reject different stages. `CommitRevealDisabled` blocks the commit-reveal path before any stored
commit lookup runs because the scheme is off on that network. `NoWeightsCommitFound` means
commit-reveal is active and the reveal step could not find a matching stored commit
([No Weights Commit Found](https://docs.learnbittensor.org/errors/subtensor#noweightscommitfound),
[Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs)).

- **CommitRevealDisabled** — the network has not enabled commit-reveal.
- **NoWeightsCommitFound** — commit-reveal is enabled, but no matching stored commit exists.

## Reader Boundary

This page defines the meaning of the error label and the disabled-scheme gate on the commit-reveal
path. It does not describe reveal timing, commit queue limits, or how the hyperparameter is
configured; those are separate topics
([Commit-Reveal](https://docs.learnbittensor.org/concepts/commit-reveal),
[Commit Reveal Weights Enabled](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#commitrevealweightsenabled)).
