# TAO

TAO is the network token used in Bittensor incentive, staking, subnet reserve, and emissions
context. It sits at the center of Bittensor's incentive system
([Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction)), and emissions
include newly created TAO alongside subnet-specific alpha tokens
([Emission](https://docs.learnbittensor.org/learn/emissions)).

TAO is network-scoped. In Dynamic TAO, it appears beside subnet-scoped alpha tokens, so the
distinction between TAO and alpha affects how emission, staking, reserve, and denomination language
is interpreted across Bittensor reference material.

## Network Token Role

TAO is the token of the Bittensor network as a whole. The
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction) connects TAO to the
network's incentive design, where Bittensor uses token incentives to coordinate miners, validators,
and subnets.

This makes TAO broader than any one subnet. A subnet can have its own alpha token, but TAO remains
the network-level token that appears across incentive, staking, emission, and reserve terminology.

The term also works as a boundary marker. When Bittensor material discusses TAO, it is referring to
the network token; when it discusses alpha, it is referring to a subnet-specific token. Keeping
those two scopes separate prevents subnet-token behavior from being mistaken for network-token
behavior.

## Emission Role

TAO is part of Bittensor's emission system. In the
[Emission](https://docs.learnbittensor.org/learn/emissions) reference, emissions include newly
created TAO and subnet-specific alpha tokens moving through the system.

That means TAO should be read separately from subnet alpha. Both can appear in the same emission
discussion, but TAO names the network token while alpha names subnet-specific assets.

Emission language can therefore contain two asset layers at once. TAO belongs to the network-token
layer, while alpha belongs to the subnet-token layer. The same emission discussion may involve both,
but they are not interchangeable units.

This distinction matters in reward context. TAO can describe network-level issuance and reserve
movement, while alpha can describe subnet-local distribution and accounting. The terms meet inside
Dynamic TAO tokenomics, but each keeps its own asset scope.

## Subnet Reserve Role

TAO also appears inside subnet pool language. The
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets) reference
pairs a TAO reserve with a subnet-specific alpha reserve in subnet pools.

In that pool setting, TAO is the network-token side of the pair. Alpha reserve is the subnet-token
side. Dynamic TAO connects those two sides inside subnet tokenomics.

The reserve wording is narrower than the general TAO token concept. A TAO reserve is pool-held TAO
inside a subnet liquidity-pool context, not every TAO balance and not the alpha reserve. The phrase
therefore combines the network token with a specific subnet-pool role.

This is why TAO can appear in subnet pages without becoming a subnet token. The subnet contributes
the pool context; TAO contributes the network-token side of the pool pair
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

## Staking Role

TAO can be used in staking context. Staking and delegation connect stake to validators in Bittensor
([Staking and Delegation](https://docs.learnbittensor.org/staking-and-delegation/delegation)).

In subnet staking, TAO interacts with subnet alpha through the subnet's tokenomics. In root-subnet
context, stake is expressed in TAO. Staking language can therefore involve TAO, alpha, or the
relationship between them.

This does not make every staking reference a TAO reference. Some staking pages focus on validators,
delegation, or subnet-specific stake; TAO is the relevant term when the article is naming the
network token used in that staking context
([Staking and Delegation](https://docs.learnbittensor.org/staking-and-delegation/delegation)).

## RAO Denomination

RAO is a smaller denomination of TAO, not a separate token system. The
[Glossary: RAO](https://docs.learnbittensor.org/resources/glossary#rao) gives RAO as one billionth
of a TAO.

This makes RAO useful for precise amounts. TAO names the network token at the familiar unit, while
RAO names the finer denomination of the same token.

The denomination relationship is one-way. RAO derives its meaning from TAO; it is not a separate
asset class, subnet token, or liquidity-pool role. Documentation that uses RAO is still discussing
TAO-denominated value at a smaller unit
([Glossary: RAO](https://docs.learnbittensor.org/resources/glossary#rao)).

## Alpha Token Contrast

TAO and alpha tokens have different scopes. The
[Glossary: Alpha Tokens](https://docs.learnbittensor.org/resources/glossary#alpha-tokens) treats
alpha tokens as subnet-specific assets, while TAO is the network token.

That contrast is central to Dynamic TAO. TAO can sit beside alpha in subnet pools and emissions, but
the two names do not refer to the same asset.

The contrast also helps separate subnet-specific supply language from network-token language. Alpha
tokens vary by subnet. TAO remains the network token that can be paired with those subnet assets in
pool and emission contexts
([Glossary: Alpha Tokens](https://docs.learnbittensor.org/resources/glossary#alpha-tokens)).

## Term Placement

TAO names the network token. RAO names a smaller denomination of TAO. Alpha tokens name
subnet-specific assets. TAO reserve names the pool-held TAO side of a subnet pool
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

These terms are related because they often appear together in subnet tokenomics, but each one names
a different part of the system.

## Environment Boundary

The [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks) reference
separates mainnet, testnet, and localnet. TAO remains the network-token term across those
environments, but amounts, emissions, and pool balances belong to the network environment in which
they are recorded.

The
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction#subnet-development)
frames subnet development across localnet, testnet, and mainnet. TAO terminology can appear in each
environment, while conclusions about incentives or reserves need the matching environment, subnet,
and tokenomics context attached.

For reference use, this boundary keeps the article focused on terminology rather than a particular
network state. TAO identifies the network token; the environment identifies where a concrete amount,
reserve, emission, or staking relationship belongs.
