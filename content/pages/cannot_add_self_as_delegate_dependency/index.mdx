# Cannot Add Self As Delegate Dependency

`CannotAddSelfAsDelegateDependency` is a contracts pallet error raised when a contract tries to add
its own code hash as a delegate dependency. The API errors reference summarizes it as "Can not add a
delegate dependency to the code hash of the contract itself"
([Subtensor API Errors: CannotAddSelfAsDelegateDependency](https://docs.learnbittensor.org/subtensor-api/errors#cannotaddselfasdelegatedependency)).

## What It Means

Bittensor supports an Ethereum-compatible smart-contract environment on Subtensor
([Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials)). In that setting, a
contract keeps a stored list of delegate dependencies on other code hashes it may call through
delegation. `CannotAddSelfAsDelegateDependency` means the submitted dependency matches the
contract's own code hash, so the runtime rejects the add operation
([Subtensor API Errors: CannotAddSelfAsDelegateDependency](https://docs.learnbittensor.org/subtensor-api/errors#cannotaddselfasdelegatedependency)).

This is a self-reference rejection. It does not, by itself, mean the contract already depends on a
different code hash, that the contract has reached the maximum number of dependencies, or that a
named dependency is missing from storage.

## Why It Appears

This error appears when a contracts operation tries to add a delegate dependency whose code hash is
the contract itself
([Subtensor API Errors: CannotAddSelfAsDelegateDependency](https://docs.learnbittensor.org/subtensor-api/errors#cannotaddselfasdelegatedependency)).

## Distinction from Delegate Dependency Already Exists

`CannotAddSelfAsDelegateDependency` and `DelegateDependencyAlreadyExists` both block adding a
delegate dependency, but on different checks. `CannotAddSelfAsDelegateDependency` is summarized as
"Can not add a delegate dependency to the code hash of the contract itself."
`DelegateDependencyAlreadyExists` is summarized as "The contract already depends on the given
delegate dependency."
([Subtensor API Errors: CannotAddSelfAsDelegateDependency](https://docs.learnbittensor.org/subtensor-api/errors#cannotaddselfasdelegatedependency),
[Subtensor API Errors: DelegateDependencyAlreadyExists](https://docs.learnbittensor.org/subtensor-api/errors#delegatedependencyalreadyexists)).

- **CannotAddSelfAsDelegateDependency** — the submitted dependency is the contract's own code hash.
- **DelegateDependencyAlreadyExists** — the contract already depends on the given dependency.

## Distinction from Max Delegate Dependencies Reached

`CannotAddSelfAsDelegateDependency` and `MaxDelegateDependenciesReached` both stop an add operation,
but they reject different problems. `CannotAddSelfAsDelegateDependency` rejects a self-referencing
dependency. `MaxDelegateDependenciesReached` is summarized as "The contract has reached its maximum
number of delegate dependencies."
([Subtensor API Errors: CannotAddSelfAsDelegateDependency](https://docs.learnbittensor.org/subtensor-api/errors#cannotaddselfasdelegatedependency),
[Subtensor API Errors: MaxDelegateDependenciesReached](https://docs.learnbittensor.org/subtensor-api/errors#maxdelegatedependenciesreached)).

- **CannotAddSelfAsDelegateDependency** — the submitted dependency is the contract's own code hash.
- **MaxDelegateDependenciesReached** — the contract has no room for another dependency.

## Reader Boundary

This page defines the meaning of the error label from the API reference. It does not report the code
hash stored for a specific contract on a network or describe how a contract should redesign its
dependency structure
([Subtensor API Errors: CannotAddSelfAsDelegateDependency](https://docs.learnbittensor.org/subtensor-api/errors#cannotaddselfasdelegatedependency),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
