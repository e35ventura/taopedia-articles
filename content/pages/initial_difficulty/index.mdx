# Initial Difficulty

Initial Difficulty is a subtensorModule runtime constant, listed in the chain's constants metadata
as initialDifficulty, with the value 10000000 and the summary "Initial Difficulty"
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).
It provides the default value a subnet's Difficulty takes.

## What It Means

Difficulty is per-subnet chain state that sets how hard a subnet's proof-of-work registration puzzle
is. Initial Difficulty is the default a subnet's Difficulty is set to when the subnet is created;
from there the value is held per subnet and can differ between subnets
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).
The live Difficulty in force on a subnet such as netuid 1 is that subnet's own chain state and can
differ from this default, so the constant names the seed value rather than the live one.

## Distinction from Initial Min Difficulty

Initial initial difficulty and initialMinDifficulty both seed per-subnet defaults but for different
points. initialDifficulty seeds the starting difficulty a subnet registers at, while
initialMinDifficulty, valued at 10000000, seeds the floor the difficulty may not fall below
([Subtensor API Constants: initialMinDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmindifficulty-u64)).
The two are separate defaults a subnet starts with, each held per subnet and each able to differ
once set for that subnet.

## Distinction from Initial Max Difficulty

Initial initial difficulty and initialMaxDifficulty both seed per-subnet defaults but for different
points. initialDifficulty seeds the starting difficulty a subnet registers at, while
initialMaxDifficulty, valued at 4611686018427387903, seeds the ceiling the difficulty may not exceed
([Subtensor API Constants: initialMaxDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxdifficulty-u64)).
The two are separate defaults a subnet starts with, each held per subnet and each able to differ
once set for that subnet.

## Distinction from Initial Burn

Initial initial difficulty and initialBurn both seed per-subnet defaults but for different points.
initialDifficulty seeds the starting difficulty a subnet registers at, while initialBurn, valued at
100000000, seeds the default cost of the separate burn registration path
([Subtensor API Constants: initialBurn](https://docs.learnbittensor.org/subtensor-api/constants#initialburn-u64)).
The two are separate defaults a subnet starts with, each held per subnet and each able to differ
once set for that subnet.

## Why a Default Exists

Providing a default means every new subnet starts with a defined Difficulty rather than an undefined
one. Because the default is fixed as a constant, the value a subnet's Difficulty begins at is known
in advance, even though a subnet may later hold a different value once it is set for that subnet
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).

## Reader Boundary

Initial Difficulty is the default constant that seeds a subnet's Difficulty; it is not the live
per-subnet value, which can differ once set for a subnet, and it reflects the current runtime
configuration rather than a fixed protocol rule. It does not report the value in force on any subnet
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).
