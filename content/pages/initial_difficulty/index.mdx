# Initial Difficulty

Initial difficulty is a subtensorModule runtime constant, listed in the chain's constants metadata
as initialDifficulty, with the value 10000000 and the summary "Initial Difficulty"
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).
It supplies the default value a subnet's Difficulty uses.

## What It Means

Difficulty is held per subnet and sets how hard that subnet's proof-of-work registration puzzle is.
Initial difficulty is the default this per-subnet value falls back to before a different difficulty
applies for a subnet
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).
The Difficulty in force on a subnet such as netuid 1 is that subnet's own chain state and can differ
from this default.

## Distinction from Min and Max Difficulty

Initial difficulty is the default starting value, while the minimum and maximum difficulty
constants, valued at 10000000 and 4611686018427387903, bound the range a subnet's difficulty may
occupy
([Subtensor API Constants: initialMinDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmindifficulty-u64),
[Subtensor API Constants: initialMaxDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxdifficulty-u64)).
This constant is the seed inside that range, not the floor or the ceiling.

## Reader Boundary

Initial difficulty is a default constant, not the live per-subnet difficulty, and it reflects the
current runtime configuration rather than a fixed protocol rule
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).
