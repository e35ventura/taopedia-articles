# Initial Difficulty

Initial difficulty is a subtensorModule runtime constant, listed in the chain's constants metadata
as initialDifficulty, with the value 10000000 and the summary "Initial Difficulty"
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).
It seeds the proof-of-work registration difficulty a subnet begins with.

## What It Means

Proof-of-work registration requires a caller to solve a computational puzzle, and the difficulty
sets how hard that puzzle is. Initial difficulty is the starting value a subnet is seeded with when
it is created, before the difficulty adjusts in response to registration activity
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).
It is a single network-wide seed value rather than a per-subnet setting a reader configures
directly.

## Distinction from Min Difficulty

Initial difficulty is the starting point, while min difficulty is the floor the difficulty may not
fall below. The initial minimum difficulty constant is 10000000, the same as the seed, and it bounds
how low the adjusting difficulty can go
([Subtensor API Constants: initialMinDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmindifficulty-u64)).
One is where difficulty begins; the other is the lowest it is allowed to reach.

## Distinction from Max Difficulty

Max difficulty is the corresponding ceiling. The initial maximum difficulty constant is
4611686018427387903, and it bounds how high the adjusting difficulty can climb
([Subtensor API Constants: initialMaxDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxdifficulty-u64)).
Together the minimum and maximum difficulty constants define the range the difficulty moves within,
and initial difficulty is the seed inside that range.

## Distinction from Registration Burn

Difficulty governs the proof-of-work path to registration, where a caller spends computation to
solve a puzzle. That is separate from the burn path, where a caller instead pays a TAO cost bounded
by the min burn and max burn constants
([Subtensor API Constants: initialMinBurn](https://docs.learnbittensor.org/subtensor-api/constants#initialminburn-u64),
[Subtensor API Constants: initialMaxBurn](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxburn-u64)).
Initial difficulty seeds the computational side of registration, while the burn constants seed the
cost side; they concern different ways a registration can be priced.

## Why a Starting Value Exists

Seeding a starting difficulty means a newly created subnet has a defined puzzle hardness from its
first block rather than an undefined one. From that seed the difficulty then adjusts over time
toward keeping registration activity in line with the target
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).
The constant fixes the starting point, not the ongoing adjusted value.

## Reader Boundary

Initial difficulty is a single network-wide constant, not a per-subnet value, and it reflects the
current runtime configuration rather than a fixed protocol rule; the value could change in a future
runtime upgrade. It names the starting proof-of-work difficulty and does not report the live,
adjusted difficulty in force on any subnet
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).
