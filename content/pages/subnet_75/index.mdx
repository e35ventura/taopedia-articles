Hippius is Bittensor Subnet 75. The [Hippius website](https://hippius.com/) describes the project as
decentralized cloud infrastructure for storage, virtual machines, and applications, while the
[Hippius README source](https://raw.githubusercontent.com/thenervelab/thebrain/main/README.md)
frames it as a Bittensor subnet for distributed storage, compute, and blockchain management.

The Hippius README describes the project as a decentralized infrastructure subnet for distributed
storage, compute, and blockchain management. It says Hippius enables decentralized file storage and
computation across a network of miners and validators, with IPFS integration, resource marketplaces,
and offchain workers for system metrics.

## What Hippius Provides

Hippius provides infrastructure for decentralized cloud services. Its public materials describe file
storage, virtualized compute resources, and application-oriented cloud services as the main
workloads coordinated by the subnet.

The repository README frames the system around storage and compute resources. Storage work is tied
to IPFS-based file handling, capacity tracking, file health, and replication status. Compute work is
tied to virtualized resources, task execution, resource allocation, and performance metrics.

## Miner and Validator Roles

Hippius describes two miner roles. Storage miners run IPFS nodes, manage storage infrastructure, and
report storage capacity, file health, and replication status. Compute miners provide virtualized
compute resources, manage task execution, and report resource availability and performance.

Validators verify network operations and collect performance data. The README also says validators
monitor storage and compute usage and help manage replication and task assignment. At the Bittensor
level, validator weights are processed through [[Yuma Consensus]].

## Cloud Workload Context

Hippius' source materials frame the subnet as decentralized cloud infrastructure rather than a
single-purpose storage market. The website emphasizes decentralized storage, virtual machines, and
apps, while the README describes distributed storage and computation coordinated through miners and
validators.

That makes Subnet 75 a workload-diverse infrastructure subnet. Storage work is tied to file
availability, IPFS-based handling, capacity, and replication health. Compute work is tied to
virtualized resources, task execution, resource allocation, and performance reporting.

The shared context is that both workload families become measurable network services. A storage
miner contributes by maintaining reliable storage infrastructure, while a compute miner contributes
by making virtualized resources available for tasks.

## Coordination Context

The README separates storage miners, compute miners, and validators into distinct network roles.
Storage miners operate IPFS-backed storage infrastructure; compute miners operate virtualized
compute resources; validators verify operations, collect performance data, and help coordinate
replication and task assignment.

This role separation helps explain why Hippius is described as cloud infrastructure instead of only
file hosting. The subnet needs storage capacity, compute availability, monitoring, and validation to
work together before those services can be converted into Bittensor weights.

The README also identifies reputation-based worker management, resource marketplaces, and offchain
workers for system metrics as core features. In practical terms, the subnet's reward signal depends
on reliable infrastructure behavior that validators can observe, not on a miner simply claiming
capacity.
