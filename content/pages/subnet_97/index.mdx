Albedo is Bittensor Subnet 97. Its on-chain identity describes the subnet as "alchemical
intelligence" and lists [unarbos/albedo](https://github.com/unarbos/albedo) as the subnet's GitHub
repository.

## What Albedo Provides

The
[Albedo project overview](https://raw.githubusercontent.com/unarbos/albedo/main/website/llms.txt)
describes the subnet as a king-of-the-hill competition for Qwen3-4B language models. At any time,
one model holds the title of reigning king. Miners submit challenger models that are matched
head-to-head against the king on coding trajectories drawn from a public dataset, and an ensemble of
independent large language models judges which side performs better. A challenger that beats the
king takes the crown and becomes the model that others must then beat.

The same overview frames Albedo as a trajectory-distillation network: every match publishes its full
turn-by-turn transcripts, not just the final scores. Those transcripts are openly available, so
researchers can study the winning behavior or use it to train new models.

## Validation Boundary

Albedo's public mining guide describes a strict submission boundary. Challenger models are expected
to remain in the Qwen3-4B family, keep the architecture and tokenizer aligned with the seed model,
and avoid custom modeling code or quantized substitutes. That boundary keeps the competition focused
on fine-tuning quality rather than on swapping in unrelated model architectures.

This validation layer is part of the subnet's evaluation meaning. A miner is not rewarded merely for
publishing any model artifact; the model first has to pass artifact checks that make it comparable
with the incumbent. The guide also describes near-duplicate rejection, which helps keep the
competition pointed at meaningfully different challengers instead of repeated copies of the same
model.

For readers, this makes Albedo narrower than a general model marketplace. It is a controlled
fine-tuning contest: challengers compete under a shared model class and are judged by whether their
behavior beats the current king on the subnet's evaluation path.

## Miner and Validator Roles

Miners compete by training and submitting challenger models that aim to outperform the current king.
The Albedo documentation describes a challenger as taking the crown when it wins its duel against
the incumbent, so improvements can accumulate across successive champions.

Validators organize the competition: they detect new challengers, run each match against the
reigning king, and record the outcome on-chain by setting weights. Rewards follow a "king chain" in
which emissions are shared between the current champion and a handful of recent former champions
that remain on the subnet. Operators should treat the repository as the source of truth for current
participant guidance.

## Reign and Transcript Context

Albedo's project overview describes winners as being promoted into a rolling five-king chain. That
matters because the subnet does not only reward a single current model in isolation; it preserves a
short lineage of recent winners that shaped the competition. New challengers therefore compete
against an incumbent whose position reflects the latest successful improvement path.

The transcript publication described by the same source is also important. Albedo's output is not
just a leaderboard rank. The public match traces make the behavior of winning and losing models
inspectable after evaluation, which supports the subnet's trajectory-distillation framing. The
subnet produces a competitive signal and a corpus of evaluated coding trajectories.
