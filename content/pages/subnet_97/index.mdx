Albedo is Bittensor Subnet 97. Its on-chain identity describes the subnet as "alchemical
intelligence", lists [us-east-1.hippius.com/albedo](https://us-east-1.hippius.com/albedo/index.html)
as the subnet URL, and lists [unarbos/albedo](https://github.com/unarbos/albedo) as the subnet's
GitHub repository.

## What Albedo Provides

The Albedo README describes the subnet as a king-of-the-hill, trajectory-distillation network on
Bittensor. Miners upload model challengers, and the reigning "king" model and a challenger duel on
rollouts sampled from a pinned SWE-ZERO dataset, scored by an ensemble of independent large language
model judges. Every duel publishes its full turn-by-turn traces, which the README presents as data
for downstream distillation.

According to the README, a challenger dethrones the king when it wins on at least one judge
dimension and loses on none, with ties allowed on the remaining dimensions. The duel parameters,
judge models, dataset pin, and architecture locks are pinned in the repository's `chain.toml`.
Emissions follow a "king chain": the reward splits across the current king and up to four previously
dethroned kings that remain registered on the subnet.

## Miner and Validator Roles

The README describes miners as training a challenger model that improves on the current king,
publishing it as an immutable digest-pinned reference, and posting an on-chain reveal so validators
can evaluate it. A challenger that is crowned becomes the new king.

Validators scan on-chain reveals, dispatch each accepted challenger into a duel against the current
king on a GPU evaluation server, crown a new king when a duel is accepted, and set weights on-chain.
Published duel traces let researchers export training data without participating in mining.
Operators should treat the repository as the source of truth for current participant guidance.

## On-Chain Identity

Live SN97 data is available on [TaoStats](https://taostats.io/subnets/97). Readers can also
reproduce the chain identity fields with the Bittensor CLI command documented in the
[btcli reference](https://docs.learnbittensor.org/btcli/#btcli-subnets-get-identity):
`btcli subnets get-identity --netuid 97 --network finney`.

That Finney identity reports the subnet name as Albedo and the GitHub repo as unarbos/albedo.
