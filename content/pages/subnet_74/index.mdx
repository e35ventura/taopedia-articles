Gittensor is Bittensor Subnet 74. It turns open-source contribution into a rewarded service:
developers earn emissions for pull requests that are merged into a set of whitelisted repositories.
The subnet code is maintained in the
[entrius/gittensor](https://github.com/entrius/gittensor/tree/main) repository under an MIT license.

## What Gittensor Rewards

Most Bittensor subnets reward a model output or a data service. Gittensor instead rewards completed
software work. A contribution only counts once it has been merged, which ties rewards to changes
that repository maintainers actually accepted rather than to raw activity or submission volume.

The repository describes three principles behind this design: real work is rewarded because only
merged pull requests earn emissions, quality is weighted over quantity through semantic analysis of
the code change, and the merge-plus-GitHub-verification requirement makes the reward harder to game
with fake or duplicated accounts.

## Miner and Validator Roles

Miners are the contributing developers. They register a GitHub personal access token with validators
through the subnet CLI, then contribute to whitelisted repositories. Per the repository, no separate
miner neuron is required; the GitHub identity is what links a developer's merged work to on-chain
rewards.

Validators run the scoring service. They authenticate that a miner controls the linked GitHub
account, verify which pull requests were merged, and score each contribution before writing weights.
The repository lists the scoring inputs as code quality, repository allocation (the emission share
assigned to each whitelisted repository), and programming-language weights tied to file types. Those
validator weights then feed into [[Yuma Consensus]], which converts them into the incentive split
across miners and validators.

## On-Chain Identity

Live SN74 data, including metagraph state and alpha token pool information, is available on
[TaoStats](https://taostats.io/subnets/74), which lists the subnet under the name Gittensor. Readers
can reproduce the subnet's registered identity fields with the Bittensor CLI command documented in
the [btcli reference](https://docs.learnbittensor.org/btcli/#btcli-subnets-get-identity):
`btcli subnets get-identity --netuid 74 --network finney`.

The Finney subnet identity for netuid 74 points to the
[entrius/gittensor](https://github.com/entrius/gittensor/tree/main) repository, which is the source
of truth for the GitHub URL shown in this article and for the incentive mechanism and validator
scoring code described above.
