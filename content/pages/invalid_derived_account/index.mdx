# Invalid Derived Account

`InvalidDerivedAccount` is a utility-pallet error raised when the runtime cannot decode a derived
account ID from the bytes it generated for a derivative account. The Subtensor API errors reference
lists it under utility errors
([Subtensor API Errors: InvalidDerivedAccount](https://docs.learnbittensor.org/subtensor-api/errors#invalidderivedaccount)).

## What It Means

The utility pallet can derive sub-accounts from an owner account plus a sub-account index. To do
that, it hashes fixed derivation entropy and then decodes the resulting bytes into the runtime's
`AccountId` type. `InvalidDerivedAccount` means that decode step failed, so the runtime could not
materialize a valid derived account ID from those bytes
([Subtensor source: utility/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/utility/src/lib.rs)).

This is a derived-account decode failure, not a filtered-dispatch rejection and not the error for an
oversized utility batch. The problem is specifically that the generated bytes could not be decoded
as a valid runtime account identifier
([Subtensor source: utility/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/utility/src/lib.rs)).

The practical meaning is narrow: the runtime failed to construct a valid derivative account ID.

## Why It Appears

This error appears when a utility derivative-account path asks the runtime to derive an account ID,
but the generated derivation bytes do not decode into the configured `AccountId` type
([Subtensor API Errors: InvalidDerivedAccount](https://docs.learnbittensor.org/subtensor-api/errors#invalidderivedaccount),
[Subtensor source: utility/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/utility/src/lib.rs)).

The code shows the exact boundary. `derivative_account_id` hashes the tuple of a fixed prefix, the
owner account, and the sub-account index, then passes those bytes through `AccountId::decode`. When
that decode returns an error, the helper maps it to `InvalidDerivedAccount`
([Subtensor source: utility/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/utility/src/lib.rs)).

This is not the rejection for a forbidden origin, and it is not the rejection for an inner call that
a filter blocks. It is the specific error for failing to decode the derived account identifier.

## Distinction from Bad Origin

`InvalidDerivedAccount` and `BadOrigin` can both stop utility-related calls, but they reject
different things. `BadOrigin` means the call was invoked from an origin that is not permitted for
the outer dispatch. `InvalidDerivedAccount` means the runtime could not decode the derived account
ID that a derivative-account flow needs
([Subtensor API Errors: BadOrigin](https://docs.learnbittensor.org/subtensor-api/errors#badorigin),
[Subtensor source: utility/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/utility/src/lib.rs)).

- **BadOrigin** — the outer dispatch origin is not allowed.
- **InvalidDerivedAccount** — the runtime could not decode the derived account ID.

## Distinction from Call Filtered

`InvalidDerivedAccount` and `CallFiltered` can both appear around wrapped utility dispatch, but they
apply at different stages. `InvalidDerivedAccount` happens while constructing the derivative account
identifier. `CallFiltered` happens later when a dispatched inner call is blocked by the runtime's
active call filter
([Subtensor API Errors: CallFiltered](https://docs.learnbittensor.org/subtensor-api/errors#callfiltered),
[Subtensor source: utility/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/utility/src/lib.rs),
[Subtensor source: utility/tests.rs](https://github.com/opentensor/subtensor/blob/main/pallets/utility/src/tests.rs)).

- **InvalidDerivedAccount** — the derivative account ID could not be decoded.
- **CallFiltered** — a later inner call is blocked by the runtime filter.

## Reader Boundary

This page defines the meaning of the error label and the decode failure that raises it. It does not
describe every utility wrapper that can use derivative accounts or every dispatch rule that can run
after a derivative account is constructed; those are separate parts of utility-pallet behavior
([Subtensor source: utility/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/utility/src/lib.rs)).
