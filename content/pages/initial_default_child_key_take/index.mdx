# Initial Default Child Key Take

Initial Default Child Key Take is a subtensorModule runtime constant, listed in the chain's
constants metadata as initialDefaultChildKeyTake, with the value 0 and the summary "Initial default
childkey take"
([Subtensor API Constants: initialDefaultChildKeyTake](https://docs.learnbittensor.org/subtensor-api/constants#initialdefaultchildkeytake-u16)).
It supplies the default value a subnet's default childkey take uses.

## What It Means

default childkey take is held per subnet and sets the share a child hotkey keeps of the emissions
from stake a parent hotkey allocates to it. Initial Default Child Key Take is the default this
per-subnet value falls back to before a different value applies for a subnet
([Subtensor API Constants: initialDefaultChildKeyTake](https://docs.learnbittensor.org/subtensor-api/constants#initialdefaultchildkeytake-u16)).
The default childkey take in force on a subnet such as netuid 1 is that subnet's own chain state and
can differ from this default.

## Distinction from Min and Max Childkey Take

Initial Default Child Key Take is the default childkey take, while initialMaxChildKeyTake, valued at
11796, is the ceiling a childkey take may be set to; initialMinChildKeyTake, valued at 0, is the
floor a childkey take may be set to
([Subtensor API Constants: initialMaxChildKeyTake](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxchildkeytake-u16),
[Subtensor API Constants: initialMinChildKeyTake](https://docs.learnbittensor.org/subtensor-api/constants#initialminchildkeytake-u16)).

## Reader Boundary

Initial Default Child Key Take is a default constant, not the live per-subnet default childkey take,
and it reflects the current runtime configuration rather than a fixed protocol rule
([Subtensor API Constants: initialDefaultChildKeyTake](https://docs.learnbittensor.org/subtensor-api/constants#initialdefaultchildkeytake-u16)).
