# Too Many Freezes

`TooManyFreezes` is a balances pallet error raised when placing a new balance freeze on an account
would exceed the maximum number of freezes the runtime allows. The pallet source describes it as
"Number of freezes exceed `MaxFreezes`"
([Subtensor API Errors: TooManyFreezes](https://docs.learnbittensor.org/subtensor-api/errors#toomanyfreezes)).

## What It Means

Balance freezes are used by pallets to prevent an account from spending a portion of its free
balance, while the funds remain visible in the free balance total. Each freeze is tracked by a
freeze identifier, and each account may have a limited number of active freezes. `TooManyFreezes`
fires when a pallet tries to add a freeze to an account that already has the maximum number
([Subtensor API Errors: TooManyFreezes](https://docs.learnbittensor.org/subtensor-api/errors#toomanyfreezes)).

Frozen balance cannot be transferred or spent while the freeze is active. Freezes are lifted when
the originating pallet removes them
([Subtensor API Errors: TooManyFreezes](https://docs.learnbittensor.org/subtensor-api/errors#toomanyfreezes)).

## Why It Appears

This error appears when a pallet attempts to set or update a freeze on an account and the insertion
into the on-chain freeze list fails because the list has reached `MaxFreezes`. Removing an existing
freeze first would allow a new one to be added
([Subtensor API Errors: TooManyFreezes](https://docs.learnbittensor.org/subtensor-api/errors#toomanyfreezes)).

## Distinction from Too Many Holds

`TooManyFreezes` and `TooManyHolds` both limit per-account balance tracking entries, but they apply
to different mechanisms. `TooManyHolds` fires when a hold cannot be added because the hold list is
full. `TooManyFreezes` fires when a freeze cannot be added because the freeze list is full. Holds
and freezes track balance restrictions using separate on-chain lists
([Subtensor API Errors: TooManyHolds](https://docs.learnbittensor.org/subtensor-api/errors#toomanyholds)).

- **TooManyHolds** — hold list is full; new hold cannot be placed.
- **TooManyFreezes** — freeze list is full; new freeze cannot be placed.

## Distinction from Too Many Reserves

`TooManyFreezes` and `TooManyReserves` both block pallet-initiated balance restrictions, but they
apply to different APIs. `TooManyReserves` applies to the named-reserve API. `TooManyFreezes`
applies to the freezes API, which tracks spending restrictions rather than reserved amounts
([Subtensor API Errors: TooManyReserves](https://docs.learnbittensor.org/subtensor-api/errors#toomanyreserves)).

- **TooManyReserves** — named-reserve slots are full.
- **TooManyFreezes** — freeze list is full.

## Reader Boundary

This page defines the meaning of the error label and the freeze-count check that raises it. It does
not report the current number of active freezes on any account; that is live chain state
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
