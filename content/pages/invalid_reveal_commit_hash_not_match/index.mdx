# Invalid Reveal Commit Hash Not Match

`InvalidRevealCommitHashNotMatch` means the reveal's weight vector, salt, and version key did not
hash to any active stored commit for that hotkey and netuid. The standard-errors reference describes
it as "Committed hash does not equal the hashed reveal data"
([Subtensor Standard Errors](https://docs.learnbittensor.org/subtensor-api/errors#invalidrevealcommithashnotmatch)).

Commit-reveal submission binds a later reveal to an earlier commitment through a shared hash. If the
reveal uses different inputs than the commit was built from, the chain cannot pair them
([Commit-Reveal](https://docs.learnbittensor.org/concepts/commit-reveal)).

## What It Means

[Commit-reveal](https://docs.learnbittensor.org/concepts/commit-reveal) weight submission happens in
two steps: a hash commitment first, then the actual weights and salt later.
`InvalidRevealCommitHashNotMatch` means the chain recomputed the reveal hash and found no matching
entry among the caller's remaining non-expired commits, so the reveal was rejected and stored
commits were left unchanged
([Subtensor Standard Errors](https://docs.learnbittensor.org/subtensor-api/errors#invalidrevealcommithashnotmatch)).

This is a hash-mismatch failure: the caller may still hold pending commits, but none of them match
the `(uids, values, salt, version_key)` submitted in the reveal.

## Why It Appears

This error appears on the reveal side after commit-reveal is enabled for the target netuid. It fires
when the reveal uses the wrong salt, an edited weight vector, a mismatched version key, or otherwise
submits inputs that no longer correspond to any stored commitment
([Subtensor Standard Errors](https://docs.learnbittensor.org/subtensor-api/errors#invalidrevealcommithashnotmatch)).

When debugging, confirm a pending commit exists before treating this as a missing-commit failure.
Then compare lookup and timing errors: `NoWeightsCommitFound` means no usable stored commit was
found for that hotkey and netuid, while `ExpiredWeightCommit` means the hash matched a commit that
had already aged out
([Subtensor Standard Errors: NoWeightsCommitFound](https://docs.learnbittensor.org/subtensor-api/errors#noweightscommitfound),
[Subtensor Standard Errors: ExpiredWeightCommit](https://docs.learnbittensor.org/subtensor-api/errors#expiredweightcommit)).

The practical meaning is narrow: the reveal inputs do not correspond to any commitment the chain
still holds. The problem is not that commit-reveal is disabled or that the reveal simply arrived
before its eligible epoch
([Subtensor Standard Errors: CommitRevealDisabled](https://docs.learnbittensor.org/subtensor-api/errors#commitrevealdisabled),
[Subtensor Standard Errors: RevealTooEarly](https://docs.learnbittensor.org/subtensor-api/errors#revealtooearly)).

## Distinction from No Weights Commit Found

`InvalidRevealCommitHashNotMatch` and `NoWeightsCommitFound` both reject a reveal call, but they
detect different defects. `NoWeightsCommitFound` means the chain found no matching active stored
commit for that hotkey and netuid. `InvalidRevealCommitHashNotMatch` means stored commits exist, but
none of them hash to the reveal's submitted inputs
([Subtensor Standard Errors: NoWeightsCommitFound](https://docs.learnbittensor.org/subtensor-api/errors#noweightscommitfound)).

- **NoWeightsCommitFound** — no matching active stored commit exists for the reveal.
- **InvalidRevealCommitHashNotMatch** — stored commits exist, but the reveal hash matches none of
  them.

## Distinction from Expired Weight Commit

`InvalidRevealCommitHashNotMatch` and `ExpiredWeightCommit` both appear when a reveal hash fails to
match any remaining active commit, but they reject different causes. `ExpiredWeightCommit` means the
hash matched a stored commit that had already been pruned as expired.
`InvalidRevealCommitHashNotMatch` means the hash matched no stored commit at all
([Subtensor Standard Errors: ExpiredWeightCommit](https://docs.learnbittensor.org/subtensor-api/errors#expiredweightcommit)).

- **ExpiredWeightCommit** — the hash matched a stored commit, but that commit had already expired.
- **InvalidRevealCommitHashNotMatch** — the hash matched no stored commit at all.

## Reader Boundary

This page defines the meaning of the error label and the hash-mismatch condition that raises it. It
does not describe the full commit-reveal lifecycle, reveal timing windows, or how expired commits
are pruned; those are separate topics
([Commit-Reveal](https://docs.learnbittensor.org/concepts/commit-reveal)).
