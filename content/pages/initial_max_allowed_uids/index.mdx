# Initial Max Allowed Uids

Initial Max Allowed Uids is a subtensorModule runtime constant, listed in the chain's constants
metadata as initialMaxAllowedUids, with the value 256 and the summary "Initial maximum allowed
network UIDs"
([Subtensor API Constants: initialMaxAllowedUids](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxalloweduids-u16)).
It supplies the default value a subnet's MaxAllowedUids uses.

## What It Means

MaxAllowedUids is held per subnet and caps how many UIDs a subnet may hold at one time. Initial Max
Allowed Uids is the default this per-subnet value falls back to before a different value applies for
a subnet
([Subtensor API Constants: initialMaxAllowedUids](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxalloweduids-u16)).
The MaxAllowedUids in force on a subnet such as netuid 1 is that subnet's own chain state and can
differ from this default.

## Distinction from Min Allowed UIDs and Max Validators

Initial Max Allowed Uids is the default maximum UID count, while initialMinAllowedUids, valued at
64, is the minimum number of UIDs a subnet may hold; initialMaxAllowedValidators, valued at 128, is
the maximum validators a subnet may have
([Subtensor API Constants: initialMinAllowedUids](https://docs.learnbittensor.org/subtensor-api/constants#initialminalloweduids-u16),
[Subtensor API Constants: initialMaxAllowedValidators](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxallowedvalidators-u16)).

## Reader Boundary

Initial Max Allowed Uids is a default constant, not the live per-subnet MaxAllowedUids, and it
reflects the current runtime configuration rather than a fixed protocol rule
([Subtensor API Constants: initialMaxAllowedUids](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxalloweduids-u16)).
