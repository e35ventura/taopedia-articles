# Network Immunity Period

Network immunity period is a subnet hyperparameter, listed as `NetworkImmunityPeriod` in Bittensor
documentation, that sets the number of blocks during which a newly registered subnet is protected
from deregistration. The
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters) reference
lists `NetworkImmunityPeriod` alongside other parameters that govern subnet registration and
lifecycle on the Bittensor network.

The parameter applies at the point of subnet registration. Once the immunity window elapses, the
subnet is subject to the standard deregistration conditions that apply to all active subnets on the
network.

Bittensor allows multiple subnets to coexist on the network, each operating independently with its
own hyperparameter configuration. `NetworkImmunityPeriod` gives newly registered subnets a defined
window to begin establishing activity before they can be evaluated for deregistration.

## What It Controls

`NetworkImmunityPeriod` sets the block count for the post-registration protection window. A subnet
that was registered more recently than `NetworkImmunityPeriod` blocks ago is treated as immune
during the deregistration evaluation step
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

The parameter applies uniformly at the network level. Each subnet begins its immunity window at the
block of its registration, and the window lasts exactly `NetworkImmunityPeriod` blocks from that
point.

## Distinction from Immunity Period

`ImmunityPeriod` is a per-subnet hyperparameter that protects individual neurons from being pruned
from a subnet's neuron roster shortly after they register. `NetworkImmunityPeriod` operates at the
subnet level rather than the neuron level: it protects the subnet itself from being deregistered
from the network, not individual neurons from being pruned from a subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

The two parameters address protection at different layers. `ImmunityPeriod` is configured per-subnet
and governs neuron retention within a subnet. `NetworkImmunityPeriod` governs subnet retention
within the network.

## Documented Type

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `NetworkImmunityPeriod` as an integer hyperparameter measured in blocks. The block
count begins at the subnet's registration block and counts forward to determine when the immunity
window ends.

Because the value is an integer block count, a larger `NetworkImmunityPeriod` corresponds to a
longer protection window. The value is part of the network's hyperparameter state and is not
specific to any individual subnet's configuration.

## Network and Environment Scope

The [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks) reference
separates mainnet, testnet, and localnet environments. The `NetworkImmunityPeriod` value in effect
on mainnet is independent of the value configured on testnet or localnet, because each network holds
its own hyperparameter state.

A subnet registered on mainnet is protected by the mainnet `NetworkImmunityPeriod` value. The same
subnet registered on testnet falls under the testnet value for that parameter.
