# Initial Adjustment Interval

Initial Adjustment Interval is a subtensorModule runtime constant, listed in the chain's constants
metadata as initialAdjustmentInterval, with the value 100 and the summary "Initial adjustment
interval"
([Subtensor API Constants: initialAdjustmentInterval](https://docs.learnbittensor.org/subtensor-api/constants#initialadjustmentinterval-u16)).
It supplies the default value a subnet's AdjustmentInterval uses.

## What It Means

AdjustmentInterval is held per subnet and sets the number of blocks between recalibrations of a
subnet's registration difficulty and burn. Initial Adjustment Interval is the default this
per-subnet value falls back to before a different value applies for a subnet
([Subtensor API Constants: initialAdjustmentInterval](https://docs.learnbittensor.org/subtensor-api/constants#initialadjustmentinterval-u16)).
The AdjustmentInterval in force on a subnet such as netuid 1 is that subnet's own chain state and
can differ from this default.

## Distinction from Adjustment Alpha and Target

Initial Adjustment Interval is the default number of blocks between adjustments, while
initialAdjustmentAlpha, valued at 0, is the smoothing weight applied at each adjustment;
initialTargetRegistrationsPerInterval, valued at 2, is the target registrations per interval the
adjustment aims for
([Subtensor API Constants: initialAdjustmentAlpha](https://docs.learnbittensor.org/subtensor-api/constants#initialadjustmentalpha-u64),
[Subtensor API Constants: initialTargetRegistrationsPerInterval](https://docs.learnbittensor.org/subtensor-api/constants#initialtargetregistrationsperinterval-u16)).

## Reader Boundary

Initial Adjustment Interval is a default constant, not the live per-subnet AdjustmentInterval, and
it reflects the current runtime configuration rather than a fixed protocol rule
([Subtensor API Constants: initialAdjustmentInterval](https://docs.learnbittensor.org/subtensor-api/constants#initialadjustmentinterval-u16)).
