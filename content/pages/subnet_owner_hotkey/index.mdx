# Subnet Owner Hotkey

Subnet owner hotkey is a per-subnet setting, listed in the documentation as `SubnetOwnerHotkey`,
that names the [hotkey](https://docs.learnbittensor.org/resources/glossary#hotkey) associated with a
subnet's owner and can change which hotkey holds that role. The
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters) reference
lists it as the setting that changes the hotkey of the subnet owner.

## What It Controls

The setting records the hotkey tied to subnet ownership and lets the owner update it. A subnet owner
is identified on-chain through their keys; subnet owner hotkey is the hotkey side of that identity,
used for owner-level operations on the subnet
([Glossary: Subnet Creator](https://docs.learnbittensor.org/resources/glossary#subnet-creator)).

It does not change who controls the owning
[coldkey](https://docs.learnbittensor.org/resources/glossary#coldkey) or the owner's share of
emissions. It names the hotkey associated with the owner role for that subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Documented Description and Setter

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `SubnetOwnerHotkey` as the setting that changes the subnet owner's hotkey. Because
each subnet carries its own ownership state, the owner hotkey is defined per subnet and applies only
within that subnet.

The value in force is per-subnet chain state, so the current owner hotkey should be read for the
subnet in question rather than assumed from another subnet.

## Distinction from Coldkey

In Bittensor's key model, the coldkey is the secure custody key while the hotkey is the operational
key used for online actions. Subnet owner hotkey names the operational hotkey for the owner role; it
is not the owning coldkey that ultimately holds custody
([Glossary: Coldkey](https://docs.learnbittensor.org/resources/glossary#coldkey),
[Glossary: Hotkey](https://docs.learnbittensor.org/resources/glossary#hotkey)).

- **Owning coldkey** — the custody key behind subnet ownership.
- **Subnet owner hotkey** — the operational hotkey for owner-level actions.

## Distinction from Subnet Owner Take

Subnet owner take is the share of subnet emissions paid to the owner, while subnet owner hotkey
names the key associated with the owner role. One is an economic share; the other is an identity key
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Subnet owner take** — the owner's emission share.
- **Subnet owner hotkey** — the hotkey tied to the owner role.

## BTCLI and Live State

Subnet ownership state, including owner key information, is per-subnet chain state that can be read
for a selected netuid through Bittensor tooling
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Because the owner hotkey can be updated, an ownership claim should be tied to current chain state
for the relevant netuid rather than to a previously observed key.

## Why an Updatable Owner Hotkey Matters

Allowing the owner hotkey to change supports key rotation and operational security. An owner can
move the operational hotkey for their subnet without giving up the underlying coldkey custody, which
keeps the owner role recoverable and maintainable
([Glossary: Hotkey](https://docs.learnbittensor.org/resources/glossary#hotkey)).

For readers, subnet owner hotkey is the key that represents the owner role for online operations,
and the fact that it is updatable is why ownership claims should reference current chain state
rather than a fixed key
([Glossary: Subnet Creator](https://docs.learnbittensor.org/resources/glossary#subnet-creator)).
