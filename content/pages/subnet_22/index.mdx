Desearch is the decentralized real-time intelligence subnet (netuid 22). It coordinates a
competitive network of miners that serve live search data — spanning the open web, X/Twitter, and
other sources — which powers the [Desearch](https://desearch.ai) API and console products. The
subnet is built and operated by [datura-ai](https://github.com/datura-ai).

Rather than relying on a centralized search index, Desearch delegates search queries to a field of
independent miner operators. Validators continuously probe miners with synthetic and organic
queries, then score responses against independent reference providers. Miners that consistently
return accurate, timely results earn higher weights and therefore greater [[Yuma Consensus]]
rewards.

## How the Mechanism Works

At the heart of SN22 is a challenge-response scoring loop. Validators generate queries — covering
web search, X/Twitter search, and multi-source intelligence — and broadcast them to the miner field
as Bittensor synapse messages. Each miner returns its best answer within a defined time window.

Validators do not trust miner responses at face value. Each response is independently verified
against external data providers, with correctness measured across dimensions such as relevance,
freshness, and completeness. Scores are aggregated into a rolling scoring window, giving validators
a smoothed view of each miner's reliability over time rather than reacting to individual query
results.

Weight-setting translates these accumulated scores into on-chain validator weights. Miners with
stronger scoring histories attract larger weight assignments, and — through [[Yuma Consensus]] —
larger shares of the subnet's alpha token emissions.

An organic-traffic pathway also exists: authorized Desearch services route live user queries through
the validator, meaning real search traffic directly shapes the production dataset used for scoring.
Miners that perform well on synthetic benchmarks but struggle under live query load are naturally
penalized over time.

## Participating as a Miner

Miners on SN22 register a hotkey on netuid 22 and run an axon that declares search capacity and
responds to incoming synapse queries. To be competitive, miners need the ability to serve web search
results through a third-party search API and, optionally, real-time X/Twitter data. Response latency
matters: queries have a hard deadline, and slow responses count against a miner's cumulative score.

Miners self-report their search capabilities through a manifest, which tells validators what query
types that miner can handle. Validators use this manifest to route appropriate queries. A miner that
claims web search capacity but returns poor results will quickly accumulate negative scoring and
lose weight.

Registering on a subnet with 256 neurons means new entrants compete against established operators
with polished infrastructure. Prospective miners should review
[datura-ai/desearch](https://github.com/datura-ai/desearch) for current protocol requirements before
registering.

## Participating as a Validator

Validators run a core scoring service that issues queries and updates on-chain weights, alongside a
sidecar API that exposes organic search endpoints to authorized Desearch platform services.
Validators require credentials for at least one independent verification provider so that miner
responses can be cross-checked without relying on miner-supplied data.

Scoring windows are persisted locally, allowing validators to smooth out transient network issues
and reward miners with consistent long-term performance rather than penalizing momentary failures.
Public miner status endpoints expose aggregate scoring data, supporting transparency across the
subnet.

Weight updates follow the standard [[Yuma Consensus]] cadence. High uptime is important for
validators: missed scoring windows reduce scoring fidelity and can affect a validator's own reward
share. Full setup documentation is available in the
[repository](https://github.com/datura-ai/desearch).
