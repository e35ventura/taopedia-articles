# Subnet Protocol

A subnet protocol is the rule set for validator-miner interaction inside a Bittensor subnet
([Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

The term belongs to incentive-mechanism vocabulary. It names the interaction pattern around work,
not the work target itself, the scoring model, or the full subnet design.

## Interaction Model

The subnet protocol describes how validators ask for work and how miners return responses. The
official glossary frames the term around validator-miner interaction, including how tasks are
requested and responses are provided
([Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

For readers, this makes protocol the interaction layer between a subnet's task and its evaluation
method. It explains the exchange shape without deciding whether a returned answer should receive a
high or low score.

## Relationship to the Task

Subnet task and subnet protocol are related but separate ideas. The task names the work miners are
expected to perform, while the protocol names how validators and miners exchange that work
([Glossary: Subnet Task](https://docs.learnbittensor.org/resources/glossary#subnet-task),
[Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol)).

This distinction keeps the content of the work separate from the communication rules around it. A
text-generation subnet, a data subnet, and a compute subnet can have different tasks even though
each still needs a protocol for requests, responses, and evaluation handoff.

## Relationship to the Scoring Model

The scoring model is the evaluation method. A subnet protocol can define how responses are obtained,
while a scoring model defines how validators judge those responses for the subnet's incentive
mechanism
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

Keeping protocol and scoring separate prevents a request-and-response rule from being treated as the
full evaluation rule. The protocol gets responses into a form validators can evaluate; the scoring
model explains how those responses are converted into evaluation signals.

## Role Context

Subnet protocols sit between miner and validator roles. Miners produce responses inside the subnet's
rules, and validators evaluate returned work against the subnet's standards
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol)).

The protocol helps organize those interactions. It does not replace the miner role, the validator
role, or the incentive mechanism that connects evaluated output to rewards.

## Axon-Dendrite Context

Bittensor also uses axon and dendrite vocabulary for subnet communication. The glossary describes
axons as receiving incoming synapse objects, while dendrites communicate with axons using the
server-client Axon-dendrite protocol
([Glossary: Axon](https://docs.learnbittensor.org/resources/glossary#axon),
[Glossary: Dendrite](https://docs.learnbittensor.org/resources/glossary#dendrite)).

That vocabulary is compatible with subnet protocol, but it is not the same term. Axon and dendrite
name communication components; subnet protocol names the rule set for how validators and miners
interact around the subnet's work.

## Synapse Context

Synapse objects are the message objects used in Bittensor subnet communication. The glossary
describes synapses as the main vehicle for information exchange between subnet validators and subnet
miners ([Glossary: Synapse](https://docs.learnbittensor.org/resources/glossary#synapse),
[Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol)).

For article readers, synapse vocabulary helps explain the transport side of the exchange. Subnet
protocol remains broader: it describes the interaction expectations around requests and responses,
including how returned work becomes available for validator evaluation.

## Incentive-Mechanism Context

A subnet protocol matters because interaction rules are part of how a subnet turns work into
evaluated output. The protocol works alongside the task and scoring model inside the incentive
mechanism
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

That means protocol claims should stay attached to the subnet's incentive design. A useful protocol
description explains the interaction pattern without turning it into a complete reward formula.

## Reading Protocol Claims

Protocol claims should identify the interaction being described. A useful claim says what role asks
for work, what role responds, and how the response becomes available for evaluation. It should not
silently collapse the protocol, task, scoring model, and reward accounting into one idea
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism),
[Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol)).

This is especially important when comparing subnet articles. Two subnets can both rely on
validator-miner interaction while still asking for different work and judging returned responses by
different standards.

Subnet protocol should be read as concept vocabulary for miner-validator interaction. It is not a
claim that every subnet uses the same exchange pattern, not a status report, and not a substitute
for the subnet's own incentive-mechanism documentation
([Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

The stable article-level point is that a subnet protocol defines the request-and-response rules by
which miners and validators interact inside a subnet.
