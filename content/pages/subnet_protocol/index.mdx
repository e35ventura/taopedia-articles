# Subnet Protocol

A subnet protocol is the rule set for miner-validator interaction inside a Bittensor subnet
([Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

The term belongs to incentive-mechanism vocabulary. It names how subnet roles exchange work for
evaluation, not the work target itself, the scoring method, or the full subnet design.

## Interaction Role

The subnet protocol describes the interaction pattern between validators and miners. The glossary
frames that pattern around how tasks are requested and responses are provided, while broader subnet
documentation explains why subnets can each have their own goals and standards
([Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

For readers, protocol is the interaction layer between a task and an evaluation. It explains how the
subnet's roles meet around work before that work is scored.

## Relationship to the Task

Subnet task and subnet protocol are related but separate ideas. The task names the work miners are
expected to perform, while the protocol names the role interaction around that work
([Glossary: Subnet Task](https://docs.learnbittensor.org/resources/glossary#subnet-task),
[Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol)).

This distinction keeps the content of the work separate from the rules of exchange. A subnet can
change what work it asks for without making the word protocol mean the same thing as task.

## Relationship to the Scoring Model

The scoring model is the evaluation method. A subnet protocol defines role interaction, while a
scoring model defines how validators judge returned work for the subnet's incentive mechanism
([Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

Keeping protocol and scoring separate prevents the interaction rule from being treated as the full
evaluation rule. The protocol gets work into an evaluable context; the scoring model explains how
that work is judged.

## Role Context

Subnet protocols sit between miner and validator roles. Miners produce work for the subnet, and
validators evaluate that work against the subnet's standards
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Glossary: Subnet Miner](https://docs.learnbittensor.org/resources/glossary#subnet-miner),
[Glossary: Subnet Validator](https://docs.learnbittensor.org/resources/glossary#subnet-validator)).

The protocol helps organize those interactions. It does not replace the miner role, the validator
role, or the incentive mechanism that connects evaluated output to rewards.

## Incentive-Mechanism Context

A subnet protocol matters because role interaction is one part of the subnet's incentive design. The
official incentive-mechanism guide places task, protocol, and scoring beside each other as related
pieces of the system that turns subnet work into evaluated output
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism),
[Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol)).

That makes protocol a middle concept. It is more specific than the general idea of a subnet, but it
is narrower than a complete incentive design.

## Reading Protocol Claims

Protocol claims should identify the interaction being described. A useful claim says which subnet
roles are involved, what work is being exchanged, and how that exchange relates to later evaluation
([Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

The term should not be stretched into a status report, a reward formula, or a claim that all subnets
use identical interaction rules. It is concept vocabulary for miner-validator interaction inside a
subnet
([Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

The stable article-level point is that a subnet protocol defines the rules by which miners and
validators exchange work for evaluation.
