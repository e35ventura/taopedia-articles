# Subnet Creation and Incentive Mechanisms

A subnet is a specialized market within Bittensor where miners produce a targeted digital commodity
and validators evaluate that work. Subnet creators define the incentive mechanism—the explicit rules
and evaluation setup that guide validators when scoring miners.

References: [Docs Home](https://docs.bittensor.com/),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism),
Subnet pages (e.g., [Subnet 7](https://docs.bittensor.com/subnet-pages/subnet-7))

## What subnet creators do

- Specify the work to be produced (e.g., model inference, retrieval, storage, compute).
- Define the evaluation process and metrics that validators should apply.
- Provide datasets, prompts, or protocols for validators to use when testing miners.
- Publish transparent rules so miners can optimize and validators can reproduce evaluations.

## Validators and miners within the subnet

- **Validators**: Run the mechanism, evaluate miners, and submit weights that represent relative
  performance.
- **Miners**: Register to the subnet, produce outputs, and compete to maximize validator scores.

Reference: [Validators](https://docs.learnbittensor.org/validators),
[Mining](https://docs.bittensor.com/miners/)

## From mechanism to rewards

- Validator-submitted weights are aggregated (e.g., via Yuma Consensus) to derive final allocations.
- Emissions of TAO are distributed to miners and validators per the aggregated outcome.
- Stakers delegating to validators share in validator dividends.

References: [Emission](https://docs.bittensor.com/emissions),
[Yuma Consensus](https://docs.learnbittensor.org/yuma-consensus/)

## Designing good mechanisms

- **Measurable**: Metrics are objective or reproducible.
- **Robust**: Hard to game; resilient to adversarial behavior.
- **Transparent**: Rules and datasets are disclosed to enable fair participation.
- **Timely**: Evaluations can be run regularly so incentives stay current.

## Lifecycle (high level)

1. Draft mechanism and publish specification (tasks, metrics, scoring).
2. Stand up validator reference implementations and datasets.
3. Launch the subnet; miners register and start competing.
4. Iterate on the mechanism as needed to improve signal quality and anti-gaming.

## Relationship to Multiple Mechanisms

Subnet creators define incentive mechanisms for their subnets. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#subnet-creator) notes that subnet
creators can configure multiple incentive mechanisms to distribute emissions across different types
of work or evaluation criteria.

For readers, subnet creation still names task and evaluation design. A created subnet may later run
more than one incentive mechanism under that design work.

References:
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets),
[Glossary: Subnet Creator](https://docs.learnbittensor.org/resources/glossary#subnet-creator)

## Relationship to Incentive Mechanism

Subnet creation and an incentive mechanism are related but different parts of Bittensor subnet
design vocabulary. Subnet creation names the work of defining what a subnet asks for and how it will
be evaluated, while an incentive mechanism names the rule context that connects that work to
validator evaluation and rewards. The
[Glossary: Subnet Creator](https://docs.learnbittensor.org/resources/glossary#subnet-creator)
describes the role that defines subnet work and evaluation, and the
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)
describes the system that governs consensus among subnet validators.

For readers, subnet creation answers who defines subnet work and evaluation, while an incentive
mechanism answers the rule context that makes that work measurable inside a subnet.

References:
[Glossary: Subnet Creator](https://docs.learnbittensor.org/resources/glossary#subnet-creator),
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)

## Relationship to Subnet Task

Subnet creation and a subnet task are related but different parts of subnet design vocabulary.
Subnet creation covers the broader work of defining a subnet's requested work and evaluation setup,
while a subnet task names only the work target miners are asked to perform inside that design. The
[Glossary: Subnet Creator](https://docs.learnbittensor.org/resources/glossary#subnet-creator)
describes the creator role around subnet work definition, and the
[Glossary: Subnet Task](https://docs.learnbittensor.org/resources/glossary#subnet-task) describes
the work miners perform within an incentive mechanism.

For readers, subnet creation answers how a subnet's work target is designed, while a subnet task
answers what work miners are asked to produce inside that subnet.

References:
[Glossary: Subnet Creator](https://docs.learnbittensor.org/resources/glossary#subnet-creator),
[Glossary: Subnet Task](https://docs.learnbittensor.org/resources/glossary#subnet-task)

## Relationship to Subnet Miner

Subnet creation and a subnet miner are related but different parts of Bittensor subnet vocabulary.
Subnet creation defines the work and evaluation context a subnet will use, while a subnet miner
names the role that performs that work after miners register and compete inside the subnet. The
[Glossary: Subnet Creator](https://docs.learnbittensor.org/resources/glossary#subnet-creator)
describes the design-side role, and the
[Glossary: Subnet Miner](https://docs.learnbittensor.org/resources/glossary#subnet-miner) describes
the entity that performs tasks given by subnet validators.

For readers, subnet creation answers how a subnet's work target is defined, while a subnet miner
answers which role produces that work inside the live subnet market.

References:
[Glossary: Subnet Creator](https://docs.learnbittensor.org/resources/glossary#subnet-creator),
[Glossary: Subnet Miner](https://docs.learnbittensor.org/resources/glossary#subnet-miner)

## Relationship to Netuid

Subnet creation and a netuid are related but different parts of Bittensor subnet vocabulary. Subnet
creation names the design work that defines a subnet's task and evaluation rules, while a netuid
selects which subnet context is in scope once that subnet exists on the network. The
[Glossary: Subnet Creator](https://docs.learnbittensor.org/resources/glossary#subnet-creator)
describes the creator role around subnet design, and the
[Glossary: Netuid](https://docs.learnbittensor.org/resources/glossary#netuid) places netuid at the
subnet level for live subnet context.

For readers, subnet creation answers how a subnet's work and evaluation are defined, while a netuid
answers which subnet market is being discussed after that subnet is operating on chain.

References:
[Glossary: Subnet Creator](https://docs.learnbittensor.org/resources/glossary#subnet-creator),
[Glossary: Netuid](https://docs.learnbittensor.org/resources/glossary#netuid)
