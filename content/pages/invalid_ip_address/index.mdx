# Invalid Ip Address

`InvalidIpAddress` is a documented Subtensor standard error raised by both the `serve_axon` and
`serve_prometheus` extrinsics. The standard-errors reference describes it as "Invalid IP address"
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#invalidipaddress)).

## What It Means

Both extrinsics validate the submitted IP value through the same shared function,
`is_valid_ip_address`, before accepting a serving record. The function rejects an address that does
not pass the rules for its declared IP type: for an IPv4 address it rejects any value at or above
`u32::MAX` and the specific loopback value `0x7f000001` (127.0.0.1); for an IPv6 address it rejects
the maximum `u128` value and the loopback value `1` (`::1`)
([Subtensor source: serving.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/serving.rs)).

The function also takes an `allow_zero` flag, and the two extrinsics call it differently:
`serve_axon` passes `true`, so a zero IP address is accepted there, while `serve_prometheus` passes
`false`, so a zero IP address is rejected. The same shared check applies different zero-address
tolerance depending on which extrinsic called it
([Subtensor source: serving.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/serving.rs)).

## Why It Appears

The check runs purely on the submitted value and the declared IP type; it does not depend on
registration status, subnet state, or any other chain data. An out-of-range value, a loopback
address, or an unpermitted zero address for the calling extrinsic is enough to raise
`InvalidIpAddress` regardless of anything else about the call
([Subtensor source: serving.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/serving.rs)).

## Distinction from Invalid Ip Type

`InvalidIpAddress` and `InvalidIpType` are checked back to back by the same two extrinsics, but they
validate different fields. `InvalidIpType` fires when the declared type code is anything other than
4 or 6, checked through `is_valid_ip_type` before the address value is examined at all.
`InvalidIpAddress` only applies once the type code has already passed that check, since the address
rules depend on which type was declared
([Subtensor Standard Errors: InvalidIpType](https://docs.learnbittensor.org/errors/subtensor#invalidiptype),
[Subtensor source: serving.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/serving.rs)).

- **InvalidIpType** — the declared IP type code is not 4 or 6.
- **InvalidIpAddress** — the address value fails the format or range rule for its declared type.

## Distinction from Invalid Port

`InvalidIpAddress` and `InvalidPort` validate different parts of the same serving record.
`InvalidIpAddress` is checked early, against the IP value itself. `InvalidPort` is checked later, in
`validate_axon_data` or the equivalent prometheus validation, and fires only when the submitted port
is zero
([Subtensor Standard Errors: InvalidPort](https://docs.learnbittensor.org/errors/subtensor#invalidport),
[Subtensor source: serving.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/serving.rs)).

- **InvalidIpAddress** — the IP value itself fails validation.
- **InvalidPort** — the port value is zero.

## Reader Boundary

This page defines the meaning of the error label and the format/range rule that raises it. It does
not describe registration requirements, the serving rate limit, or any other check that `serve_axon`
and `serve_prometheus` perform; those are separate checks with their own error labels
([Subtensor source: serving.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/serving.rs)).
