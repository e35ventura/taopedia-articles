# Failed To Schedule

`FailedToSchedule` is a scheduler pallet error raised when the runtime cannot schedule a call. The
API errors reference summarizes it as "Failed to schedule a call"
([Subtensor API Errors: FailedToSchedule](https://docs.learnbittensor.org/subtensor-api/errors#failedtoschedule)).

## What It Means

Subtensor uses the scheduler pallet to queue calls for dispatch at a specified future block.
`FailedToSchedule` means the scheduler could not store the call for that future dispatch, so the
scheduling request fails without naming a more specific scheduler rejection in the API summary
([Subtensor API Errors: FailedToSchedule](https://docs.learnbittensor.org/subtensor-api/errors#failedtoschedule)).

This is a generic scheduling failure label. It does not, by itself, mean the submitted target block
is in the past, that a reschedule would leave the call at the same block, or that no matching
scheduled call exists in storage.

## Why It Appears

This error appears when a scheduler operation that should queue a call for future dispatch cannot
complete that storage step
([Subtensor API Errors: FailedToSchedule](https://docs.learnbittensor.org/subtensor-api/errors#failedtoschedule)).

## Distinction from Target Block Number In Past

`FailedToSchedule` and `TargetBlockNumberInPast` both stop scheduler scheduling paths, but with
different API summaries. `FailedToSchedule` is summarized as "Failed to schedule a call."
`TargetBlockNumberInPast` is summarized as "Given target block number is in the past."
([Subtensor API Errors: FailedToSchedule](https://docs.learnbittensor.org/subtensor-api/errors#failedtoschedule),
[Subtensor API Errors: TargetBlockNumberInPast](https://docs.learnbittensor.org/subtensor-api/errors#targetblocknumberinpast)).

- **FailedToSchedule** — the scheduler failed to schedule the call.
- **TargetBlockNumberInPast** — the submitted target block number is in the past.

## Distinction from Reschedule No Change

`FailedToSchedule` and `RescheduleNoChange` both stop scheduler operations from succeeding, but on
different checks. `FailedToSchedule` is summarized as "Failed to schedule a call."
`RescheduleNoChange` is summarized as "Reschedule failed because it does not change scheduled time."
([Subtensor API Errors: FailedToSchedule](https://docs.learnbittensor.org/subtensor-api/errors#failedtoschedule),
[Subtensor API Errors: RescheduleNoChange](https://docs.learnbittensor.org/subtensor-api/errors#reschedulenochange)).

- **FailedToSchedule** — the scheduler failed to schedule the call.
- **RescheduleNoChange** — the reschedule would not change the scheduled time.

## Reader Boundary

This page defines the meaning of the error label from the API reference. It does not diagnose which
scheduler storage step failed on a network or choose a valid scheduling payload
([Subtensor API Errors: FailedToSchedule](https://docs.learnbittensor.org/subtensor-api/errors#failedtoschedule),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
