# Validator Registration

Validator registration is the validator-specific case of register in a Bittensor subnet. The
official
[Validating: Validator registration](https://docs.learnbittensor.org/validators#validator-registration)
documentation describes registration as the step in which a validator registers a hotkey with a
subnet to receive a UID on that subnet.

## Validator-Specific Scope

The broader [Register](https://docs.learnbittensor.org/resources/glossary#register) glossary entry
covers subnet entry for participants generally. Validator registration narrows that concept to
validators: the participant receiving the UID slot is a subnet validator rather than a miner.

This keeps the term role-specific. Register names the general subnet-entry process, while validator
registration names the validator side of that vocabulary.

## Hotkey and UID Slot Context

Validator registration connects a validator hotkey to a subnet UID slot. The
[Glossary: UID Slot](https://docs.learnbittensor.org/resources/glossary#uid-slot) defines a UID slot
as a position occupied by a subnet miner or subnet validator within a subnet, and the validating
documentation explains that the registering hotkey becomes the holder of that slot.

For readers, validator registration should be read as subnet-participation vocabulary, not as a
wallet backup guide or a live registration-cost quote.

References: [Working with Keys](https://docs.learnbittensor.org/keys/working-with-keys),
[Validating: Validator registration](https://docs.learnbittensor.org/validators#validator-registration)

## Contrast with Miner Registration

Miner registration and validator registration share the register label but apply to different subnet
roles. The [Mining: Miner registration](https://docs.learnbittensor.org/miners#miner-registration)
documentation describes miners registering to receive a UID for mining work, while validator
registration describes validators registering for validation participation in the same subnet slot
vocabulary.

Choosing the correct term depends on which role is entering the subnet, not on whether the subnet
runs one or many incentive mechanisms.

## Validation Permit Context

Validator registration is only the entry step. Ongoing validation participation also involves
validator-permit context described in official validating documentation. The
[Glossary: Validator Permit](https://docs.learnbittensor.org/resources/glossary#validator-permit)
marks whether a subnet participant has validation rights inside a subnet.

For readers, validator registration names entry into a UID slot; validator permit names ongoing
validation-right context after registration.

References:
[Glossary: Validator Permit](https://docs.learnbittensor.org/resources/glossary#validator-permit),
[Validating: Validator registration](https://docs.learnbittensor.org/validators#validator-registration)

## Relationship to Deregistration

Register and deregistration are opposite directions in subnet capacity vocabulary. The
[Glossary: Deregistration](https://docs.learnbittensor.org/resources/glossary#deregistration)
describes removing a low-performing subnet participant when capacity rules require replacement,
while validator registration describes a validator entering that capacity picture.

Validator deregistration is the validator-specific removal counterpart. Together, these terms
describe validator entry and exit vocabulary inside subnet UID management.

References:
[Validator Deregistration](https://docs.learnbittensor.org/validators#validator-deregistration),
[Glossary: Deregistration](https://docs.learnbittensor.org/resources/glossary#deregistration)

## Relationship to Multiple Mechanisms

A validator registers into one subnet that may run more than one incentive mechanism. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms) notes
that validators must evaluate miners separately for each mechanism.

For readers, validator registration still names validator entry into a UID slot. Mechanism count
belongs with subnet incentive design rather than with the registration label itself.

References:
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets),
[Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)
