Proxy wallets are a Bittensor security pattern where one account is allowed to act on behalf of
another account. The protected account is often called the safe wallet or real account, while the
proxy account performs approved operations without requiring the safe wallet's coldkey to be used
for every action.

This is useful when a wallet controls valuable TAO, alpha stake, or subnet ownership. A proxy can
support day-to-day operations while the more sensitive coldkey remains in a higher-security
environment.

## Why Proxies Matter

In Bittensor, a coldkey controls sensitive wallet authority, including balances, stake, and
ownership-related operations. Keeping that coldkey offline reduces exposure, but it can make routine
operations harder. A proxy relationship creates a controlled delegation path so another account can
perform selected actions for the safe wallet.

The security value comes from limits. Bittensor proxy relationships can be scoped by proxy type, so
the proxy is only allowed to make certain categories of calls. They can also use a delay, which
gives the safe wallet holder time to notice and reject a pending proxy action before it executes.

## Safe Wallet and Proxy Wallet

The safe wallet is the account being protected. Its private key and seed phrase should be handled as
high-value secrets, especially on Finney where wallet actions can affect real funds or subnet
ownership.

The proxy wallet is the account given limited authority to act for the safe wallet. It still needs
careful key handling, but it can be placed in a more operational environment when its permissions
are narrow enough for the intended task.

## Practical Boundaries

Proxy wallets are not a replacement for good key security. A broad or unrestricted proxy can still
create serious risk, and a proxy with no delay gives less time to respond if the proxy key is
compromised. The official docs therefore emphasize least-privilege proxy types, careful handling of
both accounts, and using unrestricted authority only when a narrower proxy type does not fit.

Pure proxies are a related but different pattern. They are keyless accounts controlled through a
delegator and are mainly useful for account indirection patterns such as multisignature setups. For
ordinary coldkey protection, regular proxy wallets are usually the relevant concept.
