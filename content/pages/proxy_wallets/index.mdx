# Proxy Wallets

Proxy wallets are delegated accounts that can perform limited actions for another Bittensor account.
They matter because [wallets](https://docs.learnbittensor.org/keys/wallets) control transaction
signing, TAO access, and staking actions, while
[proxy relationships](https://docs.learnbittensor.org/keys/proxies) can narrow which account needs
to be active for routine work.

## Why proxy wallets exist

The purpose of a proxy relationship is to reduce operational exposure. A protected wallet can keep
its broader authority while a separate account handles a narrower set of actions. That makes proxies
part of wallet safety, not a replacement for careful key management. In Bittensor,
[proxy relationships](https://docs.learnbittensor.org/keys/proxies) are built around delegation, and
[wallet authority](https://docs.learnbittensor.org/keys/wallets) is security-sensitive because
wallets control signed actions.

## Permission boundaries

A proxy relationship is useful only because the delegated account is not meant to have unlimited
wallet authority. Bittensor [proxy permissions](https://docs.learnbittensor.org/keys/proxies) are
shaped by proxy type, so the delegated account is limited to the class of actions the relationship
allows. This distinction keeps proxy wallets separate from simply sharing wallet access.

## Protected and delegated accounts

Proxy Wallets are easiest to understand as a relationship between a protected account and a
delegated account. The protected account remains the source of authority, while the delegated
account performs allowed actions through the proxy relationship. Because Bittensor
[wallets](https://docs.learnbittensor.org/keys/wallets) control transaction signing, TAO access, and
staking actions, proxies add a permission boundary around selected actions.

## Delay and revocation context

Proxy relationships can include controls that affect when delegated actions become usable and
whether delegated access remains available. At a concept level, these controls are part of the
permission boundary: a proxy should be understood as an account relationship that can be limited,
changed, or removed by the controlling account. In the
[Bittensor proxy model](https://docs.learnbittensor.org/keys/proxies), those controls belong to the
same delegated-permission relationship.

## Security context

A proxy wallet does not make unsafe wallet handling safe. It reduces the need to expose a broader
authority for every action, but the delegated account still signs transactions within the permission
scope it receives. This is why proxy wallets fit next to [[wallets|Wallets]] as a wallet-safety
topic. A [proxy relationship](https://docs.learnbittensor.org/keys/proxies) changes which account
can perform selected actions; it does not remove the need to protect every signing account in that
relationship.
