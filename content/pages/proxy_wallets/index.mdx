# Proxy Wallets

Proxy wallets are delegated accounts that can act for another Bittensor account within a defined
permission boundary. The official [Proxies overview](https://docs.learnbittensor.org/keys/proxies)
describes proxies as a way for one account to make calls on behalf of another, while the
[wallets guide](https://docs.learnbittensor.org/keys/wallets) explains that wallets sign
transactions, access TAO, and manage stake.

For Taopedia readers, the useful idea is separation. A proxy relationship lets routine wallet
activity move through a delegated account without treating that delegated account as the full owner
of the original wallet.

## What Proxy Wallets Do

A proxy relationship separates two roles: the account being represented and the account allowed to
act for it. The represented account keeps the underlying authority. The proxy account is only useful
because the relationship grants it a narrower role.

That makes proxy wallets different from sharing a seed phrase or transferring assets to another
wallet. The delegated account does not become the original wallet; it receives permission to perform
selected actions for it.

## Permission Boundaries

Proxy security depends on permission scope. The
[Proxies overview](https://docs.learnbittensor.org/keys/proxies) describes proxy relationships as
permissioned rather than all-or-nothing. In practice, that means a delegated account should be given
only the role it actually needs.

This distinction is the main security value of proxies. A narrowly scoped proxy can reduce the
amount of authority exposed during routine activity. A broadly scoped proxy is more powerful, so its
security risk is larger too.

## Delays and Revocation

Proxy relationships can include a delay. With a delay, a delegated action is not immediate. The
official [wallets guide](https://docs.learnbittensor.org/keys/wallets) describes proxies in terms of
limited, delayed operations, which is why delay settings matter for wallet security.

The represented account can also remove a proxy relationship. According to the
[Proxies overview](https://docs.learnbittensor.org/keys/proxies), removing the relationship stops
the delegated account from acting on behalf of the represented account.

## Wallet Safety Context

Proxy wallets belong in wallet safety because they change which account is used for selected
actions. The [wallets guide](https://docs.learnbittensor.org/keys/wallets) describes wallets as the
place where transaction signing and TAO-related control happen, so delegation should be read as a
security boundary rather than a convenience label.

This article does not try to list every proxy mode or provide operating instructions. The safer
Taopedia-level takeaway is that a proxy should be understood by asking three questions: which
account is represented, which account is delegated, and what permission boundary sits between them.

## Security Context

A proxy wallet is not a substitute for secure key handling. It narrows which account needs to be
active for a task, but the delegated account still signs transactions within the authority it has
been given. If the proxy has broad permissions or no delay, compromise of the proxy account can
still be serious.

For that reason, proxy-wallet claims should specify the represented account, the delegated account,
the permission scope, and whether a delay is used. Without those details, "using a proxy" is too
vague to describe the actual security boundary.
