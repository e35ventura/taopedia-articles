# Initial Max Allowed Validators

Initial Max Allowed Validators is a subtensorModule runtime constant, listed in the chain's
constants metadata as initialMaxAllowedValidators, with the value 128 and the summary "Initial
maximum allowed validators per network"
([Subtensor API Constants: initialMaxAllowedValidators](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxallowedvalidators-u16)).
It supplies the default value a subnet's MaxAllowedValidators uses.

## What It Means

MaxAllowedValidators is held per subnet and caps how many neurons on a subnet may hold validator
status. Initial Max Allowed Validators is the default this per-subnet value falls back to before a
different value applies for a subnet
([Subtensor API Constants: initialMaxAllowedValidators](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxallowedvalidators-u16)).
The MaxAllowedValidators in force on a subnet such as netuid 1 is that subnet's own chain state and
can differ from this default.

## Distinction from Allowed UID Defaults

Initial Max Allowed Validators is the default validator cap, while initialMaxAllowedUids, valued at
256, is the maximum number of UIDs a subnet may hold; initialMinAllowedUids, valued at 64, is the
minimum number of UIDs a subnet may hold
([Subtensor API Constants: initialMaxAllowedUids](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxalloweduids-u16),
[Subtensor API Constants: initialMinAllowedUids](https://docs.learnbittensor.org/subtensor-api/constants#initialminalloweduids-u16)).

## Reader Boundary

Initial Max Allowed Validators is a default constant, not the live per-subnet MaxAllowedValidators,
and it reflects the current runtime configuration rather than a fixed protocol rule
([Subtensor API Constants: initialMaxAllowedValidators](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxallowedvalidators-u16)).
