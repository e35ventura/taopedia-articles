# Regenerating a Key

Regenerating a key refers to recovering wallet key material from recovery information. In Bittensor
wallet context, documentation treats key material and recovery phrases as security-sensitive.

## What It Represents

Regenerating a key is the wallet recovery action that recreates a lost or deleted coldkey or hotkey
from its associated mnemonic
([Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key),
[Working with Keys](https://docs.learnbittensor.org/keys/working-with-keys)).

Recovery information can restore access to wallet keys, so it should be protected with the same care
as other sensitive wallet material
([Handle your Seed Phrase/Mnemonic Securely](https://docs.learnbittensor.org/keys/handle-seed-phrase)).

Regeneration reproduces the original key rather than producing a new one. The same mnemonic maps
back to the same key material each time, which is why recovery restores the original
[SS58 address](https://docs.learnbittensor.org/resources/glossary#ss58-encoded) instead of a
different on-chain identity
([Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key),
[Glossary: Mnemonic](https://docs.learnbittensor.org/resources/glossary#mnemonic)).

Anyone who obtains the mnemonic can reproduce that key, so recovery words deserve the same
protection as the key files they replace.

## Each Key Has Its Own Recovery Material

Bittensor wallet creation can produce separate recovery material for the coldkey and for each
hotkey. The [Working with Keys](https://docs.learnbittensor.org/keys/working-with-keys) guide notes
that a unique mnemonic is generated for each key and shown at creation time.

Regenerating a key therefore restores only the key tied to the mnemonic being used. A coldkey
recovery phrase and a hotkey recovery phrase are different secrets tied to different signing roles
in the [Wallets](https://docs.learnbittensor.org/keys/wallets) model. The mnemonic must match the
specific coldkey or hotkey being restored
([Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key),
[Glossary: Coldkey](https://docs.learnbittensor.org/resources/glossary#coldkey),
[Glossary: Hotkey](https://docs.learnbittensor.org/resources/glossary#hotkey)).

## Development Stage Context

The
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction#subnet-development)
describes subnet development as moving from localnet to testnet and then mainnet. Key regeneration
can restore wallet files in any environment, but custody stakes rise on mainnet where restored keys
may control real TAO and stake
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

Localnet and testnet recovery exercises should not be read as proof of production wallet custody
behavior on another network.

## Distinction from Seed Phrase Security

Seed phrase security names handling practices for recovery words. Regenerating a key names the
restore action those words enable
([Handle your Seed Phrase/Mnemonic Securely](https://docs.learnbittensor.org/keys/handle-seed-phrase),
[Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key)).

## Distinction from Mnemonic

A mnemonic is the recovery phrase itself. Regenerating a key is the procedure that uses it to
rebuild a lost coldkey or hotkey
([Glossary: Mnemonic](https://docs.learnbittensor.org/resources/glossary#mnemonic),
[Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key)).

## Distinction from Coldkeys

A coldkey is the custody key that controls TAO and hotkeys. Regenerating a key can restore that
coldkey from its mnemonic when local files are lost
([Glossary: Coldkey](https://docs.learnbittensor.org/resources/glossary#coldkey),
[Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key)).

## Distinction from Local Wallet

Regenerating a key is the restore action recovery words enable for a specific wallet key. A local
wallet is the on-disk wallet file structure those keys are stored in after creation
([Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key),
[Glossary: Local Wallet](https://docs.learnbittensor.org/resources/glossary#local-wallet)).

- **Regenerating a key** — restore action from recovery material.
- **Local wallet** — on-disk wallet file that holds generated keys.

Restore vocabulary names the recovery action; local-wallet vocabulary names the storage container
([Working with Keys](https://docs.learnbittensor.org/keys/working-with-keys)).

## Distinction from Public Key

A public key is the openly shareable component of a wallet keypair, used to verify signatures and
identify an account, while regenerating a key is the procedure that rebuilds a lost coldkey or
hotkey from its mnemonic
([Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key)).

- **Regenerating a key** — the recovery action that reconstructs lost key material.
- **Public key** — the shareable component that recovery reproduces unchanged, so others verify the
  same identity afterward.

## Distinction from Private Key

A private key is the secret component that authorizes transactions and signs operations, whereas
regenerating a key is the recovery step that reproduces that secret from the mnemonic when local
files are gone
([Glossary: Private Key](https://docs.learnbittensor.org/resources/glossary#private-key)).

- **Regenerating a key** — the action that restores access when key files are lost.
- **Private key** — the secret signing component that restoration brings back, which is why the
  mnemonic deserves the same protection.

## Distinction from Hotkey Swap

Regenerating a key recreates lost hotkey files from saved recovery material. Hotkey swap is an
on-chain rotation that moves subnet participation from an old hotkey to a replacement hotkey under
the same coldkey when the operational key may have leaked
([Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key),
[Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

- **Regenerating a key** — recovery path when local key files are missing.
- **Hotkey swap** — on-chain rotation when the hotkey should be replaced but the coldkey remains
  trusted.

A deleted hotkey file may call for regeneration from its mnemonic. A suspected hotkey leak may call
for hotkey swap without treating the coldkey as lost
([Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

## Distinction from Coldkey Swap

Regenerating a key restores coldkey or hotkey material from a mnemonic when local files are lost.
Coldkey swap migrates on-chain wallet identity to a new coldkey address after recovery material is
compromised or a controlled migration is authorized
([Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key),
[Coldkey Swap](https://docs.learnbittensor.org/keys/coldkey-swap),
[Handle your Seed Phrase/Mnemonic Securely](https://docs.learnbittensor.org/keys/handle-seed-phrase)).

- **Regenerating a key** — recovery action that reproduces the same key material.
- **Coldkey swap** — identity migration to a new coldkey under documented on-chain rules.

Recovery restores local signing files. Coldkey swap changes the controlling coldkey on chain when
exposed recovery words or a deliberate migration require it.

## Distinction from Register

Regenerating a key restores wallet key files from recovery material. Register is the subnet-entry
process that purchases a UID slot on a selected netuid
([Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key),
[Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register)).

- **Regenerating a key** — offline recovery of coldkey or hotkey signing material.
- **Register** — on-chain admission that claims a subnet UID slot.

Restored hotkey files can sign operational work again, but subnet participation still depends on the
registration and permit context already on chain. Live chain state determines what a restored key
can operate after recovery completes
([Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register)).

## Distinction from Hotkeys

A hotkey is the operational key used for subnet work. Regenerating a key can restore that hotkey
from its mnemonic when local files are lost, without creating a new on-chain hotkey identity
([Glossary: Hotkey](https://docs.learnbittensor.org/resources/glossary#hotkey),
[Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key)).

- **Hotkey** — operational signing key for subnet roles.
- **Regenerating a key** — recovery action that rebuilds the same hotkey material from its mnemonic.

Hotkey swap replaces the operational key on chain; regeneration rebuilds the original hotkey files
when they are missing locally.

## Distinction from Multisig

Regenerating a key recreates one lost coldkey or hotkey from its associated mnemonic. Multisig is
the M-of-N approval model that distributes shared coldkey custody across several signatories
([Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key),
[Secure a Coldkey with a Multisig Wallet](https://docs.learnbittensor.org/keys/multisig)).

- **Regenerating a key** — recovery action for one key file tied to one mnemonic.
- **Multisig** — threshold custody model requiring multiple signatory approvals.

Losing one signatory key may be survivable when the remaining signatories can still meet the
threshold. Regeneration restores the specific key tied to the mnemonic being used rather than
changing how many approvals the wallet requires
([Secure a Coldkey with a Multisig Wallet](https://docs.learnbittensor.org/keys/multisig)).

## Distinction from Yuma Consensus

Regenerating a key is the process of recreating a lost or deleted coldkey or hotkey from its
associated mnemonic. It names wallet recovery vocabulary, not the on-chain step that turns validator
weight submissions into emission shares
([Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key),
[Working with Keys](https://docs.learnbittensor.org/keys/working-with-keys)).

Yuma Consensus is the on-chain process that converts submitted validator weights into emission
shares after evaluation completes. Key regeneration restores signing material offline; it does not
recreate subnet UID slots or validator permits by itself
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Emission](https://docs.learnbittensor.org/learn/emissions)).

Readers should keep key-recovery vocabulary separate from the settlement step. Regenerating a key
answers how wallet keys are restored from a mnemonic; Yuma Consensus answers how validator weights
become emission shares in a subnet
([Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Regenerating a key** — recreating coldkey or hotkey material from a mnemonic.
- **Yuma Consensus** — on-chain weight aggregation that settles emissions.

## Distinction from Seed Phrase

Regenerating a key and a seed phrase relate as a recovery action and the input it consumes. A seed
phrase is the human-readable word sequence that can recover wallet key material, while regenerating
a key is the act of recovering that key material from such recovery information
([Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key),
[Glossary: Seed Phrase](https://docs.learnbittensor.org/resources/glossary#seed-phrase),
[Glossary: Mnemonic](https://docs.learnbittensor.org/resources/glossary#mnemonic)).

- **Seed phrase** — the word sequence that can recover wallet key material.
- **Regenerating a key** — the act of recovering key material from that information.

## Reader Boundary

This page defines the term. It does not ask readers to enter a recovery phrase, expose keys, or
follow a specific recovery action. The
[Working with Keys](https://docs.learnbittensor.org/keys/working-with-keys) documentation is the
better source for current security-sensitive wallet actions.
