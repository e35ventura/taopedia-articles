Talisman AI is Bittensor Subnet 45, a perception subnet aimed at producing on-chain trading
insights. In its current phase the subnet analyzes social media activity relevant to Bittensor,
starting with X: miners turn raw posts into structured analysis, and validators verify that analysis
before it is rewarded and stored for downstream use. The incentive-mechanism code is maintained in
the [Team-Rizzo/talisman-ai](https://github.com/Team-Rizzo/talisman-ai) repository.

## What the Subnet Produces

The subnet's output is structured, labeled signals extracted from social posts rather than the posts
themselves. For each post a miner identifies which subnet it concerns and assigns categorical labels
such as sentiment and content type, producing an enriched record that a downstream agent could act
on. A coordination service hands out batches of posts to work on and stores the completed analysis,
so the network functions as a pipeline that converts public chatter into a queryable dataset.

## Signal Layer Context

The [Talisman AI README](https://github.com/Team-Rizzo/talisman-ai/blob/main/README.md) frames SN45
as the perception layer for a broader financial reasoning agent. The source is explicit that the
subnet does not decide what to trade; it feeds the agent with validated, high-quality signal data.
That distinction matters for readers because the subnet's product is not a final recommendation. It
is the signal layer that makes later reasoning possible.

The same README describes the current phase as social-media sentiment for Bittensor-relevant
activity, starting with X. Miners search for high-value posts that are relevant to specific subnets,
and validators verify accuracy and enforce quality. At the article level, this means a miner's
useful contribution is a structured interpretation of a post: which subnet it concerns, what
sentiment or content type it carries, and whether that interpretation can pass validation.

This framing keeps the article centered on data quality. Talisman AI rewards labeled signal records
that can be stored and used downstream. The README's perception, reasoning, and action layers
explain why SN45 focuses on collecting and validating signal data before later reasoning and action
layers use it.

## Validation Context

The
[validator module documentation](https://github.com/Team-Rizzo/talisman-ai/blob/main/talisman_ai/validator/README.md)
describes the validator as independently verifying miner submissions and enforcing quality
standards. It also describes validation as a background process that grades posts, submits completed
results, and updates miner scores for weight setting.

For readers, the important point is the separation between miner analysis and validator
verification. A miner can submit an enriched post record, but that record only becomes useful signal
data if it survives validator-side checks. The validator documentation describes this as comparing
miner classifications against validator analysis before the result affects score management.

That validation layer explains why the article treats Talisman AI as a structured-signal subnet. The
subnet is trying to produce validated records about Bittensor-related activity, with miners
supplying candidate analysis and validators deciding whether that analysis is accurate enough to
count.

## Miner and Validator Roles

Miners receive batches of posts from validators and analyze each one with a language model,
returning enriched records — for example, the subnet a post is about, its sentiment on a five-point
scale, and its content type. The miner's job is accurate classification at scale, not opinion.

Validators enforce quality by re-doing the work. A validator independently re-analyzes a sampled
subset of a miner's batch and requires an exact match on the key categorical fields; if any sampled
post disagrees, the entire batch is rejected and the miner is penalized for that epoch, while a
fully matching batch is accepted. Rewards are tracked as per-epoch points, validators share compact
epoch snapshots with each other, and weights are set on chain on a delayed epoch window. Those
weights feed into [[Yuma Consensus]], which converts them into the incentive split across miners and
validators.

## On-Chain Identity

Live SN45 data, including metagraph state and alpha token pool information, is available on
[TaoStats](https://taostats.io/subnets/45). Readers can reproduce the subnet's registered identity
fields with the Bittensor CLI command documented in the
[btcli reference](https://docs.learnbittensor.org/btcli/#btcli-subnets-get-identity):
`btcli subnets get-identity --netuid 45 --network finney`.

The Finney subnet identity for netuid 45 points to the
[Team-Rizzo/talisman-ai](https://github.com/Team-Rizzo/talisman-ai) repository, which is the source
of truth for the analysis and verification process described above.
