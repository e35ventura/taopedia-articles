# Wallet Applications

Wallet applications are the software interfaces people use to view wallet information, prepare
transactions, manage stake, and interact with Bittensor wallet keys. The official
[Wallets, Coldkeys and Hotkeys in Bittensor](https://docs.learnbittensor.org/keys/wallets) guide
distinguishes wallet applications from the cryptographic wallet itself and from hardware-wallet
devices that hold private keys.

The useful reader distinction is simple. A cryptographic wallet is the identity and signing
authority. A wallet application is the software that helps a user interact with that identity.
Confusing those two layers can lead to unsafe assumptions about where private keys live and what a
piece of software can do.

## What It Represents

A wallet application is the software interface for viewing wallet state, preparing transactions,
managing stake, and connecting custody devices. The cryptographic wallet is the coldkey and hotkey
identity and signing authority; the application is the visible layer that helps a user interact with
that identity without being the identity itself
([Wallets, Coldkeys and Hotkeys in Bittensor](https://docs.learnbittensor.org/keys/wallets)).

The same cryptographic wallet can appear through different applications. Changing the app does not
change underlying balances, addresses, or on-chain identity; it changes the interface and the
operational risk around how keys are used.

Permissionless wallet apps can display public wallet information from a coldkey public key alone.
Read-only work on balances, stake, validators, and subnet state belongs in the lowest-risk pattern
whenever a task does not require signing
([Wallets, Coldkeys and Hotkeys in Bittensor](https://docs.learnbittensor.org/keys/wallets),
[Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

Value-bearing applications prepare transfers, staking, and unstaking actions that require review of
destination, amount, network context, and signing source. Full-featured tooling is still needed for
advanced authority such as hotkey management, subnet management, and governance participation
([Wallets, Coldkeys and Hotkeys in Bittensor](https://docs.learnbittensor.org/keys/wallets)).

Applications can also companion hardware or offline signers. Compatible wallet apps prepare actions
while a Ledger device or Polkadot Vault holds the private key and signs what the user approves. The
app prepares and broadcasts; the signer protects custody material
([Using Ledger Hardware Wallet](https://docs.learnbittensor.org/staking-and-delegation/using-ledger-hw-wallet),
[Polkadot Vault](https://vault.novasama.io/)).

Wallet applications display addresses and transaction details, but users still must verify
destinations. Address-poisoning guidance warns against relying on recent history or shortened
displays when sending funds
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

The security question is what authority the environment can exercise: public viewing, hotkey
operations, proxy coldkey actions, or primary coldkey custody. Read-only exploration sits on the
low-risk side; staking, transfers, and coldkey-sensitive operations sit on the high-risk side where
the signing interface is also where address mistakes usually happen
([Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

## Development Stage Context

The
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction#subnet-development)
describes subnet development as moving from localnet to testnet and then mainnet. Wallet-application
examples should be read against that network boundary rather than as proof of production custody
behavior on another network
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from External Wallet

A wallet application is the software interface used to view wallet state and prepare actions. An
external wallet names custody or signing control managed outside the local Bittensor wallet path
([Wallets](https://docs.learnbittensor.org/keys/wallets),
[Glossary: External Wallet](https://docs.learnbittensor.org/resources/glossary#external-wallet)).

Interface vocabulary names which app is being used; external-wallet vocabulary names where custody
or signing control lives.

## Distinction from Coldkeys

A coldkey is the security-sensitive key that holds TAO balances and owns hotkeys. A wallet
application is the software interface that helps a user view state and prepare transactions
([Glossary: Coldkey](https://docs.learnbittensor.org/resources/glossary#coldkey),
[Wallets, Coldkeys and Hotkeys](https://docs.learnbittensor.org/keys/wallets)).

Key material names custody authority; application vocabulary names the interaction layer around it.

## Distinction from Wallets

A wallet is the cryptographic identity formed by coldkey and hotkey pairs. A wallet application is
the software that presents that identity and helps prepare signed actions
([Wallets, Coldkeys and Hotkeys](https://docs.learnbittensor.org/keys/wallets)).

Identity vocabulary names what is owned on chain; application vocabulary names the interface used to
act on it.

## Distinction from Hotkeys

Hotkeys are operational keys used for subnet-facing signing on connected infrastructure. Wallet
applications may help prepare or relay actions but do not replace the hotkey's operational role
([Glossary: Hotkey](https://docs.learnbittensor.org/resources/glossary#hotkey),
[Wallets, Coldkeys and Hotkeys](https://docs.learnbittensor.org/keys/wallets)).

Operational key vocabulary and interface software answer different questions in the same workflow.

## Distinction from Ledger Hardware Wallet

Ledger hardware wallet is a signing device that keeps keys off the online machine. A wallet
application may connect to that device while preparing transactions on the online side
([Using Ledger Hardware Wallet](https://docs.learnbittensor.org/staking-and-delegation/using-ledger-hw-wallet)).

Application vocabulary names preparation software; hardware-wallet vocabulary names the offline
signing device.

## Distinction from Polkadot Vault

Polkadot Vault is an offline mobile signer for coldkey material. Wallet applications typically run
on the online side that prepares transactions for review and broadcast
([Polkadot Vault](https://vault.novasama.io/),
[Wallets, Coldkeys and Hotkeys](https://docs.learnbittensor.org/keys/wallets)).

Offline signer and online interface sit on opposite sides of the air-gapped workflow.

## Distinction from Yuma Consensus

Wallet applications are software interfaces for viewing wallet state and preparing transactions.
Yuma Consensus is the on-chain process that converts submitted validator weights into emission
shares ([Wallets, Coldkeys and Hotkeys](https://docs.learnbittensor.org/keys/wallets),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Wallet applications** — software interfaces for wallet interaction.
- **Yuma Consensus** — on-chain weight aggregation that settles emissions.

## Reader Boundary

Wallet applications should not be read as interchangeable custody guarantees. They are software
interfaces with different supported actions, signing boundaries, and security assumptions. The
underlying wallet identity remains tied to key material and on-chain records.

This article explains the term, not a setup procedure. It does not endorse a specific application,
rank wallets, or ask readers to enter keys. Security-sensitive wallet actions should be checked
against current official wallet documentation.
