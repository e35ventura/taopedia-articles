# Initial Min Difficulty

Initial Min Difficulty is a subtensorModule runtime constant, listed in the chain's constants
metadata as initialMinDifficulty, with the value 10000000 and the summary "Initial Min Difficulty"
([Subtensor API Constants: initialMinDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmindifficulty-u64)).
It supplies the default value a subnet's MinDifficulty uses.

## What It Means

MinDifficulty is held per subnet and sets the floor a subnet's proof-of-work registration difficulty
may not fall below. Initial Min Difficulty is the default this per-subnet value falls back to before
a different value applies for a subnet
([Subtensor API Constants: initialMinDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmindifficulty-u64)).
The MinDifficulty in force on a subnet such as netuid 1 is that subnet's own chain state and can
differ from this default.

## Distinction from Initial and Max Difficulty

Initial Min Difficulty is the default floor of the difficulty range, while initialDifficulty, valued
at 10000000, is the starting difficulty a subnet registers at; initialMaxDifficulty, valued at
4611686018427387903, is the ceiling the difficulty may not exceed
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64),
[Subtensor API Constants: initialMaxDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxdifficulty-u64)).

## Reader Boundary

Initial Min Difficulty is a default constant, not the live per-subnet MinDifficulty, and it reflects
the current runtime configuration rather than a fixed protocol rule
([Subtensor API Constants: initialMinDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmindifficulty-u64)).
