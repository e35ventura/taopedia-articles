# Initial Min Difficulty

Initial Min Difficulty is a subtensorModule runtime constant, listed in the chain's constants
metadata as initialMinDifficulty, with the value 10000000 and the summary "How the
initialMinDifficulty runtime constant provides the default floor for a subnet's proof-of-work
registration difficulty, the lower end of the difficulty range."
([Subtensor API Constants: initialMinDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmindifficulty-u64)).
It provides the default value a subnet's MinDifficulty takes.

## What It Means

MinDifficulty is per-subnet chain state that sets the floor a subnet's proof-of-work registration
difficulty may not fall below. Initial Min Difficulty is the default a subnet's MinDifficulty is set
to when the subnet is created; from there the value is held per subnet and can differ between
subnets. For example, a subnet such as netuid 1 begins with its MinDifficulty set to this default
([Subtensor API Constants: initialMinDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmindifficulty-u64)).
The constant is the seed default, not itself the live per-subnet value.

## Distinction from Initial Max Difficulty

Initial initial min difficulty and initialMaxDifficulty both seed per-subnet defaults but for
different points. initialMinDifficulty seeds the floor of the difficulty range, while
initialMaxDifficulty, valued at 4611686018427387903, seeds the ceiling of the difficulty range
([Subtensor API Constants: initialMaxDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxdifficulty-u64)).
The two are separate defaults a subnet starts with, each held per subnet and each able to differ
once set for that subnet.

## Distinction from Initial Difficulty

Initial initial min difficulty and initialDifficulty both seed per-subnet defaults but for different
points. initialMinDifficulty seeds the floor of the difficulty range, while initialDifficulty,
valued at 10000000, seeds the starting difficulty a subnet registers at
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).
The two are separate defaults a subnet starts with, each held per subnet and each able to differ
once set for that subnet.

## Why a Default Exists

Providing a default means every new subnet starts with a defined MinDifficulty rather than an
undefined one. Because the default is fixed as a constant, the value a subnet's MinDifficulty begins
at is known in advance, even though a subnet may later hold a different value once it is set for
that subnet
([Subtensor API Constants: initialMinDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmindifficulty-u64)).

## Constant Versus Live Value

It helps to read initialMinDifficulty and a subnet's live MinDifficulty as two different things. The
constant is a fixed figure in the runtime that supplies the starting value; the live MinDifficulty
is per-subnet chain state that begins at that figure and is thereafter maintained for each subnet on
its own
([Subtensor API Constants: initialMinDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmindifficulty-u64)).
Two subnets can share the same default from this constant yet hold different live values later.

## Reader Boundary

Initial Min Difficulty is the default constant that seeds a subnet's MinDifficulty; it is not the
live per-subnet value, which can differ once set for a subnet, and it reflects the current runtime
configuration rather than a fixed protocol rule. It does not report the value in force on any subnet
([Subtensor API Constants: initialMinDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmindifficulty-u64)).
