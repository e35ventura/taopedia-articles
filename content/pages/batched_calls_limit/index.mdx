# Batched Calls Limit

Batched calls limit is a utility pallet runtime constant, listed in the chain's constants metadata
as batchedCallsLimit, with the value 10922 and the summary "The limit on the number of batched
calls"
([Subtensor API Constants: batchedCallsLimit](https://docs.learnbittensor.org/subtensor-api/constants#batchedcallslimit-u32)).
It caps how many individual calls a single utility batch extrinsic may carry.

## What It Means

The utility pallet lets an account bundle several calls into one extrinsic so they are submitted
together instead of one at a time. Batched calls limit sets the ceiling on how many calls that
bundle may contain: a batch may carry up to 10922 calls, and a batch that exceeds the limit is not
accepted
([Subtensor API Constants: batchedCallsLimit](https://docs.learnbittensor.org/subtensor-api/constants#batchedcallslimit-u32)).
The cap applies to the count of calls inside one batch, not to how many batches an account may
submit over time.

## What Batching Is For

Batching lets an account group a set of actions into a single submission rather than sending each
one separately. A caller that wants several calls to travel together uses a batch so they are
presented to the chain as one extrinsic. Batched calls limit is the value that fixes how large any
one such bundle may be, so the convenience of grouping calls stays within a defined maximum
([Subtensor API Constants: batchedCallsLimit](https://docs.learnbittensor.org/subtensor-api/constants#batchedcallslimit-u32)).
A caller with more calls than the limit allows must split them across more than one batch rather
than sending them all in a single extrinsic.

## Why the Limit Exists

The limit keeps any single batch within a fixed maximum size, so one submission cannot bundle an
unbounded number of calls. Fixing the ceiling as a constant means the largest possible batch is
known in advance rather than left open
([Subtensor API Constants: batchedCallsLimit](https://docs.learnbittensor.org/subtensor-api/constants#batchedcallslimit-u32)).
The cap on batch size is a separate matter from the outcome of the individual calls, each of which
is still subject to its own ordinary requirements.

## Distinction from Max Scheduled Per Block

Batched calls limit and the scheduler's per-block cap both count calls, but for different
mechanisms. Batched calls limit caps how many calls one batch extrinsic carries when it is submitted
and run together, while max scheduled per block, valued at 50, caps how many scheduled calls the
scheduler runs from its queue in a single block
([Subtensor API Constants: maxScheduledPerBlock](https://docs.learnbittensor.org/subtensor-api/constants#maxscheduledperblock-u32)).
Batching groups calls into one immediate extrinsic; scheduling defers calls to future blocks under a
separate per-block ceiling.

## Reader Boundary

Batched calls limit is a single network-wide constant, not a per-subnet value, and it reflects the
current runtime configuration rather than a fixed protocol rule; the value could change in a future
runtime upgrade. It caps the number of calls in one batch and does not by itself describe the
weight, fees, or success of the individual calls inside the batch
([Subtensor API Constants: batchedCallsLimit](https://docs.learnbittensor.org/subtensor-api/constants#batchedcallslimit-u32)).
