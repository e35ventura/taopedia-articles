## Miner and Validator Roles

The subnet-specific miner and validator roles cannot be described reliably from the registered
identity fields alone. At the Bittensor level, miners compete for incentive and validators submit
weights that feed into [[Yuma Consensus]], but Subnet 117's public identity does not specify the
task that distinguishes this subnet.

## Repository Context

The GitHub repository listed in the on-chain identity is
[helionlink/Chi](https://github.com/helionlink/Chi). Its README describes Chi as a "vibe-codable
Bittensor subnet template" rather than as a production mechanism for a specific subnet market. That
distinction matters because a template repository can explain how someone might build a subnet, but
it does not by itself define what Subnet 117 miners produce or what validators measure.

For readers, the linked repository is therefore evidence about the source attached to the identity,
not evidence of a complete subnet task. It supports saying that the identity points to a template
project. It does not support adding claims about a live scoring model, data source, reward formula,
or validator workflow unless those claims appear in a more specific public source.

This keeps the article's boundary conservative. A subnet can be live on chain even when its public
identity fields do not explain the mechanism. In that situation, Taopedia can report the registered
name, placeholder fields, listed repository, and live TaoStats page, while avoiding unsupported
claims about the market behind the netuid.

The general Bittensor role structure still applies at a high level: miners compete and validators
submit weights for Yuma Consensus. What remains unknown is the subnet-specific task that would make
Subnet 117 distinct from a generic template. The current public sources do not provide enough detail
to identify that task reliably.

That is different from a repository with a README that names a dataset, evaluation loop, or miner
submission format. Chi's public README is intentionally broad: it presents a starting point for
creating a subnet idea. Until a more specific source is registered or published, the safest factual
description is that Subnet 117's identity points to a template repository while its live mechanism
is not publicly documented in the identity fields.
