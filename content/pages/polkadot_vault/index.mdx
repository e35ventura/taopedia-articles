# Polkadot Vault

Polkadot Vault is an offline mobile signing environment that can be used as a hardware-wallet style
custody device for Bittensor coldkeys. The official
[Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)
guide describes Polkadot Vault, formerly Parity Signer, as a way to turn a dedicated offline
smartphone into a cold-signing device.

In Taopedia terms, Polkadot Vault is important because it separates transaction preparation from
private-key custody. An online device can prepare a transaction, while the Vault device remains
offline and signs through a QR-based workflow. That makes it a custody concept rather than a
general-purpose Bittensor wallet application.

## What It Represents

Polkadot Vault uses an air-gapped signing model. The private key is generated on the Vault device,
which is kept in airplane mode, and transactions pass between the online and offline devices through
QR codes without connecting the signer to the network
([Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security),
[Polkadot Vault](https://vault.novasama.io/)).

The online side prepares a payload; the Vault device scans, displays, and signs it; the signed
result returns for broadcast from the connected interface. Signing and broadcasting are separate
steps: the Vault device produces a signature, while the online wallet application submits it to the
chain ([Wallets, Coldkeys and Hotkeys in Bittensor](https://docs.learnbittensor.org/keys/wallets)).

That boundary is online preparation versus offline signing, not merely phone versus laptop. Air gap
reduces private-key exposure, but users still must verify destination, amount, call type, network
context, and proxy relationships before approving a payload. Vault is a signing boundary, not proof
that the surrounding workflow is correct
([Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

The workstation-security guide notes Polkadot Vault can decode and sign any Subtensor extrinsic,
while Ledger wallet apps expose a more limited supported-operation set. Vault therefore fits custody
discussions where a signer may need to approve a wider range of prepared Subtensor calls, not only
the subset exposed by a particular wallet-app screen
([Subtensor Extrinsics](https://docs.learnbittensor.org/subtensor-api/extrinsics)).

Vault is a custody device choice for the primary coldkey, not a validator server, miner server, or
daily hotkey environment. Layered use keeps the coldkey offline, prefers scoped proxies for repeated
operations, and treats each signature as a high-authority act
([Proxies overview](https://docs.learnbittensor.org/keys/proxies)).

## Development Stage Context

The
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction#subnet-development)
describes subnet development as moving from localnet to testnet and then mainnet. Vault signing
examples should be read against that network boundary: localnet and testnet exercises do not carry
the same custody stakes as mainnet, where air-gapped coldkey signing protects live TAO
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from Coldkey

A coldkey is the ownership key that controls TAO balances and hotkeys. Polkadot Vault is an offline
signing environment that can hold coldkey material away from the online device that prepares
transactions ([Glossary: Coldkey](https://docs.learnbittensor.org/resources/glossary#coldkey),
[Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

Key-role vocabulary names custody authority; Vault vocabulary names the air-gapped signing setup.

- **Coldkey** — ownership key that controls TAO balances and hotkeys.
- **Polkadot Vault** — offline signing environment for that custody key.

## Distinction from Private Key

A private key is the protected secret of a wallet's cryptographic key pair that authorizes actions,
while Polkadot Vault is an air-gapped signing environment that holds that key material offline and
signs transactions away from the online device
([Glossary: Private Key](https://docs.learnbittensor.org/resources/glossary#private-key),
[Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

- **Private key** — the protected secret that authorizes wallet actions.
- **Polkadot Vault** — the air-gapped environment that holds and signs with it offline.

## Distinction from Ledger Hardware Wallet

Ledger hardware wallet and Polkadot Vault both keep signing keys off the online machine. Vault uses
an air-gapped mobile signer with QR transaction transfer rather than a USB hardware device
([Using Ledger Hardware Wallet](https://docs.learnbittensor.org/staking-and-delegation/using-ledger-hw-wallet),
[Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

- **Ledger hardware wallet** — USB hardware signer with wallet-app operation limits.
- **Polkadot Vault** — air-gapped mobile signer with broader Subtensor extrinsic coverage.

## Distinction from Proxy Wallets

Proxy wallets grant a separate online account scoped authority to act for a protected coldkey.
Polkadot Vault keeps the coldkey on an offline device and signs approved payloads there
([Proxies overview](https://docs.learnbittensor.org/keys/proxies),
[Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

Vault is useful for high-authority setup moments when a primary coldkey approves initial proxy
relationships from an offline signer, while routine activity can move to scoped proxy keys.

- **Polkadot Vault** — offline custody and signing for the primary coldkey.
- **Proxy wallet** — scoped online delegation with narrower authority.

## Distinction from Wallet Applications

Wallet applications prepare and broadcast transactions on the online side. Polkadot Vault holds the
private key and produces signatures on an offline device
([Wallets, Coldkeys and Hotkeys in Bittensor](https://docs.learnbittensor.org/keys/wallets),
[Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security),
[Polkadot Vault](https://vault.novasama.io/)).

The official wallets guide notes that the Polkadot browser extension can be used with Polkadot
Vault. That pairing keeps interface software on the online side while the Vault device signs
approved payloads.

- **Polkadot Vault** — offline signer that holds the private key.
- **Wallet application** — online interface that prepares and broadcasts transactions.

## Distinction from Hotkeys

Hotkeys are operational keys used for subnet-facing work on connected infrastructure. Polkadot Vault
is a coldkey custody option that keeps signing material off the online machine
([Glossary: Hotkey](https://docs.learnbittensor.org/resources/glossary#hotkey),
[Glossary: Coldkey](https://docs.learnbittensor.org/resources/glossary#coldkey)).

Operational signing and offline custody sit on different tiers of the wallet model.

## Distinction from Mnemonic

A mnemonic is a word sequence used to regenerate and restore Bittensor coldkeys and hotkeys, whereas
Polkadot Vault is the offline device on which a key is generated and used to sign without leaving
that device ([Glossary: Mnemonic](https://docs.learnbittensor.org/resources/glossary#mnemonic)).

- **Polkadot Vault** — keeps a generated key offline and produces signatures on the air-gapped
  device.
- **Mnemonic** — a word-list secret that can recover the same key if the device is lost.

## Distinction from SS58 Encoded Address

SS58 encoding is an SS58-formatted account address derived from a public key and used as the
destination for TAO transfers, while Polkadot Vault is concerned with the private key that
authorizes those transfers while staying offline
([Glossary: SS58 Encoded](https://docs.learnbittensor.org/resources/glossary#ss58-encoded)).

- **Polkadot Vault** — guards the private signing key on an offline device.
- **SS58 encoded address** — the public, shareable account address derived from a public key.

## Distinction from Yuma Consensus

Polkadot Vault is an offline mobile signing environment for air-gapped Bittensor coldkey custody.
Yuma Consensus is the on-chain process that converts submitted validator weights into emission
shares
([Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Polkadot Vault** — offline mobile signer for air-gapped coldkey custody.
- **Yuma Consensus** — on-chain weight aggregation that settles emissions.

## Reader Boundary

Polkadot Vault should not be read as a tutorial, a recommendation to move funds without current
setup documentation, or a replacement for key-management discipline. It is the concept term for an
offline mobile signer that can hold coldkey material away from the online device that prepares
Bittensor transactions.

Compatibility, supported networks, app screens, and transaction flows can change. Before using Vault
with live funds, readers should check the current official Polkadot Vault documentation and the
current Bittensor wallet-security documentation.
