# Subtensor API

The Subtensor API is a developer-facing interface in the Bittensor Python SDK. The official
[Subtensor API](https://docs.learnbittensor.org/sdk/subtensor-api) guide describes it as an optional
modular entry point for reaching Subtensor features through grouped client operations instead of one
flat method list.

For Taopedia readers, the useful distinction is scope. [[subtensor|Subtensor]] is Bittensor's
blockchain layer and system of record. The Subtensor API is a software access surface that helps
applications connect to that layer. It exposes protocol operations without becoming the protocol
rule that validates them.

Sources: [Subtensor API](https://docs.learnbittensor.org/sdk/subtensor-api),
[Bittensor Tools](https://docs.learnbittensor.org/concepts/tools)

## Interface, Not Protocol

The Subtensor API organizes related SDK operations by topic areas such as chain queries, staking,
subnet activity, wallet access, and submitted chain actions. That grouping helps discovery in client
code. It does not create new runtime pallets, consensus rules, subnet mechanisms, or blockchain
services.

The official guide also distinguishes synchronous and asynchronous client modes. That choice affects
how an application reaches the SDK, not how Subtensor validates a submitted action on chain.

Sources: [Subtensor API](https://docs.learnbittensor.org/sdk/subtensor-api),
[Managing Subtensor Connections](https://docs.learnbittensor.org/sdk/managing-subtensor-connections)

## Relationship to Bittensor Tools

The Subtensor API belongs on the developer-library side of [[bittensor_tools|Bittensor Tools]].
Libraries, terminal interfaces, and wallet interfaces all help people and software reach Bittensor
features, but they sit around the protocol rather than replacing it.

For readers, the Subtensor API should be read as one programmatic access surface within that tool
family. It can support applications that query network state, prepare submissions, monitor activity,
or integrate wallet and subnet workflows. Those uses still depend on Subtensor rules, selected
network context, and the surrounding SDK version.

Sources: [Bittensor Tools](https://docs.learnbittensor.org/concepts/tools),
[Subtensor API](https://docs.learnbittensor.org/sdk/subtensor-api)

## Relationship to Subtensor

[[subtensor|Subtensor]] records transactions, rankings, and incentive-related chain activity. The
Subtensor API helps software reach that chain layer through the SDK. A successful client call still
depends on live network state, account permissions, and runtime rules on the connected chain.

This keeps two ideas separate that can otherwise blur together. Subtensor is the blockchain layer
being accessed. The Subtensor API is the client-side interface that helps applications interact with
it. Network reads and submitted actions observed through the SDK still belong to Subtensor's
reference surfaces, not to the SDK interface itself.

References: [Glossary: Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor),
[Subtensor API](https://docs.learnbittensor.org/sdk/subtensor-api)

## Relationship to Extrinsics

[[extrinsics|Extrinsics]] are submitted chain actions that ask the Subtensor runtime to change state
or perform a supported operation. The Subtensor API can expose paths for preparing and submitting
those actions, but an extrinsic remains a runtime request rather than an SDK method.

For readers, the Subtensor API helps software reach extrinsic-related workflows. Whether a
submission succeeds still depends on runtime validation, fees, account state, and the selected
network environment.

References: [Subtensor extrinsics](https://docs.learnbittensor.org/subtensor-api/extrinsics),
[Subtensor API](https://docs.learnbittensor.org/sdk/subtensor-api)

## Naming Note

Official SDK documentation often writes the interface name as SubtensorAPI, while the current Python
implementation exposes SubtensorApi. That difference is naming and packaging context inside the SDK.
It does not identify a separate Bittensor protocol or chain layer.

Applications should treat the official SDK guide and the installed SDK version as the authoritative
names for the interface they are using.

Sources: [Subtensor API](https://docs.learnbittensor.org/sdk/subtensor-api),
[Bittensor SDK v10 Migration Guide](https://docs.learnbittensor.org/sdk/migration-guide)

## Reader Boundary

This article explains the Subtensor API as a Taopedia concept within Bittensor tooling. It is not a
method reference, migration checklist, connection guide, or substitute for the current SDK
documentation.

Exact module groupings, client modes, import paths, and supported operations can change between SDK
releases. Detailed usage belongs in the official Subtensor API guide and related SDK references.

References: [Subtensor API](https://docs.learnbittensor.org/sdk/subtensor-api),
[Managing Subtensor Connections](https://docs.learnbittensor.org/sdk/managing-subtensor-connections),
[Bittensor SDK v10 Migration Guide](https://docs.learnbittensor.org/sdk/migration-guide)
