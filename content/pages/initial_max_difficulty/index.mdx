# Initial Max Difficulty

Initial max difficulty is a subtensorModule runtime constant, listed in the chain's constants
metadata as initialMaxDifficulty, with the value 4611686018427387903 and the summary "Initial Max
Difficulty"
([Subtensor API Constants: initialMaxDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxdifficulty-u64)).
It provides the default value a subnet's MaxDifficulty hyperparameter takes.

## What It Means

MaxDifficulty is per-subnet chain state that caps how hard a subnet's proof-of-work registration
puzzle may become. Initial max difficulty is the default a subnet's MaxDifficulty is set to when the
subnet is created; from there the value is held per subnet and can differ between subnets. For
example, a subnet such as netuid 1 begins with its MaxDifficulty set to this default
([Subtensor API Constants: initialMaxDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxdifficulty-u64)).
The constant is the seed default, not itself the live per-subnet ceiling.

## Distinction from Min Difficulty

Initial max difficulty seeds the per-subnet ceiling, while the initial minimum difficulty constant,
valued at 10000000, seeds the per-subnet floor
([Subtensor API Constants: initialMinDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmindifficulty-u64)).
Together the two defaults establish the range a subnet's registration difficulty may move within
before either bound is changed for that subnet.

## Distinction from Initial Difficulty

Initial difficulty, valued at 10000000, seeds the starting difficulty a subnet registers at, while
initial max difficulty seeds the ceiling that starting value may rise toward
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).
One default is the starting point; the other default is the top of the range the live difficulty
stays under.

## Distinction from Registration Burn

The difficulty ceiling concerns the proof-of-work path to registration, where a caller spends
computation. That is separate from the burn path, where a caller pays a TAO cost whose default
bounds come from the min burn and max burn constants
([Subtensor API Constants: initialMaxBurn](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxburn-u64)).
Initial max difficulty seeds the computational ceiling of registration, not the cost side.

## Why a Default Ceiling Exists

Providing a default ceiling means every new subnet starts with a defined upper bound on registration
difficulty rather than an undefined one. Because the default is fixed as a constant, the value a
subnet's MaxDifficulty begins at is known in advance, even though a subnet may later hold a
different ceiling
([Subtensor API Constants: initialMaxDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxdifficulty-u64)).

## Reader Boundary

Initial max difficulty is the default constant that seeds a subnet's MaxDifficulty; it is not the
live per-subnet ceiling, which can differ once set for a subnet, and it reflects the current runtime
configuration rather than a fixed protocol rule. It does not report the adjusted difficulty in force
on any subnet
([Subtensor API Constants: initialMaxDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxdifficulty-u64)).
