# Initial Max Difficulty

Initial max difficulty is a subtensorModule runtime constant, listed in the chain's constants
metadata as initialMaxDifficulty, with the value 4611686018427387903 and the summary "Initial Max
Difficulty"
([Subtensor API Constants: initialMaxDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxdifficulty-u64)).
It sets the ceiling for the proof-of-work registration difficulty.

## What It Means

Proof-of-work registration requires solving a computational puzzle whose hardness is the difficulty.
That difficulty adjusts over time in response to registration activity, and initial max difficulty
is the highest value it is allowed to reach
([Subtensor API Constants: initialMaxDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxdifficulty-u64)).
The value is a single network-wide bound rather than a per-subnet setting a reader configures
directly.

## Distinction from Min Difficulty

Initial max difficulty is the ceiling, while min difficulty is the floor. The initial minimum
difficulty constant is 10000000, and it bounds how low the difficulty may fall
([Subtensor API Constants: initialMinDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmindifficulty-u64)).
Together the two form the range the adjusting difficulty stays within: no lower than the minimum, no
higher than this maximum.

## Distinction from Initial Difficulty

Initial difficulty is the seed the difficulty starts at, valued at 10000000, while initial max
difficulty is the highest it can climb to from there
([Subtensor API Constants: initialDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialdifficulty-u64)).
One is the starting point; the other is the upper limit on where adjustment can take it.

## Distinction from Registration Burn

The difficulty ceiling governs the proof-of-work path to registration, where a caller spends
computation. That is separate from the burn path, where a caller pays a TAO cost bounded by the min
burn and max burn constants
([Subtensor API Constants: initialMaxBurn](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxburn-u64)).
Initial max difficulty caps the computational side of registration, not the cost side.

## Why a Ceiling Exists

Capping the difficulty means the proof-of-work puzzle cannot become arbitrarily hard no matter how
registration demand pushes the adjusting difficulty upward. With the ceiling fixed as a constant,
the hardest the puzzle can ever be is known in advance
([Subtensor API Constants: initialMaxDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxdifficulty-u64)).
The bound shapes the top of the difficulty range, and is separate from the live value the difficulty
settles at.

## Reader Boundary

Initial max difficulty is a single network-wide constant, not a per-subnet value, and it reflects
the current runtime configuration rather than a fixed protocol rule; the value could change in a
future runtime upgrade. It names the ceiling of the proof-of-work difficulty and does not report the
live, adjusted difficulty in force on any subnet
([Subtensor API Constants: initialMaxDifficulty](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxdifficulty-u64)).
