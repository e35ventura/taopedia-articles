# Validator Trust

Validator trust is a validator-side Yuma Consensus metric. It sums each validator's clipped weight
contributions across miners after consensus filtering
([Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

The term matters because validators can assign different weights to miner work. Consensus clipping
reduces weight values that sit outside the shared benchmark, and validator trust is read after that
filtering step
([Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust)).

## What It Represents

Validator trust sums how much clipped weight a validator contributed across miners after consensus
filtering on a selected subnet. On netuid 1, examples illustrate one subnet's validator-side clipped
influence reading; they should not be read as representing production metrics on another network
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust)).

## Clipping Path Before Validator Trust

Validator trust is read only after Yuma Consensus clips the
[weight matrix](https://docs.learnbittensor.org/resources/glossary#weight-matrix). Each validator
submits a [weight vector](https://docs.learnbittensor.org/resources/glossary#weight-vector); Yuma
compares those values against the per-miner
[consensus score](https://docs.learnbittensor.org/resources/glossary#consensus-score) benchmark and
caps weights that exceed it with `W̄_ij = min(W_ij, W̄_j)`
([Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping),
[Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score)).

Validator trust therefore sums those capped contributions across miners after that benchmark is
applied, not from raw submitted scores alone
([Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust)).

## How Validator Trust Is Summed

For each validator `i`, documentation defines validator trust as the sum of that validator's
consensus-clipped weights across all miners in the subnet: `T_vi = Σ_j W̄_ij`
([Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust)).

Higher totals mean the validator contributed more clipped weight that still counted toward
consensus. Lower totals mean more of that validator's submitted influence was trimmed when weights
were compared with the shared benchmark
([Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

## Miner Trust Versus Validator Trust

[Trust](https://docs.learnbittensor.org/resources/glossary#trust) and validator trust are both read
after clipping in the same Yuma pass but on opposite sides of evaluation. Trust is a per-miner ratio
`T_j = R_j / P_j` showing how much pre-rank support survived filtering. Validator trust sums each
validator's clipped weights across miners
([Glossary: Trust](https://docs.learnbittensor.org/resources/glossary#trust),
[Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust)).

A validator can read high validator trust when its clipped contributions sum large across miners,
while an individual miner can still read low trust if validators disagreed sharply about that
miner's work ([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

## Distinction from Subjective Evaluation

Subjective evaluation is the challenge that subnet work often has no single correct answer, so
validators may score the same submission differently. Validator trust sums clipped weight
contributions across miners after Yuma resolves those differing judgments into one settlement
pass—not how closely one validator's opinions matched a separate alignment score
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism),
[Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

- **Subjective evaluation** — no single answer key; validators may disagree on scores.
- **Validator trust** — validator-side clipped influence summed across miners.

## Distinction from Weight Copying

Weight copying is when a validator reuses visible weight signals instead of independently evaluating
miners. Validator trust sums clipped contributions across miners—a copier that mirrors visible
consensus can still read high clipped totals even when the submission was not independently formed
([Weight Copying Problem](https://docs.learnbittensor.org/concepts/weight-copying-in-bittensor),
[Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

- **Weight copying** — dependence on another validator's published scores.
- **Validator trust** — validator-side clipped influence summed across miners.

## Distinction from Consensus Score

Consensus score is the per-miner clipping benchmark used to cap outlier validator weights. Validator
trust sums one validator's clipped contributions across miners after that benchmark is applied
([Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust),
[Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

- **Consensus score** — per-miner agreement benchmark used for clipping.
- **Validator trust** — validator-side clipped influence summed across miners.

## Distinction from Rank

Rank is the miner-side result after validator weights are filtered and aggregated. Validator trust
stays on the validator side of that same Yuma pass
([Glossary: Rank](https://docs.learnbittensor.org/resources/glossary#rank),
[Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust)).

- **Rank** — miner-side standing after aggregation.
- **Validator trust** — validator-side clipped influence summed across miners for one pass.

## Distinction from Dividends

Dividends are validator-side emission shares credited from smoothed bonds multiplied by miner
incentives. Validator trust sums clipped weight contributions across miners in the same pass—not the
bond-based payout share itself
([Yuma Consensus: Validator emissions](https://docs.learnbittensor.org/learn/yuma-consensus#validator-emissions),
[Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust),
[Glossary: Dividends](https://docs.learnbittensor.org/resources/glossary#emission)).

- **Dividends** — validator-side payout results from bonds and miner incentives.
- **Validator trust** — validator-side clipped influence summed across miners.

## Distinction from Weight Vector

A weight vector is one validator's submitted evaluation signals. Validator trust summarizes that
validator's clipped influence after the full weight matrix is filtered
([Glossary: Weight Vector](https://docs.learnbittensor.org/resources/glossary#weight-vector),
[Glossary: Weight Matrix](https://docs.learnbittensor.org/resources/glossary#weight-matrix),
[Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust)).

- **Weight vector** — one validator's input signal before aggregation.
- **Validator trust** — summed clipped influence from that validator's row after filtering.

## Distinction from Weight Matrix

A weight matrix stacks validator weight vectors into the grouped input Yuma Consensus processes.
Validator trust summarizes each validator's clipped influence after that grouped input is filtered
on the selected subnet
([Glossary: Weight Matrix](https://docs.learnbittensor.org/resources/glossary#weight-matrix),
[Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Weight matrix** — assembled validator input entering consensus.
- **Validator trust** — validator-side influence after that input is processed.

## Distinction from Validator Permit

- **Validator permit** — per-subnet flag gating whether a UID's weights enter aggregation.
- **Validator trust** — validator-side clipped influence summed after the settlement pass.

Holding a permit does not imply high validator trust; the permit gates the next submission while
validator trust reports clipped influence from the settlement pass that has already run
([Glossary: Validator Permit](https://docs.learnbittensor.org/resources/glossary#validator-permit),
[Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph)).

## Distinction from Yuma Consensus

- **Validator trust** — validator-side clipped influence summed after filtering.
- **Yuma Consensus** — tempo pass that turns submitted weights into emission shares.

## Reader Boundary

Validator trust is a validator-side Yuma Consensus metric read after clipping, not a standalone
reputation label, miner-side trust score, or dividend forecast
([Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).
