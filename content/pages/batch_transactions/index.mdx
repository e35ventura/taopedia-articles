# Batch Transactions

Batch transactions let Bittensor submit multiple chain calls together as one on-chain transaction.
The official [Batch Transactions](https://docs.learnbittensor.org/learn/batch-transactions)
documentation describes three utility-pallet variants: batch, batch all, and force batch. At the
Taopedia level, the important idea is that batching changes how calls are submitted together, not
what each inner call means.

## Why Batches Exist

Batching is useful when several related chain calls should be sent as one grouped transaction. That
can reduce repeated round trips to the chain and can let a user choose a failure-handling model that
fits the group. The official Bittensor batch-transaction page frames batching as a way to submit
multiple calls in one on-chain transaction.

## Batch Variants

Bittensor documentation distinguishes the batch variants by how the group handles failures. A normal
batch can process calls in order and stop when a call fails. A batch-all style transaction is used
when the group should behave as an all-or-nothing unit. A force-batch style transaction is used when
the group should continue processing later calls even if an earlier call fails.

Those differences matter because a grouped transaction is not automatically safer or simpler than
the calls inside it. The selected variant determines how much the group depends on every inner call
succeeding.

## Fees

Batching does not erase the cost of the inner work. The official
[Transaction Fees in Bittensor](https://docs.learnbittensor.org/learn/fees) documentation explains
that batch transaction fees aggregate the fees of the inner calls, with additional overhead for the
batch wrapper. A batch should therefore be read as grouped execution, not as a fee waiver.

## Careful Interpretation

A batch transaction is a submission pattern, not a new kind of subnet logic. Claims about a batch
should say which calls are grouped, which failure model is used, and which source supports the
claim. Without that context, "batched" only means that multiple calls were submitted together. Exact
behavior, fees, and failure outcomes still depend on the selected batch variant and the individual
calls inside the group.
