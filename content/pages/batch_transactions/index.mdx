# Batch Transactions

Batch transactions let a Bittensor user submit several operations together as a single on-chain
transaction. The official
[Batch Transactions](https://docs.learnbittensor.org/learn/batch-transactions) documentation
describes this capability as a way to send multiple calls at once, useful for tasks like staking to
several hotkeys, performing operations together, or reducing the number of round-trips to the chain.

## Why Batching Helps

Sending operations one at a time means repeated submissions and repeated waiting. The batch
documentation frames batching as a way to group related actions so they travel to the chain
together, which is convenient when several operations naturally belong to the same intent.

For readers, a batch is a container for calls rather than a new kind of operation. The individual
actions inside are the same ones a user could send separately; batching only changes how they are
submitted.

References: [Batch Transactions](https://docs.learnbittensor.org/learn/batch-transactions),
[Glossary: Extrinsics](https://docs.learnbittensor.org/resources/glossary#extrinsics)

## Variants by Error Handling

The batch documentation explains that the variants differ only in how they treat a failure partway
through. One variant stops at the first failing call while letting earlier calls stand. Another is
all-or-nothing, reverting every call if any one fails. A third continues past failures, skipping the
calls that do not succeed.

For readers, the choice is about whether partial success is acceptable. Use the all-or-nothing form
when every inner call must succeed together, the stop-at-first form when earlier results may remain,
and the continue-past form when failures should simply be skipped.

References: [Batch Transactions](https://docs.learnbittensor.org/learn/batch-transactions),
[Understand Bittensor](https://docs.learnbittensor.org/learn/introduction)

## Fees Across a Batch

Batching changes submission, not the underlying cost model. The
[Transaction Fees in Bittensor](https://docs.learnbittensor.org/learn/fees) documentation describes
how fees are charged on state-changing operations and notes that batch transactions have their own
fee treatment across the grouped calls.

For readers, a batch does not make its inner operations free. The fee picture still follows the
calls inside the batch rather than the act of batching itself.

References: [Transaction Fees in Bittensor](https://docs.learnbittensor.org/learn/fees),
[Batch Transactions](https://docs.learnbittensor.org/learn/batch-transactions)

## Reader Boundary

Batch transactions should not be read as a command tutorial, a fee quote, or a guarantee that
grouped calls always succeed. Whether to batch and which variant to use depend on the task, and
current behavior belongs in official references and live chain state. This article describes the
concept of bundling multiple operations into one submission.
