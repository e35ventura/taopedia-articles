# Staking Precompile

The Staking Precompile is the Bittensor EVM interface that exposes staking operations to smart
contracts running inside the Bittensor EVM layer. The official
[Bittensor EVM: Examples and Precompiles](https://docs.learnbittensor.org/evm-tutorials/examples)
documentation lists it among the Bittensor-specific precompiled contracts available on the EVM, and
the
[Staking and delegation overview](https://docs.learnbittensor.org/staking-and-delegation/delegation)
describes the underlying staking system those operations connect to.

In Taopedia terms, the Staking Precompile names an EVM-side interface, not a staking strategy or a
subnet role. It belongs alongside the H160 address and token bridging concepts because it is part of
how the EVM layer reaches into Bittensor's native staking system.

## Why the Staking Precompile Exists

Bittensor's native staking system runs on the Substrate side of the chain, where stake is normally
managed through Substrate-style SS58 wallets. The
[Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials) documentation
describes a separate EVM execution environment on the same Bittensor blockchain, and smart contracts
in that environment need a way to interact with staking without leaving the EVM context.

For readers, the Staking Precompile exists to bridge that gap. It lets an EVM smart contract perform
staking operations that would otherwise require crossing back into the Substrate side of the chain.
Without it, EVM contracts would be isolated from the staking system that drives Bittensor's
incentive structure.

References:
[Bittensor EVM: Examples and Precompiles](https://docs.learnbittensor.org/evm-tutorials/examples),
[Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials)

## What the Staking Precompile Does

The Staking Precompile exposes staking operations to EVM smart contracts. The
[Bittensor EVM: Examples and Precompiles](https://docs.learnbittensor.org/evm-tutorials/examples)
documentation describes the available operations, which include adding stake to a hotkey, removing
stake from a hotkey, moving stake between hotkeys, and transferring stake between coldkeys. The same
interface also exposes stake-amount queries and proxy-management operations.

For readers, the key behavior is that these are the same staking operations available on the
Substrate side, made accessible from inside the EVM layer. The precompile does not introduce a new
staking system; it connects the existing one to EVM smart contracts.

References:
[Bittensor EVM: Examples and Precompiles](https://docs.learnbittensor.org/evm-tutorials/examples),
[Staking and delegation overview](https://docs.learnbittensor.org/staking-and-delegation/delegation)

## Relationship to Staking

The Staking Precompile and staking are related but different parts of Bittensor reward handling. The
[Glossary: Staking](https://docs.learnbittensor.org/resources/glossary#staking) describes staking as
attaching TAO to a validator hotkey to increase stake and consensus power, while the Staking
Precompile names the EVM interface that lets smart contracts perform that attachment.

For readers, staking names the act of committing TAO to a validator, while the Staking Precompile
names the EVM-side gateway to that act. One is a reward-system operation; the other is an interface
layer. The precompile depends on staking existing, but it is not staking itself.

References: [Glossary: Staking](https://docs.learnbittensor.org/resources/glossary#staking),
[Staking and delegation overview](https://docs.learnbittensor.org/staking-and-delegation/delegation)

## Relationship to Bittensor EVM Smart Contracts

The Staking Precompile and Bittensor EVM smart contracts are related because the precompile is one
of the interfaces an EVM smart contract can use. The
[Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials) documentation notes
that EVM smart contracts execute solely on the Bittensor blockchain, and the
[precompile list](https://docs.learnbittensor.org/evm-tutorials/examples) shows the Staking
Precompile alongside other Bittensor-specific precompiles available to those contracts.

For readers, Bittensor EVM smart contracts name the execution environment, while the Staking
Precompile names one specific interface inside it. A smart contract can call the precompile to
stake, but the precompile is not the contract itself — it is the gateway the contract reaches
through.

References: [Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials),
[Bittensor EVM: Examples and Precompiles](https://docs.learnbittensor.org/evm-tutorials/examples)

## Relationship to H160 Address

The Staking Precompile and the H160 address are related because H160 is the account format the EVM
layer uses, and the precompile operates inside that layer. The
[H160 Address](https://docs.learnbittensor.org/evm-tutorials/convert-h160-to-ss58) documentation
describes the Ethereum-style account format used in the EVM, and staking operations exposed by the
precompile are performed from H160-account contexts.

For readers, the H160 address names the EVM-side account format, while the Staking Precompile names
the interface that performs staking from inside that format. The address identifies who is staking;
the precompile is how they stake from the EVM side.

References: [H160 Address](https://docs.learnbittensor.org/evm-tutorials/convert-h160-to-ss58),
[Bittensor EVM: Examples and Precompiles](https://docs.learnbittensor.org/evm-tutorials/examples)

## Relationship to Token Bridging

The Staking Precompile and token bridging are related because both connect the EVM layer to
Bittensor's native systems. The
[Token Bridging](https://docs.learnbittensor.org/evm-tutorials/bridge-vtao) documentation describes
moving TAO between Substrate and EVM account contexts, and the Staking Precompile is one of the
interfaces an EVM-smart-contract user can reach after bridging TAO into the EVM layer.

For readers, token bridging names the capability of moving TAO into the EVM context, while the
Staking Precompile names one thing that TAO can then do inside that context. The bridge brings the
asset in; the precompile lets it participate in staking.

References: [Token Bridging](https://docs.learnbittensor.org/evm-tutorials/bridge-vtao),
[Bittensor EVM: Examples and Precompiles](https://docs.learnbittensor.org/evm-tutorials/examples)

## Reader Boundary

This article defines the Staking Precompile as a concept. It does not describe contract addresses,
function signatures, code examples, or step-by-step integration. Readers should use the official
Bittensor EVM documentation for implementation detail and current interface parameters.
