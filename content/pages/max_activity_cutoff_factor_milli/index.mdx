# Max Activity Cutoff Factor Milli

Max activity cutoff factor milli is a subtensorModule runtime constant, listed in the chain's
constants metadata as maxActivityCutoffFactorMilli, with the value 50000 and the summary "Upper
bound for the activity-cutoff factor (per-mille)"
([Subtensor API Constants: maxActivityCutoffFactorMilli](https://docs.learnbittensor.org/subtensor-api/constants#maxactivitycutofffactormilli-u32)).
It defines the largest activity cutoff factor a subnet owner is allowed to configure.

## What It Means

The activity cutoff factor is a per-subnet hyperparameter expressed in per-mille epochs, meaning
thousandths of an epoch, that sets how much validator inactivity a subnet tolerates before a
validator stops counting for epoch participation
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)). Max
activity cutoff factor milli does not set that value; it caps how large an owner may set it. The
constant works together with minActivityCutoffFactorMilli, whose value is 1000 and whose summary is
"Lower bound for the activity-cutoff factor (per-mille)"
([Subtensor API Constants: minActivityCutoffFactorMilli](https://docs.learnbittensor.org/subtensor-api/constants#minactivitycutofffactormilli-u32)).
Together the two constants bound the owner-settable factor to the range 1000 through 50000
per-mille.

## Owner Setting and the Bounds Error

The bound applies to the owner path. When a subnet owner sets the activity cutoff factor, the value
must fall within the minActivityCutoffFactorMilli–maxActivityCutoffFactorMilli range. A value
outside that range is rejected with the `ActivityCutoffFactorMilliOutOfBounds` error
([Subtensor API Errors: ActivityCutoffFactorMilliOutOfBounds](https://docs.learnbittensor.org/subtensor-api/errors#activitycutofffactormillioutofbounds)).
For example, an owner configuring the factor on a subnet such as netuid 1 cannot choose a value
above 50000 per-mille.

## Per-Mille Meaning

Per-mille means thousandths of an epoch, so 1000 per-mille corresponds to one epoch and 50000
per-mille corresponds to fifty epochs. The maximum of 50000 therefore lets an owner tolerate up to
about fifty epochs of validator silence, while the default activity cutoff factor of 13889 sits at
roughly fourteen epochs
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)). Because
the window is expressed relative to the epoch, its block length scales with the subnet's tempo
rather than being a fixed block count.

## Distinction from Activity Cutoff Factor

Max activity cutoff factor milli and the activity cutoff factor are different kinds of value. The
activity cutoff factor is the per-subnet hyperparameter a subnet carries and applies during epoch
processing, while max activity cutoff factor milli is a fixed network-wide runtime constant that
only bounds the largest value an owner may set that hyperparameter to
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Subtensor API Constants: maxActivityCutoffFactorMilli](https://docs.learnbittensor.org/subtensor-api/constants#maxactivitycutofffactormilli-u32)).
One is the ceiling; the other is the chosen value that must sit under it on the owner path.

## Reader Boundary

Max activity cutoff factor milli is a single network-wide constant, not a per-subnet value, and it
reflects the current runtime configuration rather than a fixed protocol rule; the bound could change
in a future runtime upgrade. It is not the live activity cutoff factor of any subnet, and it does
not by itself determine whether a particular validator is counted as active
([Subtensor API Constants: maxActivityCutoffFactorMilli](https://docs.learnbittensor.org/subtensor-api/constants#maxactivitycutofffactormilli-u32)).
