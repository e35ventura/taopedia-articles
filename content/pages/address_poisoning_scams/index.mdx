# Address Poisoning Scams

Address poisoning is a wallet scam that uses lookalike destination addresses to mislead users during
routine wallet activity. In Bittensor, the address-poisoning guide frames the risk around checking
destination addresses before signing value-bearing actions
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

The concept is a prevention topic. It explains how a valid-looking address can still be the wrong
destination, especially when interfaces abbreviate long addresses.

## Lookalike Address Risk

The scam works by making an unintended destination look familiar enough to trust. Long wallet
addresses are often shortened in interfaces, and a malicious address can resemble a legitimate one
at the visible edges
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

That makes address display part of the risk. The visible prefix or suffix may look familiar while
the full address points somewhere else.

## Recent-History Trap

Address poisoning often abuses convenience. A lookalike address may appear near legitimate wallet
activity, so selecting from recent history can feel safer than it is
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

The trap is contextual familiarity. A user may recognize the apparent shape of an address without
confirming that the complete destination matches the intended recipient.

## Destination Verification

The core safety boundary is destination verification before signing. The relevant question is not
only whether an address is syntactically valid; it is whether that address is the intended
destination
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

This distinction keeps prevention focused on the final destination. Visual familiarity, recent
history, and address validity do not replace full-destination confirmation.

## Valid-Address Boundary

Address poisoning depends on a subtle distinction: the scam address can be a real wallet address and
still be the wrong recipient. The wallet-address glossary describes addresses as public-key-derived
identifiers, while the address-poisoning guide focuses on checking the intended destination before
signing a value-bearing action
([Glossary: Wallet Address](https://docs.learnbittensor.org/resources/glossary#wallet-address),
[Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

For readers, validity and intent should stay separate. A valid-looking address may pass format
checks, but it still needs to match the recipient the user actually meant to pay.

## Address Terms

Address poisoning targets wallet-address interpretation. A wallet address is a public-key-derived
identifier used for sending and receiving TAO, while a public key is shareable key material used for
account reference
([Glossary: Wallet Address](https://docs.learnbittensor.org/resources/glossary#wallet-address),
[Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key)).

The scam exploits confusion between valid identifiers. It does not require the intended address to
become invalid; it only needs the wrong address to be selected.

## Recovery Boundary

Wrong-destination actions are prevention-first risks. The address-poisoning guide warns that outside
organizations may not be able to recover tokens lost through theft, scams, or accidental key loss
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

That makes the topic different from a recovery workflow. The safety value comes from confirming the
destination before the action is signed.

## Development Stage Context

The
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction#subnet-development)
describes subnet development as moving from localnet to testnet and then mainnet. Bittensor
documentation also separates mainnet, testnet, and localnet environments
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

Address poisoning is still a wallet-safety concept across environments because the risky step is
choosing a destination address. The consequence, however, depends on the environment and action. A
mainnet loss, a testnet example, and a local demonstration do not carry the same value exposure.

## Distinction from Coldkey

Address poisoning scams trick users into sending funds to look-alike addresses in transaction
history. A coldkey is the primary custody key that holds balances and authorizes wallet actions
([Glossary: Coldkey](https://docs.learnbittensor.org/resources/glossary#coldkey),
[Security Best Practices](https://docs.learnbittensor.org/getting-started/best-practices-wallet-security)).

- **Address poisoning scams** — deceptive look-alike addresses in visible history.
- **Coldkey** — primary custody key for balances and authority.

Scam vocabulary warns about misleading copies; coldkey vocabulary names the custody key being
targeted ([Wallets, Coldkeys and Hotkeys](https://docs.learnbittensor.org/keys/wallets)).

## Distinction from Transfer

Address poisoning scams exploit visible transaction history to misdirect the next transfer. A
transfer is the on-chain action that moves TAO between accounts
([Glossary: Transfer](https://docs.learnbittensor.org/resources/glossary#transfer),
[Security Best Practices](https://docs.learnbittensor.org/getting-started/best-practices-wallet-security)).

- **Address poisoning scams** — social trick using look-alike destination addresses.
- **Transfer** — on-chain movement of TAO between accounts.

Scam vocabulary names the deception; transfer vocabulary names the action being misdirected
([Subtensor extrinsics](https://docs.learnbittensor.org/subtensor-api/extrinsics)).

## Distinction from Phishing

Phishing and address poisoning are both wallet-safety scams, but they exploit different steps.
Phishing is social deception that tries to get a user to reveal a secret such as the seed phrase,
while address poisoning plants a lookalike destination address so a value-bearing action is sent to
the wrong recipient
([Phishing and seed-phrase guidance](https://docs.learnbittensor.org/keys/handle-seed-phrase),
[Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

Phishing targets secret disclosure so the attacker can rebuild the wallet, while address poisoning
targets destination selection so a correctly signed action reaches the attacker's address. Defending
against one does not by itself defend against the other.

## Distinction from Hotkey

Address poisoning and the hotkey name a deception and a signing key. Address poisoning is a
destination-selection scam that plants a lookalike wallet address for a value-bearing action, while
a hotkey is the component of a Bittensor wallet responsible for less secure operations such as
signing messages into the network
([Glossary: Hotkey](https://docs.learnbittensor.org/resources/glossary#hotkey)). A correctly
functioning hotkey can still sign an action that reaches the wrong recipient when the destination
was poisoned.

- **Address poisoning** — corrupts which destination an action is sent to, independent of how it is
  signed.
- **Hotkey** — the key that signs network operations, which can faithfully sign an action aimed at a
  poisoned destination.

## Distinction from Mnemonic

Address poisoning and the mnemonic name a prevention concern and a recovery mechanism. Address
poisoning is a destination-selection deception that sends a value-bearing action to a lookalike
address, while a mnemonic is a sequence of words used to regenerate keys, in case of loss, and
restore coldkeys and hotkeys in the Bittensor wallet
([Glossary: Mnemonic](https://docs.learnbittensor.org/resources/glossary#mnemonic)). A mnemonic
restores key access after loss, but it does not reverse a value-bearing action already directed to a
poisoned destination.

- **Address poisoning** — a prevention-first risk where safety comes from confirming the destination
  before signing.
- **Mnemonic** — a key-restoration tool, which does not undo a send to the wrong recipient.

## Distinction from Wallet

Bittensor wallets are used for actions involving TAO and subnet participation. Wallet documentation
places wallets around signing, access, and stake management, while the address-poisoning guide
focuses on the destination chosen for a value-bearing action
([Wallets](https://docs.learnbittensor.org/keys/wallets),
[Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

This makes destination review a wallet-safety concern, not a cosmetic interface detail. The wallet
may be functioning normally even when the chosen destination is wrong.

## Distinction from Yuma Consensus

Address poisoning scams name destination-verification risk when copying wallet addresses. Yuma
Consensus is the on-chain mechanism that converts validator weight submissions into emission shares
each tempo and does not involve address-book deception
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Emission](https://docs.learnbittensor.org/learn/emissions)).

Poisoning vocabulary belongs to wallet safety and transfer destination review. Yuma Consensus
vocabulary belongs to validator weight settlement on a subnet.

- **Address poisoning scam** — tricking a user into sending funds to a look-alike address.
- **Yuma Consensus** — on-chain mechanism that turns validator weights into emission shares.

## Reader Boundary

Address poisoning scams should be read as destination-verification risk. The term is not a wallet
bug, a public-key failure, or a recovery guarantee
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams),
[Wallets](https://docs.learnbittensor.org/keys/wallets)).

The stable reference point is that a familiar-looking address can be valid and still be the wrong
destination.
