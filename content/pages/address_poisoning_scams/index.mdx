# Address Poisoning Scams

Address poisoning is a wallet scam that uses lookalike destination addresses to mislead users during
routine wallet activity. In Bittensor, the address-poisoning guide frames the risk around checking
destination addresses before signing value-bearing actions
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

## What It Represents

The scam makes an unintended destination look familiar enough to trust. Long wallet addresses are
often shortened in interfaces, so a malicious address can resemble a legitimate one at the visible
edges while the full address points somewhere else
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

Readers should separate two ideas that are easy to merge:

- **Valid address** — a real, syntactically correct
  [wallet address](https://docs.learnbittensor.org/resources/glossary#wallet-address).
- **Intended destination** — the recipient the user actually meant to pay.

A poisoned address can be valid and still be the wrong recipient. Format checks, visual familiarity,
and recent-history convenience do not replace full-destination confirmation before signing
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

A lookalike may also appear near legitimate activity in recent history, so selecting from history
can feel safer than it is. The trap is contextual familiarity: recognizing the apparent shape of an
address without confirming the complete destination
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

Address poisoning targets which destination is chosen, not whether the signing key is compromised.
An uncompromised [coldkey](https://docs.learnbittensor.org/resources/glossary#coldkey) can still
authorize a correctly signed transfer to the wrong recipient when the destination was poisoned
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

Wrong-destination losses are prevention-first risks. The guide warns that outside organizations may
not recover tokens lost through theft, scams, or accidental sends, so the safety value comes from
confirming the destination before the action is signed
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

## Vanity Generation Matches Edge Characters

The [Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams) guide
explains that attackers do not need to compromise an existing wallet to produce a dangerous
lookalike. They use vanity address generation: searching through many newly generated key pairs
until one yields a
[wallet address](https://docs.learnbittensor.org/resources/glossary#wallet-address) whose visible
beginning and ending characters match a target they want to impersonate.

Official documentation describes that search as computationally expensive but still profitable when
a user later sends value to the wrong destination. A regular user cannot pick a personal address
directly, but an attacker can keep generating pairs until the visible edges line up with someone
they observed on-chain or in a shared payment request.

That mechanism sits upstream of interface abbreviations. The scam address is a real, independently
generated destination whose similarity is manufactured at the character edges rather than through
any defect in the victim's coldkey or wallet software
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

## Dust Transfers Seed Wallet History

Address poisoning often begins with a tiny inbound transfer. The official guide warns that
unexpected transfers for very small amounts are likely attempts to seed a wallet's transaction
history with a lookalike address
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

Those dust movements are not meant to steal funds through the micro-payment itself. They are setup
steps that place a confusing destination near legitimate activity so a hurried copy from recent
history feels plausible later. The trap depends on that seeded entry being treated as familiar
context rather than on breaking address validity rules.

Recognizing dust as a probable poisoning signal therefore belongs to attack recognition, not only to
the final send step. A surprise small credit can be the moment the trap address enters the wallet
surface a user later trusts when moving
[TAO](https://docs.learnbittensor.org/resources/glossary#tao-tau)
([Glossary: Transfer](https://docs.learnbittensor.org/resources/glossary#transfer)).

## Wallet Tools Can Flag Suspicious Addresses

Official guidance notes that some wallet applications and blockchain scanners now flag suspicious
addresses or hide poisoning attempts, and it recommends keeping wallet software updated
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)). The same
page states that the TAO.app UI includes a warning for addresses flagged as suspicious.

Those warnings sit alongside user-side destination verification rather than replacing it. A flagged
lookalike may be blocked or highlighted before a value-bearing action is signed, but the underlying
risk still begins with selecting the wrong
[wallet address](https://docs.learnbittensor.org/resources/glossary#wallet-address).

Tooling updates therefore change how early the trap surfaces, not whether a manufactured lookalike
can exist on-chain. Updated wallet surfaces can shrink the window where a seeded address looks
normal in history alone ([Wallets](https://docs.learnbittensor.org/keys/wallets)).

## Development Stage Context

Address poisoning is a wallet-safety concept across environments because the risky step is choosing
a destination address. The consequence depends on the environment: a mainnet loss, a testnet
example, and a local demonstration do not carry the same value exposure
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from Coldkey

Address poisoning names destination-selection deception. A coldkey names the key that owns a wallet
and authorizes its funds
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams),
[Glossary: Coldkey](https://docs.learnbittensor.org/resources/glossary#coldkey)).

- **Address poisoning** — corrupts which destination a signed action reaches.
- **Coldkey** — custody authority that approves the action itself.

An address-poisoning loss is not evidence that the coldkey was breached.

## Distinction from Transfer

Address poisoning corrupts which address a transfer targets. A transfer is the wallet action that
moves TAO to a chosen destination
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams),
[Glossary: Transfer](https://docs.learnbittensor.org/resources/glossary#transfer)).

- **Address poisoning** — deception that sends a correctly signed transfer to the wrong recipient.
- **Transfer** — the legitimate action of moving TAO to an intended address.

## Distinction from Phishing

Phishing tries to obtain a secret such as a seed phrase. Address poisoning plants a lookalike
destination so a value-bearing action reaches the wrong recipient
([Phishing and seed-phrase guidance](https://docs.learnbittensor.org/keys/handle-seed-phrase),
[Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

- **Phishing** — secret disclosure so an attacker can rebuild the wallet.
- **Address poisoning** — destination selection so a signed action reaches the attacker's address.

Defending against one does not by itself defend against the other.

## Distinction from Hotkey

A hotkey signs network operations. Address poisoning corrupts the destination those operations
target ([Glossary: Hotkey](https://docs.learnbittensor.org/resources/glossary#hotkey)).

- **Address poisoning** — corrupts which destination an action is sent to.
- **Hotkey** — operational key that can faithfully sign an action aimed at a poisoned destination.

## Distinction from Mnemonic

A mnemonic restores key access after loss. It does not reverse a value-bearing action already
directed to a poisoned destination
([Glossary: Mnemonic](https://docs.learnbittensor.org/resources/glossary#mnemonic)).

- **Address poisoning** — prevention-first risk; safety comes from confirming the destination before
  signing.
- **Mnemonic** — key-restoration tool, not an undo for a send to the wrong recipient.

## Distinction from Yuma Consensus

Address poisoning names destination-verification risk during transfers. Yuma Consensus converts
validator weights into emission shares on a subnet
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Address poisoning scam** — tricking a user into sending funds to a look-alike address.
- **Yuma Consensus** — on-chain mechanism that turns validator weights into emission shares.

## Reader Boundary

Address poisoning scams should be read as destination-verification risk. The term is not a wallet
bug, a public-key failure, or a recovery guarantee
([Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams),
[Wallets](https://docs.learnbittensor.org/keys/wallets)).
