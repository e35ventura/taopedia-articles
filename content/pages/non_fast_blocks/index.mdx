# Non-fast Blocks

Non-fast blocks name ordinary block timing in contrast with fast blocks. Official Bittensor
documentation presents the term alongside fast blocks in local-development context.

References:
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks),
[Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks)

## Local Context

The term helps readers distinguish two local timing concepts. Fast blocks refer to accelerated local
block production. Non-fast blocks refer to the non-accelerated side of that same local distinction.

References:
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks),
[Glossary: Local Blockchain](https://docs.learnbittensor.org/resources/glossary#local-blockchain)

## Twelve-Second Interval Context

The [Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)
describes non-fast blocks as a development-only configuration that adheres to Subtensor's default
12-second block interval, simulating production timing for features like delayed subnet activation.
Readers should treat this as a local timing setting rather than a live mainnet behavior label.

References:
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks),
[Run a Local Bittensor Blockchain Instance](https://docs.learnbittensor.org/local-build/deploy)

## Relationship to Localnet

Non-fast blocks and localnet are related but name different parts of local development context. The
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks) reference includes
localnet as a user-controlled development environment, while the
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)
describes ordinary local block timing inside that setting.

For readers, localnet is the environment label, while non-fast blocks are a timing configuration
used when simulating production-like block intervals during local development.

References: [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)

## Relationship to Local Blockchain

Non-fast blocks and local blockchain are related but name different parts of local development
context. The
[Glossary: Local Blockchain](https://docs.learnbittensor.org/resources/glossary#local-blockchain)
describes a private chain used for development and testing, while the
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)
describes ordinary local block timing that follows Subtensor's default 12-second interval.

For readers, local blockchain is the isolated development chain, while non-fast blocks are a timing
setting used within that local environment. Neither term describes live mainnet block behavior on
its own.

References:
[Glossary: Local Blockchain](https://docs.learnbittensor.org/resources/glossary#local-blockchain),
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)

## Relationship to Fast Blocks

Non-fast blocks and fast blocks name opposite sides of the same local timing distinction. The
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)
describes ordinary local block timing with Subtensor's default 12-second interval, while the
[Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks) describes
accelerated local production.

For readers, non-fast blocks help simulate production timing in development, while fast blocks trade
that simulation for speed. Neither term describes live mainnet or testnet block behavior.

References:
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks),
[Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks)

## Relationship to Bittensor Networks

Non-fast blocks and Bittensor Networks name related but different parts of local development
context. The [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)
reference groups mainnet, testnet, and localnet, while the
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)
describes ordinary local block timing inside that localnet setting.

For readers, Bittensor Networks is the environment label, while non-fast blocks are a timing
configuration used within localnet to simulate production-like intervals. Non-fast blocks do not
describe live mainnet or testnet behavior.

References: [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)

## Reader Boundary

This page defines the term. It does not describe live public network behavior or a subnet reward
mechanism.

## Relationship to Subtensor

Non-fast blocks and Subtensor are related but different parts of Bittensor chain vocabulary.
Subtensor names Bittensor's layer 1 blockchain and system of record, while non-fast blocks name a
development-only local configuration that follows Subtensor's default 12-second block interval on a
private chain instance. The
[Glossary: Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor) describes the
blockchain layer, and the
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)
describes ordinary local block timing in development.

For readers, Subtensor names the chain layer, while non-fast blocks name a local timing setting that
simulates production-like intervals on that layer during development.

References: [Glossary: Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor),
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)

## Relationship to Block

Non-fast blocks and a block are related but different parts of Bittensor chain timing vocabulary. A
[block](https://docs.learnbittensor.org/resources/glossary#block) names one unit of chain
progression on Subtensor, while non-fast blocks name a local configuration that keeps that
progression at Subtensor's default 12-second interval during development testing. The
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)
describes that development-only timing setting rather than live mainnet or testnet behavior.

For readers, a block is the chain progression unit, while non-fast blocks name the local interval
used when simulating production-like block timing.

References: [Glossary: Block](https://docs.learnbittensor.org/resources/glossary#block),
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)

## Relationship to Extrinsics

Non-fast blocks and extrinsics are related but different parts of Bittensor local development
vocabulary. Extrinsics name signed transactions and calls submitted to Subtensor, while non-fast
blocks set the local block interval at which those submissions can be included during development
testing. The [Glossary: Extrinsics](https://docs.learnbittensor.org/resources/glossary#extrinsics)
describes signed transactions submitted to the chain, and the
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)
describes ordinary local block timing.

For readers, extrinsics name the submitted chain actions under test, while non-fast blocks name the
local inclusion cadence used when simulating production-like timing.

References: [Glossary: Extrinsics](https://docs.learnbittensor.org/resources/glossary#extrinsics),
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)

## Relationship to Tempo

Non-fast blocks and tempo are related but different timing concepts in Bittensor vocabulary.
[Tempo](https://docs.learnbittensor.org/resources/glossary#tempo) names the number of blocks between
subnet reward calculation cycles, while non-fast blocks name local block timing that follows
Subtensor's default 12-second interval during development testing. The
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)
describes that local timing setting rather than live mainnet or testnet cadence.

For readers, tempo counts blocks between reward cycles, while non-fast blocks name the local block
interval used when simulating production-like timing during development.

References: [Glossary: Tempo](https://docs.learnbittensor.org/resources/glossary#tempo),
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)
