# Root Claim Type

Root claim type is the Keep or Swap setting for handling alpha dividends earned through Root Subnet
staking. Keep leaves processed dividends as originating-subnet alpha, while Swap converts processed
dividends to TAO and restakes them on Root
([Root Claim overview](https://docs.learnbittensor.org/staking-and-delegation/root-claims)).

The term belongs to dividend-handling vocabulary. It names the selected outcome for processed root
claims, not a separate staking action or balance report.

## Claim Setting

Root claim type is the preference applied when accumulated root-claim dividends are processed. It
chooses between the Keep and Swap dividend outcomes
([Root Claim overview](https://docs.learnbittensor.org/staking-and-delegation/root-claims)).

That makes root claim type different from claim timing. Claim timing answers when accumulated
dividends are processed; root claim type answers how those dividends are handled.

## Keep and Swap Outcomes

Keep leaves earned alpha on the subnet that generated the dividend. Swap converts accumulated alpha
dividends to TAO and restakes the resulting TAO on the Root Subnet
([Root Claim overview](https://docs.learnbittensor.org/staking-and-delegation/root-claims)).

For readers, Keep is the alpha-retention outcome and Swap is the TAO-restaking outcome. Neither term
changes the definition of Root Subnet staking by itself.

Keep preserves the originating-subnet alpha form after the dividend is processed. That makes it
useful as vocabulary for articles that need to distinguish retained alpha dividends from Root Subnet
stake.

Swap changes the processed dividend into TAO that is restaked on Root. That makes it useful as
vocabulary for articles that need to separate dividend handling from the initial staking position.

Both outcomes describe the handled dividend, not the full relationship between a Root staker,
validator selection, and later reward accounting. The article term should stay attached to the
claim-output choice.

## Root Claims Relationship

Root claims name the broader process for handling accumulated dividends. Root claim type is the
setting used inside that process
([Root Claim overview](https://docs.learnbittensor.org/staking-and-delegation/root-claims)).

This keeps the vocabulary precise. A root claim is the processing event; root claim type is the Keep
or Swap setting that determines the dividend outcome during processing.

The distinction matters because root claims can be discussed as an activity, while root claim type
is only the selected outcome for that activity. Saying that a claim used Keep or Swap is more
specific than saying a claim happened.

In article prose, root claim type should therefore appear where the reader needs to know the handled
form of the dividend. It should not replace broader root-claim wording when the topic is only the
existence of claim processing.

## Root Staking Context

Root Subnet is the staking context where TAO can be delegated through validators, and root claim
type describes what happens to dividends produced through that position
([Glossary: Root Subnet](https://docs.learnbittensor.org/resources/glossary#root-subnetsubnet-zero),
[Root Claim overview](https://docs.learnbittensor.org/staking-and-delegation/root-claims)).

Root staker names the TAO holder using Root Subnet staking. Root claim type names the
dividend-handling preference tied to claim processing
([Glossary: Root Staker](https://docs.learnbittensor.org/resources/glossary#root-staker)).

That boundary keeps the person, the staking context, and the dividend outcome separate. A reader can
identify the Root staker without assuming which claim type was selected for later dividends.

## Emission Context

Root claim type belongs near emissions vocabulary because the underlying subject is dividend
handling. Emissions supply the broader reward context, while root claim type decides whether the
processed dividend stays as alpha or becomes TAO restaked on Root
([Emission](https://docs.learnbittensor.org/learn/emissions),
[Root Claim overview](https://docs.learnbittensor.org/staking-and-delegation/root-claims)).

That makes the term narrower than emissions overall. It is the claim-output preference, not the full
reward distribution model.

The emission article-level context explains why dividends exist; root claim type explains only how
one class of processed Root Subnet dividend is handled. Keeping those layers separate helps avoid
turning a narrow Keep-or-Swap term into a general emissions definition.

## Network Context

Bittensor documentation separates localnet, testnet, and mainnet environments
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

Root-claim-type examples should keep that environment boundary attached. A localnet or testnet
example can illustrate Keep or Swap behavior, but it is not evidence of a mainnet root-claim
outcome.

This is especially important when examples are used for explanation. The concept can be stable
across environments while any observed outcome remains tied to the environment where it was
observed.

## Reader Boundary

Root claim type should be read as a concept for dividend handling. It does not describe how to set
the preference, initiate a claim, quote claim thresholds, or report exact conversion outcomes
([Root Claim overview](https://docs.learnbittensor.org/staking-and-delegation/root-claims)).

The stable article-level point is that root claim type names the Keep or Swap setting that
determines whether processed Root Subnet dividends remain as subnet alpha or are converted to TAO
and restaked on Root.
