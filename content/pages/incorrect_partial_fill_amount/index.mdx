# Incorrect Partial Fill Amount

`IncorrectPartialFillAmount` is a documented limit-orders error raised when a limit-order execution
submission uses an invalid partial-fill amount or fill mode. The Subtensor API error reference
describes it as "Incorrect partial fill amount provided"
([Subtensor API Errors: IncorrectPartialFillAmount](https://docs.learnbittensor.org/subtensor-api/errors#incorrectpartialfillamount)).

## What It Means

The `is_order_valid` helper — used by both `execute_orders` and `execute_batched_orders` — applies
two related checks that both return `IncorrectPartialFillAmount`.

When the signed submission includes a partial-fill amount, the runtime requires that amount to be
greater than zero and less than or equal to the remaining fill allowance. For a new order, the
allowance is the full order amount. For an order already marked partially filled, the allowance is
the order amount minus what has already been filled
([Subnet Liquidity Pools](https://docs.learnbittensor.org/subnets/understanding-subnets#liquidity-pools),
[Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

When the signed submission omits a partial-fill amount, the runtime treats the call as a one-shot
full execution of the order amount. That path returns `IncorrectPartialFillAmount` if the order is
already in partially filled status, because the remaining balance must be completed with an explicit
partial-fill amount instead
([Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

These checks run after relayer-presence and partial-fills-enabled validation on the partial-fill
path, or after the same earlier gates when evaluating the one-shot full-fill branch
([Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

This is a fill-amount or fill-mode rejection, not proof that partial fills are disabled on the order
or that the signature failed verification.

## Why It Appears

On the partial-fill branch, this error appears when the submitted amount is zero, larger than the
remaining allowance, or otherwise outside the allowed range for the order's current fill state. On
the one-shot branch, it appears when a relayer retries full execution against an order that already
has partial fill progress recorded on chain
([Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

When debugging the partial-fill branch, compare against earlier rejections on the same path.
`RelayerRequiredForPartialFill` means the order has no relayer restriction while a partial fill was
requested. `PartialFillsNotEnabled` means the order was not created with partial fills turned on
([Relayer Required For Partial Fill](https://docs.learnbittensor.org/errors/subtensor#relayerrequiredforpartialfill),
[Partial Fills Not Enabled](https://docs.learnbittensor.org/errors/subtensor#partialfillsnotenabled),
[Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

## Distinction from Partial Fills Not Enabled

`IncorrectPartialFillAmount` and `PartialFillsNotEnabled` both involve partial execution, but at
different checks. `PartialFillsNotEnabled` means the order does not allow partial fills at all.
`IncorrectPartialFillAmount` means partial fills are allowed but the submitted amount or fill mode
does not satisfy the bounds rules
([Partial Fills Not Enabled](https://docs.learnbittensor.org/errors/subtensor#partialfillsnotenabled),
[Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

- **PartialFillsNotEnabled** — partial fills are not enabled on the order.
- **IncorrectPartialFillAmount** — the partial-fill amount or fill mode is invalid.

## Distinction between partial-fill amount and one-shot retry paths

`IncorrectPartialFillAmount` uses the same error label on two branches of `is_order_valid`, but for
different reasons. On the partial-fill branch, the submitted amount must be positive and within the
remaining fill allowance. On the one-shot branch, a submission without a partial-fill field is
rejected when the order already has partially filled status
([Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

- **Partial-fill branch** — the submitted partial amount is zero or above the remaining allowance.
- **One-shot branch** — full execution was requested against an already partially filled order.

## Distinction from Order Already Processed

`IncorrectPartialFillAmount` and `OrderAlreadyProcessed` both involve order fill state, but at
different checks. `OrderAlreadyProcessed` means the derived order ID is already stored as fulfilled.
`IncorrectPartialFillAmount` on the one-shot branch means the order is partially filled but not yet
fulfilled, and therefore cannot accept another full one-shot execution
([Order Already Processed](https://docs.learnbittensor.org/errors/subtensor#orderalreadyprocessed),
[Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

- **OrderAlreadyProcessed** — the order is already fulfilled.
- **IncorrectPartialFillAmount** — the fill amount or fill mode is invalid for the current status.

## Reader Boundary

This page defines the meaning of the error label and the partial-fill bounds checks that raise it.
It does not report live fill progress for any order on a network; that is order state readers can
query separately
([Subnet Liquidity Pools](https://docs.learnbittensor.org/subnets/understanding-subnets#liquidity-pools),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
