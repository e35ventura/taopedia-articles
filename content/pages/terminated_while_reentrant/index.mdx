# Terminated While Reentrant

`TerminatedWhileReentrant` is a contracts pallet error raised when a contract tries to terminate
while it is still active in the current call chain. The API errors reference summarizes it as
"Termination of a contract is not allowed while the contract is already on the call stack"
([Subtensor API Errors: TerminatedWhileReentrant](https://docs.learnbittensor.org/subtensor-api/errors#terminatedwhilereentrant)).

## What It Means

Some contracts operations can reach a point where a contract would try to terminate itself while
that same contract is still active in the ongoing call chain. `TerminatedWhileReentrant` means the
runtime rejects that termination attempt instead of allowing the contract to remove itself mid-call
([Subtensor API Errors: TerminatedWhileReentrant](https://docs.learnbittensor.org/subtensor-api/errors#terminatedwhilereentrant)).

This is a termination-during-active-call failure. It does not, by itself, mean the contract has
already been terminated, that execution trapped for another reason, or that a constructor ended the
contract during deployment.

## Why It Appears

This error appears when a contracts operation reaches a termination attempt while the same contract
is still active in the current call chain
([Subtensor API Errors: TerminatedWhileReentrant](https://docs.learnbittensor.org/subtensor-api/errors#terminatedwhilereentrant)).

## Distinction from Contract Terminated

`TerminatedWhileReentrant` and `ContractTerminated` both involve contract termination, but they
describe different states. `TerminatedWhileReentrant` means termination is rejected because the
contract is still active in the current call chain. `ContractTerminated` means the contract has
already been terminated and is no longer available
([Subtensor API Errors: TerminatedWhileReentrant](https://docs.learnbittensor.org/subtensor-api/errors#terminatedwhilereentrant),
[Subtensor API Errors: ContractTerminated](https://docs.learnbittensor.org/subtensor-api/errors#contractterminated)).

- **TerminatedWhileReentrant** — termination is rejected while the contract is still active.
- **ContractTerminated** — the contract is already terminated and unavailable.

## Distinction from Terminated In Constructor

`TerminatedWhileReentrant` and `TerminatedInConstructor` both involve a contract trying to terminate
itself, but they fail in different situations. `TerminatedWhileReentrant` is about termination while
the contract is already active in the current call chain. `TerminatedInConstructor` is summarized as
"A contract self destructed in its constructor"
([Subtensor API Errors: TerminatedWhileReentrant](https://docs.learnbittensor.org/subtensor-api/errors#terminatedwhilereentrant),
[Subtensor API Errors: TerminatedInConstructor](https://docs.learnbittensor.org/subtensor-api/errors#terminatedinconstructor)).

- **TerminatedWhileReentrant** — termination is attempted while the contract is still active in the
  call chain.
- **TerminatedInConstructor** — the contract self-destructs in its constructor.
