# Loss Function

A loss function names the optimization target that a subnet's incentive mechanism steers miners
toward. The official
[Glossary: Loss Function](https://docs.learnbittensor.org/resources/glossary#loss-function)
describes incentive mechanisms as loss functions that guide subnet miners toward desirable outcomes,
using the machine-learning sense of a function that measures distance from a desired result.

## Incentive Mechanism Context

In Bittensor subnet design, the loss-function idea belongs inside incentive-mechanism vocabulary.
The
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)
defines incentive mechanisms as systems that drive miner behavior and govern validator consensus,
and
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)
places the task, protocol, and evaluation method together as parts of that design.

Loss function is not a separate reward payout label. It names what miners are being steered to
optimize under the subnet's evaluation rules.

## Miner and Validator Context

Loss-function language describes the target side of subnet evaluation. Miners produce work that the
subnet values, and validators measure that work against the subnet's standards. The
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets) documentation
describes subnets as markets where miners produce a digital commodity and validators measure the
work.

This keeps three ideas distinct: the **subnet task** names the work target, the **incentive
mechanism** names the rule context, and **loss function** names the optimization framing for what
counts as better miner behavior.

## Relationship to Objective Function

Loss function and objective function are closely related in subnet prose. The
[Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function)
describes the goal a subnet is continuously optimizing for through its incentive mechanism. Loss
function emphasizes the distance-from-target framing, while objective function emphasizes the goal
being pursued.

Both terms belong to subnet design vocabulary rather than to wallet, governance, or live emission
reports.

## Reader Boundary

Loss function should not be read as a live score, a validator recommendation, or a reward
calculation. It is a concept term for what subnet incentive rules steer miners toward. Individual
subnet evaluation standards and scoring details belong to the subnet's own documentation rather than
to this glossary entry.
