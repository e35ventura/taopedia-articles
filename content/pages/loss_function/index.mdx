# Loss Function

A loss function measures error between an output and a desired result. In Bittensor context, the
term is useful when discussing subnet tasks that evaluate model or service performance, because
validators need a way to compare submitted work against the subnet's target.

References:
[Glossary: Loss Function](https://docs.learnbittensor.org/resources/glossary#loss-function),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)

## Evaluation Context

A lower loss usually means the measured output is closer to the desired result, while a higher loss
means the measured output is farther away. Subnets can define different tasks, so the relevant loss
or scoring measure depends on what that subnet is trying to evaluate.

Reference:
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)

## Relationship to Incentives

A loss function is not a reward by itself. It is part of evaluation: it helps turn work quality into
a score or comparison. A subnet's incentive mechanism can then use those evaluations when validators
produce weights and when consensus translates evaluations into emissions.

References:
[Glossary: Loss Function](https://docs.learnbittensor.org/resources/glossary#loss-function),
[Yuma Consensus](https://docs.learnbittensor.org/yuma-consensus/)

## Reader Boundary

This page defines the term at a high level. It does not specify the loss function for any live
subnet or recommend a scoring design. Subnet-specific scoring should be checked from that subnet's
current documentation or source material.
