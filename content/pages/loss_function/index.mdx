# Loss Function

A loss function is a way to describe the gap between a desired output and an observed result. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#loss-function) applies the term to
Bittensor by describing incentive mechanisms as loss functions that steer subnet miners toward
desired outcomes.

## Subnet Context

Loss function is useful as an interpretation of why a subnet's incentive design matters. A subnet
asks miners to produce work, validators evaluate that work, and the incentive mechanism turns those
evaluations into signals that affect rewards.
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets) describes
subnets as markets where miners produce a digital commodity and validators measure miner work.

This makes the loss function a subnet-specific idea. It depends on what the subnet is trying to
produce and what its validators are expected to recognize as better or worse output.

## Relationship To Incentive Mechanisms

The official
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)
page explains that each subnet has one or more incentive mechanisms, with scoring models that define
how validators evaluate miner work. The glossary's loss-function framing is another way to read the
same design pressure: miners are steered toward outcomes that score well under the subnet's
evaluation method.

The term should not be stretched into a single universal formula for all Bittensor. Different
subnets can define different tasks, interaction patterns, and scoring models.

## Relationship To Scoring

A subnet scoring model is the more concrete evaluation method. A loss function is the optimization
framing behind that method: it explains what kind of gap the subnet is trying to shrink or what kind
of behavior it is trying to encourage. The
[Glossary: Subnet scoring model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)
defines scoring as the component that converts miner responses into numerical scores.

For readers, the distinction is simple. Scoring is how work is evaluated; loss function is the
conceptual pressure that makes the evaluation point toward a desired outcome.

## Reader Boundary

Loss function should not be read as a live emissions rule, a validator recommendation, or a complete
description of any one subnet's code. It is a conceptual term for the optimization signal expressed
through subnet incentive design.
