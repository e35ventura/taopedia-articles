# Loss Function

In machine learning, a loss function is a mathematical function that measures the difference between
a predicted output and the ground truth. In Bittensor, a subnet's incentive mechanism plays that
role: it acts as a loss function that steers subnet miners toward the outcome the subnet considers
desirable.

References: [Loss Function](https://docs.learnbittensor.org/resources/glossary#loss-function),
[Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)

## From Prediction Error to Network Incentive

A classic loss function rewards a model for getting closer to the truth and penalizes it for moving
away. A Bittensor subnet reproduces that pressure at the network level: instead of adjusting one
model's weights, the incentive mechanism defines what good work looks like and rewards miners in
proportion to how well their work meets it. The subnet, not a single training loop, becomes the
thing being optimized.

References:
[Anatomy of an Incentive Mechanism](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)

## The Objective It Optimizes

A loss function only has meaning relative to a goal. The goal a subnet continuously optimizes for,
through its incentive mechanism, is its objective function. The loss function is how distance from
that objective is measured; the objective function is the target that distance is measured against.
Reading one without the other loses the point of both.

References:
[Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function),
[Loss Function](https://docs.learnbittensor.org/resources/glossary#loss-function)

## Each Subnet Defines Its Own

There is no single network-wide loss function. Each subnet defines the task it evaluates and the way
it scores responses, so the loss function is specific to that subnet's purpose. A loss function that
makes sense for a text subnet says nothing about what a prediction or storage subnet should reward.
This is why a claim about how miners are scored should name the subnet it describes rather than
generalize across Bittensor.

References: [Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)

## How the Signal Becomes Reward

The loss function does not pay miners by itself. Validators evaluate miner work against the subnet's
mechanism and submit weights expressing those judgments, and Yuma Consensus aggregates the
validators' weights into the consensus that drives emissions. The loss function shapes what
validators are looking for; Yuma Consensus turns the resulting signals into the rewards miners
actually receive.

References: [Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Anatomy of an Incentive Mechanism](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)

## Reader Boundary

Read a loss function as the standard a subnet measures miner work against, expressed through its
incentive mechanism, not as a fixed formula shared by the whole network or as the payout step
itself. It defines what the subnet is trying to minimize the gap toward; consensus and emissions are
separate stages that act on the signals it produces.

[Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function)
