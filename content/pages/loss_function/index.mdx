# Loss Function

A loss function is a machine-learning idea that Bittensor borrows to describe how incentive
mechanisms steer subnets. The official
[Glossary: Loss Function](https://docs.learnbittensor.org/resources/glossary#loss-function)
describes it as a mathematical function that measures the difference between a predicted output and
the ground truth, and notes that in Bittensor incentive mechanisms act as loss functions that steer
subnet miners toward desirable outcomes.

## Why the Analogy Matters

In machine learning, a model improves by reducing the value a loss function reports. Bittensor
reuses that framing at the subnet level: instead of a single model minimizing error, a subnet's
incentive mechanism rewards miners whose work moves closer to the outcome the subnet wants. The
[Anatomy of an Incentive Mechanism](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)
documentation presents this reward shaping as the core of subnet design.

For readers, loss function is a conceptual lens, not a setting. It explains why a subnet rewards
some responses over others rather than naming a value to configure.

## Relationship to Incentive Mechanism

A loss function and an incentive mechanism describe the same steering idea at different levels. The
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)
describes the mechanism that connects subnet work, validator evaluation, and emission outcomes,
while loss function is the machine-learning analogy for what that mechanism is doing: pushing miner
behavior toward a target.

For readers, incentive mechanism names the concrete Bittensor construct, while loss function names
the mathematical intuition behind why it rewards the responses it does.

References:
[Glossary: Loss Function](https://docs.learnbittensor.org/resources/glossary#loss-function),
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)

## Relationship to Objective Function

A loss function and an objective function are closely related framings of subnet optimization. The
[Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function)
describes the goal a subnet continuously optimizes for through its incentive mechanism, while a loss
function describes the gap-from-target measure that optimization works to reduce.

For readers, objective function names what the subnet is trying to achieve, while loss function
names the measure of how far current results sit from that goal.

References:
[Glossary: Loss Function](https://docs.learnbittensor.org/resources/glossary#loss-function),
[Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function)

## Relationship to Subnet Scoring Model

A loss function and a subnet scoring model both concern how subnet work is judged. The
[Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)
describes how validators evaluate miner responses inside a subnet, while loss function is the
machine-learning intuition for why lower-error responses should score better.

For readers, subnet scoring model names the concrete evaluation procedure, while loss function names
the conceptual reason the procedure favors responses closer to the desired output.

References:
[Glossary: Loss Function](https://docs.learnbittensor.org/resources/glossary#loss-function),
[Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)

## Reader Boundary

Loss function should not be read as a configurable subnet parameter, a specific formula for any one
subnet, or a ranking of subnets. It is a concept term that borrows machine-learning language to
explain how Bittensor incentive mechanisms steer miners toward desirable outcomes.
