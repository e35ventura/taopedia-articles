# Pulse Verification Error

`PulseVerificationError` is a documented drand-pallet error. The Subtensor API errors reference
summarizes it as: "the pulse could not be verified"
([Subtensor API Errors: PulseVerificationError](https://docs.learnbittensor.org/subtensor-api/errors#pulseverificationerror)).

## What It Means

The drand pallet's `write_pulse` extrinsic verifies each submitted pulse before it stores anything.
`PulseVerificationError` is the rejection when that verifier step returns an error, so the runtime
cannot treat the submitted pulse as valid
([Subtensor source: drand/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/drand/src/lib.rs)).

This is a verification failure, not an ordering failure. The runtime stops at the verifier step
before it can apply later checks such as whether the round number is newer than the last stored
round
([Subtensor source: drand/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/drand/src/lib.rs),
[Subtensor API Errors: InvalidRoundNumber](https://docs.learnbittensor.org/subtensor-api/errors#invalidroundnumber)).

## Why It Appears

`write_pulse` iterates through the submitted pulses and calls the configured verifier on each one.
When that verifier returns an error, the pallet maps that result directly to
`PulseVerificationError`
([Subtensor API Errors: PulseVerificationError](https://docs.learnbittensor.org/subtensor-api/errors#pulseverificationerror),
[Subtensor source: drand/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/drand/src/lib.rs)).

The tests show this exact failure mode. A pulse payload with an invalid verification path causes
`write_pulse` to fail with `PulseVerificationError`, and no pulse is written into storage for that
round
([Subtensor test: drand/tests.rs](https://github.com/opentensor/subtensor/blob/main/pallets/drand/src/tests.rs)).

## Distinction from Invalid Round Number

`PulseVerificationError` and `InvalidRoundNumber` both block `write_pulse`, but they fail at
different stages. `PulseVerificationError` means the runtime cannot verify the submitted pulse at
all. `InvalidRoundNumber` means verification passed, but the pulse round still fails the monotonic
round check
([Subtensor API Errors: PulseVerificationError](https://docs.learnbittensor.org/subtensor-api/errors#pulseverificationerror),
[Subtensor API Errors: InvalidRoundNumber](https://docs.learnbittensor.org/subtensor-api/errors#invalidroundnumber)).

- **PulseVerificationError** — the submitted pulse cannot be verified.
- **InvalidRoundNumber** — the pulse verifies, but its round number is not acceptable for storage.

## Reader Boundary

This page defines the meaning of the error label in the drand pulse-verification step. It does not
describe every drand storage rule or beacon-configuration detail; it focuses on the verifier failure
that raises `PulseVerificationError`
([Subtensor source: drand/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/drand/src/lib.rs)).
