Chain reads are interactions that inspect current Bittensor chain state. They are different from
submitted actions that ask the Subtensor runtime to change state.

The official [Transaction Fees in Bittensor](https://docs.learnbittensor.org/learn/fees) page
separates chain reads from state-changing actions and notes that reading chain state is free. The
official [Subtensor Storage](https://docs.learnbittensor.org/subtensor-api/storage) reference shows
the kinds of runtime storage entries that can be queried.

## How Chain Reads Fit

Chain reads are the lookup side of interacting with Subtensor. They let software inspect exposed
runtime state, such as named storage entries, without asking the runtime to record a new change.

This is the opposite side of the distinction described in the official
[Subtensor extrinsics](https://docs.learnbittensor.org/subtensor-api/extrinsics) reference, which
lists submitted runtime methods. A read checks state; an extrinsic submits an action.

## Why the Distinction Matters

The read-versus-submit distinction helps readers understand why some Bittensor interactions only
retrieve information while others can change chain state and carry fees. A chain read belongs to the
first group.

This article is a conceptual orientation, not a complete catalog of queryable storage entries. The
official storage reference is the source of truth for current names and paths.
