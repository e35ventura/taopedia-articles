# Registration Allowed

Registration allowed is a per-subnet hyperparameter, listed in the documentation as
`NetworkRegistrationAllowed`, that controls whether neuron registration is enabled on a subnet. When
it is on, new neurons can register on that subnet; when it is off, the subnet does not accept new
registrations.

References: [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)

## What It Controls

The hyperparameter acts as a switch over registration for a subnet. It does not change how
registration works or what it costs; it only sets whether registration is currently open. With the
switch off, attempts to register on that subnet are not accepted until it is turned back on.

Reference: [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)

## Default and Setting

The documentation lists a default of enabled and marks the parameter as set at the root level rather
than by the subnet owner. Whether registration is open on a given subnet is per-subnet chain state
and can differ from the default, so the live setting should be read for that subnet.

Reference: [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)

## Subnet Context

Registration allowed is one of the subnet hyperparameters, the on-chain state variables that
configure a single subnet, for example netuid 1. Because each subnet carries its own
hyperparameters, the registration switch is defined per subnet and applies only within that subnet.

Reference: [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)

## Relationship to Registration

Registration is how a neuron claims a place on a subnet. This hyperparameter sits one level above
that process: it decides whether registration is available at all on the subnet right now. The two
are connected because the switch gates the action, while the registration process and its cost
describe how the action runs when it is permitted.

References:
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Register](https://docs.learnbittensor.org/resources/glossary#register)

## Reader Boundary

This page defines the concept at a high level. It does not report whether registration is currently
open on any particular subnet. That is live chain state and should be checked for the relevant
netuid. The documented default is enabled, and the parameter is governed at the root level.

Reference: [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)

## The Switch Does Not Change Registration Cost

When registration is allowed on a subnet, the hyperparameter opens the door to new neuron
registration but does not alter how the dynamic registration burn is calculated. Official
[Register](https://docs.learnbittensor.org/resources/glossary#register) vocabulary still describes
the cost as dynamic and bounded by subnet parameters such as min burn and max burn on a subnet such
as netuid 1.

Readers should therefore separate availability from economics. Registration allowed answers whether
new entries are accepted right now; register and burn vocabulary answer what a successful entry
costs when the switch is on
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

References:
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register)

## Root Governance Sets the Default Open State

Subnet [hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters) split
between root-level and owner-settable values. Registration allowed is documented at the root level
with a default of enabled, unlike owner-controlled registration economics such as min burn or max
burn on a subnet such as netuid 1.

That governance split explains why the article treats the live open-or-closed state as per-subnet
chain information to read for the subnet in question, while the documented default describes the
network's baseline expectation that registration remains available unless root policy changes it.

References:
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Create a Subnet](https://docs.learnbittensor.org/subnets/create-a-subnet)

## A Subnet Can Exist Before Registration Matters

Official [Create a Subnet](https://docs.learnbittensor.org/subnets/create-a-subnet) guidance
separates subnet creation from the
[start call](https://docs.learnbittensor.org/resources/glossary#start-call) that begins emissions.
Registration allowed governs whether new neurons can join once a subnet is operating, but it does
not by itself describe whether the subnet has been created or activated.

That lifecycle ordering keeps three ideas apart. Subnet creation places the subnet on chain, the
start call turns on emissions, and registration allowed decides whether additional neurons can
register into the running subnet economy.

References: [Create a Subnet](https://docs.learnbittensor.org/subnets/create-a-subnet),
[Glossary: Start Call](https://docs.learnbittensor.org/resources/glossary#start-call)
