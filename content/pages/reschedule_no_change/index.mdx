# Reschedule No Change

`RescheduleNoChange` is a scheduler pallet error raised when a reschedule would not change the
scheduled time. The API errors reference summarizes it as "Reschedule failed because it does not
change scheduled time"
([Subtensor API Errors: RescheduleNoChange](https://docs.learnbittensor.org/subtensor-api/errors#reschedulenochange)).

## What It Means

Subtensor uses the scheduler pallet to queue calls for dispatch at a specified future block. A
reschedule operation moves an already queued call to a new target block. `RescheduleNoChange` means
the submitted target block is the same as the call's current scheduled time, so the runtime rejects
the reschedule as a no-op
([Subtensor API Errors: RescheduleNoChange](https://docs.learnbittensor.org/subtensor-api/errors#reschedulenochange)).

This is a no-op reschedule rejection. It does not, by itself, mean the submitted target block is in
the past, that the scheduler could not store the call for another reason, or that no matching
scheduled call exists in storage.

## Why It Appears

This error appears when a scheduler reschedule supplies a target block that matches the call's
existing scheduled time
([Subtensor API Errors: RescheduleNoChange](https://docs.learnbittensor.org/subtensor-api/errors#reschedulenochange)).

## Distinction from Target Block Number In Past

`RescheduleNoChange` and `TargetBlockNumberInPast` both block scheduler reschedule paths, but on
different checks. `RescheduleNoChange` is summarized as "Reschedule failed because it does not
change scheduled time." `TargetBlockNumberInPast` is summarized as "Given target block number is in
the past."
([Subtensor API Errors: RescheduleNoChange](https://docs.learnbittensor.org/subtensor-api/errors#reschedulenochange),
[Subtensor API Errors: TargetBlockNumberInPast](https://docs.learnbittensor.org/subtensor-api/errors#targetblocknumberinpast)).

- **RescheduleNoChange** — the reschedule would not change the scheduled time.
- **TargetBlockNumberInPast** — the submitted target block number is in the past.

## Distinction from Failed To Schedule

`RescheduleNoChange` and `FailedToSchedule` both stop a scheduler operation from succeeding, but
with different API summaries. `RescheduleNoChange` is summarized as "Reschedule failed because it
does not change scheduled time." `FailedToSchedule` is summarized as "Failed to schedule a call"
([Subtensor API Errors: RescheduleNoChange](https://docs.learnbittensor.org/subtensor-api/errors#reschedulenochange),
[Subtensor API Errors: FailedToSchedule](https://docs.learnbittensor.org/subtensor-api/errors#failedtoschedule)).

- **RescheduleNoChange** — the reschedule would not change the scheduled time.
- **FailedToSchedule** — the scheduler failed to schedule the call.

## Reader Boundary

This page defines the meaning of the error label from the API reference. It does not report the
scheduled time stored for a specific call on a network or choose a different target block
([Subtensor API Errors: RescheduleNoChange](https://docs.learnbittensor.org/subtensor-api/errors#reschedulenochange),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
