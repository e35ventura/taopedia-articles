# Trust

Trust is a Bittensor consensus metric that describes how much of a miner's original validator
support remains after consensus clipping. The official glossary defines trust as the relationship
between final rank and pre-rank in Yuma Consensus.

References: [Trust](https://docs.learnbittensor.org/resources/glossary#trust),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)

## What Trust Represents

Validators evaluate miner work by submitting weights. Before those signals become a consensus
result, outlier assignments can be clipped. Trust describes the effect of that clipping on the
evaluated miner: high trust means the original support was largely preserved, while lower trust
means more of that support was reduced by the consensus process.

References: [Trust](https://docs.learnbittensor.org/resources/glossary#trust),
[Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score)

## Relationship to Rank

Rank and trust are closely related but not the same concept. Rank is the consensus-adjusted
evaluation result. Trust describes how much the path from pre-rank to final rank changed during
consensus filtering. In practical reading, rank says where the miner landed after aggregation; trust
says how much clipping affected that result.

References: [Rank](https://docs.learnbittensor.org/resources/glossary#rank),
[Trust](https://docs.learnbittensor.org/resources/glossary#trust)

## Relationship to Validator Trust

Trust is read from the evaluated miner's side of the process. Validator trust is read from the
validator's side, describing how much of a validator's submitted weight signal remains after
filtering. Keeping the two separate avoids treating trust as a general reputation score for every
participant.

References: [Trust](https://docs.learnbittensor.org/resources/glossary#trust),
[Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust)

## Relationship to Consensus Score

Consensus score is the threshold-like agreement signal used during clipping. Trust is an outcome
metric after that filtering has affected an evaluated miner's support. The two concepts are related
because trust depends on how much validator support survives the consensus threshold.

References: [Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Trust](https://docs.learnbittensor.org/resources/glossary#trust)

## Relationship to Multiple Mechanisms

Trust is usually discussed for one incentive mechanism at a time, but subnets can also run multiple
mechanisms in parallel. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms) notes
that each mechanism operates with its own bond pool for Yuma Consensus calculations.

For readers, trust still describes how much consensus clipping affected a miner's evaluation, but
the mechanism context matters. Trust for one mechanism should be read separately when a subnet uses
more than one evaluation system.

References:
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets),
[Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)

## Careful Interpretation

Trust should be read inside a subnet's evaluation context. It is not a universal quality label, not
an operating instruction, and not a promise about future results. The Taopedia-level meaning is the
role it plays in explaining how consensus clipping changes miner-side evaluation.

References: [Trust](https://docs.learnbittensor.org/resources/glossary#trust),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)

## Relationship to Yuma Consensus

Trust and Yuma Consensus address related but different parts of Bittensor subnet incentive flow.
Yuma Consensus aggregates validator weight signals into miner incentives and validator dividends,
while trust describes how much of an evaluated miner's original validator support remains after
consensus clipping inside that process. The
[Glossary: Trust](https://docs.learnbittensor.org/resources/glossary#trust) defines trust as the
relationship between final rank and pre-rank, and
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus) describes the aggregation and
clipping flow that produces those values.

For readers, Yuma Consensus names the broader aggregation process, while trust names a miner-side
outcome metric after consensus clipping inside that process.

References: [Glossary: Trust](https://docs.learnbittensor.org/resources/glossary#trust),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)

## Relationship to Validator Weights

Trust and validator weights address related but different parts of subnet evaluation structure.
Validator weights are the evaluation signals validators submit for miners, while trust describes how
much of an evaluated miner's original validator support remains after those signals are filtered
through consensus clipping. The
[Glossary: Validator Weights](https://docs.learnbittensor.org/resources/glossary#validator-weights)
describes the per-validator evaluation inputs, and the
[Glossary: Trust](https://docs.learnbittensor.org/resources/glossary#trust) describes the
post-clipping outcome for an evaluated miner.

For readers, validator weights name the evaluation submissions, while trust names how much of the
resulting miner support survived consensus filtering.

References:
[Glossary: Validator Weights](https://docs.learnbittensor.org/resources/glossary#validator-weights),
[Glossary: Trust](https://docs.learnbittensor.org/resources/glossary#trust)

## Relationship to Weight Matrix

Trust and the weight matrix address related but different parts of Yuma Consensus vocabulary. The
weight matrix collects validator weight vectors as structured input to Yuma Consensus, while trust
describes how much of an evaluated miner's support remains after that input is filtered and
aggregated. The
[Glossary: Weight Matrix](https://docs.learnbittensor.org/resources/glossary#weight-matrix)
describes the matrix built from validator submissions, and the
[Glossary: Trust](https://docs.learnbittensor.org/resources/glossary#trust) describes the miner-side
clipping outcome.

For readers, the weight matrix names the organized validator input collection, while trust names how
much evaluated miner support survived after consensus processing of that input.

References:
[Glossary: Weight Matrix](https://docs.learnbittensor.org/resources/glossary#weight-matrix),
[Glossary: Trust](https://docs.learnbittensor.org/resources/glossary#trust)

## Relationship to Miner Evaluation

Trust and miner evaluation address related but different parts of subnet outcome vocabulary. Miner
evaluation names the process by which validators judge miner work inside a subnet, while trust
describes a consensus outcome metric that reflects how much original validator support for an
evaluated miner remained after clipping. The
[Glossary: Miner Evaluation](https://docs.learnbittensor.org/resources/glossary#miner-evaluation)
describes the evaluation process, and the
[Glossary: Trust](https://docs.learnbittensor.org/resources/glossary#trust) describes the
relationship between final rank and pre-rank after consensus filtering.

For readers, miner evaluation names the judging process, while trust names a post-consensus outcome
metric for how much support survived filtering.

References:
[Glossary: Miner Evaluation](https://docs.learnbittensor.org/resources/glossary#miner-evaluation),
[Glossary: Trust](https://docs.learnbittensor.org/resources/glossary#trust)
