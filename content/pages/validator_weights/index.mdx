# Validator Weights

Validator weights are evaluation signals set by subnet validators. They express how validators
assess miner work inside a subnet before Yuma Consensus filters and aggregates those signals into
subnet outcomes ([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

The term is subnet-specific. A validator weight only has meaning inside the task, scoring method,
and incentive setting that produced it, so it is different from a general validator reputation
score.

## Distinction from Liquid Alpha

Validator weights are the evaluation signals validators submit for miners. Liquid alpha adjusts bond
smoothing after those signals enter the consensus-based bond path
([Glossary: Weight Vector](https://docs.learnbittensor.org/resources/glossary#weight-vector),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

Liquid alpha does not replace validator weights. It governs how quickly bond history responds once
submitted weights pass through consensus clipping and enter the bond update path on a subnet
([Yuma Consensus: Bonds](https://docs.learnbittensor.org/learn/yuma-consensus#bonds)).

Readers should treat validator weights as the per-miner scores a validator records, and liquid alpha
as a smoothing parameter applied after those scores influence bond updates
([Glossary: Weight Vector](https://docs.learnbittensor.org/resources/glossary#weight-vector),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Validator weights** — per-miner evaluation scores submitted by validators.
- **Liquid alpha** — bond-smoothing parameter applied after consensus processes those scores.

## Distinction from Weight Setting

Validator weights are the evaluation values inside a submission. Weight setting is the validator
action that records those values on chain each epoch
([Glossary: Weight Setting](https://docs.learnbittensor.org/resources/glossary#weight-setting),
[Glossary: Weight Vector](https://docs.learnbittensor.org/resources/glossary#weight-vector)).

- **Validator weights** — miner evaluation values in a submission.
- **Weight setting** — validator action that records scores on chain.

Weight setting is the on-chain action that stores a validator's miner scores for the current epoch.
Those stored values are what readers mean by validator weights when discussing subnet evaluation
signals before Yuma Consensus aggregates them
([Glossary: Weight Setting](https://docs.learnbittensor.org/resources/glossary#weight-setting),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

## Distinction from Validator Trust

Validator weights are evaluation signals validators submit about miner work. Validator trust
measures how much of a validator's influence survives consensus clipping
([Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust),
[Glossary: Weight Vector](https://docs.learnbittensor.org/resources/glossary#weight-vector)).

- **Validator weights** — evaluation signals submitted about miner work.
- **Validator trust** — validator-side influence after clipping.

Submission vocabulary and post-clipping influence vocabulary answer different consensus layers
([Yuma Consensus: Clipping](https://docs.learnbittensor.org/learn/yuma-consensus#clipping)).

## Distinction from TAO Weight

TAO weight and validator weights answer different questions. TAO weight helps determine
stake-derived influence when stake weight is formed, while validator weights express a validator's
miner evaluations inside Yuma Consensus
([Glossary: TAO Weight](https://docs.learnbittensor.org/resources/glossary#tao-weight),
[Glossary: Validator Weights](https://docs.learnbittensor.org/resources/glossary#weight-vector),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **TAO weight** — how TAO stake counts when forming stake weight.
- **Validator weights** — the validator's submitted miner evaluations.

## Distinction from Yuma Consensus

Validator weights are the per-miner scores a validator records on chain through weight setting. Yuma
Consensus settles those submissions into emission shares each tempo
([Glossary: Weight Vector](https://docs.learnbittensor.org/resources/glossary#weight-vector),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Validator weights** — submitted miner evaluation values before Yuma settlement.
- **Yuma Consensus** — on-chain mechanism that uses validator weights to determine emission shares.

## Distinction from Stake Weight

Validator weights and stake weight are different inputs to consensus. Validator weights are the
per-miner scores a validator submits to rate miner performance, while stake weight is the
stake-derived influence that determines how heavily that validator's submitted weights count when
Yuma Consensus aggregates them
([Glossary: Weight Vector](https://docs.learnbittensor.org/resources/glossary#weight-vector),
[Glossary: Stake Weight](https://docs.learnbittensor.org/resources/glossary#stake-weight),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

Official subnet documentation explains validator stake weight as the computed influence behind a
validator position. A validator can submit high miner scores, but those signals count in proportion
to the stake weight attached to that validator on the selected netuid
([Understanding Subnets: Validator stake weight](https://docs.learnbittensor.org/subnets/understanding-subnets#validator-stake-weight)).

Readers should not treat submitted scores as equal across validators. Two validators may assign
similar miner evaluations, yet their rows in the weight matrix carry different influence if their
stake weights differ at the same consensus step
([Glossary: Weight Matrix](https://docs.learnbittensor.org/resources/glossary#weight-matrix),
[Glossary: Stake Weight](https://docs.learnbittensor.org/resources/glossary#stake-weight)).

- **Validator weights** — the per-miner scores a validator submits.
- **Stake weight** — the stake-based influence applied to those weights in consensus.

## Reader Boundary

Validator weights name subnet evaluation signals. They describe submitted miner-work assessments
rather than miner leaderboards, reward guarantees, validator permits, or a complete explanation of
Yuma Consensus ([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

Specific examples belong to the subnet, mechanism, network, and source that produced the value at
the time of observation.
