# Stake Weight

Stake weight is the subnet-level stake measure used to describe validator influence in Bittensor
consensus. It is the computed stake value tied to consensus power and emissions inside a subnet
([Glossary: Stake Weight](https://docs.learnbittensor.org/resources/glossary#stake-weight),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

The term links staking vocabulary to consensus evaluation. It answers how much influence a submitted
evaluation carries after stake context is applied, while validator weights answer what was signaled
about miner work.

## Consensus Influence

In Yuma Consensus, validators submit evaluation signals and the consensus process weights those
signals before producing subnet outcomes
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Glossary: Validator Weights](https://docs.learnbittensor.org/resources/glossary#validator-weights)).

This measure is the influence side of that path. It does not replace the evaluation signal; it
scales how strongly the submitted signal participates in the subnet consensus process
([Glossary](https://docs.learnbittensor.org/resources/glossary#stake-weight),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

This is why the term matters in plain English: two validators can submit signals into the same
subnet process, but their stake context affects how those signals count when consensus is computed.

## Components and Neighboring Terms

The measure combines alpha stake, TAO stake, and TAO weight in subnet context
([Glossary](https://docs.learnbittensor.org/resources/glossary#stake-weight),
[Glossary: TAO Weight](https://docs.learnbittensor.org/resources/glossary#tao-weight)).

The staking-total term and the validation-eligibility term have different jobs. One describes
backing, while the other concerns eligibility in a subnet
([staking total](https://docs.learnbittensor.org/resources/glossary#effective-stake),
[validation eligibility](https://docs.learnbittensor.org/resources/glossary#validator-permit)).

Together, these terms give readers a compact map: backing, eligibility, TAO contribution, and the
consensus measure are related but separate concepts.

## Signal Path

Validator weights are the evaluation values. Weight vectors organize one validator's submissions,
and weight matrices collect those vectors for the subnet-level consensus process
([Glossary: Weight Vector](https://docs.learnbittensor.org/resources/glossary#weight-vector),
[Glossary: Weight Matrix](https://docs.learnbittensor.org/resources/glossary#weight-matrix)).

The measure sits beside that input structure as the influence value applied around validator
submissions. Later result terms such as rank, trust, and validator trust describe what happens after
the signals are filtered and interpreted
([Glossary: Rank](https://docs.learnbittensor.org/resources/glossary#rank),
[Glossary: Trust](https://docs.learnbittensor.org/resources/glossary#trust),
[Glossary: Validator Trust](https://docs.learnbittensor.org/resources/glossary#validator-trust)).

## Subnet and Environment Scope

The measure belongs inside the subnet context that uses it. Validators evaluate miner work according
to subnet-specific standards, and Yuma Consensus interprets those signals inside that setting
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

Bittensor separates mainnet, testnet, and localnet environments. Examples from one environment
should not be treated as evidence for another because subnet tasks, validators, and stake conditions
can differ ([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Introduction to Bittensor: Subnet development](https://docs.learnbittensor.org/learn/introduction#subnet-development)).

Localnet examples are isolated development examples. Testnet examples are shared non-production
examples. Mainnet interpretation belongs to the mainnet subnet and consensus context being
discussed.

## Reading the Term

The term applies to validator influence inside subnet consensus. It belongs to consensus
interpretation, separate from staking procedures, permit status, miner results, and the full Yuma
Consensus mechanism ([Glossary](https://docs.learnbittensor.org/resources/glossary#stake-weight),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

The concise reading is: validator weights say what a validator signaled, and this measure explains
how strongly that signal counts in the subnet consensus process.

## Alpha Stake Enters the Weight Calculation Through Subnet Pool Position

The
[Understanding Subnets: Validator stake weight](https://docs.learnbittensor.org/subnets/understanding-subnets#validator-stake-weight)
documentation describes stake weight as combining alpha stake,
[TAO](https://docs.learnbittensor.org/resources/glossary#tao) stake, and
[TAO weight](https://docs.learnbittensor.org/resources/glossary#tao-weight) inside a subnet. The
alpha stake component originates from validator staking positions in subnet liquidity pools under
the Dynamic TAO model. When a validator holds a staking position inside a subnet's pool denominated
in [alpha tokens](https://docs.learnbittensor.org/resources/glossary#alpha-tokens), that position
contributes an alpha-denominated stake value to the overall stake weight calculation for that
subnet. The alpha pool position is therefore not a separate asset class held outside the staking
model; it enters the same consensus influence framework that TAO-based staking uses, but through the
subnet's own token denomination
([Glossary: Stake Weight](https://docs.learnbittensor.org/resources/glossary#stake-weight),
[Glossary: Alpha Tokens](https://docs.learnbittensor.org/resources/glossary#alpha-tokens)).

The [TAO weight](https://docs.learnbittensor.org/resources/glossary#tao-weight) component works
alongside alpha stake to complete the combined stake weight measure. TAO weight converts a
validator's TAO stake contribution into the subnet's consensus influence framework using a scaling
factor that reflects the validator's TAO proportion relative to the subnet's staking context. Alpha
stake performs the same translation on the subnet side, representing the validator's pool position
in terms comparable to the TAO contribution. The combined result is a single stake weight value that
captures the validator's full consensus influence inside the subnet, drawing from both the
subnet-specific alpha pool position and the TAO-denominated staking side
([Glossary: TAO Weight](https://docs.learnbittensor.org/resources/glossary#tao-weight),
[Understanding Subnets: Validator stake weight](https://docs.learnbittensor.org/subnets/understanding-subnets#validator-stake-weight),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

That two-component structure separates the alpha and TAO sides of the staking picture without
collapsing them into a single balance or treating stake weight as a raw token count. The conversion
steps — alpha stake from the subnet pool position and TAO weight from the TAO contribution — produce
a normalized influence measure rather than a simple sum of holdings. A validator with a large alpha
pool position but small TAO stake will have a different stake weight profile than one with large TAO
stake and small alpha pool exposure in the same subnet. Stake weight describes how those differences
combine into a single influence value inside the
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus) process for that subnet
([Glossary: Stake Weight](https://docs.learnbittensor.org/resources/glossary#stake-weight),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

Keeping alpha stake and effective stake separate in this context avoids a reading error that
conflates pool position with delegation totals.
[Effective stake](https://docs.learnbittensor.org/resources/glossary#effective-stake) names the
total staked TAO associated with a delegate across both their own stake and nominator contributions
at the delegation layer. Alpha stake in the stake weight context names the alpha-denominated pool
position inside a specific subnet under Dynamic TAO. The two terms belong to different parts of the
staking vocabulary: effective stake describes a delegation-layer total denominated in TAO, while
alpha stake within stake weight describes a subnet pool contribution that enters the consensus
influence calculation in a subnet-specific token denomination
([Glossary: Effective Stake](https://docs.learnbittensor.org/resources/glossary#effective-stake),
[Glossary: Alpha Tokens](https://docs.learnbittensor.org/resources/glossary#alpha-tokens),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

This subnet-specific scope is why stake weight comparisons are most meaningful within the same
subnet. A validator with high stake weight in one subnet holds that influence relative to the
validator set and alpha pool configuration of that specific subnet. Comparing raw stake weight
values across different subnets can produce misleading conclusions because each subnet's alpha token
supply, pool depth, and validator set create a different normalization context. The
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus) process interprets stake
weight inside the subnet where it was computed, not across a shared cross-subnet scale
([Glossary: Stake Weight](https://docs.learnbittensor.org/resources/glossary#stake-weight),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
