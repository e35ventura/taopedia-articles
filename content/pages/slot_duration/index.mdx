# Slot Duration

Slot duration is an aura pallet runtime constant, listed in the chain's constants metadata as
slotDuration, with the value 12000 and the summary "The slot duration Aura should run with,
expressed in milliseconds"
([Subtensor API Constants: slotDuration](https://docs.learnbittensor.org/subtensor-api/constants#slotduration-u64)).
Because it is expressed in milliseconds, 12000 is twelve seconds, the length of one block-production
slot.

## What It Means

Aura is the block-production mechanism, and it produces blocks in slots. Slot duration sets how long
one of those slots is: twelve seconds
([Subtensor API Constants: slotDuration](https://docs.learnbittensor.org/subtensor-api/constants#slotduration-u64)).
In practice this is the chain's target block time, the pace at which new blocks are expected to
arrive. The value is a single network-wide setting rather than a per-subnet one, so every subnet
sits on the same underlying block cadence.

## Distinction from Minimum Period

Slot duration and the timestamp minimum period are related but distinct. Minimum period, valued at
6000 milliseconds, is the minimum time between blocks, and the runtime wires it as half of the slot
duration
([Subtensor API Constants: minimumPeriod](https://docs.learnbittensor.org/subtensor-api/constants#minimumperiod-u64)).
So slot duration is the full slot length at 12000 milliseconds, while the minimum period is half
that at 6000 milliseconds. One names the slot pace; the other names the minimum spacing derived from
it.

## Why the Slot Length Matters

Many chain values are counted in blocks rather than seconds, so the slot duration is what converts a
block count into wall-clock time. A duration given as a number of blocks lasts that many multiples
of twelve seconds
([Subtensor API Constants: slotDuration](https://docs.learnbittensor.org/subtensor-api/constants#slotduration-u64)).
This is why block-counted settings elsewhere translate to calendar time only once the slot duration
is known.

## Distinction from Tempo

Slot duration and tempo both relate to timing but measure different things. Slot duration is the
time one block takes, at twelve seconds, while tempo is a count of blocks between a subnet's Yuma
Consensus epoch transitions
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)). One is
seconds per block; the other is blocks per epoch. Combining them gives an epoch's wall-clock length,
so a tempo counted in blocks becomes a span in minutes or hours only through the slot duration.

## Reader Boundary

Slot duration is a single network-wide constant, not a per-subnet value. It is a runtime constant
whose effective value is expected not to change while the chain is running, since altering the slot
duration on a running chain would disrupt block production. It names the target slot length and does
not guarantee that every block is produced exactly twelve seconds apart
([Subtensor API Constants: slotDuration](https://docs.learnbittensor.org/subtensor-api/constants#slotduration-u64)).
