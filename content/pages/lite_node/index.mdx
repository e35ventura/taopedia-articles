# Lite Node

A lite node is a type of public subtensor node that synchronizes with the Bittensor blockchain using
warp synchronization. The official
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes) documentation describes a
lite node as a node configured to sync primarily with finalized blocks rather than the entire
blockchain, retaining only recent data and using significantly less storage than a full archive
node.

In Taopedia terms, a lite node is the fast, lightweight way to connect to the live Bittensor
mainchain or testchain. It exists alongside the archive node as one of the two public subtensor node
types, and it is distinct from a local blockchain, which is an isolated development chain.

## Warp Synchronization

The defining behavior of a lite node is warp synchronization. The
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes) documentation explains that
a lite node warps — jumps directly — to the latest finalized block, downloading the complete
blockchain state at that point. This lets the node reach a usable, synchronized state quickly
instead of processing every block from the genesis block onward.

Warp synchronization is what makes a lite node suitable as a local entry point into the Bittensor
network. The node gets up and running fast and can serve subnet participants with minimal storage
requirements, because it does not hold the full historical ledger.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Storage and Data Retention

A lite node retains only recent data and offers limited historical access. The
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes) documentation places the
lite node opposite the archive node on storage: the lite node uses significantly less storage
because it does not keep the entire blockchain history, while the archive node stores every block
from genesis onward.

For readers, the practical distinction is historical depth. A lite node can serve current chain
state and recent activity, but it is not designed for querying old blocks. The official
documentation recommends using an archive node to retrieve blockchain data older than the previous
300 blocks, so a lite node should not be read as a source of deep historical data.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Verification of Chain History

Although a lite node does not process every block, it still verifies the legitimacy of the chain.
The [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes) documentation states
that a lite node downloads and verifies finality proofs all the way back to the genesis block. These
proofs confirm the chain's history is valid without requiring the node to store or process each
block individually.

This means a lite node is not a trusted or unverified node. It confirms the canonical chain through
finality proofs while keeping its storage footprint small. The node also continues to download and
process historical blocks in the background when it is less busy, gradually building a more complete
local database without blocking its primary synchronization role.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Relationship to Archive Node

A lite node and an archive node are the two public subtensor node types, and they trade storage for
historical depth in opposite ways. The
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes) documentation describes the
archive node as downloading and validating every block from genesis to the most recent block,
storing the entire blockchain history for full state access.

For readers, the lite node prioritizes speed and low storage by keeping only recent finalized state,
while the archive node prioritizes completeness by keeping the full history. The same documentation
notes that full synchronization on an archive node is significantly slower than the warp sync used
by a lite node, and that archive nodes require substantially more storage space.

Applications that need historical blockchain data — such as block explorers, indexers, and analytics
tools — use archive nodes. Participants that only need current chain state — such as miners and most
subnet validators — can use lite nodes.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Relationship to Public Subtensor

A lite node is one of the two forms a public subtensor node can take. The
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)
describes a public subtensor node as a publicly accessible node synchronized with the Bittensor
network, and the [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)
documentation identifies lite nodes and archive nodes as the two synchronization modes for such a
node.

For readers, public subtensor names the public-access concept, while lite node names the
storage-efficient synchronization mode. A lite node can synchronize with either the Bittensor
mainchain or the testchain, matching the public-access scope described for public subtensor nodes.

References:
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Distinct from a Neuron

A subtensor node, including a lite node, is not the same as a Bittensor neuron. The
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes) documentation emphasizes
that a subtensor node holds a copy of the blockchain database, while a neuron is a subnet validator
or subnet miner that exists inside a subnet and does not contain the blockchain database.

For readers, this keeps the two concepts separate: a lite node is blockchain infrastructure that
stores and serves chain state, while a neuron is a subnet participant evaluated by the incentive
mechanism. A subnet miner may connect through a local lite node, but the miner and the node are
different objects.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)
