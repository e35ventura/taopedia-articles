# Lite Node

A lite node is a type of public Subtensor node that stores only limited blockchain data. The
official [Glossary: Lite Node](https://docs.learnbittensor.org/resources/glossary#lite-node)
describes it as a public Subtensor node that keeps limited blockchain data and relies on archive
nodes for full historical data.

## Why Limited Data Matters

Subtensor is the blockchain layer that records Bittensor transactions, stake, and emissions. A lite
node keeps a recent working set of chain data rather than the entire history, which lowers storage
needs while still supporting current chain interaction. The
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes) documentation frames lite nodes
as the lighter option for workloads that do not need deep historical lookups.

For readers, lite node names a node configuration choice about how much history is retained, not a
separate network or a validator role.

## Public Node Context

A lite node is one kind of
[public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor) access
point. Public Subtensor refers to publicly reachable chain access, and lite node describes the
limited-data variant of that access. Both sit on the connection side of Bittensor vocabulary rather
than the staking or consensus side.

This article does not describe node installation steps, hardware sizing, or endpoint URLs. Those
details belong in official node-operation references and live infrastructure data.

References: [Glossary: Lite Node](https://docs.learnbittensor.org/resources/glossary#lite-node),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)

## Relationship to Archive Node

A lite node and an archive node are related but describe different storage profiles for public
Subtensor nodes. A lite node stores limited blockchain data, while the
[Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node) describes
a node that stores the entire blockchain history for complete data access.

For readers, lite node names the lightweight option, while archive node names the full-history
option that lite nodes depend on when deeper history is needed.

References: [Glossary: Lite Node](https://docs.learnbittensor.org/resources/glossary#lite-node),
[Glossary: Archive Node](https://docs.learnbittensor.org/resources/glossary#archive-node)

## Relationship to Subtensor

A lite node and Subtensor are related but different scopes in Bittensor vocabulary. The
[Glossary: Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor) describes
Subtensor as Bittensor's blockchain layer and system of record, while a lite node is a node
configuration that serves a limited slice of that chain to clients.

For readers, Subtensor names the blockchain itself, while lite node names a lightweight way of
running and exposing access to that chain.

References: [Glossary: Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)

## Relationship to Mainchain

A lite node and the mainchain are related but different parts of network vocabulary. The
[Glossary: Mainchain](https://docs.learnbittensor.org/resources/glossary#mainchain) describes the
primary production Bittensor network, while a lite node is a node type that can serve limited data
from that network to readers and tools.

For readers, mainchain names which network is being served, while lite node names a lightweight way
of connecting to that network without storing its full history.

References: [Glossary: Mainchain](https://docs.learnbittensor.org/resources/glossary#mainchain),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)

## Reader Boundary

Lite node should not be read as a recommendation to run any particular node, as a hardware guide, or
as a public endpoint list. It is the concept term for a public Subtensor node that stores limited
Bittensor blockchain data and relies on archive nodes for full historical queries.
