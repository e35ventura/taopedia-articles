# Lite Node

A lite node is the storage-efficient form of a public subtensor node in Bittensor. The official
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes) documentation defines two
public subtensor node types — the lite node and the archive node — that differ in how much
blockchain history they retain. A lite node is the one that prioritizes a small storage footprint
and recent state over a complete historical record.

In Taopedia terms, a lite node names a node type, not a subnet role or a wallet concept. It belongs
to the same family as the public subtensor: a publicly accessible node synchronized with the
Bittensor network, distinct from a local blockchain used only for isolated development.

## Conceptual Role

The useful way to read lite node is as the lightweight end of a storage trade-off. A node that holds
the entire Bittensor blockchain, from the genesis block to the current block, needs substantial and
growing storage. The [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)
documentation introduces the lite node as the alternative that keeps storage requirements small
while still reaching a synchronized state.

For readers, the concept is about what the node type represents: a participant-side entry point into
the live Bittensor mainchain or testchain that does not carry the cost of storing full history. The
term names the trade-off, not a procedure for running a node.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Relationship to Archive Node

Lite node and archive node are the two named public subtensor node types, and they sit at opposite
ends of the storage-and-history trade-off. The
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes) documentation describes the
archive node as the type that stores the entire blockchain history, from genesis to the most recent
block, providing full state access for historical data.

For readers, the distinction is what each node type keeps. A lite node keeps recent finalized state
and offers limited historical access, while an archive node keeps the complete history. The same
documentation notes that reaching a synchronized state takes meaningfully different time and storage
between the two types, because the archive node processes the full chain and the lite node does not.

This makes the two terms a conceptual pair: lite node names recent-state access at low storage cost,
and archive node names full-history access at high storage cost. They are not different networks or
different chains — they are two ways of participating as a public subtensor node.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Historical Access Boundary

A lite node is not a source of deep historical data. The
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes) documentation recommends
using an archive node to retrieve blockchain data older than the previous 300 blocks, which places a
concrete boundary on what a lite node is expected to serve.

For readers, this keeps the lite node concept scoped. It is the node type for current chain state
and recent activity, not for analytics, audits, or queries against old blocks. Those use cases
belong to the archive node side of the pair.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Relationship to Public Subtensor

A lite node is one of the two forms a public subtensor node can take. The
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)
describes a public subtensor node as a publicly accessible node synchronized with the Bittensor
network, and the [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)
documentation identifies lite nodes and archive nodes as the two synchronization modes for such a
node.

For readers, public subtensor names the public-access concept, while lite node names the
storage-efficient form of it. A lite node can be associated with either the Bittensor mainchain or
the testchain, matching the public-access scope described for public subtensor nodes.

References:
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Distinct from a Neuron

A lite node, like any subtensor node, is not the same as a Bittensor neuron. The
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes) documentation emphasizes
that a subtensor node holds blockchain data, while a neuron is a subnet validator or subnet miner
that exists inside a subnet and does not hold the blockchain database.

For readers, this keeps two layers separate. A lite node is blockchain infrastructure — it stores
and serves chain state. A neuron is a subnet participant that the incentive mechanism evaluates. A
subnet miner may be associated with a lite node, but the miner and the node are different concepts
that should not be read as interchangeable.

References: [Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes)

## Reader Boundary

This article defines the lite node as a concept. It does not describe node-operation steps, hardware
requirements, synchronization commands, or current storage figures. Readers should use the official
subtensor node documentation for operational detail, requirements, and configuration.
