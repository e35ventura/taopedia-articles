# Max Locks

Max locks is a balances pallet runtime constant, listed in the chain's constants metadata as
maxLocks, with the value 50 and the summary "The maximum number of locks that should exist on an
account"
([Subtensor API Constants: maxLocks](https://docs.learnbittensor.org/subtensor-api/constants#maxlocks-u32)).
The trusted documentation adds that the value is not strictly enforced and is used for weight
estimation.

## What It Means

A balance lock restricts part of an account's balance from being used while the lock is in place.
Max locks names the number of such locks an account is expected to hold, set at 50, but the
documentation states this is not strictly enforced and instead informs weight estimation
([Subtensor API Constants: maxLocks](https://docs.learnbittensor.org/subtensor-api/constants#maxlocks-u32)).
The word "should" in its summary reflects that it is a planning figure rather than a hard failure
boundary: it guides how the runtime estimates weight, not a point at which an extra lock is
rejected. Because the figure feeds weight estimation, it represents the lock count the runtime plans
around rather than a limit an account is stopped at.

## Distinction from Max Reserves

Max locks and max reserves both carry the value 50 in the balances pallet, but they differ in how
firmly they apply. Max reserves is a strict cap: it bounds the number of named reserves an account
can hold, and exceeding it raises the TooManyReserves error
([Subtensor API Constants: maxReserves](https://docs.learnbittensor.org/subtensor-api/constants#maxreserves-u32),
[Subtensor API Errors: TooManyReserves](https://docs.learnbittensor.org/subtensor-api/errors#toomanyreserves)).
Max locks, by contrast, is not strictly enforced, so it is a guideline for locks rather than an
error-raising ceiling.

## Distinction from Max Freezes

The same contrast holds against max freezes, which also carries the value 50. Max freezes is
strictly enforced: exceeding the number of freeze locks on an account raises the TooManyFreezes
error
([Subtensor API Constants: maxFreezes](https://docs.learnbittensor.org/subtensor-api/constants#maxfreezes-u32),
[Subtensor API Errors: TooManyFreezes](https://docs.learnbittensor.org/subtensor-api/errors#toomanyfreezes)).
Max locks does not have an equivalent enforced error in the reference; it names the expected lock
count for weight estimation instead.

- **maxLocks** - 50; not strictly enforced, used for weight estimation.
- **maxReserves** - 50; strict cap, exceeding it raises TooManyReserves.
- **maxFreezes** - 50; strict cap, exceeding it raises TooManyFreezes.

## Reader Boundary

Max locks is a single network-wide constant, not a per-subnet value, and it reflects the current
runtime configuration rather than a fixed protocol rule; the value could change in a future runtime
upgrade. It names the expected lock count used for weight estimation and does not report how many
locks any specific account currently holds, which is live chain state
([Subtensor API Constants: maxLocks](https://docs.learnbittensor.org/subtensor-api/constants#maxlocks-u32)).
