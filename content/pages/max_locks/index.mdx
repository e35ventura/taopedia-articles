# Max Locks

Max locks is a balances pallet runtime constant, listed in the chain's constants metadata as
maxLocks, with the value 50 and the summary "The maximum number of locks that should exist on an
account"
([Subtensor API Constants: maxLocks](https://docs.learnbittensor.org/subtensor-api/constants#maxlocks-u32)).
It caps how many balance locks a single account may hold at one time.

## What It Means

A balance lock restricts part of an account's balance from being used, so that portion cannot be
freely spent while the lock is in place. Max locks sets the ceiling on how many such locks one
account may hold at the same time: up to 50
([Subtensor API Constants: maxLocks](https://docs.learnbittensor.org/subtensor-api/constants#maxlocks-u32)).
The value applies uniformly across accounts; it is not a per-subnet or configurable-per-account
setting.

## Distinction from Max Reserves

Max locks and max reserves are both per-account limits in the balances pallet, and both share the
value 50, but they bound different lists. Max reserves bounds the number of named reserves an
account can hold, and exceeding it raises the TooManyReserves error
([Subtensor API Constants: maxReserves](https://docs.learnbittensor.org/subtensor-api/constants#maxreserves-u32),
[Subtensor API Errors: TooManyReserves](https://docs.learnbittensor.org/subtensor-api/errors#toomanyreserves)).
Locks and named reserves are separate ways of restricting part of a balance, each with its own cap.

## Distinction from Max Freezes

Max locks also sits alongside max freezes, which likewise shares the value 50. Max freezes bounds
the number of individual freeze locks on an account, and exceeding it raises the TooManyFreezes
error
([Subtensor API Constants: maxFreezes](https://docs.learnbittensor.org/subtensor-api/constants#maxfreezes-u32),
[Subtensor API Errors: TooManyFreezes](https://docs.learnbittensor.org/subtensor-api/errors#toomanyfreezes)).
The three caps cover three separate per-account lists: locks, named reserves, and freezes.

- **maxLocks** - 50; the cap on balance locks.
- **maxReserves** - 50; exceeding it raises TooManyReserves.
- **maxFreezes** - 50; exceeding it raises TooManyFreezes.

## Distinction from Existential Deposit

Max locks and the existential deposit are both balances-pallet settings that touch an account, but
they concern different things. The existential deposit, valued at 500, is the minimum balance an
account must keep to stay open
([Subtensor API Constants: existentialDeposit](https://docs.learnbittensor.org/subtensor-api/constants#existentialdeposit-u64)).
Max locks is a count of how many locks an account may hold, not an amount of balance. One is a
minimum balance to remain active; the other is a limit on a per-account list.

## Reader Boundary

Max locks is a single network-wide constant, not a per-subnet value, and it reflects the current
runtime configuration rather than a fixed protocol rule; the value could change in a future runtime
upgrade. It caps how many locks an account may hold and does not report how many locks any specific
account currently has, which is live chain state
([Subtensor API Constants: maxLocks](https://docs.learnbittensor.org/subtensor-api/constants#maxlocks-u32)).
