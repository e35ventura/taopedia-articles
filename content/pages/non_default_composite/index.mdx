# Non Default Composite

`NonDefaultComposite` is a system pallet error raised when an account-removal operation is blocked
because the account's composite data is not at its default values. The API docs describe it as
"Suicide called when the account has non-default composite data"
([Subtensor API Errors: NonDefaultComposite](https://docs.learnbittensor.org/subtensor-api/errors#nondefaultcomposite)).

## What It Means

An account holds composite data that must be cleared before the account can be removed. When that
data has not been reduced to its default state, the removal is rejected. This is a composite-data
guard, not a balance check or a reference-count check
([Subtensor API Errors: NonDefaultComposite](https://docs.learnbittensor.org/subtensor-api/errors#nondefaultcomposite)).

## Distinction from Non Zero Ref Count

`NonDefaultComposite` and `NonZeroRefCount` are both system pallet errors that block account
removal, but they guard different conditions. `NonZeroRefCount` fires when the account's reference
count is non-zero. `NonDefaultComposite` fires when the account still holds non-default composite
data
([Subtensor API Errors: NonZeroRefCount](https://docs.learnbittensor.org/subtensor-api/errors#nonzerorefcount),
[Subtensor API Errors: NonDefaultComposite](https://docs.learnbittensor.org/subtensor-api/errors#nondefaultcomposite)).

- **NonZeroRefCount** — account's reference count is non-zero.
- **NonDefaultComposite** — account holds non-default composite data.

## Reader Boundary

This page defines the error label and the composite-data guard on the account-removal path. It does
not report an account's current composite state or describe how to clear that data
([Subtensor API Errors: NonDefaultComposite](https://docs.learnbittensor.org/subtensor-api/errors#nondefaultcomposite)).
