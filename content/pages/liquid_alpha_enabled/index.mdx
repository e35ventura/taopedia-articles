# Liquid Alpha Enabled

Liquid alpha enabled is a per-subnet hyperparameter, listed as `LiquidAlphaOn` in Bittensor
documentation, that switches the consensus-based weight feature on or off for a subnet. The
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters) reference
lists `LiquidAlphaOn` alongside the related `AlphaHigh` and `AlphaLow` parameters that configure the
liquid alpha range when the feature is active
([Consensus-based Weights](https://docs.learnbittensor.org/concepts/consensus-based-weights)).

The term names the enablement flag for liquid alpha. It is a boolean setting, not a numeric range
value. The `AlphaHigh` and `AlphaLow` parameters configure the numeric behavior of liquid alpha;
`LiquidAlphaOn` determines whether that behavior applies on the subnet at all.

## What It Controls

`LiquidAlphaOn` sets whether the liquid alpha feature is active on the subnet. When the flag is off,
the subnet uses a fixed alpha value for consensus weight behavior. When the flag is on, the subnet
uses the dynamic consensus-based weight mechanism configured by the `AlphaHigh` and `AlphaLow` range
([Consensus-based Weights](https://docs.learnbittensor.org/concepts/consensus-based-weights),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

The flag is set at the subnet level, so different subnets can have liquid alpha active or inactive
independently of each other. The active state for netuid 1 belongs to that subnet's hyperparameter
configuration and does not apply to other subnets.

## Relation to Alpha High and Alpha Low

`AlphaHigh` and `AlphaLow` set the upper and lower bounds of the dynamic alpha range that liquid
alpha uses to adjust consensus weight behavior. `LiquidAlphaOn` is the precondition: the `AlphaHigh`
and `AlphaLow` range is relevant only when `LiquidAlphaOn` is active for the subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Glossary: Alpha High](https://docs.learnbittensor.org/resources/glossary#alpha-high),
[Glossary: Alpha Low](https://docs.learnbittensor.org/resources/glossary#alpha-low)).

The three parameters belong to the same liquid alpha configuration group. The flag controls whether
the group applies; the range parameters configure the group's behavior when it does.

## Relation to Liquid Alpha

The [liquid alpha](https://docs.learnbittensor.org/concepts/consensus-based-weights) article
describes how consensus-based weights adjust validator bond behavior based on alignment over time.
`LiquidAlphaOn` is the hyperparameter that enables or disables that mechanism at the subnet level.

The feature and its enablement flag are separate concepts. The feature describes the mechanism; the
flag is the per-subnet switch that activates or deactivates it.

## Documented Type

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `LiquidAlphaOn` as a boolean subnet hyperparameter. Each subnet holds its own flag
state, so the enabled status on netuid 1 can differ from the status on another subnet.

The active value is per-subnet chain state. A flag reading from one subnet should not be treated as
evidence for the liquid alpha status of any other subnet.

## Network and Environment Scope

The [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks) reference
separates mainnet, testnet, and localnet environments. A liquid alpha enabled reading from one
environment is not evidence for the same flag state in another environment, because each network
holds independent subnet hyperparameter state.

On mainnet, `LiquidAlphaOn` is the live per-subnet flag that governs whether production consensus
weight behavior uses the liquid alpha mechanism for the selected netuid.

## Evidence Boundary

`LiquidAlphaOn` is an enablement flag. It does not name a specific alpha value, a consensus score,
or a validator bond amount. Those are results inside the consensus process; the flag is the
per-subnet switch that determines whether the liquid alpha mechanism is active
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Consensus-based Weights](https://docs.learnbittensor.org/concepts/consensus-based-weights)).

A claim about liquid alpha enabled should name the relevant subnet and its current flag state. The
flag value for netuid 1 is that subnet's own chain state.
