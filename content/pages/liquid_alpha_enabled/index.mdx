# Liquid Alpha Enabled

Liquid alpha enabled is a per-subnet hyperparameter, listed in the documentation as
`LiquidAlphaEnabled`, that turns on the
[liquid alpha](https://docs.learnbittensor.org/concepts/consensus-based-weights) feature for bond
smoothing. The reference describes it as enabling liquid alpha, with a default of false so subnets
use the ordinary bonds moving average path unless an owner opts in
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## What It Controls

The hyperparameter is the on-off switch for liquid alpha, not the alpha bounds themselves. When it
is enabled, validator-miner bond updates can use per-pair alignment-responsive smoothing instead of
the single subnet-wide smoothing factor from
[bonds moving average](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#bondsmovingaverage);
when it is disabled, bond smoothing follows the standard moving-average path
([Consensus-based Weights](https://docs.learnbittensor.org/concepts/consensus-based-weights),
[Yuma Consensus: Bonding mechanics](https://docs.learnbittensor.org/learn/yuma-consensus#bonding)).

Liquid alpha varies bond responsiveness by pair according to consensus alignment. Enabling the flag
activates that bond path on the selected netuid; it does not replace validator weight submission or
Yuma settlement itself ([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

The flag is owner-tunable per subnet, so netuid 1 can keep the default while another netuid enables
liquid alpha, and the live value is chain state rather than a network constant
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Documented Type and Default

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `LiquidAlphaEnabled` as a `Bool` with a default of false and marks the permission
required to change it as subnet owner
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

With the default off, bond smoothing uses the ordinary moving-average model unless an owner enables
liquid alpha for that netuid.

## Reading the Live Value for netuid 1

Liquid alpha enabled is per-subnet chain state, so any live claim is tied to a specific netuid. For
the documented example netuid 1 on Finney mainnet, the flag appears in that subnet's hyperparameter
table, which the reference describes under viewing a subnet's hyperparameters
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters)).
The infobox uses netuid 1 only as an example label; other subnets expose their own values
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from Liquid Alpha

Liquid alpha enabled is the per-subnet hyperparameter that turns the feature on. Liquid alpha is the
consensus-based bond-smoothing model itself — varying EMA response by validator-miner pair according
to alignment
([Consensus-based Weights](https://docs.learnbittensor.org/concepts/consensus-based-weights),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Liquid alpha enabled** — whether the per-pair liquid alpha path is active.
- **Liquid alpha** — the variable bond-smoothing model that runs when enabled.
