# Owner Hyperparam Rate Limit

Owner hyperparam rate limit is a per-subnet hyperparameter, listed in the documentation as
`OwnerHyperparamRateLimit`, that sets the minimum wait between subnet-owner hyperparameter changes.
The reference lists a default of two tempos, so owners cannot retune eligible settings every block
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## What It Controls

The hyperparameter governs how frequently a subnet owner may change owner-settable hyperparameters,
not which parameters exist or what values they may take. It is a cadence limit on configuration
updates rather than a limit on miner serving, weight commits, or registration burns
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Because the wait is counted in [tempos](https://docs.learnbittensor.org/resources/glossary#tempo)
rather than blocks, the same limit spans more wall-clock time on a subnet with a long tempo and less
on one with a short tempo. A subnet owner tuning other settings must account for both this limit and
the subnet's epoch length
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Glossary: Tempo](https://docs.learnbittensor.org/resources/glossary#tempo)).

It does not replace individual parameter semantics. Each hyperparameter still has its own meaning;
owner hyperparam rate limit only spaces out how often the owner may invoke those setters
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

The limit is owner-tunable per subnet, so netuid 1 can use the default while another netuid allows
faster or slower retuning, and the live value is chain state rather than a network constant
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Documented Type and Default

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `OwnerHyperparamRateLimit` as a `u16` with a default of two tempos and marks the
permission required to change it as subnet owner
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Because each subnet carries its own hyperparameters, the rate limit on one netuid can differ from
the documented default and from the limit on another subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Reading the Live Value for netuid 1

Owner hyperparam rate limit is per-subnet chain state, so any live claim is tied to a specific
netuid. For the documented example netuid 1 on Finney mainnet, the limit appears in that subnet's
hyperparameter table, which the reference describes under viewing a subnet's hyperparameters
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters)).
The infobox uses netuid 1 only as an example label; other subnets expose their own values
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from Weights Rate Limit

Weights rate limit bounds how soon a validator may submit weights again after a prior commit. Owner
hyperparam rate limit bounds how soon a subnet owner may change owner-settable hyperparameters again
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Weights rate limit** — minimum wait between validator weight commits.
- **Owner hyperparam rate limit** — minimum wait between owner hyperparameter updates.
