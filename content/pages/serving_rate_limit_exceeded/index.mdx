# Serving Rate Limit Exceeded

ServingRateLimitExceeded means a miner or validator tried to publish or refresh an axon or
prometheus endpoint before the subnet's serving rate limit had cleared since the last update. The
standard-errors reference describes it as "Rate limit exceeded for axon serve/publish"
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#servingratelimitexceeded)).

## What It Means

Subnet participants publish axon and prometheus endpoint information on-chain so other participants
can reach them. Each subnet applies the [[serving_rate_limit|Serving Rate Limit]] hyperparameter to
pace how often the same caller may update that serving information on a given netuid.
ServingRateLimitExceeded means the new serve call arrived before that wait had cleared, so the
endpoint update is rejected
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#servingratelimitexceeded),
[Subnet Hyperparameters: ServingRateLimit](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#servingratelimit)).

This is a serving pacing failure. It does not, by itself, mean the hotkey is unregistered on the
subnet, that the submitted IP address failed validation, or that the port field was zero.

## Why It Appears

This error appears when a participant retries an axon or prometheus endpoint update too soon on the
same subnet. That can happen when automation republishes serving metadata on a short loop, when a
client resubmits after a transient failure without checking the last successful serve block, or when
the subnet's serving rate limit is set higher than the operator expected
([Subnet Hyperparameters: ServingRateLimit](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#servingratelimit),
[Understanding Neurons](https://docs.learnbittensor.org/learn/neurons#neuron-to-neuron-communication)).

Readers can confirm the live serving rate limit for a subnet through the hyperparameter view before
retrying
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters)).

When debugging, compare against other serve-path rejections. [[invalid_ip_type|Invalid IP Type]] and
[[invalid_ip_address|Invalid IP Address]] mean the endpoint address failed validation.
[[invalid_port|Invalid Port]] means the submitted port was not usable. ServingRateLimitExceeded
means the endpoint payload may be acceptable, but the retry arrived too soon
([Subtensor Standard Errors: InvalidIpType](https://docs.learnbittensor.org/errors/subtensor#invalidiptype),
[Subtensor Standard Errors: InvalidIpAddress](https://docs.learnbittensor.org/errors/subtensor#invalidipaddress),
[Subtensor Standard Errors: InvalidPort](https://docs.learnbittensor.org/errors/subtensor#invalidport)).

The practical meaning is narrow: wait for the serving rate limit to clear, then retry.

## Distinction from Invalid Port

ServingRateLimitExceeded and [[invalid_port|Invalid Port]] both appear on axon and prometheus serve
failures, but they reject different problems. Invalid Port means the submitted port was not usable.
Serving Rate Limit Exceeded means the caller retried an endpoint update before the serving wait had
cleared
([Subtensor Standard Errors: InvalidPort](https://docs.learnbittensor.org/errors/subtensor#invalidport),
[Subtensor Standard Errors: ServingRateLimitExceeded](https://docs.learnbittensor.org/errors/subtensor#servingratelimitexceeded)).

## Distinction from Invalid IP Address

ServingRateLimitExceeded and [[invalid_ip_address|Invalid IP Address]] both block endpoint updates,
but for different reasons. Invalid IP Address means the encoded IP value failed address validation.
Serving Rate Limit Exceeded means the timing of the retry failed the subnet's serving pacing rule
([Subtensor Standard Errors: InvalidIpAddress](https://docs.learnbittensor.org/errors/subtensor#invalidipaddress),
[Subtensor Standard Errors: ServingRateLimitExceeded](https://docs.learnbittensor.org/errors/subtensor#servingratelimitexceeded)).

## Reader Boundary

This page defines the meaning of the error label and the serving pacing check it represents. It does
not report the live serving rate limit for a specific subnet or describe IP and port validation
rules; those depend on chain reads and separate error topics at submission time
([Subnet Hyperparameters: ServingRateLimit](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#servingratelimit),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
