Chutes is Bittensor Subnet 64, a serverless compute platform for AI. It lets developers run AI
applications — most commonly model inference — on GPU capacity supplied by the subnet's miners,
without renting or managing their own servers. The work is matched and paid through Bittensor:
miners supply compute, developers consume it, and the network rewards miners for the capacity they
provide. The platform's tooling is maintained in the
[chutesai/chutes](https://github.com/chutesai/chutes) repository.

## What the Subnet Provides

The subnet's product is on-demand AI compute. A developer brings an application, such as a hosted
language model, and Chutes runs it on whatever GPUs are available, starting and stopping capacity as
traffic rises and falls. For the end user this looks like a serverless endpoint: there is no fixed
server to provision, and usage is billed as it happens.

This makes Chutes a two-sided market. The supply side is GPU owners who want to earn for their
hardware; the demand side is developers and applications that need inference or other GPU workloads;
and Bittensor's incentive layer is what scores the supply and routes rewards to it.

## Runtime Model

The [Chutes README](https://raw.githubusercontent.com/chutesai/chutes/main/README.md) describes the
platform around three basic objects. An image is the container environment a workload runs on, a
chute is the application deployed on top of that image, and a cord is an individual callable
function inside the chute. This vocabulary matters because it separates the developer-facing
application from the miner-supplied GPU machine that actually runs it.

For readers, a chute is best understood as the unit of deployed work. A developer packages a model
or application into a chute, chooses the kind of GPU capacity it needs, and the platform places live
instances onto available miner hardware. The public [Chutes site](https://chutes.ai) presents the
same service from the user side: serverless AI compute where applications can run without a fixed
server owned by the developer.

That runtime model is why Chutes differs from a benchmark subnet. The useful output is not a single
answer returned to a validator. It is continuing service capacity: miners keep GPU machines
available, users send work to deployed chutes, and the platform has to match demand with hardware
that can run the application.

## Validation Context

The README also names GraVal as the graphics-card validation library used to check that the GPUs
miners claim to operate are authentic and correctly represented. It describes validation checks such
as device-information challenges, VRAM-capacity checks, matrix operations seeded by device
information, filesystem checks, and pings.

Those details explain the validator role at the article level without turning the page into an
operator guide. A validator is not just counting that a miner registered a machine; it needs
evidence that the advertised hardware exists and can serve real workloads. That validation layer is
what lets the subnet reward useful compute capacity instead of rewarding unverified claims about
compute capacity.

## Miner and Validator Roles

Miners contribute GPU machines that host and run the deployed applications. A miner's value to the
network comes from the real hardware it makes available and how reliably it serves the workloads
placed on it.

Validators score miners and keep the marketplace honest. A central concern for any compute network
is whether a miner is actually running the GPUs it claims, so Chutes has validators run authenticity
checks against miners' hardware in addition to observing how well they serve deployed applications.
Those validator scores become the weights that feed into [[Yuma Consensus]], which converts them
into the incentive split across miners and validators.

## On-Chain Identity

The live Finney identity for netuid 64 registers the subnet name as Chutes, with the description
"Breakthrough Serverless Compute for AI, At Scale." The registered project website is
[chutes.ai](https://chutes.ai) and the GitHub repository is
[chutesai/chutes](https://github.com/chutesai/chutes), which documents the platform and validation
behavior described above. Live subnet data is available on
[TaoStats](https://taostats.io/subnets/64).
