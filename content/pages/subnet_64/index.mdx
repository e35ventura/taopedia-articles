Chutes is Bittensor Subnet 64, a serverless compute platform for AI. It lets developers deploy
containerized applications — most commonly model inference endpoints — that run on GPU capacity
contributed by the subnet's miners, scaling up and down on demand rather than requiring a developer
to manage servers. The platform's command-line interface and development kit are maintained in the
[chutesai/chutes](https://github.com/chutesai/chutes) repository.

## What the Subnet Provides

The subnet's product is on-demand AI compute. Its model is built around a few concepts from the
repository: an image is a Docker image (with CUDA and Python) that applications run on; a chute is
an application that runs on top of an image, similar to a single web service; and a cord is an
individual function or endpoint within a chute. A developer packages a model or workload as a chute
and deploys it, and the platform runs it serverlessly on available GPUs, handling autoscaling and
billing.

This makes Chutes a supply-and-demand market: miners supply GPU capacity, developers deploy chutes
that consume it, and Bittensor's incentive layer scores the supply and routes rewards.

## Miner and Validator Roles

Miners contribute GPU nodes that host and execute chutes. Because the value of a miner depends on
the hardware it really provides, the platform needs a way to confirm that a miner's claimed GPUs are
genuine.

That is the role of GraVal, the GPU-validation component described in the repository: it runs as
middleware inside a chute to decrypt traffic from the validator and perform verification steps such
as device-info challenges and filesystem checks, helping ensure miners are running the GPUs they
claim. Validators use this verification, along with the running of deployed chutes, to score miners,
and those scores become the weights that feed into [[Yuma Consensus]], which converts them into the
incentive split across miners and validators.

## On-Chain Identity

Live SN64 data, including metagraph state and alpha token pool information, is available on
[TaoStats](https://taostats.io/subnets/64). Readers can reproduce the subnet's registered identity
fields with the Bittensor CLI command documented in the
[btcli reference](https://docs.learnbittensor.org/btcli/#btcli-subnets-get-identity):
`btcli subnets get-identity --netuid 64 --network finney`.

The Finney subnet identity for netuid 64 points to the
[chutesai/chutes](https://github.com/chutesai/chutes) repository, which is the source of truth for
the platform concepts and GPU-validation mechanism described above.
