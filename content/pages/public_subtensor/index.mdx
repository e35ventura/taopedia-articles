# Public Subtensor

Public Subtensor refers to publicly reachable access to the Bittensor chain layer. It is an access
context, not a separate blockchain. In plain terms, Public Subtensor is about reachability: public
access to Subtensor, while Subtensor itself remains the blockchain layer and system of record
([Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Glossary: Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)).

## What Public Subtensor Means

The public-access part of the term matters. Public Subtensor describes access to Subtensor through a
publicly reachable network context, while Subtensor itself names the Bittensor blockchain layer.
That chain layer is the shared record for Bittensor state
([Glossary: Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor)).

This distinction keeps the concept narrow. Public Subtensor does not rename the chain, create a new
runtime, or describe every node operation detail. It identifies the public-access context for
reaching the Subtensor chain layer.

That is why the term should stay close to access language. It can describe how the chain is reached,
but it should not be used as a shortcut for every Subtensor mechanism
([Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)).

## Network Context

Public Subtensor should be read with network context attached. Mainnet, testnet, and localnet are
different environments, so public access can expose shared network state only for the environment
being reached ([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

A public-access example from one environment should not be treated as a universal Bittensor fact.
The relevant network, endpoint context, queried state, and block context determine how strong a
statement can be.

A testnet public endpoint and a mainnet public endpoint can both be publicly reachable, but they do
not expose the same chain history. The network being reached still matters
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)).

## Public Access Versus Local Development

Public Subtensor is different from private local development context. The
[Glossary: Local Blockchain](https://docs.learnbittensor.org/resources/glossary#local-blockchain)
places local blockchain work in a private, isolated development setting. That local context can
demonstrate chain behavior, but it is not the same as publicly reachable Subtensor access.

The distinction is useful when reading examples. A local run can show how a mechanism behaves in an
isolated environment, while Public Subtensor describes access to shared chain context. Local
observations and public-network observations answer different questions.

A local blockchain can be useful for testing, but it is not public access to shared Bittensor chain
state. Public Subtensor is about the publicly reachable side of that distinction
([Glossary: Local Blockchain](https://docs.learnbittensor.org/resources/glossary#local-blockchain),
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)).

## Access Versus Mechanism

Public Subtensor names an access context, not a protocol mechanism. Through public access, an
observer can inspect chain state exposed by Subtensor, but the access context is not itself the
mechanism that creates that state.

For example, public access can expose state that belongs to staking, consensus, or emissions
contexts, but the access context does not produce those mechanisms. The relevant mechanism still
needs its own explanation
([Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Emissions](https://docs.learnbittensor.org/learn/emissions)).

## Concept Boundary

Public Subtensor does not provide endpoint recommendations, connection procedures, node-management
guidance, or private account diagnosis. It is a concept for public chain access
([Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)).

That boundary keeps the topic conceptual. Mechanism examples should still identify the relevant
network context, because public access on one Bittensor environment does not automatically represent
another environment
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

The stable article-level point is that Public Subtensor means publicly reachable access to the
Subtensor chain layer. It is not a new chain, a mechanism, an endpoint endorsement, or a local
development environment
([Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)).
