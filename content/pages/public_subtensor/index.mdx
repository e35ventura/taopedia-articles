# Public Subtensor

Public Subtensor refers to publicly reachable access to the Bittensor chain layer. It is an access
context, not a separate blockchain
([Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)).

## What It Represents

Public Subtensor names how observers reach shared
[Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor) chain state through a
publicly reachable network context. It is not the chain itself, a subnet participant role, or a
protocol mechanism that creates emissions or consensus outcomes.

Readers should separate four access ideas that sound similar:

- **Public Subtensor** — publicly reachable access to the Subtensor chain layer.
- **Subtensor** — the layer-one blockchain and system of record.
- **Chain read** — read-only inspection performed through an available access path.
- **Local blockchain** — private isolated development context, not publicly reachable shared access
  ([Glossary: Local Blockchain](https://docs.learnbittensor.org/resources/glossary#local-blockchain)).

Public access can expose readable chain state, but it does not make every chain action
permissionless. Permissionless reads and state-changing extrinsics follow different authority rules
([Bittensor CLI: Permissions Guide](https://docs.learnbittensor.org/btcli/btcli-permissions),
[Subtensor extrinsics](https://docs.learnbittensor.org/subtensor-api/extrinsics)). A reader can
query public chain data without wallet keys; moving balances, setting weights, or submitting other
signed actions still requires the appropriate coldkey or hotkey material.

Public access also does not substitute for mechanism documentation. A public endpoint may expose
state affected by coinbase or consensus processes, but the access path does not produce emissions or
replace mechanism references
([Coinbase Implementation](https://docs.learnbittensor.org/navigating-subtensor/emissions-coinbase)).

When using public-access evidence, keep the layers separate:

- **Public access** — how the chain was reached.
- **Storage query** — which readable state surface was inspected.
- **Event record** — what runtime activity was emitted.
- **Extrinsic surface** — what runtime action was submitted.
- **Network context** — which environment supplied the observation.

A storage read through public access can support a statement about observed chain state on that
network. It does not by itself prove signing authority, mechanism behavior on another network, or
future endpoint availability
([Subtensor Storage](https://docs.learnbittensor.org/subtensor-api/storage),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

Public chain access on testnet does not describe mainnet state. Localnet chain access is isolated
rather than publicly reachable shared access.

## Distinction from Subtensor

- **Subtensor** — layer-one blockchain and system of record.
- **Public Subtensor** — publicly reachable access to that chain layer.

## Distinction from Mainchain

- **Mainchain** — Bittensor's primary production network context.
- **Public Subtensor** — publicly reachable access surface to the Subtensor chain layer.

## Distinction from Chain Reads

- **Public Subtensor** — where the chain is reached publicly.
- **Chain read** — read-only inspection performed through that access path.

## Distinction from Network

- **Public Subtensor** — publicly reachable chain-layer access vocabulary.
- **Network** — environment selector such as mainnet, testnet, or localnet for the observation.

## Reader Boundary

Public Subtensor should not be read as private key access, wallet custody, endpoint-operator
guarantees, or connection procedures. It names publicly reachable chain-layer access vocabulary
([Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)).
