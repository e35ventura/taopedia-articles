# Public Subtensor

Public Subtensor refers to publicly reachable Bittensor chain access. Official Bittensor
documentation uses Subtensor to describe the blockchain layer that supports Bittensor network state.

References:
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Subtensor](https://docs.learnbittensor.org/subtensor-nodes)

## Network Context

The term is useful when distinguishing public chain access from local development context. Public
Subtensor belongs to the live network side of that distinction, while local blockchain context is
private and development-oriented.

References:
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)

## Relationship to Subtensor

Public Subtensor and Subtensor are related but name different layers of the same picture. The
[Glossary: Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor) describes
Bittensor's layer 1 blockchain and the system of record for transactions and rankings, while the
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)
describes publicly reachable access to that chain layer.

For readers, Subtensor is the chain layer itself, while Public Subtensor names live public access to
it. The term does not rename Subtensor and should not be read as a separate blockchain.

References: [Glossary: Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor),
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)

## Relationship to Local Blockchain

Public Subtensor and local blockchain name opposite sides of Bittensor chain access. The
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)
describes publicly reachable chain access, while the
[Glossary: Local Blockchain](https://docs.learnbittensor.org/resources/glossary#local-blockchain)
describes a private chain used for development and testing.

For readers, Public Subtensor belongs to live network access context, while local blockchain belongs
to isolated development context. The two terms should not be read as interchangeable network labels.

References:
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Glossary: Local Blockchain](https://docs.learnbittensor.org/resources/glossary#local-blockchain)

## Relationship to Bittensor Networks

Public Subtensor and Bittensor Networks name related but different parts of live chain context. The
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks) reference groups
mainnet, testnet, and localnet, while the
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)
describes publicly reachable access to the Subtensor chain layer.

For readers, Bittensor Networks is the environment label, while Public Subtensor names public access
to Subtensor inside mainnet and testnet context. It does not describe private local blockchain
development.

References: [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)

## Public Access Scope

Public Subtensor should be read as public access to the Subtensor chain layer, not as a separate
blockchain. The official Subtensor Nodes page describes a public subtensor node as synchronizing
with the Bittensor network and says it can connect with either the Bittensor mainchain or the
testchain. That makes the term an access-context label: it describes how chain data can be reached,
not a new protocol layer.

This distinction keeps the article precise. A public Subtensor access point can expose chain state
for reading or interaction, but the underlying records still belong to the selected Bittensor
network context. A claim about Public Subtensor should therefore say whether it is discussing public
access, the chain layer itself, or the network being inspected.

References: [Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes),
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)

## Mainchain, Testchain, and Network Context

Public Subtensor should not be collapsed into Mainchain. Mainchain is the production chain context,
while Public Subtensor names publicly reachable access that can be connected to mainchain or
testchain according to the official node documentation. Those are related ideas, but they answer
different questions.

The Bittensor Networks documentation gives the broader environment framing around mainnet, testnet,
and localnet. A public access claim should keep that environment label visible. A mainnet
observation, a testnet observation, and a local development observation should not be presented as
the same public chain fact just because each can involve Subtensor vocabulary.

References: [Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)

## Evidence and Query Context

Public Subtensor matters to readers because public chain access can support source-backed claims
about chain-visible data. The official chain-inspection guide describes using Polkadot.js to connect
to Subtensor in order to query chain state, submit extrinsics, and inspect runtime metadata. For a
reference article, the safe evidence point is the read side: public access can help verify what the
selected network exposes as public state.

That evidence still has scope. A query result is tied to the selected network and moment in chain
history. It does not explain every cause behind the value, and it does not prove the same value is
present on another environment. Public Subtensor can make evidence reachable; it does not remove the
need to name the context being inspected.

References:
[Inspecting the Chain with Polkadot.js](https://docs.learnbittensor.org/concepts/inspecting-the-chain),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)

## Access Versus Authority

Public access is not the same as authority to change chain state. A reader can inspect public
Subtensor data without that read automatically moving funds, registering a participant, changing
stake, or voting. The official fee documentation separates free chain reads from state-changing
activity, and the chain-inspection guide separately names querying state and submitting extrinsics.

This boundary is important for wallet and tooling topics. Public Subtensor can be the access path
through which chain state is observed, but submitted actions still have their own signing, fee,
role, and outcome rules. Articles should not treat "publicly reachable" as meaning "permissionless
to change."

References: [Transaction Fees in Bittensor](https://docs.learnbittensor.org/learn/fees),
[Inspecting the Chain with Polkadot.js](https://docs.learnbittensor.org/concepts/inspecting-the-chain)

## Node-Operation Boundary

The Subtensor Nodes documentation includes operational material about running public subtensor
nodes. That material is useful as a source for the concept, but this article should not duplicate
setup steps, endpoint choices, command examples, or sync-mode instructions. Those details can change
and belong in the current official node documentation.

For Taopedia readers, the stable concept is narrower: Public Subtensor names public reachability to
Subtensor chain access in a mainchain or testchain context. Operational choices such as node type,
connection endpoint, and deployment method are implementation details around that access, not the
definition of the term.

Reference: [Subtensor Nodes](https://docs.learnbittensor.org/subtensor-nodes)

## Reader Boundary

This page defines the term and explains how to interpret public access claims. It does not provide
endpoint recommendations, connection steps, setup commands, or node-operation guidance. Readers
should use current official Bittensor documentation when they need operational details.
