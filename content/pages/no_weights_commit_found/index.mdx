# No Weights Commit Found

`NoWeightsCommitFound` means a reveal weight extrinsic arrived, but the chain could not find a
matching stored commit for that hotkey and netuid. The standard-errors reference describes it as "No
commit found for hotkey+netuid combination"
([Subtensor Standard Errors](https://docs.learnbittensor.org/subtensor-api/errors#noweightscommitfound)).

Commit-reveal submission is scoped per hotkey and subnet: a reveal must pair with a pending commit
stored for the same caller on the same netuid
([Commit-Reveal](https://docs.learnbittensor.org/concepts/commit-reveal)).

## What It Means

[Commit-reveal](https://docs.learnbittensor.org/concepts/commit-reveal) weight submission happens in
two steps: a commitment first, then a later reveal that must match a stored pending commit for the
same hotkey and subnet. `NoWeightsCommitFound` means the reveal step did not find such a stored
commit, so the chain rejected the reveal instead of applying weights
([Subtensor Standard Errors](https://docs.learnbittensor.org/subtensor-api/errors#noweightscommitfound)).

This error is raised on the reveal side after commit-reveal is enabled for the target netuid. The
chain looked in the active pending-commit queue for that hotkey and netuid and found nothing usable
to consume — not because the scheme is off or because the reveal arrived before its window opened.

## Why It Appears

This error appears on the reveal side, not the commit side. The reveal call reached the point where
the chain looked for a prior stored commit, but there was nothing usable to reveal for that hotkey,
subnet, and provided commitment hash
([Subtensor Standard Errors](https://docs.learnbittensor.org/subtensor-api/errors#noweightscommitfound)).

When debugging, confirm the commit extrinsic succeeded for the same hotkey and netuid before chasing
reveal timing. Then rule out extrinsic-family and timing errors: `CommitRevealDisabled` means
commit-reveal is off on that netuid, while `RevealTooEarly` means a matching commit may exist but
the reveal window has not opened yet
([Subtensor Standard Errors: CommitRevealDisabled](https://docs.learnbittensor.org/subtensor-api/errors#commitrevealdisabled),
[Subtensor Standard Errors: RevealTooEarly](https://docs.learnbittensor.org/subtensor-api/errors#revealtooearly)).

The practical meaning is narrow: there is no matching active commit available for this reveal to
consume. The problem is not that commit-reveal is disabled or that the reveal simply arrived too
early.

## Distinction from Expired Weight Commit

`NoWeightsCommitFound` and `ExpiredWeightCommit` are both reveal-side failures, but they reject
different states of the commit queue. `ExpiredWeightCommit` means a matching commit existed but had
already aged out into the expired set before the reveal was processed. `NoWeightsCommitFound` means
the reveal does not have a matching active stored commit to use
([Subtensor Standard Errors: ExpiredWeightCommit](https://docs.learnbittensor.org/subtensor-api/errors#expiredweightcommit)).

- **ExpiredWeightCommit** — the matching commit existed, but it had already expired.
- **NoWeightsCommitFound** — there is no matching active stored commit for the reveal.

## Distinction from Commit Reveal Disabled

`NoWeightsCommitFound` and `CommitRevealDisabled` both appear in commit-reveal troubleshooting, but
they reject different stages. `CommitRevealDisabled` blocks the commit-reveal path before any stored
commit lookup runs because the scheme is off on that network. `NoWeightsCommitFound` means
commit-reveal is active and the reveal step could not find a matching stored commit
([Subtensor Standard Errors: CommitRevealDisabled](https://docs.learnbittensor.org/subtensor-api/errors#commitrevealdisabled)).

- **CommitRevealDisabled** — the network has not enabled commit-reveal.
- **NoWeightsCommitFound** — commit-reveal is enabled, but no matching stored commit exists.

## Reader Boundary

This page defines the meaning of the error label and the missing-commit condition that raises it. It
does not describe the full commit-reveal lifecycle, how reveal timing windows are computed, or how
expired commits are pruned; those are separate checks and separate topics
([Commit-Reveal](https://docs.learnbittensor.org/concepts/commit-reveal)).
