# Stake Threshold

Stake threshold is a hyperparameter, listed in the documentation as `StakeThreshold`, that sets the
minimum stake weight a neuron must hold before it is eligible to validate on a subnet. The reference
describes it as the minimum stake required for validating, with a current value of 1000, set through
the `sudo_set_stake_threshold` extrinsic at root permission
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## What It Controls

The threshold is applied during the epoch as a filter on validator-permit candidates. The epoch
reads the stake threshold and zeroes out any hotkey whose stake weight falls below it, so neurons
under the threshold are excluded from the permit selection before ranking
([Yuma Consensus Epoch](https://docs.learnbittensor.org/navigating-subtensor/epoch),
[Validator Permit](https://docs.learnbittensor.org/validators)).

Meeting the threshold is necessary but not sufficient. After the below-threshold stakes are filtered
out, the top neurons by stake weight, typically the top 64, receive the permits; a neuron can clear
the threshold and still miss a permit if it does not rank highly enough
([Validator Permit](https://docs.learnbittensor.org/validators),
[Yuma Consensus Epoch](https://docs.learnbittensor.org/navigating-subtensor/epoch)).

The value is measured in stake weight, which the validator documentation defines as a hotkey's alpha
stake plus its TAO stake scaled by the `tao_weight` parameter. So the threshold compares against
that combined figure rather than raw TAO alone
([Validating in Bittensor](https://docs.learnbittensor.org/validators)).

## Why It Matters

Because permits are recalculated every epoch from the current stake distribution, the threshold acts
as a per-epoch floor that filters out low-commitment participants before the top-K ranking runs. It
keeps neurons with negligible stake weight out of the validator set even when permit slots are
available ([Yuma Consensus Epoch](https://docs.learnbittensor.org/navigating-subtensor/epoch),
[Understanding Neurons](https://docs.learnbittensor.org/learn/neurons)).

Only neurons that hold a permit can set non-self weights and take part in consensus, so the
threshold sits at the boundary between merely being registered and being able to validate
([Understanding Neurons](https://docs.learnbittensor.org/learn/neurons)).

## Documented Default and Setter

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `StakeThreshold` with a default of 1000 and notes it is changed through the
`sudo_set_stake_threshold` extrinsic at root permission
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

The epoch implementation reads this value with a stake-threshold getter and uses it as the minimum
stake comparison when filtering permit candidates, matching the documented minimum of 1000 stake
weight ([Yuma Consensus Epoch](https://docs.learnbittensor.org/navigating-subtensor/epoch)).

## Reading the Live Value for netuid 1

Permit selection runs per subnet, so any live claim is tied to a specific netuid. For the documented
example netuid 1 on Finney mainnet, the threshold and the resulting permit set are observed through
that subnet's hyperparameters and metagraph, which the references describe under viewing a subnet's
hyperparameters and validator requirements
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters),
[Validating in Bittensor](https://docs.learnbittensor.org/validators)). The infobox uses netuid 1
only as an example label; other subnets apply the same rule to their own stake distributions
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from Max Validators

Max validators caps how many validators a subnet allows. Stake threshold sets the minimum stake
weight a neuron needs to enter the permit candidate pool in the first place, so the two act at
different stages of permit selection
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Validating in Bittensor](https://docs.learnbittensor.org/validators)).

- **Stake threshold** — minimum stake weight to be considered for a permit.
- **Max validators** — ceiling on how many permits the subnet issues.
