# Alpha Injection

Alpha injection is the act of moving TAO into a subnet's reserve so the subnet's alpha token supply
increases through the on-chain reserve mechanism. It is the input side of the subnet's reserve
ratio, paired against alpha emission as the output side
([Glossary: ADR (Alpha Distribution Ratio)](https://docs.learnbittensor.org/resources/glossary#adr-alpha-distribution-ratio),
[Emissions](https://docs.learnbittensor.org/learn/emissions)).

The term belongs to subnet tokenomics because each subnet maintains its own alpha supply, and that
supply grows through reserve injection rather than through direct minting
([Alpha Reserve](https://docs.learnbittensor.org/concepts/alpha-reserve),
[Dynamic TAO](https://docs.learnbittensor.org/learn/dynamic-tao)).

## What the Injection Identifies

Alpha injection identifies the TAO-side event that adds alpha to a subnet. It does not describe the
alpha emission path; it names the reserve-deposit event that grows the subnet's alpha supply
([Glossary: ADR (Alpha Distribution Ratio)](https://docs.learnbittensor.org/resources/glossary#adr-alpha-distribution-ratio),
[Glossary: Alpha Reserve](https://docs.learnbittensor.org/resources/glossary#alpha-reserve)).

That keeps the supply-growth event separate from the per-block emission path. A reader can talk
about reserve-driven alpha additions without also describing the validator-and-miner emission
outcome for the same period.

The injection event is also what gives the Alpha Distribution Ratio its denominator. ADR compares
emissions to injections, so the ratio depends on a clear definition of what counts as an injection
([Glossary: ADR (Alpha Distribution Ratio)](https://docs.learnbittensor.org/resources/glossary#adr-alpha-distribution-ratio)).

## Relationship To Reserve Ratio

The subnet's reserve ratio is the on-chain ratio between TAO and alpha inside the subnet's reserve.
Alpha injection is the action that changes the TAO side of that ratio, and the resulting swap math
changes the alpha side
([Glossary: Alpha Reserve](https://docs.learnbittensor.org/resources/glossary#alpha-reserve),
[Dynamic TAO](https://docs.learnbittensor.org/learn/dynamic-tao)).

This keeps injection and reserve ratio as separate concepts that still travel together. The ratio is
the observable state; the injection is the action that moves the state toward a new ratio.

A reader can therefore describe a subnet's reserve state by walking from an injection event to the
new reserve ratio. The injection identifies the supply event; the ratio names the post-event reserve
state.

## Relationship To Alpha Emission

Alpha emission is the output side of subnet tokenomics. Alpha injection is the input side. ADR
compares the two so that subnet tokenomics can be evaluated on both supply directions
([Glossary: ADR (Alpha Distribution Ratio)](https://docs.learnbittensor.org/resources/glossary#adr-alpha-distribution-ratio),
[Glossary: Emissions](https://docs.learnbittensor.org/learn/emissions)).

That pairing keeps the alpha supply model symmetric. Without the injection side, a description of
alpha supply would only describe what miners and validators receive, not what the reserve absorbs
from incoming TAO.

The injection side is what makes the Alpha Distribution Ratio meaningful as a liquidity-pressure
signal. The ratio is only interpretable when both the input (injection) and the output (emission)
are tracked separately
([Glossary: ADR (Alpha Distribution Ratio)](https://docs.learnbittensor.org/resources/glossary#adr-alpha-distribution-ratio)).

## Relationship To Alpha Outstanding

Alpha outstanding describes subnet alpha held outside the reserve pool. Alpha injection adds alpha
to the reserve; subsequent transfers and emissions can move some of that alpha outside the reserve
over time
([Glossary: Alpha Outstanding](https://docs.learnbittensor.org/resources/glossary#alpha-outstanding),
[Glossary: Alpha Reserve](https://docs.learnbittensor.org/resources/glossary#alpha-reserve)).

This keeps injection on the reserve side of the accounting split. The injection event is what
creates the alpha that can later be classified as outstanding once it leaves the reserve.

That relationship also keeps reserve accounting layered. A claim about injection is about a reserve
event; a claim about outstanding alpha is about where reserve alpha has moved afterward.

## Subnet-Specific Scope

Alpha injection is a per-subnet concept. Two Bittensor subnets can share the same reserve-ratio
vocabulary while experiencing different injection volumes, so the injection travels with the subnet
identity rather than with the network
([Dynamic TAO](https://docs.learnbittensor.org/learn/dynamic-tao),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

That means a claim about alpha injection needs the subnet attached. An injection recorded for one
subnet is not automatically an injection for another subnet, even when both subnets use similar
Dynamic TAO mechanics.

## Reading Alpha Injection

Alpha injection is subnet reserve-input terminology. It is not the alpha emission event, not the
Alpha Distribution Ratio outcome, and not a description of any single miner's or validator's reward
path
([Glossary: ADR (Alpha Distribution Ratio)](https://docs.learnbittensor.org/resources/glossary#adr-alpha-distribution-ratio),
[Glossary: Alpha Reserve](https://docs.learnbittensor.org/resources/glossary#alpha-reserve),
[Glossary: Emissions](https://docs.learnbittensor.org/learn/emissions)).

The stable reference point is that alpha injection names the TAO-side reserve event that grows a
subnet's alpha token supply.
