# Objective Function

An objective function is the goal a Bittensor subnet continuously works toward. The official
[Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function)
describes it, in the context of machine learning and subnet operations, as the goal that a subnet is
continuously optimizing for through its incentive mechanism.

## Why the Goal Framing Matters

Every subnet exists to produce some kind of useful output. An objective function names that intended
result in optimization language: it is the target the subnet steers toward over time. The
[Anatomy of an Incentive Mechanism](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)
documentation frames subnet design as choosing what to optimize for and then rewarding work that
advances it.

For readers, objective function is a conceptual lens, not a setting. It describes what a subnet is
trying to achieve rather than naming a value to configure.

## Relationship to Incentive Mechanism

An objective function and an incentive mechanism describe the goal and the means of reaching it. The
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)
describes the mechanism that connects subnet work, validator evaluation, and emission outcomes,
while an objective function names the goal that mechanism is built to pursue.

For readers, objective function names the destination, while incentive mechanism names the reward
machinery the subnet uses to move toward it.

References:
[Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function),
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)

## Relationship to Loss Function

An objective function and a loss function are closely related framings of subnet optimization. An
objective function names the goal a subnet optimizes for, while the
[Glossary: Loss Function](https://docs.learnbittensor.org/resources/glossary#loss-function)
describes the measure of how far current output sits from the desired result that optimization works
to reduce.

For readers, objective function names what success looks like, while loss function names the
gap-from-success measure that drives miners toward that objective.

References:
[Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function),
[Glossary: Loss Function](https://docs.learnbittensor.org/resources/glossary#loss-function)

## Relationship to Subnet Scoring Model

An objective function and a subnet scoring model connect a subnet's goal to its evaluation. The
[Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)
describes how validators evaluate miner responses inside a subnet, while an objective function names
the goal that scoring is meant to advance.

For readers, objective function names what the subnet wants, while subnet scoring model names the
concrete procedure validators use to reward work that serves that goal.

References:
[Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function),
[Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)

## Reader Boundary

Objective function should not be read as a configurable subnet parameter, a specific formula for any
one subnet, or a ranking of subnets. It is a concept term for the goal a Bittensor subnet
continuously optimizes for through its incentive mechanism.
