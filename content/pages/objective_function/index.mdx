# Objective Function

An objective function describes the target a system is trying to optimize. In Bittensor subnet
context, the term helps explain what a subnet's evaluation process is meant to reward, such as
better task performance under the subnet's incentive mechanism.

References:
[Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)

## Subnet Mechanism Context

Bittensor subnets can define their own tasks and incentive mechanisms. The objective function is a
way to talk about the desired result of that evaluation without assuming that every subnet measures
the same kind of work. One subnet may reward one form of performance while another subnet optimizes
for a different task.

Reference:
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)

## Relationship to Incentives

An objective function is not the reward payment itself. It is the target that helps shape how work
is evaluated. Incentive mechanisms then connect that evaluation to weights, rankings, and emission
outcomes inside the subnet's broader reward process.

References:
[Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function),
[Yuma Consensus](https://docs.learnbittensor.org/yuma-consensus/)

## Reader Boundary

This page defines the term at a high level. It does not specify the objective function of any live
subnet or recommend one design. Subnet-specific mechanisms can change and should be checked from the
subnet's current documentation or source material.
