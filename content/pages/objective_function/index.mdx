# Objective Function

An objective function names the optimization goal that a Bittensor subnet's incentive mechanism is
continuously steering miner work toward. The objective function is the abstract target; the
incentive mechanism is the rule set that translates miner output into progress against that target
([Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

The term belongs to subnet design vocabulary because each subnet picks its own optimization target,
and that choice shapes what useful miner output looks like inside the subnet
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

## What the Objective Function Identifies

The objective function identifies the kind of improvement the subnet is trying to produce. It does
not describe the evaluation procedure itself; it names what the evaluation procedure is trying to
drive
([Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function),
[Anatomy of Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

This keeps the abstract goal separate from any single scoring or weighting step. A reader can name
the subnet's goal without committing to a particular scoring formula, validator arrangement, or
reward arithmetic.

That separation also lets a subnet keep a stable objective while its mechanism details change. The
goal the subnet is optimizing for can persist even when the exact incentive-mechanism implementation
is revised over time
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

## Relationship To Incentive Mechanism

The objective function is what an incentive mechanism is trying to advance. The mechanism supplies
the evaluation rule set; the objective function names the direction that rule set is pushing miner
work
([Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function),
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)).

That pairing is what makes incentive mechanisms meaningful in a Bittensor subnet. Without a named
objective, an evaluation rule set would only describe how work is judged, not what the subnet is
trying to improve. The objective function supplies the "toward what" that the mechanism's evaluation
answers.

The objective and the mechanism therefore travel together when describing a subnet's design. A claim
about one without the other leaves part of the subnet's purpose unstated.

## Relationship To Subnet Task

The subnet task describes the work miners are asked to perform. The objective function describes why
that work is being requested — what kind of improvement the subnet expects from well-performed miner
output ([Glossary: Subnet Task](https://docs.learnbittensor.org/resources/glossary#subnet-task),
[Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function)).

That makes the task and the objective complementary. The task names the requested work; the
objective names the optimization direction the work is meant to advance.

This pairing also keeps subnet descriptions from collapsing into either pure task language or pure
optimization language. The task is concrete output; the objective is the direction that output is
meant to move.

## Relationship To Scoring

The subnet scoring model evaluates returned miner work. The objective function describes what kind
of improvement that scoring is meant to track
([Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model),
[Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function)).

This makes the scoring model a measurement instrument relative to the objective function. The
scoring model reports how well miner output advances the objective; the objective names what
"better" means inside that measurement.

A reader can therefore describe a subnet's evaluation by walking from the objective (what is being
improved) to the scoring model (how improvement is measured) to the incentive mechanism (how
measurement is connected to rewards).

## Subnet-Specific Scope

The objective function is a per-subnet concept. Two Bittensor subnets can share the same
incentive-mechanism vocabulary while pursuing different objectives, so the objective travels with
the subnet identity rather than with the network
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

That means a claim about an objective function needs the subnet attached. The objective is one
subnet's optimization target; it does not automatically describe the goals of another subnet, even
when both subnets use similar incentive mechanism designs.

## Reading Objective Functions

An objective function is subnet optimization terminology. It is not the subnet task, the scoring
model, the incentive mechanism, or a description of any one miner's output
([Glossary: Objective Function](https://docs.learnbittensor.org/resources/glossary#objective-function),
[Glossary: Subnet Task](https://docs.learnbittensor.org/resources/glossary#subnet-task),
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)).

The stable reference point is that an objective function names the optimization goal a Bittensor
subnet's incentive mechanism is steering miner work toward.
