# Max Storage Key Len

Max storage key len is a contracts pallet runtime constant, listed in the chain's constants metadata
as maxStorageKeyLen, with the value 128 and the summary "The maximum allowable length in bytes for
storage keys"
([Subtensor API Constants: maxStorageKeyLen](https://docs.learnbittensor.org/subtensor-api/constants#maxstoragekeylen-u32)).
It caps how many bytes a single contract storage key may be.

## What It Means

A contract stores values under keys, and each key is a sequence of bytes that identifies where a
value is kept. Max storage key len sets the ceiling on how long one of those keys may be: at most
128 bytes
([Subtensor API Constants: maxStorageKeyLen](https://docs.learnbittensor.org/subtensor-api/constants#maxstoragekeylen-u32)).
A key longer than 128 bytes is not within the allowed length. The limit is a fixed byte length, not
a limit on how many keys a contract may use.

## Distinction from Max Code Len

Max storage key len and max code len are both byte-length limits in the contracts pallet, but they
bound different things. Max storage key len caps the length of a storage key at 128 bytes, while max
code len caps the length of a contract's code at 131072 bytes
([Subtensor API Constants: maxCodeLen](https://docs.learnbittensor.org/subtensor-api/constants#maxcodelen-u32)).
One limits the identifier used to store a value; the other limits the size of the contract program
itself. They apply to separate parts of a contract.

## Why a Key-Length Limit Exists

Fixing a maximum key length means every storage key stays within a known size rather than being of
unbounded length. With the cap at 128 bytes, the largest a single key can be is fixed in advance
([Subtensor API Constants: maxStorageKeyLen](https://docs.learnbittensor.org/subtensor-api/constants#maxstoragekeylen-u32)).
The limit describes the size of the key, and is separate from the size of the value stored under it.

## Distinction from Max Transient Storage Size

Max storage key len and max transient storage size are both byte limits in the contracts pallet, but
they measure different things. Max storage key len caps the length of a single storage key at 128
bytes, while max transient storage size caps the total transient storage at 1048576 bytes
([Subtensor API Constants: maxTransientStorageSize](https://docs.learnbittensor.org/subtensor-api/constants#maxtransientstoragesize-u32)).
One is the length of an individual key; the other is the overall size of a storage area. They bound
different quantities and are set independently.

## One of Several Contracts Size Limits

The contracts pallet defines several fixed size limits, and max storage key len is the one that
governs key length. It sits alongside limits such as the maximum contract code length and the
maximum transient storage size, each of which bounds a different part of a contract
([Subtensor API Constants: maxCodeLen](https://docs.learnbittensor.org/subtensor-api/constants#maxcodelen-u32)).
Reading max storage key len on its own tells a reader only about the length allowed for a key, not
about those other bounds.

## Reader Boundary

Max storage key len is a single network-wide constant, not a per-subnet value, and it reflects the
current runtime configuration rather than a fixed protocol rule; the value could change in a future
runtime upgrade. It caps the byte length of a storage key and does not describe how many keys a
contract may hold or how large the stored values may be
([Subtensor API Constants: maxStorageKeyLen](https://docs.learnbittensor.org/subtensor-api/constants#maxstoragekeylen-u32)).
