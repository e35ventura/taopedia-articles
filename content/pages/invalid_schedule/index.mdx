# Invalid Schedule

`InvalidSchedule` is a contracts pallet error raised when an invalid schedule is supplied. The API
errors reference summarizes it as "Invalid schedule supplied, e.g. with zero weight of a basic
operation"
([Subtensor API Errors: InvalidSchedule](https://docs.learnbittensor.org/subtensor-api/errors#invalidschedule)).

## What It Means

Bittensor runs an Ethereum-compatible execution layer on Subtensor for smart contracts
([Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials)). The contracts
pallet uses a schedule to define limits and weights for basic operations such as instantiation and
nested calls. `InvalidSchedule` means the submitted schedule fails that validation, so the runtime
rejects it before the schedule can be applied
([Subtensor API Errors: InvalidSchedule](https://docs.learnbittensor.org/subtensor-api/errors#invalidschedule)).

This is a schedule-validation rejection. It does not, by itself, mean nested call depth reached the
schedule limit during execution, that instantiate code exceeded a size limit, or that execution
exhausted its gas limit.

## Why It Appears

This error appears when a contracts operation supplies a schedule the runtime treats as invalid,
such as one with zero weight for a basic operation
([Subtensor API Errors: InvalidSchedule](https://docs.learnbittensor.org/subtensor-api/errors#invalidschedule)).

## Distinction from Max Call Depth Reached

`InvalidSchedule` and `MaxCallDepthReached` both involve the contracts schedule, but at different
stages. `InvalidSchedule` means the supplied schedule itself is invalid. `MaxCallDepthReached` means
execution was denied because nested call depth reached the limit already specified in the schedule
([Subtensor API Errors: MaxCallDepthReached](https://docs.learnbittensor.org/subtensor-api/errors#maxcalldepthreached),
[Subtensor API Errors: InvalidSchedule](https://docs.learnbittensor.org/subtensor-api/errors#invalidschedule)).

- **InvalidSchedule** — the supplied schedule is invalid.
- **MaxCallDepthReached** — nested call depth reached the schedule limit during execution.

## Distinction from Code Too Large

`InvalidSchedule` and `CodeTooLarge` both involve contracts limits named in the schedule, but they
reject different problems. `CodeTooLarge` is summarized as "The code supplied to
`instantiate_with_code` exceeds the limit specified in the current schedule." `InvalidSchedule` is
summarized as "Invalid schedule supplied, e.g. with zero weight of a basic operation."
([Subtensor API Errors: CodeTooLarge](https://docs.learnbittensor.org/subtensor-api/errors#codetoolarge),
[Subtensor API Errors: InvalidSchedule](https://docs.learnbittensor.org/subtensor-api/errors#invalidschedule)).

- **InvalidSchedule** — the supplied schedule is invalid.
- **CodeTooLarge** — supplied instantiate code exceeds the current schedule limit.

## Reader Boundary

([Subtensor API Errors: InvalidSchedule](https://docs.learnbittensor.org/subtensor-api/errors#invalidschedule),
