# Contract Trapped

`ContractTrapped` is a contracts pallet error raised when contract execution traps. The API errors
reference summarizes it as "Contract trapped during execution"
([Subtensor API Errors: ContractTrapped](https://docs.learnbittensor.org/subtensor-api/errors#contracttrapped)).

## What It Means

Bittensor's EVM layer runs Ethereum-compatible smart contracts on Subtensor. During a call, the
runtime can stop execution when contract code hits a trap condition. `ContractTrapped` means that
happened before the call finished normally, so the contract path halts without completing the
intended logic ([Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials),
[Subtensor API Errors: ContractTrapped](https://docs.learnbittensor.org/subtensor-api/errors#contracttrapped)).

This is a trap outcome during execution. It does not, by itself, mean the contract code hash was
missing, that execution ran out of gas, or that the submitted gas limit failed validation before the
call started.

## Why It Appears

This error appears when executed contract code reaches a trap during a call. The practical meaning
is narrow: inspect the contract logic and inputs that led to the trapped execution path before
retrying the same call
([Subtensor API Errors: ContractTrapped](https://docs.learnbittensor.org/subtensor-api/errors#contracttrapped),
[Token Bridging](https://docs.learnbittensor.org/evm-tutorials/bridge-vtao)).

## Distinction from Out Of Gas

`ContractTrapped` and `OutOfGas` both stop contract execution before normal completion, but they
indicate different failures. `OutOfGas` means execution exhausted its gas budget. `ContractTrapped`
means execution hit a trap condition during the call
([Subtensor API Errors: OutOfGas](https://docs.learnbittensor.org/subtensor-api/errors#outofgas),
[Subtensor API Errors: ContractTrapped](https://docs.learnbittensor.org/subtensor-api/errors#contracttrapped)).

- **ContractTrapped** — contract execution trapped during the call.
- **OutOfGas** — execution exhausted the allotted gas limit.

## Distinction from Code Not Found

`ContractTrapped` and `CodeNotFound` both block contract paths, but at different stages.
`CodeNotFound` means no code could be found at the supplied code hash. `ContractTrapped` means code
was present but execution trapped after the call began
([Subtensor API Errors: CodeNotFound](https://docs.learnbittensor.org/subtensor-api/errors#codenotfound),
[Subtensor API Errors: ContractTrapped](https://docs.learnbittensor.org/subtensor-api/errors#contracttrapped)).

- **ContractTrapped** — execution trapped after the call started.
- **CodeNotFound** — no code exists at the supplied code hash.

## Reader Boundary

This page defines the meaning of the error label and the trap outcome it represents during contract
execution. It does not diagnose a specific contract bug or report live code hashes on chain; those
depend on contract logic and chain state at observation time
([Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
