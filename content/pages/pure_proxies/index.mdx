# Pure Proxies

Pure proxies are keyless Bittensor accounts used as stable slots in wallet designs, especially
multisig designs. They let a shared structure keep the same visible member account while the control
arrangement behind that slot changes
([Understanding Pure Proxies](https://docs.learnbittensor.org/keys/proxies/pure-proxies)).

## Why Stable Slots Matter

Multisig wallets depend on a defined set of signatories and an approval quorum. When a team changes
members, a direct multisig layout can force a visible address change. Pure proxies reduce that churn
by placing stable keyless accounts inside the multisig structure
([Multisig Wallet guide](https://docs.learnbittensor.org/keys/multisig),
[Understanding Pure Proxies](https://docs.learnbittensor.org/keys/proxies/pure-proxies)).

The useful idea is continuity. The pure proxy slot can remain part of the shared wallet structure
while the people or organizational controls behind that slot are updated elsewhere.

## Different From Ordinary Proxy Wallets

Ordinary proxy wallets and pure proxies both add indirection, but they solve different problems.
Proxy wallets are about placing a narrower role between a wallet and routine wallet use. Pure
proxies are about giving a wallet design a stable keyless account slot
([Proxies overview](https://docs.learnbittensor.org/keys/proxies),
[Understanding Pure Proxies](https://docs.learnbittensor.org/keys/proxies/pure-proxies)).

This difference keeps the terms from collapsing into one another. A proxy wallet is a scoped
indirection pattern. A pure proxy is a durable account placeholder, most often useful when a
multisig should survive membership changes without changing the visible member list.

## Control Model

Keyless does not mean uncontrolled. A pure proxy has no private key of its own, but the surrounding
wallet structure still determines who can manage the slot. The security value comes from the larger
architecture: multisig quorum rules, separate signers, and the account structure around the pure
proxy ([Understanding Pure Proxies](https://docs.learnbittensor.org/keys/proxies/pure-proxies),
[Multisig Wallet guide](https://docs.learnbittensor.org/keys/multisig)).

That makes pure proxies an architectural tool, not a shortcut around wallet security. They help
preserve stable account references, but the controls around the slot still need to match the risk of
the wallet design.

## Multisig Continuity

The main pure-proxy use case is long-lived multisig continuity. A team can keep a shared wallet
structure stable while replacing the people or organizations behind one member slot. That reduces
the need to rebuild outside references every time a signer changes
([Understanding Pure Proxies](https://docs.learnbittensor.org/keys/proxies/pure-proxies),
[Multisig Wallet guide](https://docs.learnbittensor.org/keys/multisig)).

The concept is easiest to read as a separation of layers. Multisig defines the approval quorum. Pure
proxies define stable member slots. Ordinary proxy wallets define a different indirection pattern.

## Environment Context

Pure proxy examples can appear in localnet, testnet, or mainnet contexts, and those environments
should not be mixed. A localnet example can illustrate the account pattern, while testnet and
mainnet belong to separate Bittensor network environments with separate histories
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Introduction to Bittensor: Subnet development](https://docs.learnbittensor.org/learn/introduction#subnet-development)).

Keeping the environment attached prevents overreading examples. The same pure-proxy vocabulary can
be used while learning locally, testing in a shared environment, or discussing production wallet
architecture, but those contexts do not prove the same wallet structure.

## Concept Boundaries

Pure proxies should not be read as a recovery guide, transfer instructions, or a replacement for
every proxy wallet pattern. The term names a stable keyless account slot that can be useful inside a
multisig design
([Understanding Pure Proxies](https://docs.learnbittensor.org/keys/proxies/pure-proxies),
[Proxies overview](https://docs.learnbittensor.org/keys/proxies)).

It also should not be read as risk-free custody. The pure proxy itself is keyless, but the accounts
and quorum rules around it still determine who controls the wallet structure.
