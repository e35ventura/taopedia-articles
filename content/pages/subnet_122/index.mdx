## What CookingTAO Provides

The on-chain description states "Democratizing Bittensor Mining." The registered project website is

specific subnet mechanism is not available through the on-chain identity alone.

## Miner and Validator Roles

Subnet 122 operates under the standard Bittensor two-role structure. Miners supply a capability to
the network, and validators evaluate those contributions and assign weights. Those weights feed into
[[Yuma Consensus]], which converts validator assessments into emissions that reward the strongest
performers.

The general miner-validator pattern is described in
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets): miners
produce work for a subnet, and validators measure that work against the subnet's standards.

## Development Stage Context

The
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction#subnet-development)
describes subnet development as moving from localnet to testnet and then mainnet. For CookingTAO
(SN122), that sequence is useful reader context even though the public identity currently provides a
short project description rather than detailed mechanism documentation.

Localnet is the isolated development environment, testnet is the shared non-production environment,
and mainnet is the production Bittensor network. The
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks) reference
separates those environments, so claims about CookingTAO should identify whether they describe
private development, public testing, or the live Finney subnet.

Because CookingTAO is registered on mainnet as Subnet 122, the article should treat its live
identity as production identity data. It should not infer miner tasks, validator prompts, or reward
criteria from the broad phrase "Democratizing Bittensor Mining" without a more specific public
source.
