# Network Rate Limit

Network rate limit is a hyperparameter, listed in the documentation as `NetworkRateLimit`, that sets
the minimum wait, in blocks, between network registrations — the creation of new subnets. The
reference describes it as the rate limit for network registrations expressed in blocks, with a
default of 14,400
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## What It Controls

The hyperparameter paces how often new subnet networks can be registered, not how neurons register
within an existing subnet. It applies to the network-creation path rather than to miner or validator
admission on a running subnet, so it bounds the cadence of new subnet markets coming online
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Create a Subnet](https://docs.learnbittensor.org/subnets/create-a-subnet)).

Because the wait is counted in blocks, the real-time spacing depends on block time. The limit names
a block interval that must elapse before another network registration is accepted, independent of
any single subnet's tempo
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Glossary: Block](https://docs.learnbittensor.org/resources/glossary#block)).

It is a timing gate, not a price. The cost side of creating a subnet is the separate network lock
cost; network rate limit only governs how frequently the registration may occur
([Create a Subnet: Burn cost](https://docs.learnbittensor.org/subnets/create-a-subnet#burn-cost),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Documented Type, Default, and Setter

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `NetworkRateLimit` as a `u64` with a default of 14,400 blocks. It is changed through
the `sudo_set_network_rate_limit` extrinsic and marked as requiring root permission, reflecting that
it governs network-wide subnet creation rather than a single subnet owner's configuration
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Because it is root-governed network state, the limit is read as a network-level setting rather than
a per-subnet owner toggle
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Distinction from Serving Rate Limit

Network rate limit paces the creation of new subnets at the network level. Serving rate limit is a
per-subnet limit on how often a miner may update its serving metadata through the serve extrinsics
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Network rate limit** — wait between new subnet network registrations.
- **Serving rate limit** — wait between a miner's serving-metadata updates on a subnet.

## Distinction from Network Lock Cost

Network lock cost is the TAO amount required to create a subnet. Network rate limit is the separate
block-counted wait that paces how frequently that creation may happen
([Create a Subnet](https://docs.learnbittensor.org/subnets/create-a-subnet),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Network lock cost** — TAO price to create a new subnet.
- **Network rate limit** — block wait between new subnet registrations.
