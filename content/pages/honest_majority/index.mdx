# Honest Majority

"Honest majority" is an informal way some readers describe the effect of Yuma Consensus's
stake-weighted clipping, not a named security assumption documented by Bittensor itself. The actual
mechanism is narrower: validators set weights for a miner, and the
[kappa](https://docs.learnbittensor.org/resources/glossary#kappa) hyperparameter (default 0.5) finds
the weight value at which half of the stake, ranked by how generous each validator was, sits on
either side. Weights more generous than that benchmark are clipped down to it, so neither the miner
nor the over-generous validator is paid on the clipped portion
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

References: [Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)

## What Clipping Actually Limits

Clipping caps how far a minority of generous or colluding validators can push a miner's score above
what the stake-weighted majority supports. A validator or coordinated group holding less than the
kappa-defined stake share cannot single-handedly inflate a miner's emissions past the benchmark the
rest of the stake sets ([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

That is a specific anti-inflation mechanism, not a general guarantee that any outcome backed by
majority stake is correct. It clips weights that are too generous relative to the benchmark; it does
not, by itself, document a defense against a majority colluding to under-rate a miner or otherwise
agreeing on an inaccurate evaluation.

## Where the "Majority" Framing Comes From

Because the clipping benchmark is set by whichever side holds the kappa-defined stake share, the
practical result tracks whichever validators hold the larger share of stake on a given miner. That
is why some readers describe the mechanism using "honest majority" language borrowed from broader
distributed-systems and blockchain security thinking: if enough stake is behind an accurate
evaluation, clipping pulls outlier scores toward it
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

That framing is a simplification, not a documented Bittensor security claim. The mechanism's
behavior if most stake were behind an inaccurate evaluation is a logical implication of how clipping
works, not something the cited Yuma Consensus material states directly, and this page should not be
read as asserting it as established fact.

## Reader Boundary

This page describes clipping's effect at a high level using a common informal framing; it is not a
quote from official Bittensor terminology. The exact kappa value, stake distribution, and validator
behavior on any subnet are live, owner-configurable, and chain-specific state that should be read
from current sources rather than assumed from this overview
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).
