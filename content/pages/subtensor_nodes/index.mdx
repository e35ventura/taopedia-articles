Subtensor nodes are blockchain nodes for Bittensor's Subtensor network. The official
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes/) guide describes a public
subtensor node as an internet-connected computer synchronized with the Bittensor blockchain
database.

These nodes are infrastructure, not subnet participants. The same guide distinguishes a subtensor
node from a Bittensor neuron: a neuron is a subnet miner or validator, while a subtensor node is
part of the blockchain access layer.

## Public Node vs Local Chain

A public subtensor node connects to a Bittensor network and syncs with its blockchain state. That is
different from a local blockchain used for development or testing. The
[Subtensor Node Basics](https://docs.learnbittensor.org/subtensor-nodes/) guide separates those
uses: public nodes connect to mainchain or testchain, while local chains are isolated development
environments.

This distinction matters because applications, miners, and validators often need reliable access to
live chain state. A local development chain is useful for testing, but it is not a substitute for a
public node that follows the active network.

## Lite and Archive Nodes

Bittensor documentation describes two public subtensor node types: lite nodes and archive nodes. A
lite node is intended to get online quickly with lower storage requirements, while an archive node
keeps historical chain data for deeper historical queries and explorer-style workloads.

The [node requirements](https://docs.learnbittensor.org/subtensor-nodes/subtensor-node-requirements)
page reflects this difference in resource expectations. Archive nodes require substantially more
storage than lite nodes because they retain more historical blockchain data.

## Why Operators Run Them

Running a subtensor node gives an operator a local connection point to the Bittensor chain. Software
that needs to read chain state or submit transactions can connect through that node rather than only
through externally operated endpoints.

For most readers, the key idea is not the install procedure but the role boundary: subtensor nodes
serve the blockchain layer, while [[Mining and Validating]] describes subnet roles that operate on
top of that chain.
