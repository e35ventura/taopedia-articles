# EdDSA Cryptographic Keypairs

EdDSA cryptographic keypairs refer to the public and private key pairs generated with EdDSA, the
signature algorithm named in Bittensor wallet-key terminology. The official
[Glossary](https://docs.learnbittensor.org/resources/glossary#eddsa-cryptographic-keypairs)
describes EdDSA as the algorithm used to generate public and private key pairs for Bittensor
coldkeys and hotkeys.

## Keypair Context

A keypair has two sides: a public side that can be shared for identification or verification, and a
private side that must remain protected. The
[Public Key glossary](https://docs.learnbittensor.org/resources/glossary#public-key) describes the
public key as shareable material used for verification, encryption, and account reference. The
[Private Key glossary](https://docs.learnbittensor.org/resources/glossary#private-key) describes the
private key as the protected component used to authorize activity.

## Wallet-Key Context

In Bittensor, EdDSA keypairs sit under the wallet-key vocabulary rather than naming a separate
network role or asset. The glossary connects EdDSA key generation with coldkeys and hotkeys, while
separate articles can explain those wallet-key roles in more detail.

## Relationship to Coldkey and Hotkey Generation

The
[EdDSA Cryptographic Keypairs glossary](https://docs.learnbittensor.org/resources/glossary#eddsa-cryptographic-keypairs)
specifically names coldkeys and hotkeys as the wallet-key roles whose public and private key pairs
are generated with EdDSA. The official
[Wallets](https://docs.learnbittensor.org/getting-started/wallets/) documentation describes a
coldkey as the long-term key that controls TAO balances, stake, and transfers, and a hotkey as the
operational key used by miners, validators, and subnet actors for routine on-chain actions.

For readers, EdDSA is therefore the shared cryptographic foundation under both key roles. The same
algorithm produces both keypairs, but the resulting keys occupy different security tiers: a coldkey
is kept offline and authorizes high-value financial operations, while a hotkey can run on online
nodes for operational signing. The
[Working with Keys](https://docs.learnbittensor.org/working-with-keys/) documentation treats both
key types as part of one wallet-key system rather than as separate cryptographic families.

[EdDSA Cryptographic Keypairs glossary](https://docs.learnbittensor.org/resources/glossary#eddsa-cryptographic-keypairs),

## Relationship to Mnemonic Recovery

EdDSA keypairs in Bittensor can be regenerated from a stored mnemonic. The
[Glossary: Mnemonic](https://docs.learnbittensor.org/resources/glossary#mnemonic) describes a
mnemonic as a sequence of words used to regenerate keys in case of loss and restore coldkeys and
hotkeys in a Bittensor wallet, and the
[Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key)
defines regenerating a key as recreating a lost or deleted coldkey or hotkey using the associated
mnemonic.

For readers, this connects EdDSA to the wallet recovery path. The deterministic relationship between
a mnemonic and the EdDSA keypair it produces is what makes a saved mnemonic sufficient to restore
access to the corresponding coldkey and hotkey. The algorithm itself is not the recovery mechanism;
the mnemonic names the recovery material that, when fed back through EdDSA key generation,
reproduces the same keypair.

References: [Glossary: Mnemonic](https://docs.learnbittensor.org/resources/glossary#mnemonic),
[Glossary: Regenerating a Key](https://docs.learnbittensor.org/resources/glossary#regenerating-a-key),
[EdDSA Cryptographic Keypairs glossary](https://docs.learnbittensor.org/resources/glossary#eddsa-cryptographic-keypairs)

## Relationship to Wallet Address Derivation

A Bittensor wallet address is derived from the public side of an EdDSA keypair. The
[Glossary: Wallet Address](https://docs.learnbittensor.org/resources/glossary#wallet-address)
defines a wallet address as a unique identifier derived from a public key and used for sending and
receiving TAO tokens, and the
[Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key) describes the
public key as shareable material used for account reference. The
[Glossary: SS58 Encoded](https://docs.learnbittensor.org/resources/glossary#ss58-encoded) describes
SS58 as the compact representation used for those public-key-derived addresses.

For readers, this places EdDSA at the base of the address-derivation chain. EdDSA produces the
public/private keypair; the public side is then encoded as a wallet address that other participants
use as a TAO destination. Reading the three terms in sequence — EdDSA keypair, public key, wallet
address — keeps the cryptographic layer distinct from the address representation layer.

References:
[Glossary: Wallet Address](https://docs.learnbittensor.org/resources/glossary#wallet-address),
[Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key),
[Glossary: SS58 Encoded](https://docs.learnbittensor.org/resources/glossary#ss58-encoded)

## Reading the Term

This article is a concept boundary. It does not describe how to create, store, recover, rotate, or
use keys. For Taopedia readers, the useful point is that EdDSA names the cryptographic method behind
the public/private keypair terminology used in Bittensor.
