# EdDSA Cryptographic Keypairs

EdDSA cryptographic keypairs refer to the public and private key pairs generated with EdDSA, the
signature algorithm named in Bittensor wallet-key terminology. The official
[Glossary](https://docs.learnbittensor.org/resources/glossary#eddsa-cryptographic-keypairs)
describes EdDSA as the algorithm used to generate public and private key pairs for Bittensor
coldkeys and hotkeys.

## Keypair Context

A keypair has two sides: a public side that can be shared for identification or verification, and a
private side that must remain protected. The
[Public Key glossary](https://docs.learnbittensor.org/resources/glossary#public-key) describes the
public key as shareable material used for verification, encryption, and account reference. The
[Private Key glossary](https://docs.learnbittensor.org/resources/glossary#private-key) describes the
private key as the protected component used to authorize activity.

## Public and Private Sides

The public side and private side of an EdDSA keypair should not be treated as interchangeable wallet
data. The public side can identify or verify account-related material, while the private side is the
authority-bearing material that must stay protected. The official public-key and private-key
glossary entries make that distinction at the term level.

For Taopedia readers, this is the main reason the word "keypair" matters. It does not mean two
independent wallet identities. It means a matched public/private pair where the public component can
be referenced openly and the private component is the part that must not be exposed.

## Wallet-Key Context

In Bittensor, EdDSA keypairs sit under the wallet-key vocabulary rather than naming a separate
network role or asset. The glossary connects EdDSA key generation with coldkeys and hotkeys, while
separate articles can explain those wallet-key roles in more detail.

## Coldkey and Hotkey Vocabulary

Bittensor wallet terminology uses EdDSA keypairs in the context of coldkeys and hotkeys. The
[Wallets, Coldkeys and Hotkeys](https://docs.learnbittensor.org/keys/wallets) documentation
separates coldkeys from hotkeys by purpose: coldkeys are tied to balance-sensitive and
security-critical authority, while hotkeys are used for operational network roles such as subnet
miner or validator activity.

EdDSA does not itself decide whether a key is being used as a coldkey or hotkey. The algorithm
describes the cryptographic keypair type; the wallet model describes how Bittensor assigns meaning
to those keys. Keeping those layers separate helps avoid treating a cryptographic term as if it were
a wallet role.

## Identity and Authority Boundary

An EdDSA public key can be part of how an account or wallet is referenced, but the protected private
key is what makes authorization sensitive. That boundary is important in Bittensor because wallet
language often discusses identity, balances, stake, miners, validators, and subnet participation in
the same area of documentation.

The keypair term should therefore be read as a cryptographic foundation beneath those wallet
concepts. It does not by itself say that TAO is held, stake is delegated, a subnet UID exists, or a
validator is active. Those claims require the surrounding wallet, account, stake, or subnet context.

## Security Interpretation

EdDSA keypairs are security-relevant because private-key exposure changes who can authorize actions
associated with the wallet material. The
[Private Key glossary](https://docs.learnbittensor.org/resources/glossary#private-key) frames the
private key as the protected side of the pair, and the wallet documentation places key handling
inside the broader coldkey/hotkey security model.

This article intentionally keeps the security point conceptual. It does not provide operational
wallet-handling guidance. For a reader, the useful interpretation is that EdDSA names the
signature-keypair basis, while Bittensor wallet documentation explains how those keypairs are used
as coldkeys and hotkeys.

## Reading the Term

This article is a concept boundary. It does not describe how to create, store, recover, rotate, or
use keys. For Taopedia readers, the useful point is that EdDSA names the cryptographic method behind
the public/private keypair terminology used in Bittensor.

## What the Term Does Not Mean

EdDSA cryptographic keypairs do not name a subnet role, an address format, a token, a stake balance,
or a live account state. They also do not describe a wallet application or a custody provider. Those
topics may rely on keypairs, but they answer different questions.

The narrow definition is useful because it keeps a cryptographic term from absorbing nearby wallet
concepts. Public keys, private keys, coldkeys, hotkeys, wallet addresses, and wallet applications
can all appear in the same security discussion, but EdDSA specifically names the algorithmic keypair
context behind the public/private key material.
