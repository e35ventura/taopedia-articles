# Subtensor RPC

Subtensor RPC methods are node methods exposed by the official
[Subtensor RPC](https://docs.learnbittensor.org/subtensor-api/rpc) reference. That source describes
the page as showing JSON-RPC methods available on the Subtensor node.

## What RPC Methods Represent

The RPC reference lists named methods under namespaces. For each method, it gives the method name,
type signature, access path, and a short summary where one is available. This makes the page a map
of node-facing methods, not a complete explanation of the feature behind every method.

Reference: [Subtensor RPC](https://docs.learnbittensor.org/subtensor-api/rpc)

## Namespaces

The official reference is grouped by namespaces such as author, chain, childstate, eth, net,
offchain, payment, rpc, state, system, and web3. That grouping helps readers identify whether a
method relates to block data, node state, eth and web3 method groups, storage state, system
metadata, or the method list itself.

Reference: [Subtensor RPC](https://docs.learnbittensor.org/subtensor-api/rpc)

## Reference Context

The RPC reference includes namespaces for chain data, node state, storage state, fee information,
and method discovery. It also lists eth and web3 namespaces, where the entries include familiar
Ethereum-style method names such as accounts, blockNumber, getBalance, clientVersion, and sha3.

Reference: [Subtensor RPC](https://docs.learnbittensor.org/subtensor-api/rpc)

## Careful Interpretation

An RPC entry shows that a named node method exists and how the official reference describes it. It
should be read with its namespace, method summary, and safety label where one is present. A method
listing alone should not be treated as a guide to operating a node or building an application.

Reference: [Subtensor RPC](https://docs.learnbittensor.org/subtensor-api/rpc)
