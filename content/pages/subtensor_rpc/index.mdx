# Subtensor RPC

Subtensor RPC is the node access layer for asking a Subtensor node about chain data, node status,
fee information, storage state, and submitted actions. The official
[Subtensor RPC](https://docs.learnbittensor.org/subtensor-api/rpc) reference describes JSON-RPC
methods available on a Subtensor node and groups them by namespace.

## What RPC Represents

RPC is the vocabulary a client uses when it asks a node for information or asks the node to handle a
submitted request. In Taopedia terms, it is best read as the access surface around Subtensor rather
than as a separate Bittensor mechanism. A method can expose block data, storage state, node health,
fee information, or a submission path, depending on its namespace.

Reference: [Subtensor RPC](https://docs.learnbittensor.org/subtensor-api/rpc)

## Namespaces and Scope

RPC namespaces group related access surfaces. The chain namespace covers block and header reads, the
state namespace covers storage and metadata reads, the system namespace covers node status, and the
payment namespace covers fee-information queries. The same reference also includes Ethereum-style
namespaces such as eth, net, and web3 for EVM-compatible access exposed by the node.

For readers, the namespace is a clue about what kind of question is being asked. It is not a role,
subnet, wallet type, or governance concept.

Reference: [Subtensor RPC](https://docs.learnbittensor.org/subtensor-api/rpc)

## Relation to Subtensor References

RPC is related to, but different from, other Subtensor reference pages. [[extrinsics|Extrinsics]]
list submitted state-changing runtime methods. [[subtensor_storage|Subtensor Storage]] lists
queryable runtime state entries. [[subtensor_events|Subtensor Events]] lists emitted runtime
records, and [[subtensor_constants|Subtensor Constants]] lists runtime-defined values.

For readers, RPC is the node access layer around these references. It can expose block, state,
system, fee, submission, and EVM-compatible surfaces, but it should not be collapsed into any one of
those concepts.

References: [Subtensor RPC](https://docs.learnbittensor.org/subtensor-api/rpc),
[Subtensor extrinsics](https://docs.learnbittensor.org/subtensor-api/extrinsics),
[Subtensor Storage](https://docs.learnbittensor.org/subtensor-api/storage),
[Subtensor Events](https://docs.learnbittensor.org/subtensor-api/events)

## Public Access Context

RPC access is usually encountered through a node endpoint. The official
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor)
defines Public Subtensor as a publicly accessible node synchronized with mainchain or testchain,
while the RPC reference names the methods a node exposes.

For readers, [[public_subtensor|Public Subtensor]] explains public node access, while Subtensor RPC
explains the kind of request vocabulary exposed by a node. A public endpoint and a local node can
use the same kind of RPC vocabulary while still belonging to different network contexts.

References:
[Glossary: Public Subtensor](https://docs.learnbittensor.org/resources/glossary#public-subtensor),
[Subtensor RPC](https://docs.learnbittensor.org/subtensor-api/rpc)

## Safety and Interpretation

The RPC reference marks some methods as unsafe and marks subscription methods separately. Those
labels matter because the RPC page mixes read-style methods, submission methods, node-status
methods, and node-sensitive methods in one reference. A reader should treat an RPC entry as a
description of a node method, then use the relevant Subtensor concept article or official
documentation to understand the feature behind that method.

Reference: [Subtensor RPC](https://docs.learnbittensor.org/subtensor-api/rpc)

## Reader Boundary

This article defines the term at a high level. It does not provide endpoint recommendations, request
payloads, client setup, code snippets, or method-by-method operating guidance. The official RPC
reference is the right source for the current method list.

Reference: [Subtensor RPC](https://docs.learnbittensor.org/subtensor-api/rpc)
