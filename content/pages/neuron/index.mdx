# Neuron

In Bittensor, a neuron is the general name for a participant in a subnet. The
[Understanding Neurons](https://docs.learnbittensor.org/learn/neurons) documentation states that a
neuron is the generalized name for a participant in a subnet, which can be either a miner or a
validator. The [Glossary](https://docs.learnbittensor.org/resources/glossary#neuron) describes it as
the basic computing node in a subnet, named by analogy to a node in a neural network.

The term is useful because it lets the protocol describe registration, identity, and communication
once, for both roles, rather than separately for miners and validators.

## Miners And Validators

A neuron takes one of two roles. Per the
[Understanding Neurons](https://docs.learnbittensor.org/learn/neurons) documentation, miners and
validators use different network components: a miner runs an axon server that receives requests,
while a validator uses a dendrite client to send requests to miners. The same documentation frames
miners as the participants that perform a subnet's work and validators as the participants that
evaluate that work.

This role split is why "neuron" is the umbrella term: both are neurons, but they sit on opposite
ends of the request/response exchange within a subnet.

## Registration And UID

A neuron joins a subnet by registering. The
[Understanding Neurons](https://docs.learnbittensor.org/learn/neurons) documentation describes
registration as paying the subnet's current burn cost in exchange for a unique UID within that
subnet, and notes that the burn price decays over time and rises with each successful registration,
within minimum and maximum bounds.

The UID is a per-subnet identifier: a single key can hold UIDs in multiple subnets, and a neuron's
UID only has meaning inside the subnet that issued it.

## Communication

Neurons exchange data through a small set of components. The
[Understanding Neurons](https://docs.learnbittensor.org/learn/neurons) documentation describes the
axon as a server instance used by miners and the dendrite as a client instance used by validators,
with synapse objects encapsulating the data passed between them. A validator's dendrite sends a
synapse to a miner's axon, and the miner's response flows back along the same path.

## Reader Boundary

This article describes the neuron concept and the miner/validator roles, not the live state of any
particular participant. Exact registration costs, role behavior, and component APIs can change
across releases, so specific or current values should be read from the
[Understanding Neurons](https://docs.learnbittensor.org/learn/neurons) documentation and the
[Bittensor SDK](https://github.com/opentensor/bittensor) rather than from this concept article.
