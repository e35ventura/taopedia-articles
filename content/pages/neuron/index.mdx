# Neuron

A neuron is a registered participant in a Bittensor subnet. Official Bittensor documentation uses
the term when describing miners, validators, and the subnet metagraph state that records information
about subnet participants.

References: [Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron),
[Understanding Neurons](https://docs.learnbittensor.org/learn/neurons)

## Subnet Participant

The term neuron is used inside subnet context. A subnet can contain miner and validator
participants, and those participants are represented in subnet state rather than as generic network
accounts. This helps distinguish the participant's subnet role from the wallet keys or account
addresses used to operate it.

Reference: [Understanding Neurons](https://docs.learnbittensor.org/learn/neurons)

## Metagraph Context

The subnet metagraph documentation describes the metagraph as a snapshot containing information
about neurons in a selected subnet. In that sense, a neuron is one of the participant records whose
state can appear in subnet-level views such as stake-related state, ranks, weights, incentives, and
activity state.

References: [The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph),
[Glossary: Metagraph](https://docs.learnbittensor.org/resources/glossary#metagraph)

## Relationship to Multiple Mechanisms

A neuron is usually discussed for one incentive mechanism at a time, but subnets can also run
multiple mechanisms in parallel. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms) notes
that validators must evaluate miners separately for each mechanism.

For readers, a neuron still names one registered subnet participant, but the mechanism context
matters. Evaluation and performance readings for one mechanism should not be assumed to describe the
same neuron in another when a subnet uses more than one evaluation system.

References:
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets),
[Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)

## Relationship to Netuid

A neuron and a netuid are related but different parts of Bittensor subnet vocabulary. A netuid
selects which subnet context is in scope, while a neuron names a registered participant inside that
selected subnet. The [Glossary: Netuid](https://docs.learnbittensor.org/resources/glossary#netuid)
places netuid at the subnet level, and the
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron) describes a registered
participant in a Bittensor subnet.

For readers, netuid answers which subnet market is being discussed, while a neuron answers which
registered participant record belongs inside that subnet context.

References: [Glossary: Netuid](https://docs.learnbittensor.org/resources/glossary#netuid),
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron)

## Relationship to UID Slot

A neuron and a UID slot are related but different parts of subnet participant vocabulary. A UID slot
describes a participant position inside a subnet, while a neuron names the registered participant
associated with subnet state for that kind of position. The
[Glossary: UID Slot](https://docs.learnbittensor.org/resources/glossary#uid-slot) describes a
participant position, and the
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron) describes a registered
subnet participant represented in subnet documentation and metagraph views.

For readers, a UID slot names the position identifier, while a neuron names the participant record
that subnet state can refer to inside that subnet.

References: [Glossary: UID Slot](https://docs.learnbittensor.org/resources/glossary#uid-slot),
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron)

## Relationship to Metagraph

A neuron and a metagraph are related but different parts of subnet state vocabulary. A neuron names
one registered participant, while a metagraph names the structured subnet state view that can
include information about many neurons in a selected subnet. The
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron) describes a registered
participant, and the
[Glossary: Metagraph](https://docs.learnbittensor.org/resources/glossary#metagraph) describes
comprehensive information about a subnet's neurons.

For readers, a neuron is the participant-level term, while a metagraph is the subnet-level state
view in which neuron records appear alongside incentive and activity-related values.

References: [Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron),
[Glossary: Metagraph](https://docs.learnbittensor.org/resources/glossary#metagraph)

## Relationship to Register

A neuron and register are related but different parts of the subnet participation lifecycle.
Register describes the subnet-entry process that grants a UID slot, while a neuron names a
registered participant after that entry has placed the hotkey inside subnet participation
vocabulary. The [Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register)
describes subnet entry, and the
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron) describes a registered
subnet participant.

For readers, register names how a participant enters a subnet, while a neuron names the participant
record that subnet documentation uses once registration has succeeded.

References: [Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register),
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron)

## Reader Boundary

This page defines the term at a high level. It does not report current subnet membership, live
neuron counts, wallet ownership, or current rewards. Those values change with chain state and should
be checked from current Bittensor sources when needed.
