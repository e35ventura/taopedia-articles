# Neuron

A neuron is a registered participant in a Bittensor subnet
([Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron),
[Understanding Neurons](https://docs.learnbittensor.org/learn/neurons)). The term appears when
describing miners, validators, and metagraph state for subnet participants.

## What a Neuron Records

A neuron is the per-subnet participant record that binds a wallet's hotkey-coldkey identity to one
UID position on a netuid. The metagraph describes that record's current subnet-level values, and a
deregistration event removes it from its position in the next snapshot
([Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron),
[Glossary: Hotkey-Coldkey Pair](https://docs.learnbittensor.org/resources/glossary#hotkey-coldkey-pair),
[The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph),
[Glossary: Deregistration](https://docs.learnbittensor.org/resources/glossary#deregistration)).

Because these records are per-subnet rather than network-wide, one wallet can hold separate neuron
records on different netuids at the same time. Every neuron reference therefore carries the netuid
it belongs to ([Glossary: Netuid](https://docs.learnbittensor.org/resources/glossary#netuid),
[Understanding Neurons](https://docs.learnbittensor.org/learn/neurons)).

## What a Neuron Does in a Subnet

A neuron operates as either a subnet miner or a subnet validator, interacting under the subnet
protocol. A miner neuron typically exposes an axon endpoint that receives validator requests, while
a validator neuron uses a dendrite client to query miners and evaluate their responses
([Glossary: Subnet Miner](https://docs.learnbittensor.org/resources/glossary#subnet-miner),
[Glossary: Subnet Validator](https://docs.learnbittensor.org/resources/glossary#subnet-validator),
[Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol),
[Glossary: Axon](https://docs.learnbittensor.org/resources/glossary#axon),
[Glossary: Dendrite](https://docs.learnbittensor.org/resources/glossary#dendrite)).

The role determines what the participant does; the neuron is the registered identity that carries
that role inside one subnet's state
([Understanding Neurons](https://docs.learnbittensor.org/learn/neurons)).

## Distinction from Metagraph

Neuron names the registered participant record inside a subnet. Metagraph names the subnet state
table that holds those records
([Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron),
[The Subnet Metagraph](https://docs.learnbittensor.org/subnets/metagraph)).

- **Neuron** — registered participant record tied to a UID slot.
- **Metagraph** — subnet state table listing participant records.

## Distinction from UID Slot

Neuron names the participant record bound to a position. UID slot names the indexed position itself
on a netuid ([Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron),
[Glossary: UID Slot](https://docs.learnbittensor.org/resources/glossary#uid-slot)).

- **Neuron** — registered participant record at one UID position.
- **UID slot** — indexed position a neuron occupies on a subnet.

## Distinction from Register

Neuron names the active participant record in subnet state. Register names the entry process that
grants a UID slot on a netuid
([Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron),
[Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register)).

- **Neuron** — participant record after successful registration.
- **Register** — entry process that creates that record.

## Distinction from Subnet Miner

Subnet miner names the work-production role a neuron can hold. Neuron names the registered
participant record that carries that role on a netuid
([Glossary: Subnet Miner](https://docs.learnbittensor.org/resources/glossary#subnet-miner),
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron)).

- **Subnet miner** — role producing subnet work.
- **Neuron** — registered participant record that can hold the role.

## Distinction from Subnet Validator

Subnet validator names the evaluation role a neuron can hold. Neuron names the registered
participant record that carries that role on a netuid
([Glossary: Subnet Validator](https://docs.learnbittensor.org/resources/glossary#subnet-validator),
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron)).

- **Subnet validator** — role evaluating miner work.
- **Neuron** — registered participant record that can hold the role.

## Distinction from Hotkey-Coldkey Pair

A hotkey-coldkey pair names the wallet keys that authenticate operations. A neuron ties that
identity to one subnet's participant record and UID position
([Glossary: Hotkey-Coldkey Pair](https://docs.learnbittensor.org/resources/glossary#hotkey-coldkey-pair),
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron)).

- **Hotkey-coldkey pair** — wallet keys that authenticate operations.
- **Neuron** — registered participant record tied to a UID on one netuid.

Key-pair vocabulary and participant-record vocabulary answer different identity layers
([Understanding Neurons](https://docs.learnbittensor.org/learn/neurons)).

## Distinction from Axon

Axon names the serving endpoint a miner neuron typically exposes to receive validator requests.
Neuron names the registered participant record in subnet state
([Glossary: Axon](https://docs.learnbittensor.org/resources/glossary#axon),
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron)).

- **Axon** — serving endpoint for subnet communication.
- **Neuron** — registered participant record in subnet state.

## Distinction from Dendrite

Dendrite names the client endpoint a validator neuron uses to query miners. Neuron names the
registered participant record in subnet state
([Glossary: Dendrite](https://docs.learnbittensor.org/resources/glossary#dendrite),
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron)).

- **Dendrite** — client endpoint for subnet communication.
- **Neuron** — registered participant record in subnet state.

## Distinction from Subnet Protocol

Subnet protocol names the rule set for how validators and miners exchange work inside a subnet.
Neuron names the UID-identified participant record registered to operate within that subnet exchange
([Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol),
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

Exchange-rule vocabulary and participant-registration vocabulary answer different questions on the
same netuid.

## Distinction from Yuma Consensus

A neuron is the registered participant record on a netuid. Yuma Consensus is the tempo mechanism
that aggregates validator weights into miner incentives and validator dividends
([Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Neuron** — registered participant record on a netuid.
- **Yuma Consensus** — on-chain mechanism that uses validator weights to determine emission shares
  ([Yuma Consensus: Validator emissions](https://docs.learnbittensor.org/learn/yuma-consensus#validator-emissions)).

## Distinction from Netuid

Netuid names which subnet is in scope. Neuron names a registered participant inside that subnet's
state table ([Glossary: Netuid](https://docs.learnbittensor.org/resources/glossary#netuid)).

Every neuron claim should carry the netuid it belongs to because participant records are per-subnet,
not network-wide.

## Distinction from Deregistration

Deregistration removes a neuron from a UID slot. Neuron names the participant record while that
registration is active in subnet state
([Glossary: Deregistration](https://docs.learnbittensor.org/resources/glossary#deregistration)).

A deregistration event changes the next metagraph snapshot; it does not erase the neuron vocabulary
for historical reads at earlier blocks.

## Distinction from Subnet Task

Subnet task names the useful work miners are expected to perform inside a subnet. Neuron names the
registered participant record that performs or evaluates that work on a netuid
([Glossary: Subnet Task](https://docs.learnbittensor.org/resources/glossary#subnet-task),
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron)).

- **Subnet task** — useful work the subnet asks miners to produce.
- **Neuron** — registered participant record on a netuid.

## Distinction from Incentive Mechanism

An incentive mechanism names the evaluation rules that govern how subnet work is scored and
rewarded. A neuron names who is registered in a subnet, not the rule set that judges that
participant's role
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism),
[Glossary: Neuron](https://docs.learnbittensor.org/resources/glossary#neuron)).

- **Neuron** — registered participant record on a netuid.
- **Incentive mechanism** — evaluation rules connecting work to rewards.

## Reader Boundary

This page defines the term at a high level. It does not report current subnet membership, live
neuron counts, wallet ownership, or current rewards. Those values change with chain state and should
be checked from current Bittensor sources when needed.
