# Gas Limit Too High

`GasLimitTooHigh` is an EVM pallet error raised when the submitted gas limit is above the allowed
maximum. The API errors reference summarizes it as "Gas limit is too high"
([Subtensor API Errors: GasLimitTooHigh](https://docs.learnbittensor.org/subtensor-api/errors#gaslimittoohigh)).

## What It Means

Bittensor's EVM layer executes Ethereum-compatible transactions on Subtensor and validates gas
parameters before running the call. `GasLimitTooHigh` means the submitted gas limit exceeds the
runtime ceiling for that transaction, so the EVM path rejects the call before execution proceeds
([Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials),
[Subtensor API Errors: GasLimitTooHigh](https://docs.learnbittensor.org/subtensor-api/errors#gaslimittoohigh)).

This is a gas-limit ceiling rejection. It does not, by itself, mean the gas limit was below the
minimum, that the gas price was too low, or that fee conversion overflowed.

## Why It Appears

This error appears when an EVM transaction or contract call names a gas limit above what the runtime
allows for that submission. The practical meaning is narrow: lower the gas limit to within the
allowed maximum before resubmitting the same call
([Subtensor API Errors: GasLimitTooHigh](https://docs.learnbittensor.org/subtensor-api/errors#gaslimittoohigh),
[Token Bridging](https://docs.learnbittensor.org/evm-tutorials/bridge-vtao)).

## Distinction from Gas Limit Too Low

`GasLimitTooHigh` and `GasLimitTooLow` both reject EVM gas-limit parameters, but on opposite bounds.
`GasLimitTooHigh` means the submitted limit exceeds the runtime maximum. `GasLimitTooLow` means the
submitted limit is below the required minimum
([Subtensor API Errors: GasLimitTooLow](https://docs.learnbittensor.org/subtensor-api/errors#gaslimittoolow),
[Subtensor API Errors: GasLimitTooHigh](https://docs.learnbittensor.org/subtensor-api/errors#gaslimittoohigh)).

- **GasLimitTooHigh** — the submitted gas limit exceeds the allowed maximum.
- **GasLimitTooLow** — the submitted gas limit is below the required minimum.

## Distinction from Fee Overflow

`GasLimitTooHigh` and `FeeOverflow` both block EVM transaction submission, but at different checks.
`GasLimitTooHigh` rejects the gas limit before fee conversion is evaluated. `FeeOverflow` means the
fee amount overflowed during conversion after gas parameters were accepted for that step
([Subtensor API Errors: FeeOverflow](https://docs.learnbittensor.org/subtensor-api/errors#feeoverflow),
[Subtensor API Errors: GasLimitTooHigh](https://docs.learnbittensor.org/subtensor-api/errors#gaslimittoohigh)).

- **GasLimitTooHigh** — the submitted gas limit exceeds the allowed maximum.
- **FeeOverflow** — fee calculation overflowed during conversion.

## Reader Boundary

This page defines the meaning of the error label and the gas-limit ceiling check it represents on
EVM paths. It does not report the live maximum gas limit configured on a network or estimate gas for
a specific contract call; those depend on runtime settings and call parameters at submission time
([Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
