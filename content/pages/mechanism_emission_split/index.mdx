# Mechanism Emission Split

Mechanism emission split is a per-subnet hyperparameter, listed in the documentation as
`MechanismEmissionSplit`, that sets how emission is divided across the mechanisms on a subnet. The
reference describes it as setting the emission splits of mechanisms in a subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## What It Controls

The hyperparameter allocates shares among mechanisms, not among individual miners or validators. A
subnet can run more than one mechanism when
[mechanism count](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#mechanismcount) is
above one; mechanism emission split decides what fraction of the subnet's emission budget each
mechanism receives
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Emission](https://docs.learnbittensor.org/learn/emissions)).

It does not define the subnet task, validator weights, or Yuma Consensus bonding rules inside a
mechanism. It only partitions the emission envelope across mechanism slots before each mechanism's
own incentive path runs ([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

The split is owner-tunable per subnet, so netuid 1 can use one allocation while another netuid
divides emission differently across its mechanisms, and the live vector is chain state rather than a
network constant
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Documented Type and Setter

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `MechanismEmissionSplit` as a vector type and marks the permission required to
change it as subnet owner
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Because each subnet carries its own hyperparameters, the split vector on one netuid can differ from
another subnet's allocation and should be read for the selected subnet rather than assumed from a
reference example
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Reading the Live Value for netuid 1

Mechanism emission split is per-subnet chain state, so any live claim is tied to a specific netuid.
For the documented example netuid 1 on Finney mainnet, the split appears in that subnet's
hyperparameter table, which the reference describes under viewing a subnet's hyperparameters
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters)).
The infobox uses netuid 1 only as an example label; other subnets expose their own values
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from Mechanism Count

Mechanism count sets how many mechanisms a subnet runs. Mechanism emission split sets how emission
is divided among those mechanisms once the count is above one
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Mechanism count** — number of mechanisms on the subnet.
- **Mechanism emission split** — emission share allocated to each mechanism.

## Distinction from Incentives

Incentives are miner emission shares credited after Yuma Consensus settles validator weights inside
one mechanism. Mechanism emission split runs earlier: it partitions the subnet emission budget
across mechanism slots when mechanism count is above one, and each mechanism then runs its own
incentive path on its share
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Emission](https://docs.learnbittensor.org/learn/emissions),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

When mechanism count is one, the split vector does not change reader-facing economics; the
hyperparameter only matters on subnets that actually run multiple mechanisms
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Mechanism emission split** — per-mechanism share of the subnet emission envelope.
- **Incentives** — miner payout outcome after Yuma settles inside one mechanism.

## Distinction from Validator Dividends

Validator dividends are validator-side emission shares Yuma credits after weight settlement.
Mechanism emission split does not set take rates or dividend formulas; it only decides what fraction
of the subnet budget each mechanism receives before its own settlement pass
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Emission](https://docs.learnbittensor.org/learn/emissions)).

- **Mechanism emission split** — budget partition across mechanisms.
- **Validator dividends** — validator payout outcome after Yuma settlement.

## Distinction from Yuma Consensus

Yuma Consensus converts eligible validator weights into incentive and dividend shares at an epoch
boundary inside one mechanism. Mechanism emission split is a hyperparameter layer above that pass:
it allocates emission budget across mechanisms before each mechanism's Yuma run
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Mechanism emission split** — cross-mechanism emission allocation on the subnet.
- **Yuma Consensus** — per-mechanism settlement from weights to emission shares.
