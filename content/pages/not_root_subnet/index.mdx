# Not Root Subnet

`NotRootSubnet` is a subtensor pallet error raised when a root network weight operation is submitted
with a netuid that does not match the root subnet. The API errors reference describes it as "Netuid
does not match for setting root network weights."
([Subtensor API Errors: NotRootSubnet](https://docs.learnbittensor.org/subtensor-api/errors#notrootsubnet)).

## What It Means

Operations that set root network weights require the correct root subnet netuid. `NotRootSubnet`
fires when the submitted netuid does not match the root subnet's identifier
([Subtensor API Errors: NotRootSubnet](https://docs.learnbittensor.org/subtensor-api/errors#notrootsubnet)).

This is a netuid mismatch on the root-weight path. It does not mean the submitted subnet does not
exist, that the root network is missing from chain state, or that the caller lacks the necessary
stake or permissions.

## Why It Appears

This error appears when a call that targets the root subnet for weight setting is submitted with a
netuid that is not the root subnet's netuid
([Subtensor API Errors: NotRootSubnet](https://docs.learnbittensor.org/subtensor-api/errors#notrootsubnet)).

## Distinction from Subnet Not Exists

`NotRootSubnet` and `SubnetNotExists` both block operations that reference a netuid, but they fail
for different reasons. `SubnetNotExists` fires when the submitted netuid has no registered subnet at
all. `NotRootSubnet` fires when the submitted netuid does identify an existing subnet but that
subnet is not the root subnet, which is required for root-weight operations
([Subtensor API Errors: SubnetNotExists](https://docs.learnbittensor.org/subtensor-api/errors#subnetnotexists),
[Subtensor API Errors: NotRootSubnet](https://docs.learnbittensor.org/subtensor-api/errors#notrootsubnet)).

- **NotRootSubnet** — netuid identifies a subnet, but it is not the root subnet.
- **SubnetNotExists** — netuid does not correspond to any registered subnet.

## Distinction from Root Network Does Not Exist

`NotRootSubnet` and `RootNetworkDoesNotExist` both involve the root subnet, but they describe
opposite states. `RootNetworkDoesNotExist` fires when the root subnet itself is absent from chain
state. `NotRootSubnet` fires when the root subnet exists but the submitted netuid points to a
different subnet instead of it
([Subtensor API Errors: RootNetworkDoesNotExist](https://docs.learnbittensor.org/subtensor-api/errors#rootnetworkdoesnotexist),
[Subtensor API Errors: NotRootSubnet](https://docs.learnbittensor.org/subtensor-api/errors#notrootsubnet)).

- **NotRootSubnet** — root subnet exists; caller submitted the wrong netuid.
- **RootNetworkDoesNotExist** — root subnet is not present in chain state.
