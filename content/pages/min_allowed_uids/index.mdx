# Min Allowed UIDs

Min allowed UIDs is a per-subnet hyperparameter, listed in the documentation as `MinAllowedUids`,
that sets the minimum allowed number of
[UIDs](https://docs.learnbittensor.org/resources/glossary#uid-slot) for a subnet. The reference
describes it as the minimum allowed UIDs for a subnet, callable only by the root account
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Why It Matters

The minimum matters most when a subnet's participant set is shrunk rather than grown. A subnet owner
can reduce the live UID count with
[UID trimming](https://docs.learnbittensor.org/subnets/uid-trimming), which removes the lowest
emitters down to a chosen target and compacts survivors into consecutive indices. That resize cannot
drop a subnet arbitrarily low: the UID trimming guide documents a minimum trim target, so trimming
stops at the subnet's minimum rather than emptying it
([UID Trimming](https://docs.learnbittensor.org/subnets/uid-trimming),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

So min allowed UIDs functions as the floor side of a subnet's capacity bounds. The
[max allowed UIDs](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#maxalloweduids)
ceiling caps how many UIDs may exist, while this minimum names how few a subnet is allowed to hold,
keeping a baseline participant set on the metagraph
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Glossary: UID Slot](https://docs.learnbittensor.org/resources/glossary#uid-slot)).

It does not decide which neurons keep their UIDs or how registration is priced. Trimming uses
emitter ranking and immunity rules to choose what is removed; min allowed UIDs only bounds how far
that removal may go ([UID Trimming](https://docs.learnbittensor.org/subnets/uid-trimming)).

## Documented Type, Default, and Setter

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `MinAllowedUids` as a `u16` with a default of 64. It is changed through the
`sudo_set_min_allowed_uids` extrinsic and is callable only by the root account. The UID trimming
guide likewise documents a minimum trim target of 64 UIDs, matching this default
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[UID Trimming](https://docs.learnbittensor.org/subnets/uid-trimming)).

Because it is root-governed per-netuid state, the value on one subnet can differ from the documented
default and from the minimum on another subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from Max Allowed UIDs

Max allowed UIDs caps how many UIDs a subnet can hold; min allowed UIDs names how few it may be
reduced to. The two bound the same UID count from opposite ends
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Max allowed UIDs** — ceiling on the subnet's UID count.
- **Min allowed UIDs** — floor the subnet's UID count may be reduced to.

## Distinction from UID Trimming

UID trimming is the owner action that reduces and compacts the participant set. Min allowed UIDs is
the floor that action respects, so trimming stops at the minimum rather than removing everyone
([UID Trimming](https://docs.learnbittensor.org/subnets/uid-trimming),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **UID trimming** — the owner resize that removes low emitters to a target.
- **Min allowed UIDs** — the floor that target cannot go below.
