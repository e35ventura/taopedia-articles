# Min Allowed UIDs

Min allowed UIDs is a per-subnet hyperparameter, listed in the documentation as `MinAllowedUids`,
that sets the minimum number of [UIDs](https://docs.learnbittensor.org/resources/glossary#uid-slot)
a subnet is required to have. The reference describes it as the minimum allowed UIDs for a subnet,
callable only by the root account
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## What It Controls

The hyperparameter names the lower bound on a subnet's UID count rather than which neurons hold
those UIDs or how registration is priced. It is read together with the subnet's current UID count
and its
[max allowed UIDs](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#maxalloweduids)
ceiling, and the value it can be set to is constrained to stay below both the current UID count and
the maximum allowed UIDs for the subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Glossary: UID Slot](https://docs.learnbittensor.org/resources/glossary#uid-slot)).

Because it sits below the current and maximum counts, min allowed UIDs expresses the smallest UID
count the subnet is expected to maintain rather than a target it grows toward. The ceiling caps how
many UIDs may exist; this minimum names the floor the configuration keeps the subnet at or above
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

The value is set at root permission rather than by the subnet owner alone, reflecting network-level
control. The live minimum on netuid 1 can differ from the documented default and from another
subnet's value
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Documented Type, Default, and Setter

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `MinAllowedUids` as a `u16` with a default of 64. It is changed through the
`sudo_set_min_allowed_uids` extrinsic and is callable only by the root account
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Because each subnet carries its own value as per-netuid state, the minimum on one netuid can differ
from the documented default and from the minimum on another subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Reading the Live Value for netuid 1

Min allowed UIDs is per-subnet chain state, so any live claim is tied to a specific netuid. For the
documented example netuid 1 on Finney mainnet, the value appears in that subnet's hyperparameter
table, which the reference describes under viewing a subnet's hyperparameters
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters)).
The infobox uses netuid 1 only as an example label; other subnets expose their own values
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from Max Allowed UIDs

Max allowed UIDs sets the ceiling on how many UIDs a subnet can hold. Min allowed UIDs sets the
minimum UID count the subnet must have, and is constrained to stay below both the current count and
that ceiling
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Max allowed UIDs** — ceiling on the subnet's UID count.
- **Min allowed UIDs** — minimum UID count required, kept below the current and maximum counts.

## Distinction from Min Non Immune UIDs

Min non immune UIDs sets the minimum number of UIDs that must remain non-immune. Min allowed UIDs
sets the minimum total UID count for the subnet regardless of immune status
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Min allowed UIDs** — minimum total UID count required.
- **Min non immune UIDs** — minimum non-immune UID count within that total.
