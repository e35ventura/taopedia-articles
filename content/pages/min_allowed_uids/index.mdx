# Min Allowed UIDs

Min allowed UIDs is a per-subnet hyperparameter, listed in the documentation as `MinAllowedUids`,
that sets the minimum number of neuron slots a subnet keeps available. Each registered neuron
occupies one [UID slot](https://docs.learnbittensor.org/resources/glossary#uid-slot), so this value
is the floor beneath which a subnet's slot count is not reduced
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## What It Controls

The hyperparameter sets a lower bound on subnet UID capacity, not which neurons hold those slots or
how registration is priced. It pairs with the
[max allowed UIDs](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#maxalloweduids)
ceiling: max allowed UIDs caps how high the slot count can go, while min allowed UIDs bounds how low
it can be set
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

This floor matters when a subnet's capacity is adjusted. Reducing the UID count toward the ceiling
is constrained so the slot count does not fall below the configured minimum, keeping a baseline
number of competitive slots on the subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Glossary: UID Slot](https://docs.learnbittensor.org/resources/glossary#uid-slot)).

The value is set at root permission rather than by the subnet owner alone, reflecting network-level
control over minimum subnet size. The live floor on netuid 1 can differ from the documented default
and from another subnet's value
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Documented Type, Default, and Setter

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `MinAllowedUids` as a `u16` with a default of 64. It is changed through the
`sudo_set_min_allowed_uids` extrinsic and is callable only by the root account
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Because each subnet carries its own value, the floor on one netuid can differ from the documented
default and from the floor on another subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Reading the Live Value for netuid 1

Min allowed UIDs is per-subnet chain state, so any live claim is tied to a specific netuid. For the
documented example netuid 1 on Finney mainnet, the value appears in that subnet's hyperparameter
table, which the reference describes under viewing a subnet's hyperparameters
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters)).
The infobox uses netuid 1 only as an example label; other subnets expose their own values
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from Max Allowed UIDs

Max allowed UIDs sets the ceiling on how many neuron slots a subnet can hold. Min allowed UIDs sets
the floor beneath which that slot count is not reduced, so the two bound the same capacity range
from opposite ends
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Max allowed UIDs** — ceiling on the subnet's neuron slot count.
- **Min allowed UIDs** — floor on the subnet's neuron slot count.

## Distinction from Min Non Immune UIDs

Min non immune UIDs sets the minimum number of UIDs that must remain non-immune. Min allowed UIDs
sets the minimum total slot count for the subnet regardless of immune status
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Min allowed UIDs** — floor on total neuron slots.
- **Min non immune UIDs** — floor on non-immune slots within that total.
