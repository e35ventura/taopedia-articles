# Pruning Score

A pruning score is the value the chain uses to decide which neuron is removed when a subnet is full
and a new registration arrives. The mining documentation describes the chain looking only at
emissions, represented as the pruning score, so the score stands in for how much a neuron has been
earning. On a subnet such as netuid 1, the neuron with the lowest pruning score is the one in line
to be displaced.

References: [Mining in Bittensor](https://docs.learnbittensor.org/miners)

## Lowest Score Is Displaced First

When a full subnet receives a new registration, the neuron with the lowest pruning score is
deregistered to make room for the entrant. The documentation adds a tie rule: where two or more
neurons share the lowest pruning score, the older node is deregistered first. The score therefore
defines a removal order, with the weakest-earning neuron, and then the oldest among equals, leaving
first.

References: [Mining in Bittensor](https://docs.learnbittensor.org/miners)

## Built From Emissions

The documentation equates the pruning score with emissions directly: the chain looks at emissions,
represented as the pruning score. A neuron earning more emission carries a higher pruning score and
sits further from displacement, while one earning little stays near the bottom of the order. This is
why the score is read as a standing that builds as a neuron performs and earns over time, rather
than a separate rating set on its own.

References: [Mining in Bittensor](https://docs.learnbittensor.org/miners)

## Immunity Changes the Timing

A newly registered neuron is protected by its immunity period, during which ordinary pruning cannot
remove it. The documentation notes a last-resort exception: if every neuron is still immune, the one
with the lowest pruning score is deregistered by the next incoming registration. So immunity defers
removal while a neuron is protected, but it does not suspend the score's ordering when no
unprotected neuron is available to displace.

References: [Mining in Bittensor](https://docs.learnbittensor.org/miners),
[Glossary: Immunity Period](https://docs.learnbittensor.org/resources/glossary#immunity-period)

## Reader Boundary

This page defines the concept at a high level. Which neuron actually holds the lowest pruning score
on a given subnet at a given moment is live subnet state that changes as emissions move, so it
should be read from current chain data rather than inferred here. The durable point is the rule: the
lowest pruning score, then the oldest among ties, is displaced first, with the immunity period
deferring that removal.

References: [Mining in Bittensor](https://docs.learnbittensor.org/miners)
