# Max Call Depth Reached

`MaxCallDepthReached` is a contracts pallet error raised when nested call depth reaches the schedule
limit. The API errors reference summarizes it as "Performing a call was denied because the calling
depth reached the limit of what is specified in the schedule"
([Subtensor API Errors: MaxCallDepthReached](https://docs.learnbittensor.org/subtensor-api/errors#maxcalldepthreached)).

## What It Means

Bittensor runs an Ethereum-compatible execution layer on Subtensor for smart contracts
([Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials)). Contracts can call
other contracts, and each nested call increases the call depth. The contracts schedule sets how deep
that nesting may go. `MaxCallDepthReached` means a further nested call would exceed that schedule
limit, so the runtime denies the call before it proceeds
([Subtensor API Errors: MaxCallDepthReached](https://docs.learnbittensor.org/subtensor-api/errors#maxcalldepthreached)).

This is a call-depth ceiling rejection. It does not, by itself, mean a sandbox memory buffer was out
of bounds, that execution exhausted its gas limit, or that no code exists at a supplied hash.

## Why It Appears

This error appears when contract execution attempts a nested call at a depth that reaches the limit
named in the current contracts schedule
([Subtensor API Errors: MaxCallDepthReached](https://docs.learnbittensor.org/subtensor-api/errors#maxcalldepthreached)).

## Distinction from Out Of Bounds

`MaxCallDepthReached` and `OutOfBounds` are different contracts pallet errors with different API
summaries. `MaxCallDepthReached` is summarized as "Performing a call was denied because the calling
depth reached the limit of what is specified in the schedule." `OutOfBounds` is summarized as "A
buffer outside of sandbox memory was passed to a contract API function."
([Subtensor API Errors: OutOfBounds](https://docs.learnbittensor.org/subtensor-api/errors#outofbounds),
[Subtensor API Errors: MaxCallDepthReached](https://docs.learnbittensor.org/subtensor-api/errors#maxcalldepthreached)).

- **MaxCallDepthReached** — nested call depth reached the schedule limit.
- **OutOfBounds** — a buffer outside sandbox memory was passed to a contract API function.

## Distinction from Out Of Gas

`MaxCallDepthReached` and `OutOfGas` both stop contract execution, but on different checks.
`MaxCallDepthReached` denies a nested call because call depth reached the schedule limit. `OutOfGas`
means the executed contract exhausted its gas limit
([Subtensor API Errors: OutOfGas](https://docs.learnbittensor.org/subtensor-api/errors#outofgas),
[Subtensor API Errors: MaxCallDepthReached](https://docs.learnbittensor.org/subtensor-api/errors#maxcalldepthreached)).

- **MaxCallDepthReached** — nested call depth reached the schedule limit.
- **OutOfGas** — the executed contract exhausted its gas limit.

## Reader Boundary

This page defines the meaning of the error label from the API reference. It does not report the live
call-depth limit configured on a network or redesign a contract's call graph
([Subtensor API Errors: MaxCallDepthReached](https://docs.learnbittensor.org/subtensor-api/errors#maxcalldepthreached),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
