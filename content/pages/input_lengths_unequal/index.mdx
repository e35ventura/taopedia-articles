# Input Lengths Unequal

`InputLengthsUnequal` is a documented Subtensor standard error raised by batch weight extrinsics.
The standard-errors reference describes it as "Mismatched vector input lengths in batch reveal"
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#inputlengthsunequal)).

## What It Means

Batch weight extrinsics accept several parallel vectors that must line up one entry at a time. For
example, a batch commit pairs each target network with one commit hash, and a batch reveal pairs
each reveal's UID list, value list, salt, and version key. `InputLengthsUnequal` means those
parallel vectors were not all the same length, so the extrinsic is rejected before any per-entry
work begins
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#inputlengthsunequal),
[Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs)).

In `weights.rs`, the batch commit path compares `netuids` against `commit_hashes`, the batch reveal
path compares `uids_list`, `values_list`, `salts_list`, and `version_keys`, and the batch
`set_weights` path compares `netuids`, `weights`, and `version_keys`. Each path returns
`InputLengthsUnequal` when the required lengths do not match
([Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs)).

## Why It Appears

This error is a structural input check, not a network-state check. It fires when the caller built
the batch payload with mismatched vector sizes, such as one fewer commit hash than network entry, or
one reveal block missing a salt or version key. The rejection happens before registration, commit
queue, or reveal timing logic is evaluated
([Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs)).

For a reader, the practical meaning is narrow: the batch arrays do not line up entry by entry. The
problem is not an expired commit, a disabled commit-reveal scheme, or an invalid weight value inside
one row
([Subtensor Standard Errors: ExpiredWeightCommit](https://docs.learnbittensor.org/errors/subtensor#expiredweightcommit),
[Subtensor Standard Errors: CommitRevealDisabled](https://docs.learnbittensor.org/errors/subtensor#commitrevealdisabled)).

## Distinction from Weight Vec Not Equal Size

`InputLengthsUnequal` and `WeightVecNotEqualSize` both concern mismatched vector lengths, but at
different scopes. `WeightVecNotEqualSize` applies to a single `set_weights` call and compares the
UID list against the value list inside one weight vector. `InputLengthsUnequal` applies to batch
extrinsics and compares the top-level parallel vectors that describe multiple operations in one call
([Weight Vec Not Equal Size](https://docs.learnbittensor.org/errors/subtensor#weightvecnotequalsize),
[Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#inputlengthsunequal),
[Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs)).

- **WeightVecNotEqualSize** — one weight vector's UID and value lists differ in length.
- **InputLengthsUnequal** — the batch extrinsic's parallel input vectors differ in length.

## Reader Boundary

This page defines the meaning of the error label and the batch vector-length comparisons that raise
it. It does not describe per-entry validation inside a batch, reveal timing, or the minimum-length
rules that apply after the batch shape check passes
([Subtensor source: weights.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/subnets/weights.rs)).
