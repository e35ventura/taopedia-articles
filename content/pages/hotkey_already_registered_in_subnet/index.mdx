# Hotkey Already Registered In Subnet

HotKeyAlreadyRegisteredInSubNet means a registration call tried to assign a neuron slot to a hotkey
that already holds one on the targeted subnet. The standard-errors reference describes it as "The
caller is requesting a redundant registration for a neuron"
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#hotkeyalreadyregisteredinsubnet)).

Subnet registration gives a hotkey a UID on one subnet at a time through the burned registration
path described in the Bittensor glossary
([Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register)).

## What It Means

Each subnet tracks which hotkeys already occupy neuron slots. When a registration call targets a
subnet where the hotkey is already listed, the chain rejects the duplicate attempt instead of
creating a second slot or replacing the existing one
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#hotkeyalreadyregisteredinsubnet)).

Membership is scoped per subnet. The same hotkey may still register on other subnets where it has no
slot yet, but it cannot register twice on the same subnet through this path.

This error is about duplicate membership, not about subnet capacity, registration being turned off,
or the hotkey being absent on a different subnet. A full subnet raises
[[no_neuron_id_available|No Neuron Id Available]]. A closed registration gate raises
[[subnet_registration_disabled|Subnet Registration Disabled]]. The opposite missing-slot case is
[[hotkey_not_registered_in_subnet|Hotkey Not Registered In Subnet]].

## Why It Appears

The usual cause is submitting registration again for a hotkey that already occupies a slot on the
chosen subnet. Retry logic, copied transactions, or automation that does not refresh registration
state first can hit this error even when burn balance and coldkey pairing would otherwise succeed.

The practical meaning is narrow: the hotkey already has a slot on that subnet, so the registration
call is redundant rather than competing for a new UID.

## Distinction from Hotkey Not Registered In Subnet

These errors describe opposite membership outcomes on the same subnet lookup.
HotKeyAlreadyRegisteredInSubNet appears when registration is attempted for a hotkey that already
holds a UID there. HotKeyNotRegisteredInSubNet appears when another subnet-scoped operation, such as
weight submission, requires a UID the hotkey does not have on the targeted subnet
([Subtensor Standard Errors: HotKeyNotRegisteredInSubNet](https://docs.learnbittensor.org/errors/subtensor#hotkeynotregisteredinsubnet)).

See [[hotkey_not_registered_in_subnet|Hotkey Not Registered In Subnet]] for the missing-slot case.

## Distinction from No Neuron Id Available

Both errors can appear while troubleshooting registration, but they mean different things.
HotKeyAlreadyRegisteredInSubNet means the hotkey already holds a UID on the subnet.
NoNeuronIdAvailable means the subnet has no free neuron slots left for a new registration
([Subtensor Standard Errors: NoNeuronIdAvailable](https://docs.learnbittensor.org/errors/subtensor#noneuronidavailable)).

See [[no_neuron_id_available|No Neuron Id Available]] for the capacity case.
