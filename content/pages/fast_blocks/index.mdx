# Fast Blocks

Fast blocks are a Bittensor term for accelerated block production in a local development chain. The
glossary places the term in local development and gives the accelerated interval as 250 milliseconds
([Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks)).

The important boundary is environment. Fast blocks describe local timing, not public network timing.
They help readers recognize when an example is using compressed local block production rather than
ordinary shared-network cadence.

## Local Timing Context

Fast blocks belong to local blockchain context. A local blockchain is private, isolated, and used
for development and testing, so fast blocks should be read as a local timing label attached to that
environment
([Glossary: Local Blockchain](https://docs.learnbittensor.org/resources/glossary#local-blockchain),
[Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks)).

That scope keeps the term from being overread. A local example can move through many blocks quickly
when fast blocks are in use, but that does not make the same wall-clock timing true for mainnet or
testnet.

## Interval Contrast

The contrast with non-fast blocks is the clearest way to read the term. Fast blocks use accelerated
250 millisecond intervals, while non-fast blocks keep Subtensor's default twelve-second local block
interval ([Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks),
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)).

Both terms describe local block timing. Fast blocks compress elapsed time between locally produced
blocks; non-fast blocks preserve the ordinary interval. The difference is about local pacing, not
about different subnet roles or a separate Bittensor network.

## Network Boundary

Bittensor documentation separates mainnet, testnet, and localnet contexts. Fast blocks sit inside
the localnet side of that distinction because they describe local block production rather than a
shared network property
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks)).

This matters when an article mentions block-dependent behavior. A fast-block example can explain why
local observations advance quickly in wall-clock time, but the example should stay tied to the local
environment unless a source supports the same timing elsewhere.

## Block Evidence

A block is the unit of chain progression, while fast blocks describe how quickly those units are
produced in the local fast-block setting
([Glossary: Block](https://docs.learnbittensor.org/resources/glossary#block),
[Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks)).

That makes fast blocks useful context for interpreting local examples built around block counts,
tempos, or other block-dependent observations. The block count may be meaningful, but the shortened
wall-clock interval is part of the local timing context.

## Reader Boundary

This article explains the fast-blocks concept. It does not provide local-chain procedures, diagnose
node behavior, or report current public network timing. Claims about fast blocks should stay tied to
local development timing unless another source supports a broader network claim
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks)).
