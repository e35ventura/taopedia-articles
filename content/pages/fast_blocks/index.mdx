# Fast Blocks

Fast blocks are a local-development timing mode for Bittensor chains. The glossary defines them as a
development-only local-chain configuration that accelerates block production to 250 millisecond
intervals ([Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks)).

The term is useful because it prevents local timing examples from being mistaken for public network
behavior. Fast blocks describe how quickly a private development chain can produce blocks, not how
mainnet or testnet is expected to progress.

## Local Blockchain Context

Fast blocks belong to local blockchain work. A local blockchain is private, isolated, and used for
development and testing, so faster block production is a way to shorten feedback loops inside that
local environment
([Glossary: Local Blockchain](https://docs.learnbittensor.org/resources/glossary#local-blockchain),
[Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks)).

That local scope is the main reader boundary. A result observed under fast blocks can be useful for
checking how block-based behavior appears in a private chain, but it should not be treated as
evidence about public network cadence.

## Timing Meaning

The defining detail is the accelerated interval. Fast blocks use 250 millisecond block production,
while non-fast local blocks follow the default twelve-second interval
([Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks),
[Glossary: Non-fast blocks](https://docs.learnbittensor.org/resources/glossary#non-fast-blocks)).

Both terms are local-development timing labels. Fast blocks compress the wall-clock time between
blocks; non-fast blocks keep local testing closer to the ordinary block interval. Neither term
creates a separate public network or subnet role.

## Network Boundary

Bittensor separates mainnet, testnet, and localnet contexts. Fast blocks sit on the localnet side of
that distinction because they describe a local timing configuration rather than a property of shared
network operation
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks)).

This matters whenever an example depends on elapsed block count. A local fast-block example may
advance through many blocks quickly, but that speed is part of the local configuration. It should
not be generalized to testnet or mainnet timing without a source for that environment.

## Development Use

Local deployment documentation places block timing among local chain configuration choices. In that
context, fast blocks let development testing move through block-based behavior more quickly than a
production-like interval would allow
([Run a Local Bittensor Blockchain Instance](https://docs.learnbittensor.org/local-build/deploy),
[Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks)).

The article-level point is conceptual rather than procedural. Fast blocks identify the timing mode;
the official local-build documentation remains the source for how a local chain is configured or
run.

## Evidence Boundary

Fast-block evidence supports claims about local timing, not claims about production performance. It
can explain why a local test moved through block-dependent behavior quickly, but it does not prove
that the same wall-clock timing applies to mainnet, testnet, subnet rewards, or public chain state
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Glossary: Fast blocks](https://docs.learnbittensor.org/resources/glossary#fast-blocks)).

Readers should keep the environment attached to the claim. If a paragraph says an example used fast
blocks, the claim should remain local-development scoped unless another source supports the same
timing in a shared network context.

## Reader Boundary

This article explains the fast-blocks term. It does not provide configuration walkthroughs,
reproduce local deployment procedures, diagnose node behavior, or report current public network
timing. Those details belong to the relevant local-build documentation and the selected network
context
([Run a Local Bittensor Blockchain Instance](https://docs.learnbittensor.org/local-build/deploy),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
