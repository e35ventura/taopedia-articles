# Decoding Failed

`DecodingFailed` is a contracts pallet error raised when input passed to a contract API function
cannot be decoded as the expected type. The API errors reference summarizes it as "Input passed to a
contract API function failed to decode as expected type"
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed)).

## What It Means

Subtensor includes a contracts pallet for on-chain smart contracts. Contract API functions expect
caller-supplied input bytes to decode into a specific type before the runtime can use them.
`DecodingFailed` means those bytes do not match the expected encoding, so the API call is rejected
before it proceeds
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed)).

This is an input-decoding rejection. It does not, by itself, mean a buffer was passed outside
sandbox memory, that the contract exhausted its gas limit, or that no code exists at a supplied
hash.

## Why It Appears

This error appears when a contract API function receives input that cannot be decoded into the type
the API expects
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed)).

## Distinction from Out Of Bounds

`DecodingFailed` and `OutOfBounds` both stop a contract API call, but on different checks.
`DecodingFailed` is summarized as "Input passed to a contract API function failed to decode as
expected type." `OutOfBounds` is summarized as "A buffer outside of sandbox memory was passed to a
contract API function."
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed),
[Subtensor API Errors: OutOfBounds](https://docs.learnbittensor.org/subtensor-api/errors#outofbounds)).

- **DecodingFailed** — the input bytes do not decode as the expected type.
- **OutOfBounds** — a buffer outside sandbox memory was passed to the API function.

## Distinction from Input Forwarded

`DecodingFailed` and `InputForwarded` both involve contract API input, but the API summaries name
different problems. `DecodingFailed` means the bytes cannot be decoded as the expected type.
`InputForwarded` is summarized as "`seal_call` forwarded this contracts input. It therefore is no
longer available."
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed),
[Subtensor API Errors: InputForwarded](https://docs.learnbittensor.org/subtensor-api/errors#inputforwarded)).

- **DecodingFailed** — the input bytes do not decode as the expected type.
- **InputForwarded** — the input was already forwarded by `seal_call` and is no longer available.

## Reader Boundary

This page defines the meaning of the error label from the API reference. It does not validate a
specific input payload on a network or redesign a contract's encoding scheme
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
