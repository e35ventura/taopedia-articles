# Decoding Failed

DecodingFailed means a smart contract call received input that could not be read in the format the
call expected. The API errors reference describes it as input that "failed to decode as expected
type"
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed)).

## What It Means

Smart contract calls depend on correctly formatted input. DecodingFailed means the bytes or values
supplied with the call did not match what the contract side expected, so the call is rejected before
it can proceed on that basis
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed)).

For a reader, the practical meaning is narrow. The problem is with how the input was supplied, not
with subnet policy, wallet balance, or whether a contract exists at the target address.

This is an input-format failure. It does not, by itself, mean the contract faulted mid-run, that a
value exceeded the runtime size limit, or that a buffer fell outside the allowed memory range.

## Why It Appears

This error appears when the input attached to a contract call cannot be decoded into the expected
format
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed)).

When debugging, compare against nearby contract input errors. [[value_too_large|Value Too Large]]
means a value exceeded the configured size limit. [[out_of_bounds|Out Of Bounds]] means a buffer was
supplied outside the allowed memory range
([Subtensor API Errors: ValueTooLarge](https://docs.learnbittensor.org/subtensor-api/errors#valuetoolarge),
[Subtensor API Errors: OutOfBounds](https://docs.learnbittensor.org/subtensor-api/errors#outofbounds)).

## Distinction from Value Too Large

DecodingFailed and [[value_too_large|Value Too Large]] both involve contract input limits, but they
fail for different reasons. Value Too Large means a value exceeded the runtime's configured maximum
size. DecodingFailed means the call input could not be interpreted in the shape the contract
expected
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed),
[Subtensor API Errors: ValueTooLarge](https://docs.learnbittensor.org/subtensor-api/errors#valuetoolarge)).

## Distinction from Out Of Bounds

DecodingFailed and [[out_of_bounds|Out Of Bounds]] both stop a contract call early, but for
different input problems. Out Of Bounds means a buffer was passed outside the allowed memory range.
DecodingFailed means the supplied input could not be decoded into the expected format
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed),
[Subtensor API Errors: OutOfBounds](https://docs.learnbittensor.org/subtensor-api/errors#outofbounds)).

## Distinction from Contract Trapped

DecodingFailed and ContractTrapped both block a contract call from succeeding, but they describe
different failures. DecodingFailed means the input could not be read in the expected format before
the call could proceed on that basis. ContractTrapped means the contract faulted during the run
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed),
[Subtensor API Errors: ContractTrapped](https://docs.learnbittensor.org/subtensor-api/errors#contracttrapped)).

## Reader Boundary

This page defines the meaning of the error label and the input-format rejection it represents. It
does not identify the exact field that failed to decode or prescribe how a specific contract should
encode its arguments; those depend on contract code and call parameters at submission time
([Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
