# Decoding Failed

`DecodingFailed` is a contracts pallet error raised when call input cannot be decoded into the
expected type. The API errors reference describes it as input that "failed to decode as expected
type"
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed)).

## What It Means

Bittensor runs an Ethereum-compatible execution layer on Subtensor for smart contracts
([Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials)). DecodingFailed
means the bytes or values supplied with a contract call did not match the shape the call expected,
so the runtime rejects the call before it can proceed on that basis
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed)).

This is a pre-execution input decode failure. It does not, by itself, mean the contract trapped
during execution, that a value exceeded the runtime size limit, or that a buffer fell outside the
allowed memory range.

## Why It Appears

This error appears when the input attached to a contract call cannot be decoded into the expected
format
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed)).

The practical meaning is narrow: the problem is with how the input was encoded or supplied, not with
subnet policy, wallet balance, or whether a contract exists at the target address.

## Distinction from Value Too Large

`DecodingFailed` and `ValueTooLarge` are different contracts pallet errors with different API
summaries. `DecodingFailed` is summarized as input that "failed to decode as expected type."
`ValueTooLarge` is summarized as "The size defined in `T::MaxValueSize` was exceeded"
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed),
[Subtensor API Errors: ValueTooLarge](https://docs.learnbittensor.org/subtensor-api/errors#valuetoolarge)).

- **DecodingFailed** — input could not be read in the expected format.
- **ValueTooLarge** — a supplied value exceeded the configured size limit.

## Distinction from Out Of Bounds

`DecodingFailed` and `OutOfBounds` both stop a contract call early, but at different input checks.
`OutOfBounds` is summarized as "A buffer outside of sandbox memory was passed to a contract API
function." `DecodingFailed` is summarized as input that "failed to decode as expected type"
([Subtensor API Errors: OutOfBounds](https://docs.learnbittensor.org/subtensor-api/errors#outofbounds),
[Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed)).

- **OutOfBounds** — a buffer was outside the allowed sandbox memory range.
- **DecodingFailed** — input could not be decoded into the expected format.

## Distinction from Contract Trapped

`DecodingFailed` and `ContractTrapped` fail at different stages. `DecodingFailed` means the input
could not be decoded before the call could proceed. `ContractTrapped` means contract execution
trapped during the call
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed),
[Subtensor API Errors: ContractTrapped](https://docs.learnbittensor.org/subtensor-api/errors#contracttrapped)).

- **DecodingFailed** — input decode failed before execution proceeded.
- **ContractTrapped** — execution trapped during the call.

## Reader Boundary

This page defines the meaning of the error label and the input decode check it represents. It does
not identify which field failed to decode for a specific contract call; that depends on contract
code and call parameters at submission time
([Subtensor API Errors: DecodingFailed](https://docs.learnbittensor.org/subtensor-api/errors#decodingfailed),
[Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials)).
