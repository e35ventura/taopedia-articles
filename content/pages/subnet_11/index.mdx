# Subnet 11: TrajectoryRL

TrajectoryRL is Bittensor Subnet 11 (SN11), operated by [TrajectoryRL](https://trajrl.com/). The
subnet positions itself as an Agentic Reinforcement Learning as a Service platform, optimizing AI
agent trajectories to make agents cheaper, safer, and more reliable. Rather than training neural
networks, the subnet runs an ongoing open competition where participants engineer plain-text
instruction files — called SKILL.md packs — that teach a testee language model how to solve
operational tasks such as coding, system administration, file operations, and debugging.

References: [trajectoryRL/trajectoryRL (GitHub)](https://github.com/trajectoryRL/trajectoryRL),
[trajrl.com](https://trajrl.com/)

## How the Mechanism Works

The core mechanism is winner-take-all with a challenger threshold. At any point one pack holds the
"seated winner" position and earns 100% of miner emissions. A new pack can only dethrone the
incumbent if it improves on the seated winner's score by more than 3%. This threshold prevents
trivial perturbations from cycling the seat and rewards genuinely better instruction engineering.

Pack ownership is content-addressed: the SHA256 hash of a pack's content is its permanent
identifier. The first hotkey to submit a given hash owns it permanently. This makes authorship
verifiable on-chain without requiring miners to reveal the full contents at registration time.

Evaluation is handled by a Terminal-Bench harness that validators run independently. Each evaluation
scenario provides the testee language model with the submitted SKILL.md alongside a task, then
measures passed tests against total tests. The aggregate score determines whether a challenger pack
has cleared the 3% improvement threshold required to claim the seat.

Validator scores feed into [[Yuma Consensus]], which translates the weight-setting results into
per-block TAO emissions distributed through [[Dynamic TAO]].

References: [trajectoryRL/trajectoryRL (GitHub)](https://github.com/trajectoryRL/trajectoryRL),
[trajrl.com](https://trajrl.com/)

## Participating as a Miner

Miners on TrajectoryRL compete by writing SKILL.md instruction files — structured plain-text
documents that teach an AI agent how to handle a class of operational tasks. No GPU hardware is
required; the work is pure instruction engineering, where quality is measured entirely by how much
the submitted file improves a testee model's task-completion rate on the Terminal-Bench evaluation
suite.

The economics are sharply binary. The single pack currently holding the seated winner position earns
all miner alpha each block. Every other registered miner earns nothing until they submit a pack that
exceeds the seated winner's benchmark score by more than 3%. This winner-take-all structure means
miners are incentivized to invest heavily in quality rather than submitting incremental variations.

Pack ownership transfers automatically when a challenger wins the seat, so the miner behind the
best-performing instruction file at any given moment collects the full emission share without
splitting it with other participants.

Reference: [trajectoryRL/trajectoryRL (GitHub)](https://github.com/trajectoryRL/trajectoryRL)

## Participating as a Validator

Validators on TrajectoryRL run the Terminal-Bench evaluation harness, the independent scoring
infrastructure that determines which pack holds the seated winner position. For each evaluation
cycle, a validator fetches the challenger pack, spins up isolated task containers for each scenario
in the benchmark suite, and measures how many tests the testee language model passes when given the
SKILL.md as context.

Validator scores are signed and reported on-chain. Validators that agree with the accurate outcome —
correctly identifying whether a challenger clears the 3% improvement threshold — are rewarded
through [[Yuma Consensus]] bond dynamics, which favor early and accurate agreement with the eventual
consensus. Validators that report scores inconsistently with the broader set receive reduced
emissions.
