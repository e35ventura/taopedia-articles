# Multiple Incentive Mechanisms

Multiple incentive mechanisms let one Bittensor subnet keep more than one evaluation context. Each
context can measure a different kind of miner work while still belonging to the same subnet
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms),
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

The term belongs to subnet design vocabulary. It describes separate evaluation contexts inside one
subnet, not a recommendation, launch guide, or live report about a specific subnet.

## Single-Mechanism Contrast

An incentive mechanism connects work, validation, and reward incentives for a subnet. A subnet with
one mechanism has one evaluation context for the relevant work, while a subnet with multiple
mechanisms can keep those contexts separate
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

For readers, the important difference is separation. Multiple mechanisms do not simply mean more
activity; they mean more than one evaluation context within the subnet.

## Evaluation Separation

In a multi-mechanism subnet, validator evaluation is read per mechanism. Miner performance in one
mechanism should not be treated as the same evaluation result in another mechanism
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms),
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

This keeps mechanism-specific work from being blended into one subnet-wide score. A claim about one
mechanism should stay attached to that mechanism.

## Bond Context

The glossary connects each mechanism with its own bond-pool context. That matters because bonds are
part of how validator-miner relationships feed Yuma Consensus
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

For readers, the useful point is that mechanism separation can also separate bond context. The
article does not need to reproduce the lower-level mechanics to explain that boundary.

## Subnet Creator Context

Multiple incentive mechanisms are part of subnet design. A subnet creator can use separate
mechanisms to organize different kinds of work or evaluation criteria within one subnet
([Glossary: Subnet Creator](https://docs.learnbittensor.org/resources/glossary#subnet-creator),
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

This keeps the term tied to design context. It does not change the meaning of ordinary miner,
validator, staking, or emission vocabulary by itself.

## Task and Scoring Boundary

Mechanism separation can also separate task and scoring context. A task names the work miners are
asked to perform, while a scoring model names how returned work is judged
([Glossary: Subnet Task](https://docs.learnbittensor.org/resources/glossary#subnet-task),
[Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)).

That boundary keeps one mechanism's task or scoring standard from being read as the only task or
standard for the whole subnet.

## Reader Boundary

Multiple incentive mechanisms should be read as concept vocabulary for separate evaluation contexts
inside one subnet. It is not a claim about how many mechanisms a named subnet has, not a design
recommendation, and not a substitute for the documentation of a specific subnet
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).

The stable article-level point is that multiple incentive mechanisms let one subnet separate work,
evaluation, and bond context by mechanism.
