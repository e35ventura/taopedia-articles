# Multiple Incentive Mechanisms

Multiple incentive mechanisms let one Bittensor subnet host more than one independent evaluation
system. Each mechanism can have its own bond-pool context for Yuma Consensus calculations, and
validators evaluate miners separately for each mechanism
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms),
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

The term belongs to subnet design vocabulary. It describes parallel evaluation systems inside one
subnet, not a recommendation to use any particular design or a statement about every subnet.

## Single-Mechanism Contrast

An incentive mechanism connects subnet work, validator evaluation, and incentive outcomes inside a
subnet. Multiple incentive mechanisms extend that model by allowing several evaluation contexts to
coexist inside the same subnet
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

For readers, the distinction is separation. A single mechanism has one evaluation context; multiple
mechanisms allow separate contexts inside one subnet market.

## Evaluation Separation

When a subnet uses multiple incentive mechanisms, validator evaluation is mechanism-specific. Miner
performance in one mechanism should not be treated as the same rating picture in another mechanism
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms),
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

This separation keeps mechanism-specific tasks, protocols, and scoring models from being blended
into a single subnet-wide evaluation claim.

## Bond Pool Context

Each mechanism in a multi-mechanism subnet can use its own bond pool for Yuma Consensus
calculations. Yuma Consensus uses validator-miner bond context when aggregating validator signals,
while multiple-mechanism vocabulary adds that bond context can be separated by mechanism
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).

For readers, bond-pool separation is part of what makes the mechanisms independent. It is not just
more miners or validators inside an otherwise single evaluation path.

## Subnet Creator Context

Multiple incentive mechanisms are a subnet-design choice. Subnet creators can use separate
mechanisms to organize different kinds of work or evaluation criteria within one subnet
([Glossary: Subnet Creator](https://docs.learnbittensor.org/resources/glossary#subnet-creator),
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

This keeps the concept tied to subnet design. It does not change the meaning of miner, validator,
staking, or network-wide emission vocabulary by itself.

## Task and Scoring Boundary

Multiple incentive mechanisms can create separate task and scoring contexts. A task names the work
miners are asked to perform, and a scoring model names how returned work is evaluated
([Glossary: Subnet Task](https://docs.learnbittensor.org/resources/glossary#subnet-task),
[Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model)).

That boundary matters because a mechanism-specific task or scoring standard should not be read as
the only task or scoring standard for the whole subnet.

## Emission Boundary

Multiple incentive mechanisms can shape how evaluation is organized before rewards are allocated,
but the term is not a replacement for emission vocabulary. Emission documentation covers the broader
TAO and alpha-token reward flow ([Emission](https://docs.learnbittensor.org/learn/emissions),
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

For readers, mechanism separation explains evaluation context. Emission sources explain the reward
flow that uses evaluated results.

## Reader Boundary

Multiple incentive mechanisms should be read as a concept for parallel evaluation systems inside one
subnet. It is not a deployment recommendation, a claim about a specific subnet's mechanism count, or
a substitute for the single-mechanism incentive vocabulary used in ordinary subnet reading
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).

The stable article-level point is that multiple incentive mechanisms let one subnet separate tasks,
evaluation, and bond-pool context by mechanism.
