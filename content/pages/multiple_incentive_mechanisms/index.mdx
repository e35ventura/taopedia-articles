# Multiple Incentive Mechanisms

Multiple incentive mechanisms let one Bittensor subnet run more than one evaluation system. Each
mechanism is read as its own context for miner evaluation, validator weights, and bond tracking
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).

The concept extends the ordinary incentive mechanism idea rather than replacing it
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)).

## Single Mechanism Contrast

A single incentive mechanism connects subnet work, validator evaluation, and incentive outcomes
inside one evaluation context. Multiple incentive mechanisms mean one subnet can host several such
contexts in parallel
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

For readers, the key distinction is separation. The subnet is still one subnet, but the evaluation
contexts inside it can be distinct
([Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

## Evaluation Separation

When a subnet uses multiple mechanisms, miner performance in one mechanism is not automatically the
same rating in another. The mechanisms are meant to preserve separate evaluation contexts
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).

This matters because one subnet can support different work types or evaluation criteria without
collapsing all results into one undifferentiated score
([Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

## Bond Pool Context

Multiple incentive mechanisms also separate bond-pool context. Each mechanism can have its own bond
pool for Yuma Consensus calculations
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).

For readers, bond-pool separation is part of what makes the mechanisms independent. It keeps
validator-miner relationships tied to the relevant mechanism rather than treating every mechanism as
one shared bond context ([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

## Weight Context

Validator weights still matter in a multi-mechanism subnet, but they should be read in the context
of the mechanism they belong to. A weight signal for one mechanism is not automatically a statement
about every other mechanism in the subnet
([Glossary: Validator Weights](https://docs.learnbittensor.org/resources/glossary#validator-weights)).

That context helps explain why multiple mechanisms are more than a labeling feature. They separate
evaluation, bond pools, and weight interpretation inside one subnet
([Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

## Subnet Design Context

Multiple incentive mechanisms are a subnet design concept. They let one subnet support parallel
evaluation paths while keeping each path's rewards and bond context attached to its own mechanism
([Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

The concept should therefore be read at the subnet level, not as a network-wide default and not as a
claim that every subnet has more than one mechanism
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

## Reader Boundary

Multiple incentive mechanisms should be read as a concept for parallel evaluation systems inside one
subnet. They are not a deployment recommendation, a mechanism count for a specific subnet, or a
replacement for Yuma Consensus
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).

The stable article-level point is that one subnet can keep separate evaluation and bond contexts for
different incentive mechanisms
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).
