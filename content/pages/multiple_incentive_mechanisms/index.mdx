# Multiple Incentive Mechanisms

Multiple incentive mechanisms let one Bittensor subnet support separate evaluation systems for
different kinds of work
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).

The idea builds on the ordinary incentive mechanism concept: an incentive mechanism connects subnet
work, validator evaluation, and reward outcomes
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)).

## One Subnet, Separate Evaluations

The important reader-facing point is that one subnet can contain more than one evaluation path. Each
path can judge a different kind of work while still belonging to the same subnet
([Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

This is different from simply adding more miners to one evaluation path. Multiple mechanisms keep
the evaluation settings separate so that one mechanism's results are not automatically the results
of another
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).

## Miner Rating Context

Multiple mechanisms preserve separate miner-rating context. A miner can be evaluated one way in one
mechanism and differently in another, depending on what each mechanism is meant to measure
([Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

For readers, this means a multi-mechanism subnet should not be summarized by one undifferentiated
score. The relevant mechanism matters when interpreting miner performance
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).

## Incentive Context

Each mechanism is still an incentive mechanism: it connects work, evaluation, and rewards. The
multiple-mechanism feature changes how many evaluation systems can exist inside one subnet, not the
basic purpose of incentive mechanisms
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

That keeps the concept tied to subnet design rather than to a separate network-wide reward category
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

## Yuma Consensus Context

Multiple incentive mechanisms still sit within Bittensor's consensus vocabulary. Yuma Consensus is
the broader process that turns validator evaluation into subnet outcomes
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

The multiple-mechanism concept explains how a subnet can keep more than one evaluation path distinct
before those outcomes are interpreted
([Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

## Reader Boundary

Multiple incentive mechanisms should be read as a concept for parallel evaluation systems inside one
subnet. They are not a claim that every subnet has multiple mechanisms, and they are not a
replacement for the ordinary incentive mechanism concept
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).

The stable article-level point is that one subnet can preserve separate evaluation contexts for
different kinds of work
([Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).
