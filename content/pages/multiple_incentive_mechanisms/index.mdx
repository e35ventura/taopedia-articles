# Multiple Incentive Mechanisms

Multiple incentive mechanisms let a Bittensor subnet divide its emissions across more than one
evaluation path. The official Bittensor documentation describes this as a way for one subnet to
support distinct evaluation criteria while keeping the work inside the same subnet. Each mechanism
can evaluate miner performance separately, and the subnet's emissions are distributed across those
mechanisms rather than treated as a single undifferentiated score.

References:
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)

## Why Multiple Mechanisms Exist

An incentive mechanism defines what work a subnet values and how validators evaluate that work. Some
subnets may need to measure more than one kind of contribution. Multiple mechanisms provide a way to
separate those evaluations so one criterion does not have to stand in for every useful output. This
keeps the subnet concept intact while allowing more specialized scoring paths inside it.

References:
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism),
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)

## Separate Evaluation Paths

The official multiple-mechanism documentation says each incentive mechanism has its own weight
matrix, independent bond pools, and independent emissions. In reader terms, that means validator
evaluations are not flattened into one shared column before consensus. A miner can be evaluated
differently across mechanisms because each mechanism represents a distinct task or criterion.

Reference:
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)

## Relationship to Yuma Consensus

The same source describes each mechanism as running Yuma Consensus independently. This is important
because Yuma Consensus is the process that turns validator weights into miner and validator emission
outcomes. With multiple mechanisms, the subnet can run separate consensus paths and then combine the
resulting emission outcomes according to the subnet's mechanism split.

References:
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)

## What Changes for Participants

For miners, separate mechanisms mean performance can be judged independently across different kinds
of work. For validators, the documentation describes separate weight setting and evaluation for each
mechanism, with the same validator stake weight applying across mechanisms in the subnet. For
stakers and readers, the key point is that multiple mechanisms change how a subnet divides its own
emissions internally; they do not create a separate subnet for each criterion.

References:
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets),
[Emissions](https://docs.learnbittensor.org/learn/emissions)

## Careful Interpretation

Multiple incentive mechanisms are not a general guide to running a subnet and are not a claim about
any specific subnet's quality. Exact limits and operational steps should be checked in the official
Bittensor documentation. At the Taopedia level, the core idea is simpler: one subnet can contain
more than one evaluation path, and those paths can receive different portions of the subnet's
emissions.
