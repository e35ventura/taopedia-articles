# Multiple Incentive Mechanisms

Multiple incentive mechanisms let one Bittensor subnet run more than one evaluation system. The
glossary describes separate mechanisms as having their own bond pools for Yuma Consensus
calculations, with validators evaluating miners separately for each mechanism
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).

The concept is about separation inside one subnet. It does not mean every subnet has multiple
mechanisms, and it does not replace the ordinary incentive-mechanism idea of connecting work,
evaluation, and rewards
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)).

## Parallel Evaluation Contexts

A single incentive mechanism provides one rule context for task performance, validator evaluation,
and reward outcomes. Multiple mechanisms allow several such contexts to coexist inside the same
subnet
([Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets),
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)).

That separation matters because performance in one mechanism is not automatically performance in
another. A claim about a miner, rating, or evaluation result should identify which mechanism context
the claim belongs to.

## Bond Pool Separation

The glossary makes bond-pool separation part of the definition. Each mechanism has its own bond pool
for Yuma Consensus calculations, so a multi-mechanism subnet is not just a larger single-mechanism
subnet
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

For readers, the bond-pool boundary is the clearest evidence boundary. If two mechanisms have
separate bond pools, then ratings and bond behavior should be read in the mechanism context that
produced them.

## Validator and Miner Context

Validators evaluate miners separately for each mechanism. That means validator signals, miner
ratings, and evaluation results should not be collapsed into a single subnet-wide score without a
source that supports that aggregation
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms),
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

This keeps the article focused on interpretation rather than operation. The important concept is
parallel evaluation structure, not how to choose, deploy, or tune a specific subnet design.

## Emission Context

Multiple mechanisms can be used to distribute emissions across different kinds of work or evaluation
criteria within one subnet. Emission documentation provides the broader reward-flow context, while
multiple-mechanism documentation explains why those flows may need mechanism-level interpretation
inside the subnet ([Emission](https://docs.learnbittensor.org/learn/emissions),
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

The useful boundary is scope. Multiple incentive mechanisms describe parallel paths inside a subnet;
they do not redefine network-wide emission vocabulary by themselves.

## Evidence Boundary

The multiple-mechanism references support claims about separated evaluation systems, miner ratings,
and bond pools. They do not by themselves prove how many mechanisms a particular subnet currently
uses, whether one mechanism is better than another, or how a specific subnet should be designed.

For readers, the safe use of the term is structural: it identifies parallel evaluation contexts
inside one subnet
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).
