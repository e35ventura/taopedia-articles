# Bittensor Tools

Bittensor tools are the software surfaces developers and participants use to reach Bittensor network
features. Official documentation groups them around developer libraries, terminal interfaces, wallet
and key material, and user-facing tools
([Bittensor Tools](https://docs.learnbittensor.org/concepts/tools),
[Bittensor SDK](https://docs.learnbittensor.org/concepts/tools#bittensor-sdk),
[Bittensor CLI](https://docs.learnbittensor.org/concepts/tools#bittensor-cli),
[Wallets and Keys](https://docs.learnbittensor.org/keys/wallets)).

The label answers an access question: which interface is in use and which audience it serves.
References to subnets, consensus, and governance still name the network rules behind the feature
being reached
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Governance](https://docs.learnbittensor.org/governance)).

## Developer Libraries and Terminal Surfaces

The [Bittensor SDK](https://docs.learnbittensor.org/concepts/tools#bittensor-sdk) is the
programmatic surface for building applications that integrate with Bittensor
([Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction)). Terminal tools
such as [BTCLI](https://docs.learnbittensor.org/btcli) support direct interaction through a
command-line interface rather than through application code
([BTCLI Overview](https://docs.learnbittensor.org/btcli/overview),
[Bittensor CLI](https://docs.learnbittensor.org/concepts/tools#bittensor-cli)).

Wallet and key vocabulary sits alongside both surfaces because signed network actions depend on
account material, but the tool name still refers to the interface rather than to ownership of keys
([Wallets and Keys](https://docs.learnbittensor.org/keys/wallets),
[Bittensor Tools](https://docs.learnbittensor.org/concepts/tools#wallets-and-keys)).

## Tools and Participant Roles

Developers, miners, validators, and subnet creators can all use Bittensor tools, yet the interface
does not define the role. Subnet documentation explains work and evaluation; tool documentation
explains how participants reach those features
([Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Bittensor Tools](https://docs.learnbittensor.org/concepts/tools)).

## Network Environment Context

The
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction#subnet-development)
describes subnet work across localnet, testnet, and mainnet. The
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks) reference keeps
those environments separate so tool-related claims stay tied to the network where they apply.

## Distinction from BTCLI

Bittensor tools names the interface layer around the network — developer libraries, terminal
surfaces, and wallet interfaces. BTCLI is one terminal surface within that layer for wallet and
chain actions; it does not define subnet roles or consensus rules
([Bittensor Tools](https://docs.learnbittensor.org/concepts/tools),
[BTCLI](https://docs.learnbittensor.org/btcli),
[Bittensor SDK](https://docs.learnbittensor.org/concepts/tools#bittensor-sdk)).

## Distinction from Bittensor Python SDK

Bittensor tools cover both developer-library and terminal surfaces. The Python SDK is the
programmatic integration path, while BTCLI and other terminal tools support direct interaction
without application code
([Bittensor SDK](https://docs.learnbittensor.org/concepts/tools#bittensor-sdk),
[Bittensor CLI](https://docs.learnbittensor.org/concepts/tools#bittensor-cli),
[Wallets and Keys](https://docs.learnbittensor.org/concepts/tools#wallets-and-keys)). Account
identity remains separate from whichever tool interface is used.

## Reader Boundary

Bittensor tools should not be read as subnet roles, consensus mechanisms, or governance processes.
They name practical access vocabulary for SDK, terminal, wallet, and user-facing surfaces around the
network ([Bittensor Tools](https://docs.learnbittensor.org/concepts/tools),
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction)).

Tools answer which software surface is being used. Subnet, consensus, and governance references
explain the network concepts those surfaces reach
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Governance](https://docs.learnbittensor.org/governance)).
