# Bittensor Tools

Bittensor tools are software interfaces around the Bittensor network. They include the SDK, terminal
surfaces, and wallet/key material used to interact with network features
([Bittensor Tools: SDK](https://docs.learnbittensor.org/concepts/tools#bittensor-sdk),
[Bittensor Tools: CLI](https://docs.learnbittensor.org/concepts/tools#bittensor-cli),
[Bittensor Tools: Wallets and Keys](https://docs.learnbittensor.org/concepts/tools#wallets-and-keys),
[Wallets and Keys](https://docs.learnbittensor.org/keys/wallets)).

The tool name answers an access question: which software surface is being used, and which audience
is it meant to serve. Subnet, consensus, and governance references still explain the network rules
behind the feature being reached
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Governance](https://docs.learnbittensor.org/governance)).

## Interface Layer

Tooling sits around Bittensor roles and features. A tool can help a developer, miner, validator, or
subnet creator reach information or submit network-facing activity
([Bittensor Tools](https://docs.learnbittensor.org/concepts/tools),
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction)).

That makes the tool layer practical rather than purely conceptual. It identifies the interface used
to reach a feature: a developer library, terminal surface, wallet/key system, or user-facing tool
([Wallets and Keys](https://docs.learnbittensor.org/keys/wallets)).

## Tool Families

Bittensor tooling includes developer libraries, terminal interfaces, and account material
([Bittensor Tools](https://docs.learnbittensor.org/concepts/tools)).

Those families differ by reader and task. Libraries support software integration, terminal surfaces
support direct interaction, and wallet/key material explains the account and signing surface around
network use
([Bittensor Tools: Wallets and Keys](https://docs.learnbittensor.org/concepts/tools#wallets-and-keys),
[Wallets and Keys](https://docs.learnbittensor.org/keys/wallets)).

## SDK Surface

The SDK belongs to the developer-library side of the tool family. It gives software a programmatic
surface for Bittensor features
([Bittensor Tools: SDK](https://docs.learnbittensor.org/concepts/tools#bittensor-sdk),
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction)).

That makes SDK language strongest when the subject is integration, application behavior, or a
software surface around the network. It is weaker by itself when the subject is a subnet task,
incentive mechanism, or governance process.

## Terminal and User Interfaces

Terminal and user-facing tools help people interact with Bittensor without writing an integration.
The tools overview treats the terminal surface separately from the SDK because the audience and use
shape are different
([Bittensor Tools: CLI](https://docs.learnbittensor.org/concepts/tools#bittensor-cli),
[Bittensor CLI](https://docs.learnbittensor.org/btcli),
[BTCLI Overview](https://docs.learnbittensor.org/btcli/overview)).

Wallet/key material is nearby because accounts and signing are part of using the network. That
material is useful for explaining account context, while terminal references identify the
user-facing surface
([Bittensor Tools: Wallets and Keys](https://docs.learnbittensor.org/concepts/tools#wallets-and-keys),
[Wallets and Keys](https://docs.learnbittensor.org/keys/wallets)).

## Role and Subnet Context

Miners, validators, subnet creators, and developers can all use tools, but the tool does not define
the role. The Bittensor introduction frames Bittensor around subnets, miners, validators, and
digital commodities; tools are the software surfaces around that structure
([Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

Subnets still provide the work-and-evaluation context. The subnet model explains what is being
coordinated, while the tools overview explains the interface layer around that model.

## Network Reading

Bittensor documentation separates mainnet, testnet, and localnet contexts
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

A tooling example belongs to the environment where it was observed. Localnet examples can show
controlled behavior, testnet examples can show shared non-production conditions, and mainnet
references concern production network use.

## Reading the Term

Bittensor tools are practical access vocabulary. The term helps identify whether a page is
discussing a developer library, terminal interface, wallet/key material, or another surface around
Bittensor ([Bittensor Tools](https://docs.learnbittensor.org/concepts/tools),
[Wallets and Keys](https://docs.learnbittensor.org/keys/wallets),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

The concise reading is: tools provide access and interaction surfaces, while protocol, subnet,
consensus, governance, and wallet references explain the underlying concepts those surfaces touch.

## The SDK Is a Python Library

The official [Bittensor Tools: SDK](https://docs.learnbittensor.org/concepts/tools#bittensor-sdk)
overview describes the Bittensor SDK as a Python-based library for programmatic network access. That
language choice matters when a page is pointing toward a developer integration rather than a browser
wallet or terminal workflow.

The same overview lists SDK work such as registering miners and validators, querying and monitoring
network activity, and building applications on Bittensor's decentralized AI infrastructure
([Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register)). Those jobs
extend the SDK beyond one-off signing into ongoing software that watches chain state or wraps subnet
features for users.

When prose names the SDK, it should carry that Python and application-building context instead of
treating the library as interchangeable with every other tool surface.

References: [Bittensor Tools: SDK](https://docs.learnbittensor.org/concepts/tools#bittensor-sdk),
[Bittensor Python SDK](https://docs.learnbittensor.org/sdk)

## BTCLI Reaches Governance Functions

The [BTCLI Overview](https://docs.learnbittensor.org/btcli/overview) places governance functions
alongside wallet management, balance transfers, staking and unstaking, and node registration in the
CLI's scope. That list shows the terminal tool can reach network decision-making, not just personal
account maintenance.

[Governance](https://docs.learnbittensor.org/governance) documentation explains the broader voting
and proposal context those CLI actions touch. Governance participation through BTCLI therefore
belongs to [Glossary: Coldkey](https://docs.learnbittensor.org/resources/glossary#coldkey) signing
vocabulary rather than to permissionless chain reading.

The [Bittensor Tools: CLI](https://docs.learnbittensor.org/concepts/tools#bittensor-cli) overview
also describes BTCLI for people who prefer quick terminal commands or who manage multiple nodes and
subnet interactions. That audience fit aligns with governance and registration tasks that recur
across subnets.

References: [BTCLI Overview](https://docs.learnbittensor.org/btcli/overview),
[Governance](https://docs.learnbittensor.org/governance)

## Light Wallet Apps Stop Before Advanced Work

Official [Wallets and Keys](https://docs.learnbittensor.org/keys/wallets) documentation lists
several wallet applications with different capability levels. The mobile app and Chrome extension
support staking and TAO transfer, but they do not include hotkey management or other advanced
functionality.

The
[Glossary: Bittensor Wallet](https://docs.learnbittensor.org/resources/glossary#bittensor-wallet)
names the wallet as the identity technology underlying network operations, while the same wallet
guide states that BTCLI and the Python SDK are required for advanced work such as hotkey management,
subnet creation, and governance participation
([Glossary: Hotkey](https://docs.learnbittensor.org/resources/glossary#hotkey)).

That split helps readers choose a tool tier. Stake-and-transfer questions may fit lighter wallet
apps, while mining, validation, subnet ownership, or governance participation should be read toward
BTCLI or SDK surfaces instead.

References: [Wallets and Keys](https://docs.learnbittensor.org/keys/wallets),
[Glossary: Bittensor Wallet](https://docs.learnbittensor.org/resources/glossary#bittensor-wallet)
