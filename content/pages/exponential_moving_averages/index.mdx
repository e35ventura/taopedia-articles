# Exponential Moving Averages

An exponential moving average, or EMA, is a smoothing method. It blends a new measurement with a
running value from earlier updates
([Exponential Moving Averages](https://docs.learnbittensor.org/learn/ema)).

In Bittensor, EMA vocabulary appears around signals that should respond over time instead of
changing entirely from one observation. Examples include emission flow and validator-miner bond
behavior ([Emission](https://docs.learnbittensor.org/learn/emissions),
[Glossary: Validator-Miner Bonds](https://docs.learnbittensor.org/resources/glossary#validator-miner-bonds)).

## Smoothing Role

EMA smoothing gives newer measurements influence while keeping part of the earlier running value. A
larger smoothing factor reacts faster, while a smaller factor changes more slowly
([Exponential Moving Averages](https://docs.learnbittensor.org/learn/ema),
[Glossary: Exponential Moving Average](https://docs.learnbittensor.org/resources/glossary#exponential-moving-average-ema)).

That behavior is useful when a Bittensor signal should respond to sustained movement rather than a
single short change.

EMA does not choose the source signal. It only changes how quickly a running value incorporates new
observations, so the surrounding context still needs to identify the Bittensor value being smoothed
([Exponential Moving Averages](https://docs.learnbittensor.org/learn/ema)).

That distinction is the core boundary. The smoothing factor describes responsiveness, while the
source signal describes what is being measured. Changing one does not automatically define the
other.

## Signal Context

EMA is a method, not a complete explanation by itself. A smoothed subnet-flow signal and a smoothed
bond value can both use EMA vocabulary while describing different Bittensor concepts
([Exponential Moving Averages](https://docs.learnbittensor.org/learn/ema),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

That is why an EMA claim should name both the smoothing method and the signal being smoothed.

The same acronym can therefore appear in multiple Bittensor contexts without meaning the same system
behavior. The method is shared; the surrounding signal gives the term its local meaning.

This keeps EMA language from becoming a shortcut for the whole mechanism. Flow, bonds, and
deregistration can use EMA vocabulary, but each mechanism still needs its own source and meaning.

## Emission Flow

Bittensor uses EMA-smoothed net TAO flow when comparing subnet-level emission allocation. Smoothing
helps short movement avoid dominating the flow signal
([Emission](https://docs.learnbittensor.org/learn/emissions),
[Glossary: Subnet Weights](https://docs.learnbittensor.org/resources/glossary#subnet-weights)).

In this context, EMA names the smoothing method. Emission vocabulary supplies the allocation meaning
attached to the smoothed signal.

That keeps the emission claim narrow. EMA-smoothed flow is part of the allocation discussion, not a
standalone explanation of every subnet tokenomics outcome
([Emission](https://docs.learnbittensor.org/learn/emissions)).

In flow-based emissions, EMA belongs to subnet comparison. It smooths the flow signal before that
signal is used in allocation context, while later distribution logic still belongs to emission and
incentive-mechanism vocabulary.

That means EMA-smoothed flow is not a direct description of miner or validator outcomes. It is an
input-side smoothing context before later allocation and evaluation steps.

## Bond Context

EMAs also appear in validator-miner bond smoothing. A bond can evolve from repeated evaluation
signals instead of jumping entirely from one measurement
([Glossary: Validator-Miner Bonds](https://docs.learnbittensor.org/resources/glossary#validator-miner-bonds),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

Liquid alpha changes the EMA smoothing factor for validator-miner bonds according to consensus
alignment. It is a Bittensor rule for varying smoothing inside bond behavior rather than a separate
smoothing method
([Consensus-based Weights](https://docs.learnbittensor.org/concepts/consensus-based-weights),
[Exponential Moving Averages](https://docs.learnbittensor.org/learn/ema)).

Bond smoothing is therefore separate from the raw evaluation signal. The EMA explains how the bond
responds over repeated updates; the surrounding consensus and bond sources explain what the bond is
used for
([Glossary: Validator-Miner Bonds](https://docs.learnbittensor.org/resources/glossary#validator-miner-bonds),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

Liquid alpha makes that boundary especially important. It changes the smoothing factor used for bond
updates, while the bond still belongs to validator-miner relationship and consensus context.

## Consensus Boundary

EMA smoothing can influence values used near consensus, but it is not the consensus rule itself.
Yuma Consensus explains how validator signals are aggregated into subnet outcomes, while EMA
describes smoothing behavior for selected values
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Exponential Moving Averages](https://docs.learnbittensor.org/learn/ema)).

Keeping that boundary clear prevents the smoothing method from being treated as the full incentive
system. EMA changes how a signal responds over time; the surrounding Bittensor concept defines what
the signal means.

## Practical Limits

An EMA claim should identify what is being smoothed. In Bittensor, the phrase can refer to subnet
flow, validator-miner bonds, or another reward-related signal
([Exponential Moving Averages](https://docs.learnbittensor.org/learn/ema),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

EMA does not provide reward forecasts, validator recommendations, or point-in-time network results.
The stable point is the smoothing technique: an EMA blends new measurements with prior history so
Bittensor processes can respond to sustained changes.

Use EMA language when the focus is smoothing over repeated updates. Use the surrounding concept's
own vocabulary when the focus is emission allocation, validator-miner bonds, subnet deregistration,
or consensus output.

An exponential moving average is a smoothed signal, not the same thing as the latest raw observed
value. Bittensor documentation uses smoothed alpha-price context in subnet deregistration, where the
signal participates in a selection rule
([Exponential Moving Averages](https://docs.learnbittensor.org/learn/ema),
[Subnet Deregistration](https://docs.learnbittensor.org/subnets/subnet-deregistration)).

That source scope explains why EMA language needs the mechanism that consumes the smoothed value.
The smoothed signal is only one part of the surrounding tokenomics, consensus, or deregistration
rule.

Mainnet, testnet, and localnet are separate contexts for observed signal behavior
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)). The method can
be explained across those environments, but an observed EMA example belongs to the network and
mechanism where it was observed.
