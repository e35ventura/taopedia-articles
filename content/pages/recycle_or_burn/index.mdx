# Recycle Or Burn

Recycle or burn is a per-subnet hyperparameter, listed in the documentation as `RecycleOrBurn`, that
sets what happens to miner emission routed to burn UIDs on a subnet. The reference describes it as
choosing whether that emission is burned or recycled, with a default of burn
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## What It Controls

The hyperparameter governs the fate of emission allocated to burn UIDs, not which miners earn
incentives or how validator weights are aggregated. When set to burn, miner emission sent to burn
UIDs is destroyed; when set to recycle, the same routed emission is returned to circulation instead
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Emission](https://docs.learnbittensor.org/learn/emissions)).

That makes recycle or burn a supply-handling choice for the burn-UID path on a subnet. It does not
replace Yuma Consensus settlement, subnet owner cut rules, or the broader incentive split; it only
decides whether burn-UID allocation leaves the circulating supply or re-enters it
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Recycling](https://docs.learnbittensor.org/learn/recycling)).

The setting is owner-tunable per subnet, so netuid 1 can use the default burn mode while another
netuid recycles burn-UID emission, and the live value is chain state rather than a network constant
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Documented Type and Default

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `RecycleOrBurn` as a `RecycleOrBurnEnum` with a default of burn and marks the
permission required to change it as subnet owner
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Because each subnet carries its own hyperparameters, the burn-UID handling mode on one netuid can
differ from the documented default and from the mode active on another subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Reading the Live Value for netuid 1

Recycle or burn is per-subnet chain state, so any live claim is tied to a specific netuid. For the
documented example netuid 1 on Finney mainnet, the enum appears in that subnet's hyperparameter
table, which the reference describes under viewing a subnet's hyperparameters
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters)).
The infobox uses netuid 1 only as an example label; other subnets expose their own values
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from Recycling

Recycling is the broader economic concept of returning TAO to circulation through defined protocol
paths. Recycle or burn is the specific hyperparameter that chooses whether burn-UID miner emission
on one subnet follows the recycle path or the burn path
([Recycling](https://docs.learnbittensor.org/learn/recycling),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Recycling** — general return-to-circulation concept in Bittensor economics.
- **Recycle or burn** — per-subnet enum for burn-UID emission fate.
