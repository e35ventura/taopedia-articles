# Hotkey Already Delegate

`HotKeyAlreadyDelegate` is a subtensor pallet error raised when a hotkey attempts to become a
delegate while it is already registered as one. The API errors reference describes it as "The hotkey
is attempting to become a delegate when the hotkey is already a delegate."
([Subtensor API Errors: HotKeyAlreadyDelegate](https://docs.learnbittensor.org/subtensor-api/errors#hotkeyalreadydelegate)).

## What It Means

In Bittensor, a hotkey can be registered as a delegate, allowing other participants to stake TAO to
it and share in the rewards it earns
([Bittensor Wallets](https://docs.learnbittensor.org/getting-started/wallets)).

`HotKeyAlreadyDelegate` fires when a hotkey that is already in the delegate set attempts the
operation that would register it as a delegate again. The runtime checks delegate membership before
proceeding and rejects the redundant attempt
([Subtensor API Errors: HotKeyAlreadyDelegate](https://docs.learnbittensor.org/subtensor-api/errors#hotkeyalreadydelegate)).

This is a delegate-membership duplication check. It does not mean the hotkey lacks a subnet
registration, that the hotkey account does not exist, or that the operation was blocked for a
balance reason.

## Why It Appears

This error appears when the hotkey is already present in the delegate set and a call attempts to
register it as a delegate a second time
([Subtensor API Errors: HotKeyAlreadyDelegate](https://docs.learnbittensor.org/subtensor-api/errors#hotkeyalreadydelegate)).

## Distinction from Hotkey Already Registered In Subnet

`HotKeyAlreadyDelegate` and `HotKeyAlreadyRegisteredInSubNet` both fire when a hotkey is already
present in a set it is being added to, but they check different sets.
`HotKeyAlreadyRegisteredInSubNet` fires when a hotkey already holds a UID slot on a specific subnet
and registration is attempted again. `HotKeyAlreadyDelegate` fires when the hotkey is already in the
global delegate set
([Subtensor API Errors: HotKeyAlreadyRegisteredInSubNet](https://docs.learnbittensor.org/subtensor-api/errors#hotkeyalreadyregisteredinsubnet),
[Subtensor API Errors: HotKeyAlreadyDelegate](https://docs.learnbittensor.org/subtensor-api/errors#hotkeyalreadydelegate)).

- **HotKeyAlreadyDelegate** — hotkey is already in the delegate set.
- **HotKeyAlreadyRegisteredInSubNet** — hotkey already holds a UID on the specified subnet.

## Distinction from Hotkey Account Not Exists

`HotKeyAlreadyDelegate` and `HotKeyAccountNotExists` both involve checks on hotkeys in the subtensor
pallet, but they represent opposite conditions. `HotKeyAccountNotExists` fires when the specified
hotkey has no on-chain account. `HotKeyAlreadyDelegate` fires when the hotkey exists and is already
a delegate
([Subtensor API Errors: HotKeyAccountNotExists](https://docs.learnbittensor.org/subtensor-api/errors#hotkeyaccountnotexists),
[Subtensor API Errors: HotKeyAlreadyDelegate](https://docs.learnbittensor.org/subtensor-api/errors#hotkeyalreadydelegate)).

- **HotKeyAlreadyDelegate** — hotkey exists and is already registered as a delegate.
- **HotKeyAccountNotExists** — hotkey account does not exist on chain.
