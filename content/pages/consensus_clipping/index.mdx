# Consensus Clipping

Consensus clipping is the filtering step in Bittensor's Yuma Consensus that reduces validator
weights that fall outside the stake-weighted agreement signal. The
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus) documentation describes
clipping as the part of the process that compares validator weights with a consensus benchmark, and
the [Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score)
defines that benchmark as a stake-weighted median used to filter outlier weights.

## Why It Matters

Validators can disagree because they evaluate miner work independently. Consensus clipping lets
Bittensor aggregate those evaluations without letting a single far-away weight carry the same effect
as weights near broader validator agreement. In the glossary's explanation of consensus score, the
score becomes the threshold used before final rank calculations.

References: [Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score)

## Place in Yuma Consensus

The useful way to read consensus clipping is as a middle step between submitted validator weights
and final consensus outputs. Validators submit weights, Yuma Consensus compares those weights with
the consensus score, and the clipped result feeds later rank, trust, bond, and emission context. The
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus) page places clipping before
miner emissions, bond adjustment, and validator emission calculations.

## Relationship to Consensus Score

Consensus score names the threshold-like agreement signal. Consensus clipping names the action of
reducing weights against that signal. The distinction matters because a reader may see the consensus
score reported as a metric while clipping is the mechanism that changes which submitted weights
survive into later calculations.

References:
[Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)

## Relationship to Trust

Trust is one way to interpret the effect of clipping after it has happened. The
[Glossary: Trust](https://docs.learnbittensor.org/resources/glossary#trust) describes trust as the
relationship between final rank and pre-rank, while the consensus score entry explains that outlier
weights are clipped before final rank calculations. In plain terms, clipping changes the path from
initial validator support to consensus-adjusted support, and trust describes part of that effect.

## Reader Boundary

Consensus clipping is not a separate validator action, a manual subnet setting, or a live statement
about any particular subnet's current validators. It is a consensus-process term for how Bittensor
handles outlier validator weights inside Yuma Consensus. Exact formulas and implementation details
belong in the official Yuma Consensus and glossary references.
