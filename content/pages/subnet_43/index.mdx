Graphite is Bittensor Subnet 43, a decentralized network for solving graph optimization problems.
The
[Graphite README source](https://raw.githubusercontent.com/GraphiteAI/Graphite-Subnet/main/README.md)
describes it as a subnet for connecting miners and validators around Traveling Salesman Problem
(TSP) and related graph-optimization tasks. The subnet turns that computation into a rewarded
service: validators pose problems, miners return routes, and stronger solutions earn better rewards.

## What the Subnet Produces

The subnet's output is solved routes for graph problems. Because the optimal answer to a hard TSP
instance is expensive to compute, there is room for miners to compete on both solution quality and
speed. Problems can be expressed as coordinate inputs for undirected graphs or as edge inputs for
directed graphs, so a range of routing and ordering problems can be mapped onto the same task.

The [README](https://raw.githubusercontent.com/GraphiteAI/Graphite-Subnet/main/README.md) says
Graphite supports both coordinate inputs for undirected graphs and edge inputs for directed graphs.
That matters because a graph-optimization subnet needs a common problem format before miners can
compete on solver quality. Different input styles can represent different route and ordering
problems while still leaving validators with comparable submitted routes.

## Solver Context

Graphite's README also lists several reference solver approaches: a nearest-neighbour heuristic, a
dynamic-programming method, beam search, and a hybrid pointer-network approach. Those examples are
not the only possible strategies; they show the shape of the competition. Miners can bring
heuristic, exact, search-based, or learning-assisted approaches to the same graph task.

That solver diversity is the point of making the problem competitive. A miner can improve by finding
better tours, finding them faster, or adapting to problem cases where simple heuristics fall short.
The subnet's useful output is therefore not a single model checkpoint or dataset, but a stream of
candidate graph solutions that validators can compare.

## Reward Context

The README frames miner rewards around solution quality within a time limit. It says submitted
solutions are evaluated relative to the best solution in the cohort and a benchmark solution, with
validators penalizing solutions that fall short of the benchmark. This keeps the reward target tied
to useful route improvement rather than to returning any valid path.

For readers, the important distinction is that Graphite scoring is comparative. A route can be valid
but still weak if it is much worse than the cohort leader or fails to beat the benchmark heuristic.
That makes the subnet closer to an optimization contest than a binary correctness check.

## Miner and Validator Roles

Validators currently generate synthetic graph problems and send them to miners. Each miner solves
the problem with whatever algorithm it runs and returns a route, within a time limit. Validators
then evaluate the returned solutions.

Scoring is comparative rather than absolute. According to the repository, a miner's reward depends
on how its solution compares both to the best solution in the cohort for that problem and to a
benchmark greedy heuristic; solutions that fail to beat the benchmark are penalized. This rewards
miners for genuinely better routes instead of for merely returning something.
