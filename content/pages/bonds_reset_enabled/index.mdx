# Bonds Reset Enabled

Bonds reset enabled is a per-subnet hyperparameter, listed in the documentation as
`BondsResetEnabled`, that gates whether accumulated
[validator-miner bonds](https://docs.learnbittensor.org/resources/glossary#validator-miner-bonds)
for a neuron can be cleared on qualifying lifecycle events. It is a boolean switch with a default of
false, so bond history ordinarily persists unless a subnet owner enables clearing
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## What It Controls

The hyperparameter does not set bond strength, smoothing speed, or dividend shares. It only decides
whether the runtime may remove a neuron's entries from stored bond vectors when a reset path runs.
When the flag is false, the reset path exits without changing bond state; when it is true, the
runtime can strip that neuron's UID from bond records across validators on the subnet
([`do_reset_bonds`](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/epoch/run_epoch.rs),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

That clearing matters because bonds are smoothed relationships that accumulate across Yuma Consensus
epochs and feed into
[validator dividends](https://docs.learnbittensor.org/resources/glossary#emission). If bond entries
survive a neuron identity change unchanged, a participant could retain bond history that no longer
matches its current standing. Enabling reset lets a subnet drop those stale entries instead of
carrying them forward
([Yuma Consensus: Bonding mechanics](https://docs.learnbittensor.org/learn/yuma-consensus#bonding),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

The flag is owner-tunable per subnet, so netuid 1 can keep the default while another netuid enables
resets, and the live value is chain state rather than a network constant
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Documented Type and Default

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `BondsResetEnabled` as a `Bool` with a default of false. The documentation describes
it as determining whether bonds are reset-enabled, and marks the permission required to change it as
subnet owner
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

With the default off, subnets preserve accumulated bond history through ordinary neuron changes
unless an owner explicitly enables the reset path.

## Reading the Live Value for netuid 1

Bonds reset enabled is per-subnet chain state, so any live claim is tied to a specific netuid. For
the documented example netuid 1 on Finney mainnet, the flag appears in that subnet's hyperparameter
table, which the reference describes under viewing a subnet's hyperparameters
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters)).
The infobox uses netuid 1 only as an example label; other subnets expose their own values
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from Bonds Moving Average

Bonds moving average sets how quickly validator-miner bonds smooth toward new weights during normal
Yuma Consensus operation. Bonds reset enabled is the separate boolean that gates whether accumulated
bond entries for a neuron may be cleared when the reset path runs
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Yuma Consensus: Bonding mechanics](https://docs.learnbittensor.org/learn/yuma-consensus#bonding)).

- **Bonds moving average** — smoothing speed applied to bonds over time.
- **Bonds reset enabled** — whether accumulated bond entries may be cleared on the reset path.
