# Terminated In Constructor

`TerminatedInConstructor` is a contracts pallet error returned when a contract ends itself during
its constructor. The API errors reference summarizes it as "A contract self destructed in its
constructor"
([Subtensor API Errors: TerminatedInConstructor](https://docs.learnbittensor.org/subtensor-api/errors#terminatedinconstructor)).

## What It Means

Some contracts-pallet deployment paths run a constructor before a new contract is fully available.
`TerminatedInConstructor` means the contract ended itself during that constructor phase instead of
completing deployment
([Subtensor API Errors: TerminatedInConstructor](https://docs.learnbittensor.org/subtensor-api/errors#terminatedinconstructor)).

This is a constructor-phase termination outcome. It does not, by itself, mean a live contract at the
address was already terminated earlier, that no code exists at a supplied hash, or that the targeted
account already has a different live contract.

## Why It Appears

This error appears when contract creation reaches a constructor that terminates the contract before
deployment completes
([Subtensor API Errors: TerminatedInConstructor](https://docs.learnbittensor.org/subtensor-api/errors#terminatedinconstructor)).

## Distinction from Contract Terminated

`TerminatedInConstructor` and `ContractTerminated` both involve contract termination, but at
different stages. `TerminatedInConstructor` means the contract ended itself during its constructor.
`ContractTerminated` is summarized as "The contract has been terminated."
([Subtensor API Errors: TerminatedInConstructor](https://docs.learnbittensor.org/subtensor-api/errors#terminatedinconstructor),
[Subtensor API Errors: ContractTerminated](https://docs.learnbittensor.org/subtensor-api/errors#contractterminated)).

- **TerminatedInConstructor** — the contract terminated during its constructor.
- **ContractTerminated** — the contract has already been terminated and is no longer available.

## Distinction from Duplicate Contract

`TerminatedInConstructor` and `DuplicateContract` both arise on contract-creation paths, but the API
summaries name different problems. `TerminatedInConstructor` means the new contract terminated
during its constructor. `DuplicateContract` is summarized as "A contract with the same AccountId
already exists."
([Subtensor API Errors: TerminatedInConstructor](https://docs.learnbittensor.org/subtensor-api/errors#terminatedinconstructor),
[Subtensor API Errors: DuplicateContract](https://docs.learnbittensor.org/subtensor-api/errors#duplicatecontract)).

- **TerminatedInConstructor** — the contract terminated during its constructor.
- **DuplicateContract** — a live contract already exists at the targeted account.

## Reader Boundary

This page defines the meaning of the error label from the API reference. It does not inspect a
specific constructor on a network or redesign contract deployment logic
([Subtensor API Errors: TerminatedInConstructor](https://docs.learnbittensor.org/subtensor-api/errors#terminatedinconstructor),
