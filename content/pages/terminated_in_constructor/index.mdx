# Terminated In Constructor

`TerminatedInConstructor` is a contracts pallet error raised when a contract self-destructs during
its own constructor. The API errors reference describes it as "A contract self destructed in its
constructor. This can be triggered by a call to `seal_terminate`."
([Subtensor API Errors: TerminatedInConstructor](https://docs.learnbittensor.org/subtensor-api/errors#terminatedinconstructor)).

## What It Means

When a contract is deployed, its constructor runs first. `TerminatedInConstructor` means the
contract terminated itself during that constructor phase rather than completing initialization and
becoming available on chain
([Subtensor API Errors: TerminatedInConstructor](https://docs.learnbittensor.org/subtensor-api/errors#terminatedinconstructor)).

This is a constructor-phase termination. It does not mean execution trapped for an unrelated reason,
that the contract is still active in the call chain, or that the contract was terminated after it
had already been deployed.

## Why It Appears

This error appears when a contracts deployment reaches constructor execution and the contract
terminates itself before the constructor completes. The deployment cannot proceed once the contract
has self-destructed in its constructor
([Subtensor API Errors: TerminatedInConstructor](https://docs.learnbittensor.org/subtensor-api/errors#terminatedinconstructor)).

## Distinction from Terminated While Reentrant

`TerminatedInConstructor` and `TerminatedWhileReentrant` both involve a contract terminating itself,
but at different points. `TerminatedWhileReentrant` is rejected when the contract tries to terminate
while it is still active in the current call chain. `TerminatedInConstructor` is raised when the
contract terminates itself specifically during its constructor phase
([Subtensor API Errors: TerminatedWhileReentrant](https://docs.learnbittensor.org/subtensor-api/errors#terminatedwhilereentrant),
[Subtensor API Errors: TerminatedInConstructor](https://docs.learnbittensor.org/subtensor-api/errors#terminatedinconstructor)).

- **TerminatedInConstructor** — self-destruct occurs in the constructor before deployment.
- **TerminatedWhileReentrant** — termination is attempted while the contract is still active in the
  call chain.

## Distinction from Contract Trapped

`TerminatedInConstructor` and `ContractTrapped` both leave a contract call without the intended
result, but for different reasons. `ContractTrapped` means execution trapped during a contract call.
`TerminatedInConstructor` means the contract deliberately self-destructed in its constructor
([Subtensor API Errors: ContractTrapped](https://docs.learnbittensor.org/subtensor-api/errors#contracttrapped),
[Subtensor API Errors: TerminatedInConstructor](https://docs.learnbittensor.org/subtensor-api/errors#terminatedinconstructor)).

- **TerminatedInConstructor** — contract self-destructs during constructor execution.
- **ContractTrapped** — contract traps during execution without self-destructing.
