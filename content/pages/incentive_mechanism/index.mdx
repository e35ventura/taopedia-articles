# Incentive Mechanism

An incentive mechanism is the rule set that connects work inside a Bittensor subnet to evaluation
and reward outcomes. It explains how miner work, validator evaluation, and incentives fit together
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

The term belongs to subnet design because each subnet defines the work it wants and how that work is
evaluated ([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

## What an Incentive Mechanism Bundles

An incentive mechanism is not a single rule but a bundle the subnet's design defines together: the
subnet task that states what work miners produce, the subnet protocol that governs how validators
request that work and miners return responses, and the subnet scoring model that decides how each
response is judged
([Glossary: Subnet Task](https://docs.learnbittensor.org/resources/glossary#subnet-task),
[Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol),
[Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

Naming these pieces separately keeps the design legible. The task says what is asked, the protocol
says how it is exchanged, and the scoring model says how the answer is rated—three parts of one
mechanism rather than interchangeable terms
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

## How the Mechanism Connects Work to Rewards

Under the mechanism, miners produce work and validators evaluate it with the scoring model, then
submit the resulting weights. The mechanism defines what gets scored; it does not itself settle
rewards
([Glossary: Subnet Validator](https://docs.learnbittensor.org/resources/glossary#subnet-validator),
[Implementation of the Yuma Consensus Epoch](https://docs.learnbittensor.org/navigating-subtensor/epoch)).

Settlement is a separate, shared layer. Each tempo, Yuma Consensus reads the submitted weights,
applies stake weighting, clipping, and bonding, and credits miner incentives and validator dividends
when the epoch closes. The mechanism sets the rules of evaluation; Yuma converts the evaluation
signals those rules produce into emission shares
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Emission](https://docs.learnbittensor.org/learn/emissions)).

## One Subnet, One or More Mechanisms

A subnet can run a single incentive mechanism or several in parallel. Each mechanism is an
independent track with its own weights and bond pool, so a multi-mechanism subnet evaluates more
than one kind of work at the same time
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms),
[Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

On those subnets, a rank or weight only has meaning once the mechanism it belongs to is named.
Comparing signals across mechanisms without that index mixes separate evaluation tracks
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

## Distinction from Weight Setting

An incentive mechanism names the subnet rule set for evaluating work. Weight setting is the
validator action that records miner scores for the epoch
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism),
[Implementation of the Yuma Consensus Epoch](https://docs.learnbittensor.org/navigating-subtensor/epoch)).

- **Incentive mechanism** — evaluation rule set for work inside a subnet.
- **Weight setting** — validator action recording miner scores.

## Distinction from Yuma Consensus

An incentive mechanism names how work is judged inside a subnet. Yuma Consensus is the shared
settlement pass that aggregates submitted weights into emission shares. Subnet hyperparameters can
change scoring rules over time; Yuma remains the recurring settlement layer on every netuid
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Incentive mechanism** — subnet-local evaluation rules.
- **Yuma Consensus** — on-chain weight aggregation and payout settlement.

## Distinction from Incentives

An incentive mechanism names the evaluation design that produces validator scores. Incentives name
the miner-facing emission outcomes credited after Yuma settles those scores
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism),
[Glossary: Incentives](https://docs.learnbittensor.org/resources/glossary#incentives)).

- **Incentive mechanism** — rule set connecting work to evaluation.
- **Incentives** — miner-facing credited emission outcomes.

## Distinction from Subnet Task

Subnet task names the useful work a mechanism is designed to measure. The incentive mechanism names
the evaluation rules that connect that work to validator scoring and rewards
([Glossary: Subnet Task](https://docs.learnbittensor.org/resources/glossary#subnet-task)).

A task statement says what miners should produce; the mechanism statement says how that production
is evaluated inside the subnet.

## Distinction from Multiple Incentive Mechanisms

Multiple incentive mechanisms names the case where one subnet runs parallel evaluation tracks, each
with its own weights and bond pool. Incentive mechanism is the singular rule-set label for one of
those tracks
([Glossary: Multiple Incentive Mechanisms](https://docs.learnbittensor.org/resources/glossary#multiple-incentive-mechanisms)).

Readers on multi-mechanism subnets should name which mechanism index they mean before comparing
ranks or weights.

## Distinction from Subnet Miner

Subnet miner names the participant role that produces work inside a subnet. The incentive mechanism
names the evaluation rules that role operates under
([Glossary: Subnet Miner](https://docs.learnbittensor.org/resources/glossary#subnet-miner),
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)).

- **Subnet miner** — participant role producing subnet work.
- **Incentive mechanism** — evaluation rules governing that work.

## Distinction from Subnet Validator

Subnet validator names the participant role that evaluates miner work inside a subnet. The incentive
mechanism names the scoring rules that evaluation follows
([Glossary: Subnet Validator](https://docs.learnbittensor.org/resources/glossary#subnet-validator),
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)).

- **Subnet validator** — participant role evaluating miner work.
- **Incentive mechanism** — scoring rules governing that evaluation.

## Distinction from Incentive Compatibility

Incentive compatibility is the design goal that honest, high-quality contribution should be the most
profitable strategy. An incentive mechanism is the concrete rule set a subnet uses to evaluate work
and route rewards toward that goal
([Anatomy of an Incentive Mechanism](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism),
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)).

- **Incentive mechanism** — subnet rule set for evaluating work and shaping rewards.
- **Incentive compatibility** — design goal that honest contribution pays best.

## Distinction from Emission

An incentive mechanism names how work is evaluated inside a subnet. Emission names the broader
reward and injection flow across the network
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism),
[Emission](https://docs.learnbittensor.org/learn/emissions)).

- **Incentive mechanism** — evaluation rule set inside one subnet market.
- **Emission** — broader injection-and-distribution flow.

Mechanism vocabulary names evaluation rules; emission vocabulary names network reward flow
([Glossary: Incentives](https://docs.learnbittensor.org/resources/glossary#incentives)).

## Distinction from Subnet Protocol

An incentive mechanism names the full rule set that connects work, evaluation, and rewards inside a
subnet. Subnet protocol names one required piece of that rule set: the exchange rules for how
validators request work and miners return responses
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism),
[Glossary: Subnet Protocol](https://docs.learnbittensor.org/resources/glossary#subnet-protocol),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

Mechanism vocabulary describes the whole evaluation design; protocol vocabulary describes the
interaction pattern that creates the surface validators score.

## Distinction from Subnet Scoring Model

An incentive mechanism names the subnet rule set linking work to evaluation and rewards. Subnet
scoring model names the evaluation method validators apply to returned miner work inside that rule
set
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism),
[Glossary: Subnet Scoring Model](https://docs.learnbittensor.org/resources/glossary#subnet-scoring-model),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

Mechanism vocabulary names the design frame; scoring-model vocabulary names how returned work is
judged before weight vectors are submitted.

## Distinction from Subnet Hyperparameters

A subnet hyperparameter and the incentive mechanism name the protocol envelope and the work it
surrounds. Hyperparameters set timing, weight-flow, and limit conditions, while the incentive
mechanism defines the task, protocol, and scoring that decide what miners produce and how validators
evaluate it
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

- **Subnet hyperparameter** — the protocol envelope of timing and limits.
- **Incentive mechanism** — the task and scoring that define the subnet's work.

## Distinction from Mining And Validating

Mining and validating names the paired subnet roles of work production and evaluation. An incentive
mechanism is the rule set that turns that work into measurable validator signals and emissions
([Miners](https://docs.learnbittensor.org/miners),
[Validators](https://docs.learnbittensor.org/validators),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

- **Mining and validating** — paired role overview for subnet participation.
- **Incentive mechanism** — scoring rules that connect work to rewards.

## Reader Boundary

An incentive mechanism is a subnet evaluation concept. It is not the subnet itself, not a miner
role, and not the final consensus aggregation step
([Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism),
[Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

The stable point is that the mechanism connects what miners produce, how validators evaluate it, and
how the subnet's incentive outcomes are shaped.
