# Target Block Number In Past

`TargetBlockNumberInPast` is a scheduler pallet error raised when a submitted target block number is
in the past. The API errors reference summarizes it as "Given target block number is in the past"
([Subtensor API Errors: TargetBlockNumberInPast](https://docs.learnbittensor.org/subtensor-api/errors#targetblocknumberinpast)).

## What It Means

Subtensor uses the scheduler pallet to queue calls for dispatch at a specified future block. A
target block number names when the queued call should run. `TargetBlockNumberInPast` means the
submitted target block is already behind the current chain head, so the runtime rejects the
scheduling request
([Subtensor API Errors: TargetBlockNumberInPast](https://docs.learnbittensor.org/subtensor-api/errors#targetblocknumberinpast)).

This is a target-block timing rejection. It does not, by itself, mean the reschedule would leave the
call at the same block, that the scheduler could not store the call for another reason, or that no
matching scheduled call exists in storage.

## Why It Appears

This error appears when a scheduler operation supplies a target block number that the runtime treats
as already passed relative to the current chain head
([Subtensor API Errors: TargetBlockNumberInPast](https://docs.learnbittensor.org/subtensor-api/errors#targetblocknumberinpast)).

## Distinction from Reschedule No Change

`TargetBlockNumberInPast` and `RescheduleNoChange` both block scheduler reschedule paths, but on
different checks. `TargetBlockNumberInPast` is summarized as "Given target block number is in the
past." `RescheduleNoChange` is summarized as "Reschedule failed because it does not change scheduled
time."
([Subtensor API Errors: TargetBlockNumberInPast](https://docs.learnbittensor.org/subtensor-api/errors#targetblocknumberinpast),
[Subtensor API Errors: RescheduleNoChange](https://docs.learnbittensor.org/subtensor-api/errors#reschedulenochange)).

- **TargetBlockNumberInPast** — the submitted target block number is in the past.
- **RescheduleNoChange** — the reschedule would not change the scheduled time.

## Distinction from Failed To Schedule

`TargetBlockNumberInPast` and `FailedToSchedule` both stop a scheduler operation from succeeding,
but with different API summaries. `TargetBlockNumberInPast` is summarized as "Given target block
number is in the past." `FailedToSchedule` is summarized as "Failed to schedule a call"
([Subtensor API Errors: TargetBlockNumberInPast](https://docs.learnbittensor.org/subtensor-api/errors#targetblocknumberinpast),
[Subtensor API Errors: FailedToSchedule](https://docs.learnbittensor.org/subtensor-api/errors#failedtoschedule)).

- **TargetBlockNumberInPast** — the submitted target block number is in the past.
- **FailedToSchedule** — the scheduler failed to schedule the call.

## Reader Boundary

This page defines the meaning of the error label from the API reference. It does not report the
current chain head on a network or choose a valid future target block
([Subtensor API Errors: TargetBlockNumberInPast](https://docs.learnbittensor.org/subtensor-api/errors#targetblocknumberinpast),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
