# Root Network Does Not Exist

`RootNetworkDoesNotExist` means a root-subnet path expected Root Subnet chain state that was not
present. The standard-errors reference describes it as "The root network does not exist"
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#rootnetworkdoesnotexist)).

The check is an existence guard on Root Subnet infrastructure, not a rejection of an ordinary
mining-subnet registration call
([Subtensor source: root.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/coinbase/root.rs)).

## What It Means

Root Subnet operations assume netuid 0 is initialized in chain storage. In `do_root_register`, the
runtime calls `if_subnet_exist(NetUid::ROOT)` and returns `RootNetworkDoesNotExist` when that lookup
fails
([Subtensor source: root.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/coinbase/root.rs),
[Root Subnet / Subnet Zero](https://docs.learnbittensor.org/resources/glossary#root-subnetsubnet-zero)).

During root-claim settlement, the same error is returned when `get_subnet_account_id(NetUid::ROOT)`
cannot resolve the root subnet account needed to move TAO in the claim path
([Subtensor source: claim_root.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/staking/claim_root.rs)).

## Why It Appears

This error appears on root-specific paths that require initialized Root Subnet state. On
`do_root_register`, it means the chain did not find Root Subnet records before registration pacing
or hotkey membership checks run. In the root-claim settlement path, it means the runtime could not
resolve the root subnet account required to complete the transfer step
([Subtensor source: root.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/coinbase/root.rs),
[Subtensor source: claim_root.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/staking/claim_root.rs)).

When debugging ordinary subnet registration, rule out the separate root-subnet guard first.
`RegistrationNotPermittedOnRootSubnet` means a registration-style call targeted the Root Subnet
while that subnet exists. `SubnetNotExists` means a non-root netuid was absent from chain state
([Subtensor Standard Errors: RegistrationNotPermittedOnRootSubnet](https://docs.learnbittensor.org/errors/subtensor#registrationnotpermittedonrootsubnet),
[Subtensor Standard Errors: SubnetNotExists](https://docs.learnbittensor.org/errors/subtensor#subnetnotexists)).

The practical meaning is narrow: Root Subnet chain state or its subnet account was not available to
the call.

## Distinction from Registration Not Permitted On Root Subnet

`RootNetworkDoesNotExist` and `RegistrationNotPermittedOnRootSubnet` both involve the Root Subnet,
but they describe different failures. `RootNetworkDoesNotExist` means Root Subnet chain state or its
subnet account could not be found. `RegistrationNotPermittedOnRootSubnet` means the Root Subnet
exists, but a registration-style extrinsic targeted it instead of an ordinary mining subnet
([Subtensor Standard Errors: RegistrationNotPermittedOnRootSubnet](https://docs.learnbittensor.org/errors/subtensor#registrationnotpermittedonrootsubnet),
[Subtensor source: root.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/coinbase/root.rs)).

- **RootNetworkDoesNotExist** — Root Subnet state or account lookup failed.
- **RegistrationNotPermittedOnRootSubnet** — a registration-style call targeted the Root Subnet.

## Distinction from Subnet Not Exists

`RootNetworkDoesNotExist` and `SubnetNotExists` both signal missing subnet state, but on different
paths and netuids. `RootNetworkDoesNotExist` is the Root Subnet existence check in
`do_root_register` and root-claim settlement. `SubnetNotExists` is the standard rejection when an
ordinary subnet lookup fails on non-root extrinsics
([Subtensor Standard Errors: SubnetNotExists](https://docs.learnbittensor.org/errors/subtensor#subnetnotexists),
[Subtensor source: root.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/coinbase/root.rs)).

- **RootNetworkDoesNotExist** — Root Subnet state or account lookup failed.
- **SubnetNotExists** — the targeted ordinary subnet does not exist.

## Distinction from Hotkey Already Registered In Subnet

`RootNetworkDoesNotExist` and `HotKeyAlreadyRegisteredInSubNet` can both appear on
`do_root_register`, but at different stages. `RootNetworkDoesNotExist` is the first Root Subnet
existence check. `HotKeyAlreadyRegisteredInSubNet` is the later membership rejection when the hotkey
already holds a root UID
([Subtensor Standard Errors: HotKeyAlreadyRegisteredInSubNet](https://docs.learnbittensor.org/errors/subtensor#hotkeyalreadyregisteredinsubnet),
[Subtensor source: root.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/coinbase/root.rs)).

- **RootNetworkDoesNotExist** — Root Subnet state was not found.
- **HotKeyAlreadyRegisteredInSubNet** — the hotkey already has a root UID.

## Reader Boundary

This page defines the meaning of the error label and the Root Subnet existence checks that raise it.
It does not describe root validator admission rules, senate membership, or root-claim configuration;
those are documented separately
([Root Subnet / Subnet Zero](https://docs.learnbittensor.org/resources/glossary#root-subnetsubnet-zero),
[Root Claims](https://docs.learnbittensor.org/staking-and-delegation/root-claims)).
