# Partial Fills Not Enabled

`PartialFillsNotEnabled` is a documented limit-orders error raised when a relayer submits a
partial-fill execution against an order that does not allow partial fills. The Subtensor API error
reference describes it as "Partial fills not enabled for this order"
([Subtensor API Errors: PartialFillsNotEnabled](https://docs.learnbittensor.org/subtensor-api/errors#partialfillsnotenabled)).

## What It Means

Limit orders can be created with a partial-fills flag that controls whether they may be executed in
more than one step. The `is_order_valid` helper — used by both `execute_orders` and
`execute_batched_orders` — checks that flag when the signed submission includes a partial-fill
amount. `PartialFillsNotEnabled` means the order was not created with partial fills turned on
([Subnet Liquidity Pools](https://docs.learnbittensor.org/subnets/understanding-subnets#liquidity-pools),
[Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

The check runs only on the partial-fill branch of validation, after the order has passed the
relayer-presence requirement for partial execution and before the runtime evaluates the submitted
partial amount against remaining fill bounds
([Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

Full one-shot executions that omit a partial-fill field do not reach this gate
([Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

This is an order-configuration rejection on the partial-fill path, not proof that the signature is
invalid or that the partial-fill amount itself is out of bounds.

## Why It Appears

This error appears when a relayer submits a signed order envelope with a partial-fill amount for an
order whose payload has `partial_fills_enabled` set to false. That can happen when a client reuses a
one-shot order and adds a partial-fill field at execution time, or when automation assumes every
order supports staged fulfillment
([Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

When debugging, compare against the earlier partial-fill relayer check on the same path.
`RelayerRequiredForPartialFill` means the order stored no relayer restriction while a partial fill
was requested. `PartialFillsNotEnabled` means the relayer field is present but the order was not
created to allow partial fills
([Relayer Required For Partial Fill](https://docs.learnbittensor.org/subtensor-api/errors#relayerrequiredforpartialfill),
[Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

The next rejection on the same path is `IncorrectPartialFillAmount` when the submitted partial
amount is zero, exceeds the remaining fill allowance, or when a full-fill retry is attempted against
an order that is already partially filled
([Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

## Distinction from Relayer Required For Partial Fill

`PartialFillsNotEnabled` and `RelayerRequiredForPartialFill` both appear when a partial-fill value
is submitted, but at different checks. `RelayerRequiredForPartialFill` means the order has no
relayer restriction field. `PartialFillsNotEnabled` means the relayer field is present but the
order's partial-fills flag is off
([Relayer Required For Partial Fill](https://docs.learnbittensor.org/subtensor-api/errors#relayerrequiredforpartialfill),
[Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

- **RelayerRequiredForPartialFill** — no relayer list exists on the order.
- **PartialFillsNotEnabled** — partial fills are not enabled on the order.

## Distinction from Incorrect Partial Fill Amount

`PartialFillsNotEnabled` and `IncorrectPartialFillAmount` both involve partial execution, but at
different checks. `PartialFillsNotEnabled` is returned when the order does not allow partial fills
at all. `IncorrectPartialFillAmount` is returned later when partial fills are allowed but the
submitted amount or fill-state rules fail the bounds check
([Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

- **PartialFillsNotEnabled** — the order was not created for partial fills.
- **IncorrectPartialFillAmount** — the partial-fill amount or fill state is invalid.

## Distinction from Price Condition Not Met

`PartialFillsNotEnabled` and `PriceConditionNotMet` are both raised by `is_order_valid`, but at
different stages. `PriceConditionNotMet` compares the scaled market price against the order's limit
rule before the partial-fill branch runs. `PartialFillsNotEnabled` applies only after a partial-fill
submission has already passed earlier gates
([Price Condition Not Met](https://docs.learnbittensor.org/subtensor-api/errors#priceconditionnotmet),
[Subtensor source: limit-orders/lib.rs](https://github.com/opentensor/subtensor/blob/main/pallets/limit-orders/src/lib.rs)).

- **PriceConditionNotMet** — the market price does not satisfy the limit condition.
- **PartialFillsNotEnabled** — partial fills are not enabled on the order.

## Reader Boundary

This page defines the meaning of the error label and the partial-fills flag check that raises it. It
does not report whether partial fills are enabled on any live order; that is order state readers can
inspect separately
([Subnet Liquidity Pools](https://docs.learnbittensor.org/subnets/understanding-subnets#liquidity-pools),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
