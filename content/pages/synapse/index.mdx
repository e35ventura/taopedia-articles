A synapse is the data object used in communication between Bittensor subnet miners and validators.
The official [Understanding Neurons](https://docs.learnbittensor.org/learn/neurons) guide describes
synapses as the objects exchanged through the axon-dendrite communication pattern.

In a subnet, the synapse carries the task-specific fields that a validator sends and a miner
responds to. This makes it part of the subnet's interface: different subnet protocols can define
different synapse shapes for the work they need miners to perform.

## Role in Miner-Validator Communication

Bittensor docs describe neurons as using axons, dendrites, and synapses together. In that model, an
axon is the receiving server side, a dendrite is the sending client side, and the synapse is the
data object being exchanged.

For Taopedia readers, the practical idea is that a synapse is not the incentive mechanism itself. It
is the structured message container that lets a validator ask for work and lets a miner return the
information needed for evaluation.

## Why Synapses Matter

Synapses help make subnet communication explicit. A subnet can define what fields belong in its
requests and responses, and validators can use those fields when applying the scoring logic for that
subnet.

The official [glossary](https://docs.learnbittensor.org/resources/glossary) describes synapses as
the main vehicle used by subnet validators and miners to exchange information. That places synapses
inside the broader [[Mining and Validating]] workflow rather than in the blockchain consensus layer.
