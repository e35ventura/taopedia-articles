# External Wallet

An external wallet is wallet software or custody outside the local Bittensor wallet path. The
[External Wallet glossary entry](https://docs.learnbittensor.org/resources/glossary#external-wallet)
places the term in wallet-security vocabulary, where location and custody context matter for how a
wallet is understood.

## Custody Context

External wallet names a custody context, not a different token or subnet role. The
[wallet documentation](https://docs.learnbittensor.org/keys/wallets) gives the broader setting for
Bittensor wallet concepts, while the external-wallet glossary entry narrows the term to wallet
software or custody outside the local path.

## Wallet Application Boundary

External wallet and wallet application are related but not interchangeable. The
[external-wallet glossary entry](https://docs.learnbittensor.org/resources/glossary#external-wallet)
points to custody or software outside the local wallet path, while wallet-application vocabulary
describes the software interface used to view wallet state or prepare actions
([Wallets](https://docs.learnbittensor.org/keys/wallets),
[Wallets](https://docs.learnbittensor.org/keys/wallets)).

For readers, an external wallet answers where custody or signing control is managed. A wallet
application answers which interface is being used to interact with wallet information or actions.

## Local Wallet Contrast

The contrast term is local wallet. A
[local wallet](https://docs.learnbittensor.org/resources/glossary#local-wallet) belongs to the local
Bittensor wallet path, while an external wallet places that wallet context outside the local path.
The difference is about where wallet control is managed, not about creating a separate Bittensor
asset.

## Wallet Address Boundary

External wallet and wallet address are related but separate concepts. A
[wallet address](https://docs.learnbittensor.org/resources/glossary#wallet-address) is a
public-key-derived destination identifier for TAO, while external wallet names custody or software
context. That distinction keeps destination-address vocabulary separate from custody-location
vocabulary.

## Address-Poisoning Context

External wallets still use destination addresses, so address-poisoning risk remains relevant. The
[address-poisoning guide](https://docs.learnbittensor.org/keys/address-poisoning-scams) focuses on
lookalike destination addresses during wallet use, while the external-wallet term names where wallet
control is managed. The risk and the custody context are connected but not identical.

## External Wallet Does Not Change Destination Format

An external wallet can still sign transfers to the same SS58 destination format used elsewhere in
Bittensor wallet prose. Custody location and destination address are separate questions
([Glossary: Wallet Address](https://docs.learnbittensor.org/resources/glossary#wallet-address),
[Address Poisoning Scams](https://docs.learnbittensor.org/keys/address-poisoning-scams)).

## Signing Control Stays Separate From Subnet Roles

External wallet vocabulary belongs with wallet security and signing context. Miner, validator, and
nominator roles describe network participation rather than where keys are stored
([Staking and delegation overview](https://docs.learnbittensor.org/staking-and-delegation/delegation),
[Wallets, Coldkeys and Hotkeys](https://docs.learnbittensor.org/keys/wallets)).

## Development Stage Context

The
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction#subnet-development)
describes subnet development as moving from localnet to testnet and then mainnet. For External
Wallet, this sequence gives readers a boundary for interpreting wallet-connection examples and
network-selection notes.

The [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks) reference
separates mainnet, testnet, and localnet. Outcomes from one environment should not be treated as
proof of behavior in another.

## Hardware Signers Behind External Interfaces

Documentation describes hardware signing devices as one way to keep private key material off the
general-purpose workstation while still using a wallet application for display and transaction
preparation
([Using Ledger Hardware Wallet](https://docs.learnbittensor.org/staking-and-delegation/using-ledger-hw-wallet),
[Wallets, Coldkeys and Hotkeys](https://docs.learnbittensor.org/keys/wallets)).

That pattern is still external-wallet vocabulary when custody or signing control is managed outside
the default local Bittensor wallet path. The interface shows balances and drafts actions; the signer
approves them on a separate device
([Glossary: External Wallet](https://docs.learnbittensor.org/resources/glossary#external-wallet),
[Glossary: Private Key](https://docs.learnbittensor.org/resources/glossary#private-key)).

## Distinction from Local Wallet

Local wallet names files stored through the local Bittensor install path. External wallet names
custody or software outside that path
([Glossary: Local Wallet](https://docs.learnbittensor.org/resources/glossary#local-wallet),
[Glossary: External Wallet](https://docs.learnbittensor.org/resources/glossary#external-wallet)).

Trust-model vocabulary differs by where signing control is managed. A local wallet file on the same
machine can still be read through an external interface when signing happens outside the default
install path.

## Distinction from Wallet Address

Wallet address names a public TAO destination. External wallet names where custody or signing
control is managed
([Glossary: Wallet Address](https://docs.learnbittensor.org/resources/glossary#wallet-address),
[Glossary: External Wallet](https://docs.learnbittensor.org/resources/glossary#external-wallet)).

Destination vocabulary and custody-location vocabulary answer different questions.

## Distinction from Bittensor Wallet

Bittensor wallet names the on-chain identity container. External wallet names a custody interface
around that identity
([Glossary: Bittensor Wallet](https://docs.learnbittensor.org/resources/glossary#bittensor-wallet),
[Glossary: External Wallet](https://docs.learnbittensor.org/resources/glossary#external-wallet)).

Identity vocabulary persists across storage choices.

## Distinction from Ledger Hardware Wallet

Ledger hardware wallet names a device that holds signing material off the host. External wallet
names custody outside the local Bittensor wallet path more generally
([Using Ledger Hardware Wallet](https://docs.learnbittensor.org/staking-and-delegation/using-ledger-hw-wallet),
[Glossary: External Wallet](https://docs.learnbittensor.org/resources/glossary#external-wallet)).

Device vocabulary and custody-location vocabulary are related but not identical.

## Distinction from Private Key

Private key names protected signing material. External wallet names where that material is held or
approved during use
([Glossary: Private Key](https://docs.learnbittensor.org/resources/glossary#private-key),
[Glossary: External Wallet](https://docs.learnbittensor.org/resources/glossary#external-wallet)).

Key-material vocabulary and custody-interface vocabulary sit on different layers. External custody
does not rename the private key; it changes where approval happens during wallet use.

## Reader Boundary

External wallet should not be read as a subnet role, validator recommendation, wallet provider
endorsement, or balance state. It names custody-location vocabulary for wallet software or signing
control outside the local Bittensor wallet path
([Glossary: External Wallet](https://docs.learnbittensor.org/resources/glossary#external-wallet),
[Wallets](https://docs.learnbittensor.org/keys/wallets)).
