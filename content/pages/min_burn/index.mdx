# Min Burn

Min burn is a per-subnet hyperparameter that sets the lower bound on the dynamic TAO burn required
to register a neuron on a subnet. Official documentation describes it as the lower bound for that
registration burn, gives a default of 0.0005 TAO, and marks it owner-settable.

References: [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)

## How the Floor Works

Registering a neuron burns TAO, and that cost is dynamic: it rises as registrations occur and eases
back during quieter periods, moving between a lower and an upper bound. Min burn fixes the bottom of
that range, so the registration cost can settle toward it but not below it, keeping a baseline cost
even when demand is low.

Reference: [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)

## Per-Subnet Setting

Min burn is one of the subnet hyperparameters that configure a single subnet, for example netuid 1,
and a subnet owner can adjust it. The value in force is per-subnet chain state and can differ from
the documented default, so the real floor should be read for the subnet in question.

References:
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Register](https://docs.learnbittensor.org/resources/glossary#register)

## Floor and Live Burn Context

Min burn is easiest to read as the floor of a registration-cost range, not as the whole registration
price. The subnet-hyperparameters reference describes the burn as dynamic and bounded, while the
register glossary entry keeps the action tied to adding a neuron to a subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Register](https://docs.learnbittensor.org/resources/glossary#register)).

| Reading item    | What it explains                            | What it does not replace                |
| --------------- | ------------------------------------------- | --------------------------------------- |
| Min burn        | The lower bound for the dynamic burn        | The current live registration price     |
| Max burn        | The upper bound for the same burn range     | The floor set by the min-burn value     |
| Current burn    | The burn observed for a subnet at a moment  | The documented default for every subnet |
| Register action | The act of registering a neuron on a subnet | A guarantee about future burn levels    |
| Netuid context  | Which subnet the setting belongs to         | A global burn value across all subnets  |

This distinction matters because min burn is a per-subnet hyperparameter. Two subnets can share the
same concept while exposing different live values, and a subnet's owner-settable settings can move
the local floor away from the documented default
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

The dynamic burn still does the immediate pricing work for registration. Min burn only controls how
low that dynamic amount can fall; it does not say that every registration costs exactly the minimum
or that demand has no effect on the observed cost
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Register](https://docs.learnbittensor.org/resources/glossary#register)).

That makes the floor a constraint on the mechanism rather than a quote for the next registration.

Max burn is the paired ceiling. Reading both bounds together gives the range in which the dynamic
registration burn can move, while the live chain value answers where the burn sits inside that range
for the selected subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

The netuid context keeps the value local. A min-burn statement for one subnet should not be carried
over to another subnet unless the same on-chain setting has been checked there
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

The register action supplies the use case for the floor. A neuron registration consumes the burn
required by the selected subnet, so min burn is relevant when readers need to separate the act of
joining a subnet from the lower bound that constrains that subnet's dynamic burn
([Register](https://docs.learnbittensor.org/resources/glossary#register),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

For a reader comparing registration costs, the concept order is therefore subnet, live dynamic burn,
lower bound, and upper bound. Min burn answers the lower-bound part of that sequence; it does not
replace the subnet-specific value observed at registration time.

References:
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Register](https://docs.learnbittensor.org/resources/glossary#register)

## Reader Boundary

This page defines the concept. It does not report the min burn value or the current registration
cost on any particular subnet; those are live chain state to check for the relevant netuid.
