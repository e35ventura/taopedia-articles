# Min Burn

Min burn is a per-subnet hyperparameter that sets the lower bound on the dynamic TAO burn required
to register a neuron on a subnet. Official documentation describes it as the lower bound for that
registration burn, gives a default of 0.0005 TAO, and marks it owner-settable.

References: [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)

## How the Floor Works

Registering a neuron burns TAO, and that cost is dynamic: it rises as registrations occur and eases
back during quieter periods, moving between a lower and an upper bound. Min burn fixes the bottom of
that range, so the registration cost can settle toward it but not below it, keeping a baseline cost
even when demand is low.

Reference: [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)

## Per-Subnet Setting

Min burn is one of the subnet hyperparameters that configure a single subnet, for example netuid 1,
and a subnet owner can adjust it. The value in force is per-subnet chain state and can differ from
the documented default, so the real floor should be read for the subnet in question.

References:
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Register](https://docs.learnbittensor.org/resources/glossary#register)

## Reader Boundary

This page defines the concept. It does not report the min burn value or the current registration
cost on any particular subnet; those are live chain state to check for the relevant netuid.

## Max Burn Pairs With Min Burn as the Upper Bound

The [Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register) describes the
neuron registration burn as dynamic with explicit bounds. The burn price is bounded by `MinBurn` and
`MaxBurn`, so min burn fixes the floor while max burn fixes the ceiling for the same registration
cost on a subnet such as netuid 1
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Readers comparing burn parameters should treat the pair as one range. Min burn names the lowest
allowed registration price; max burn names the highest allowed registration price under the same
dynamic system ([Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register)).

## Each Successful Registration Can Raise the Burn Price

Official register documentation states that the dynamic burn increases on each successful
registration through `BurnIncreaseMult`. When many neurons register in a short period, the price can
move up toward the max burn bound rather than staying at the floor.

That rise is separate from the floor itself. Min burn still defines the lower limit the price can
decay toward, while the increase multiplier explains why busy registration periods push cost upward
([Mining: Miner registration](https://docs.learnbittensor.org/miners#miner-registration)).

## Burn Half-Life Lets Quiet Periods Lower Cost Toward the Floor

The same glossary entry states that registration burn decays over time according to `BurnHalfLife`.
During quieter periods, the dynamic price can fall back toward min burn instead of remaining at a
recent peak.

Static articles should describe that decay behavior rather than quoting a live registration amount.
The floor, ceiling, increase rule, and half-life together explain how registration cost moves over
time ([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).
