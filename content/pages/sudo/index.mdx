# Sudo

Sudo is the Bittensor glossary term for privileged administrative authority. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#sudo) describes it as a privileged key
for administrative actions that has been replaced by the governance protocol for enhanced security.

## Governance Context

The [Governance Overview](https://docs.learnbittensor.org/governance) explains that Bittensor
governance moves network management away from centralized control over time. In that model, the
Triumvirate creates proposals and the Senate reviews them, replacing single-authority administration
with proposal review.

## Security Transition

Before Bittensor governance, administrative actions required permission through a single privileged
sudo key. The [Governance Overview](https://docs.learnbittensor.org/governance#security) explains
that governance replaced that single-key model so approving privileged changes now requires both
Senate majority support and Triumvirate closure of a proposal.

## Reader Boundary

This article describes Sudo as a governance term. It does not identify any live holder, expose key
material, or describe privileged action execution. Readers should use official governance references
for current proposal-review context.

## Relationship to Triumvirate

Sudo and the Triumvirate are related but different parts of Bittensor governance vocabulary. Sudo
names the legacy privileged administrative key that Bittensor governance replaced, while the
Triumvirate is the proposal-origin body that creates governance items for Senate review under the
new bicameral model. The [Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo)
describes Sudo as the privileged key replaced by the governance protocol, and the
[Glossary: Triumvirate](https://docs.learnbittensor.org/resources/glossary#triumvirate) describes
the Triumvirate as responsible for creating proposals that the Senate approves or rejects.

For readers, Sudo names the single-authority model that governance moved away from, while the
Triumvirate names the proposal-creation side of the bicameral replacement that distributes
privileged decision authority.

References: [Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo),
[Glossary: Triumvirate](https://docs.learnbittensor.org/resources/glossary#triumvirate)

## Relationship to Senate

Sudo and the Senate are related but different parts of Bittensor governance vocabulary. Sudo names
the legacy privileged administrative key, while the Senate is the stake-based review body that votes
to approve or reject Triumvirate proposals under the governance protocol that replaced Sudo. The
[Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo) describes Sudo as replaced
by the governance protocol for enhanced security, and the
[Senate](https://docs.learnbittensor.org/governance/senate) documentation describes the Senate as
the body of elected delegates who review proposals before they can be closed and executed.

For readers, Sudo names the single-key administrative model, while the Senate names the
approval-gate body in the governance replacement that requires stake-based majority support before
privileged changes can proceed.

References: [Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo),
[Senate](https://docs.learnbittensor.org/governance/senate)

## Relationship to Bittensor Governance

Sudo and Bittensor governance are related but different scopes in Bittensor governance vocabulary.
Sudo names the legacy privileged administrative key that controlled network changes through
single-authority decisions, while Bittensor governance names the bicameral proposal-review process
that replaced that model. The [Governance Overview](https://docs.learnbittensor.org/governance)
explains that governance moves network management away from centralized control by requiring
Triumvirate proposal creation and Senate approval before privileged actions execute, and the
[Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo) describes Sudo as the
single privileged key that governance replaced.

For readers, Sudo names what governance replaced, while Bittensor governance names the distributed
proposal-review structure that now gates privileged network changes.

References: [Governance Overview](https://docs.learnbittensor.org/governance),
[Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo)
