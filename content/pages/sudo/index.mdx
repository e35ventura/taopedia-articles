# Sudo

Sudo is the Bittensor glossary term for privileged administrative authority. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#sudo) describes it as a privileged key
for administrative actions that has been replaced by the governance protocol for enhanced security.

## Governance Context

The [Governance Overview](https://docs.learnbittensor.org/governance) explains that Bittensor
governance moves network management away from centralized control over time. In that model, the
Triumvirate creates proposals and the Senate reviews them, replacing single-authority administration
with proposal review.

## Security Transition

Before Bittensor governance, administrative actions required permission through a single privileged
sudo key. The [Governance Overview](https://docs.learnbittensor.org/governance#security) explains
that governance replaced that single-key model so approving privileged changes now requires both
Senate majority support and Triumvirate closure of a proposal.

## Relationship to Triumvirate

Sudo and the Triumvirate sit on opposite sides of Bittensor's governance transition. Sudo names the
legacy single-key administrative authority, while the
[Glossary: Triumvirate](https://docs.learnbittensor.org/resources/glossary#triumvirate) describes
the body that creates governance proposals in the model that replaced single-key control. The
[Governance Overview](https://docs.learnbittensor.org/governance) describes governance moving
network management away from centralized control.

For readers, sudo names the privileged authority being phased out, while the Triumvirate names the
proposing body in the governance protocol that supersedes it. A privileged change that once relied
on the sudo key now begins as a Triumvirate proposal rather than a single-key action.

References: [Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo),
[Glossary: Triumvirate](https://docs.learnbittensor.org/resources/glossary#triumvirate)

## Relationship to Senate

Sudo and the Senate are related through the same governance transition. Sudo names the legacy
single-key administrative authority, while the
[Glossary: Senate](https://docs.learnbittensor.org/resources/glossary#senate) describes the elected
delegates who approve or reject proposals in the governance model that replaced it. The
[Governance Overview](https://docs.learnbittensor.org/governance#security) explains that approving
privileged changes now requires Senate majority support alongside Triumvirate closure.

For readers, sudo names the concentrated authority being replaced, while the Senate names the review
gate that distributes approval across elected delegates. The shift from sudo to Senate review is the
move from one privileged key to a proposal-approval body.

References: [Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo),
[Glossary: Senate](https://docs.learnbittensor.org/resources/glossary#senate)

## Reader Boundary

This article describes Sudo as a governance term. It does not identify any live holder, expose key
material, or describe privileged action execution. Readers should use official governance references
for current proposal-review context.
