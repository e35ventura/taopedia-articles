# Sudo

Sudo is the Bittensor glossary term for privileged administrative authority. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#sudo) describes it as a privileged key
for administrative actions that has been replaced by the governance protocol for enhanced security.

## Governance Context

The [Governance Overview](https://docs.learnbittensor.org/governance) explains that Bittensor
governance moves network management away from centralized control over time. In that model, the
Triumvirate creates proposals and the Senate reviews them, replacing single-authority administration
with proposal review.

## Security Transition

Before Bittensor governance, administrative actions required permission through a single privileged
sudo key. The [Governance Overview](https://docs.learnbittensor.org/governance#security) explains
that governance replaced that single-key model so approving privileged changes now requires both
Senate majority support and Triumvirate closure of a proposal.

## Relationship to Triumvirate

Sudo and the Triumvirate are related but different scopes in Bittensor governance vocabulary. Sudo
names the legacy single-key administrative authority that privileged changes once depended on, while
the Triumvirate names the governance body that now originates proposals for Senate review. The
[Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo) describes the replaced
privileged-key model, and the
[Glossary: Triumvirate](https://docs.learnbittensor.org/resources/glossary#triumvirate) defines the
Triumvirate as the group responsible for creating proposals.

For readers, Sudo names what governance replaced at the administrative-authority layer, while the
Triumvirate names the proposal-origin body inside the replacement process.

References: [Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo),
[Glossary: Triumvirate](https://docs.learnbittensor.org/resources/glossary#triumvirate)

## Relationship to Senate

Sudo and the Senate are related but different scopes in Bittensor governance vocabulary. Sudo names
single-key administrative authority, while the Senate names the stake-based body that approves or
rejects Triumvirate proposals before privileged call data can advance. The
[Governance Overview](https://docs.learnbittensor.org/governance) explains that governance adds
Senate majority support as a required gate, and the
[Glossary: Senate](https://docs.learnbittensor.org/resources/glossary#senate) describes the Senate
as the group of elected delegates that reviews Triumvirate proposals.

For readers, Sudo names the old centralized approval path, while the Senate names the review body in
the replacement governance flow.

References: [Governance Overview](https://docs.learnbittensor.org/governance),
[Glossary: Senate](https://docs.learnbittensor.org/resources/glossary#senate)

## Relationship to Proposal

Sudo and a proposal are related but different parts of Bittensor governance vocabulary. Sudo names
privileged administrative authority exercised through a single key, while a proposal wraps
privileged call data that moves through Triumvirate creation, Senate review, and Triumvirate close
before execution. The
[Glossary: Proposal](https://docs.learnbittensor.org/resources/glossary#proposal) defines a proposal
as an item put forward by the Triumvirate for Senate vote, and the
[Governance Overview](https://docs.learnbittensor.org/governance) describes that review path as the
replacement for direct sudo execution.

For readers, Sudo names the old direct-action model, while a proposal names the reviewed governance
item that may later execute on chain.

References: [Glossary: Proposal](https://docs.learnbittensor.org/resources/glossary#proposal),
[Governance Overview](https://docs.learnbittensor.org/governance)

## Relationship to Bicameral Legislature

Sudo and bicameral legislature are related but different scopes in Bittensor governance vocabulary.
Sudo names the single-authority model that governance replaced, while bicameral legislature names
the two-body structure — Triumvirate plus Senate — used for proposal review afterward. The
[Glossary: Bicameral Legislature](https://docs.learnbittensor.org/resources/glossary#bicameral-legislature)
defines that pairing as a two-tier proposal-approval system, and the
[Governance Overview](https://docs.learnbittensor.org/governance) explains why privileged changes
now require both Senate support and Triumvirate closure.

For readers, Sudo names the prior centralized authority pattern, while bicameral legislature names
the split review structure that replaced it.

References:
[Glossary: Bicameral Legislature](https://docs.learnbittensor.org/resources/glossary#bicameral-legislature),
[Governance Overview](https://docs.learnbittensor.org/governance)

## Relationship to Bittensor Governance

Sudo and Bittensor governance are related but different scopes in Bittensor governance vocabulary.
Bittensor governance names the full network process for reviewing and executing privileged changes,
while Sudo names the administrative authority model that process is designed to replace. The
[Governance Overview](https://docs.learnbittensor.org/governance) describes governance as moving
network management away from centralized control, and the
[Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo) notes that the privileged
sudo key has been replaced by the governance protocol for enhanced security.

For readers, Bittensor governance names the replacement review process, while Sudo names the legacy
authority pattern that process supersedes for privileged changes.

References: [Governance Overview](https://docs.learnbittensor.org/governance),
[Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo)

## Relationship to Subtensor

Sudo and Subtensor are related but different parts of Bittensor chain vocabulary. Subtensor names
Bittensor's layer 1 blockchain and system of record, while Sudo names privileged administrative
authority that once could execute changes on that chain layer through a single key. The
[Glossary: Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor) describes the
blockchain layer, and the [Governance Overview](https://docs.learnbittensor.org/governance) explains
that successfully closed proposal call data now executes on that layer after governance review
rather than through direct sudo execution alone.

For readers, Subtensor names the chain layer, while Sudo names the legacy privileged authority model
whose direct use governance is designed to replace.

References: [Glossary: Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor),
[Governance Overview](https://docs.learnbittensor.org/governance)

## Reader Boundary

This article describes Sudo as a governance term. It does not identify any live holder, expose key
material, or describe privileged action execution. Readers should use official governance references
