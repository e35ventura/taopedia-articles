# Sudo

Sudo is the Bittensor glossary term for privileged administrative authority. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#sudo) describes it as a privileged key
for administrative actions that has been replaced by the governance protocol for enhanced security.

## Governance Context

The [Governance Overview](https://docs.learnbittensor.org/governance) explains that Bittensor
governance moves network management away from centralized control over time. In that model, the
Triumvirate creates proposals and the Senate reviews them, replacing single-authority administration
with proposal review.

## Security Transition

Before Bittensor governance, administrative actions required permission through a single privileged
sudo key. The [Governance Overview](https://docs.learnbittensor.org/governance#security) explains
that governance replaced that single-key model so approving privileged changes now requires both
Senate majority support and Triumvirate closure of a proposal.

## Proposal Review Context

The [Governance Overview](https://docs.learnbittensor.org/governance) describes a bicameral
structure in which proposals move through Triumvirate and Senate review. That context explains why
Sudo remains useful as a historical governance term: it names the kind of single administrative
authority the proposal process is meant to avoid.

For readers, Sudo is best understood as a contrast term. It points to privileged action authority,
while Bittensor governance points to proposal-based review. The important distinction is not which
specific key exists today, but how authority is supposed to be checked before privileged changes are
accepted.

The security section of the governance docs says the governance protocol replaced the single sudo
key model. That replacement changes the reader's frame from possession of a privileged key to a
review process involving Senate support and Triumvirate closure. Sudo therefore belongs with
governance history and security boundaries rather than routine user activity.

This also keeps nearby role names separate. The Triumvirate and Senate are governance bodies in the
review path, while Sudo names the older privileged-authority model that governance superseded. A
proposal can involve privileged network changes without making the proposer a sudo key holder.

That distinction matters when reading governance articles together. A Triumvirate action belongs to
proposal creation or closure, and Senate action belongs to review. Sudo names neither chamber; it
names the centralized administrative authority that the bicameral process is designed to replace.

The term also helps explain why governance review is treated as a security feature. The security
benefit described in the official docs comes from moving sensitive changes away from a single key
and into a process that requires separate review and closure steps.

The [Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo) definition is
intentionally narrow. It does not make Sudo a current office, a wallet setup topic, or a guide to
administrative execution. In Taopedia, the term helps readers understand why proposal review matters
for sensitive network changes.

## Reader Boundary

This article describes Sudo as a governance term. It does not identify any live holder, expose key
material, or describe privileged action execution. Readers should use official governance references
for current proposal-review context.
