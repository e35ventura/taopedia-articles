# Sudo

Sudo is the Bittensor glossary term for privileged administrative authority. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#sudo) describes it as a privileged key
for administrative actions that has been replaced by the governance protocol for enhanced security.

## Governance Context

The [Governance Overview](https://docs.learnbittensor.org/governance) explains that Bittensor
governance moves network management away from centralized control over time. In that model, the
Triumvirate creates proposals and the Senate reviews them, replacing single-authority administration
with proposal review.

## Security Transition

Before Bittensor governance, administrative actions required permission through a single privileged
sudo key. The [Governance Overview](https://docs.learnbittensor.org/governance#security) explains
that governance replaced that single-key model so approving privileged changes now requires both
Senate majority support and Triumvirate closure of a proposal.

## Reader Boundary

This article describes Sudo as a governance term. It does not identify any live holder, expose key
material, or describe privileged action execution. Readers should use official governance references
for current proposal-review context.

## Relationship to Coinbase

Sudo and coinbase represent different kinds of Bittensor chain authority. Sudo names the privileged
administrative key that was used for human-initiated privileged actions before Bittensor governance
replaced that single-key model, as described in the
[Glossary: Sudo](https://docs.learnbittensor.org/resources/glossary#sudo) and the
[Governance Overview](https://docs.learnbittensor.org/governance). Coinbase is the per-block
Subtensor mechanism that accumulates pending emissions and triggers the Yuma Consensus epoch round
at each subnet's epoch boundary, as described by the
[Coinbase Implementation](https://docs.learnbittensor.org/subtensor-api/extrinsics#coinbase).

The important distinction is that coinbase was never in the sudo-governed category. Sudo covered
privileged human-initiated actions requiring administrative key authorization — changes that
governance now routes through the Triumvirate and Senate instead. Coinbase is an autonomous protocol
function that runs inside every block automatically, requiring no human authority, no administrative
key, and no governance proposal to execute. The governance protocol that replaced sudo governs
privileged human-initiated changes; coinbase is a built-in protocol schedule that runs regardless of
governance state.
