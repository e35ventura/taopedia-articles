# Out Of Bounds

`OutOfBounds` is a contracts pallet error raised when a buffer outside sandbox memory is passed to a
contract API function. The API errors reference summarizes it as "A buffer outside of sandbox memory
was passed to a contract API function"
([Subtensor API Errors: OutOfBounds](https://docs.learnbittensor.org/subtensor-api/errors#outofbounds)).

## What It Means

Bittensor runs an Ethereum-compatible execution layer on Subtensor for smart contracts
([Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials)). Contract execution
runs inside a sandboxed memory region, and contract API functions only accept buffers that lie
within that region. `OutOfBounds` means a call supplied a buffer pointer or slice that falls outside
the sandbox, so the runtime rejects the API access before proceeding
([Subtensor API Errors: OutOfBounds](https://docs.learnbittensor.org/subtensor-api/errors#outofbounds)).

This is a sandbox memory-boundary rejection. It does not, by itself, mean the contract exhausted its
gas limit, that no code exists at a supplied hash, or that execution trapped during the call.

## Why It Appears

This error appears when contract code or its host interaction passes a buffer outside sandbox memory
to a contract API function
([Subtensor API Errors: OutOfBounds](https://docs.learnbittensor.org/subtensor-api/errors#outofbounds)).

## Distinction from Out Of Gas

`OutOfBounds` and `OutOfGas` are different contracts pallet errors with different API summaries.
`OutOfBounds` is summarized as "A buffer outside of sandbox memory was passed to a contract API
function." `OutOfGas` is summarized as "The executed contract exhausted its gas limit."
([Subtensor API Errors: OutOfGas](https://docs.learnbittensor.org/subtensor-api/errors#outofgas),
[Subtensor API Errors: OutOfBounds](https://docs.learnbittensor.org/subtensor-api/errors#outofbounds)).

- **OutOfBounds** — a buffer outside sandbox memory was passed to a contract API function.
- **OutOfGas** — the executed contract exhausted its gas limit.

## Distinction from Max Call Depth Reached

`OutOfBounds` and `MaxCallDepthReached` both block contract execution, but on different checks.
`MaxCallDepthReached` is summarized as "Performing a call was denied because the calling depth
reached the limit of what is specified in the schedule." `OutOfBounds` is summarized as "A buffer
outside of sandbox memory was passed to a contract API function."
([Subtensor API Errors: MaxCallDepthReached](https://docs.learnbittensor.org/subtensor-api/errors#maxcalldepthreached),
[Subtensor API Errors: OutOfBounds](https://docs.learnbittensor.org/subtensor-api/errors#outofbounds)).

- **OutOfBounds** — a sandbox memory buffer boundary was violated.
- **MaxCallDepthReached** — nested call depth reached the schedule limit.

## Reader Boundary

This page defines the meaning of the error label from the API reference. It does not report sandbox
memory limits configured on a live network or diagnose a specific contract's memory layout
([Subtensor API Errors: OutOfBounds](https://docs.learnbittensor.org/subtensor-api/errors#outofbounds),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
