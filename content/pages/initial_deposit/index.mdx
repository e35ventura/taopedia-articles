# Initial Deposit

Initial deposit is a commitments pallet runtime constant, listed in the chain's constants metadata
as initialDeposit, with the value 0 and the summary "The amount held on deposit for a registered
identity"
([Subtensor API Constants: initialDeposit](https://docs.learnbittensor.org/subtensor-api/constants#initialdeposit-u64)).
The runtime sets this to zero directly, with the source itself annotating the value as Free
([runtime/src/lib.rs](https://github.com/opentensor/subtensor/blob/14bc6f9f964b9cc362e9635dd110a487fa5d15a0/runtime/src/lib.rs#L884)).

## What It Means

The set_commitment call computes a submission's total deposit from two constants: this base amount,
plus fieldDeposit charged for each additional field beyond the base. The runtime sets fieldDeposit
to zero as well, with the same Free annotation
([runtime/src/lib.rs](https://github.com/opentensor/subtensor/blob/14bc6f9f964b9cc362e9635dd110a487fa5d15a0/runtime/src/lib.rs#L885)).
Because both constants are zero, the computed deposit for any commitment is zero regardless of how
many fields it carries
([commitments/lib.rs](https://github.com/opentensor/subtensor/blob/14bc6f9f964b9cc362e9635dd110a487fa5d15a0/pallets/commitments/src/lib.rs#L286-L288),
[Subtensor API Constants: fieldDeposit](https://docs.learnbittensor.org/subtensor-api/constants#fielddeposit-u64)).

This is a single network-wide setting, not a per-subnet value. It reflects the current runtime
configuration, not a fixed protocol rule; the constants could be changed in a future runtime
upgrade.

## Reader Boundary

This page defines both deposit constants and their current zero value. It does not cover the
separate field-count or per-epoch space limits that also constrain a commitment submission
([Subtensor API Constants: initialDeposit](https://docs.learnbittensor.org/subtensor-api/constants#initialdeposit-u64)).
