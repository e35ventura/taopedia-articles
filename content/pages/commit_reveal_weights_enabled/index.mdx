# Commit Reveal Weights Enabled

Commit reveal weights enabled is a per-subnet hyperparameter, listed as `CommitRevealWeightsEnabled`
in Bittensor documentation, that switches the commit-reveal weight submission mechanism on or off
for a subnet. The
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters) reference
lists `CommitRevealWeightsEnabled` alongside the related `CommitRevealPeriod` parameter that sets
the block interval for the reveal step when the mechanism is active
([Commit Reveal](https://docs.learnbittensor.org/subnets/commit-reveal)).

The term names the enablement flag for the commit-reveal mechanism. It is a boolean setting, not a
block count or a weight value. The `CommitRevealPeriod` parameter configures the timing behavior of
the mechanism; `CommitRevealWeightsEnabled` determines whether that mechanism applies on the subnet
at all.

## What It Controls

`CommitRevealWeightsEnabled` sets whether the commit-reveal weight submission path is active on the
subnet. The flag is set at the subnet level, so different subnets can have commit-reveal active or
inactive independently of each other
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Commit Reveal](https://docs.learnbittensor.org/subnets/commit-reveal)).

The active state for netuid 1 belongs to that subnet's hyperparameter configuration and does not
apply to other subnets. A flag reading from one subnet should not be treated as evidence for the
commit-reveal status of any other subnet.

## Relation to Commit Reveal Period

`CommitRevealPeriod` sets the number of blocks between the commit step and the reveal step of the
mechanism. `CommitRevealWeightsEnabled` is the precondition: the `CommitRevealPeriod` timing is
relevant only when `CommitRevealWeightsEnabled` is active for the subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Commit Reveal](https://docs.learnbittensor.org/subnets/commit-reveal)).

The two parameters belong to the same commit-reveal configuration group. The flag controls whether
the group applies; the period parameter configures the group's timing when it does.

## Relation to Commit Reveal

The [Commit Reveal](https://docs.learnbittensor.org/subnets/commit-reveal) documentation describes
the commit-reveal weight submission mechanism and how validators use it on subnets where the
mechanism is active. `CommitRevealWeightsEnabled` is the hyperparameter that enables or disables
that mechanism at the subnet level.

The mechanism and its enablement flag are separate concepts. The mechanism describes the two-step
submission path; the flag is the per-subnet switch that activates or deactivates it.

## Relation to Weight Setting

The [weight setting](https://docs.learnbittensor.org/subnets/understanding-subnets) path describes
how validators submit evaluation weights inside a subnet. Commit reveal weights enabled determines
whether that path uses the commit-reveal approach or the direct submission path for the subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

The weight setting process and the commit-reveal flag address different questions. Weight setting is
the evaluation action; the flag configures which submission variant is required on a given subnet.

## Documented Type

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `CommitRevealWeightsEnabled` as a boolean subnet hyperparameter. Each subnet holds
its own flag state, so the enabled status on netuid 1 can differ from the status on another subnet.

The active value is per-subnet chain state. Flag values belong to the specific subnet configuration
that produced them.

## Network and Environment Scope

The [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks) reference
separates mainnet, testnet, and localnet environments. A commit reveal weights enabled reading from
one environment is not evidence for the same flag state in another environment, because each network
holds independent subnet hyperparameter state.

On mainnet, `CommitRevealWeightsEnabled` is the live per-subnet flag that governs whether production
weight submission uses the commit-reveal mechanism for the selected netuid.

## Evidence Boundary

`CommitRevealWeightsEnabled` is an enablement flag. It does not name a weight value, a reveal block,
or a validator's submission status. Those are elements inside the weight submission path; the flag
is the per-subnet switch that determines whether the commit-reveal variant of that path is required
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Commit Reveal](https://docs.learnbittensor.org/subnets/commit-reveal)).

A claim about commit reveal weights enabled should name the relevant subnet and its current flag
state. The flag value for netuid 1 is that subnet's own chain state.
