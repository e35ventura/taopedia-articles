Nodexo is Bittensor Subnet 106, operated by [NeuralInternet](https://nodexo.ai). Its on-chain
description is "tokenized ai compute." The subnet links
[neuralinternet/SN27](https://github.com/neuralinternet) as its GitHub organization and
[nodexo.ai](https://nodexo.ai) as its project site.

The subnet was previously registered to a different project. The current operator, NeuralInternet,
registered the Nodexo identity and has been running a GPU compute subnet under this netuid. The
public monitoring repository at
[neuralinternet/SN27-opencompute](https://github.com/neuralinternet/SN27-opencompute) provides open
dashboards and tooling for tracking miner performance, hardware specs, and validator state.

## How the Mechanism Works

Nodexo is a GPU compute market. Miners expose GPU hardware — including model, VRAM, and TFLOPS
performance — and respond to challenges and rental requests. Validators benchmark miners and track
their capabilities through W&amp;B (Weights &amp; Biases) under the
[neuralinternet/opencompute](https://wandb.ai/neuralinternet/opencompute) project.

The benchmark mechanism uses matrix multiplication proof-of-work challenges. A validator sends a
challenge that specifies a deterministic matrix pair; the miner computes both products on its GPU
and returns SHA-256 Merkle roots over the row hashes. The validator then requests proofs for
specific rows, which the miner provides with the corresponding Merkle siblings. This lets validators
confirm that a miner actually performed the computation on real GPU hardware without re-running the
full matrix products themselves.

Scoring draws on both benchmark performance and the GPU specifications that miners report and
validators cross-check. GPU TFLOPS (FP16 and FP32) and VRAM directly influence how validators weight
each miner's contribution through [[Yuma Consensus]].

## Participating as a Miner

Miners register on Subnet 106 and run software that advertises their GPU hardware, responds to
benchmark challenges, and handles compute allocation requests from validators. When challenged, a
miner runs the matrix computation on-device and returns Merkle roots; it must then supply Merkle
proofs for any rows the validator requests. Miners also expose a rental endpoint through which
validators can request Docker-based compute containers for specific timelines. Operators should
treat the current repository linked in the on-chain identity as the authoritative source for setup
and configuration details.

## Participating as a Validator

Validators maintain a live view of miner GPU specs by reading W&amp;B run data and benchmarking
miners directly. They issue matrix multiplication challenges, verify Merkle proofs, and record GPU
benchmark scores. Validators also handle compute rental allocation — sending allocation requests to
miners and tracking active rentals. Weights are set based on GPU capability, benchmark results, and
availability, with the resulting weight matrix submitted on-chain for [[Yuma Consensus]] to
distribute emissions.

## On-Chain Identity

Live SN106 data is available on [TaoStats](https://taostats.io/subnets/106). The on-chain identity
field registers the subnet name as Nodexo, the description as "tokenized ai compute," and lists
nodexo.ai as the subnet URL.
