# Initial Validator Prune Len

Initial Validator Prune Len is a subtensorModule runtime constant, listed in the chain's constants
metadata as initialValidatorPruneLen, with the value 1 and the summary "Initial validator context
pruning length"
([Subtensor API Constants: initialValidatorPruneLen](https://docs.learnbittensor.org/subtensor-api/constants#initialvalidatorprunelen-u64)).
It supplies the default value a subnet's ValidatorPruneLen uses.

## What It Means

ValidatorPruneLen is held per subnet and sets how many validator-context entries a subnet retains
when pruning validator data. Initial Validator Prune Len is the default this per-subnet value falls
back to before a different value applies for a subnet
([Subtensor API Constants: initialValidatorPruneLen](https://docs.learnbittensor.org/subtensor-api/constants#initialvalidatorprunelen-u64)).
The ValidatorPruneLen in force on a subnet such as netuid 1 is that subnet's own chain state and can
differ from this default.

## Distinction from Validator and UID Caps

Initial Validator Prune Len is the default validator-context pruning length, while
initialMaxAllowedValidators, valued at 128, is the maximum validators a subnet may have;
initialMaxAllowedUids, valued at 256, is the maximum number of UIDs a subnet may hold
([Subtensor API Constants: initialMaxAllowedValidators](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxallowedvalidators-u16),
[Subtensor API Constants: initialMaxAllowedUids](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxalloweduids-u16)).

## Reader Boundary

Initial Validator Prune Len is a default constant, not the live per-subnet ValidatorPruneLen, and it
reflects the current runtime configuration rather than a fixed protocol rule
([Subtensor API Constants: initialValidatorPruneLen](https://docs.learnbittensor.org/subtensor-api/constants#initialvalidatorprunelen-u64)).
