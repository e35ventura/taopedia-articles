# Subnet 1: Apex

Apex is Bittensor's first subnet (netuid 1), operated by [Macrocosmos](https://macrocosmos.ai). Its
incentive mechanism runs open competitions where miners submit algorithms and validators
continuously score those submissions against benchmarks. Rewards flow to miners whose solutions
perform best, creating a permissionless environment for algorithmic and agentic optimization
research.

## How the Mechanism Works

The [Apex overview](https://docs.macrocosmos.ai/subnets/subnet-1-apex) describes the subnet around
three layers:

- **Competition:** A defined problem domain with scoring criteria. Multiple competitions can run
  simultaneously on the subnet.
- **Round:** A discrete evaluation cycle within a competition. Submissions are scored each round,
  and cumulative performance across rounds determines a miner's rank.
- **Submission:** An algorithm a miner contributes for evaluation. Validators score each submission
  against the competition's benchmark.

Validators score active miner submissions each round. Scores feed into
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus), which translates them into
per-round emissions. Miners with consistently high-performing submissions earn the larger share. The
active competition set rotates over time
([Apex overview](https://docs.macrocosmos.ai/subnets/subnet-1-apex)).

## Miner and Validator Roles

Subnet 1 operates under the standard Bittensor two-role structure. Miners supply algorithmic
submissions for the active competition, and validators evaluate those contributions against each
competition's benchmark before setting weights
([Apex overview](https://docs.macrocosmos.ai/subnets/subnet-1-apex),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

Reward distribution follows [Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus).

## On-Chain Identity

Live SN1 data is available on [TaoStats](https://taostats.io/subnets/1). The Finney identity reports
the subnet name as Apex. It lists the GitHub repository as
[macrocosm-os/apex](https://github.com/macrocosm-os/apex), the subnet URL as apex.macrocosmos.ai,
the contact field as support@macrocosmos.ai, and the Discord channel as macrocrux. The description
reads "Open competitions for algorithmic and agentic optimization." The additional field is blank
([btcli reference](https://docs.learnbittensor.org/btcli/#btcli-subnets-get-identity)).

## Distinction from Yuma Consensus

Apex on netuid 1 is a competition-based subnet where validators score miner submissions against
rotating benchmark tasks ([Apex overview](https://docs.macrocosmos.ai/subnets/subnet-1-apex)). That
competition-scoring vocabulary names how Apex ranks miner performance on netuid 1, not the on-chain
step that turns validator weight submissions into emission shares each tempo
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

Competition scoring sits upstream of settlement. Validator assessments become weight signals that
Yuma Consensus aggregates into emission shares each tempo rather than Apex replacing that mechanism
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Emission](https://docs.learnbittensor.org/learn/emissions),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

For readers, competition rank vocabulary and consensus reward vocabulary answer different questions:
Apex names benchmark competition outcomes, while Yuma names how included validator weights become
miner incentives and validator dividends each tempo.

- **Subnet 1 (Apex)** — competition-scored benchmark subnet.
- **Yuma Consensus** — epoch-boundary settlement from validator weights to emission shares on a task
  subnet
  ([Yuma Consensus: Validator emissions](https://docs.learnbittensor.org/learn/yuma-consensus#validator-emissions)).

## Reader Boundary

Subnet 1 Apex should not be read as generic Bittensor subnet documentation, a guarantee of current
competition results, or proof that every subnet behaves like Apex. It names one mainnet subnet's
competition-based incentive context
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).
