# Liquid Alpha Disabled

`LiquidAlphaDisabled` means an alpha-bounds update was submitted while liquid alpha remains turned
off on the targeted subnet. The standard-errors reference describes it as "Attempting to set alpha
high/low while disabled"
([Subtensor Standard Errors](https://docs.learnbittensor.org/subtensor-api/errors#liquidalphadisabled)).

Liquid alpha is the consensus-driven bond-smoothing mode that lets validator-miner pairs use an
alpha value between configured low and high bounds. The `LiquidAlphaEnabled` hyperparameter is the
per-subnet switch that turns that mode on
([Subnet Hyperparameters: LiquidAlphaEnabled](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#liquidalphaenabled),
[Consensus-based Weights](https://docs.learnbittensor.org/concepts/consensus-based-weights)).

## What It Means

`sudo_set_alpha_values` writes a subnet's alpha low and alpha high bounds. `LiquidAlphaDisabled`
means the call reached that setter while `LiquidAlphaEnabled` was still false, so the chain rejected
the update and left the stored bounds unchanged
([Subtensor Standard Errors](https://docs.learnbittensor.org/subtensor-api/errors#liquidalphadisabled),
[Subnet Hyperparameters: LiquidAlphaEnabled](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#liquidalphaenabled)).

This is a feature-toggle gate. Alpha low and alpha high describe a range that only matters once
liquid alpha is enabled. With the toggle off, the subnet uses the fixed bond-smoothing path derived
from bonds moving average instead
([Subnet Hyperparameters: BondsMovingAverage](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#bondsmovingaverage),
[Yuma Consensus: Bonding mechanics](https://docs.learnbittensor.org/learn/yuma-consensus#bonding)).

## Why It Appears

This error appears when a caller submits new alpha low or alpha high values before enabling liquid
alpha on that subnet. That can happen when alpha bounds were configured in tooling but the toggle
was never turned on, when a copied extrinsic omits the enable step, or when automation assumes the
bounds are already active
([Subnet Hyperparameters: LiquidAlphaEnabled](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#liquidalphaenabled)).

When debugging, confirm authorization and timing failures first. `NotSubnetOwner` and `BadOrigin`
mean the signer lacks permission for the hyperparameter change.
`AdminActionProhibitedDuringWeightsWindow` means the call arrived during the epoch-end admin freeze
([Subtensor Standard Errors: NotSubnetOwner](https://docs.learnbittensor.org/subtensor-api/errors#notsubnetowner),
[Subtensor Standard Errors: BadOrigin](https://docs.learnbittensor.org/subtensor-api/errors#badorigin),
[Admin Action Prohibited During Weights Window](https://docs.learnbittensor.org/subtensor-api/errors#adminactionprohibitedduringweightswindow)).

The practical meaning is narrow: liquid alpha is off, so alpha bounds cannot be written yet. The
problem is not that alpha high is below the documented minimum or that alpha low falls outside the
allowed range; those bound checks apply only after the toggle is on.

## Distinction from Alpha High Too Low

`LiquidAlphaDisabled` and `AlphaHighTooLow` both appear on alpha-bounds updates, but they reject
different problems. `LiquidAlphaDisabled` means liquid alpha is still off, so the setter does not
accept bound changes at all. `AlphaHighTooLow` means liquid alpha is enabled, but the submitted
alpha high value is below the required minimum
([Subtensor Standard Errors: AlphaHighTooLow](https://docs.learnbittensor.org/subtensor-api/errors#alphahightoolow)).

- **LiquidAlphaDisabled** — liquid alpha is not enabled on the subnet.
- **AlphaHighTooLow** — alpha high is below the allowed minimum.

## Distinction from Alpha Low Out Of Range

`LiquidAlphaDisabled` and `AlphaLowOutOfRange` are paired gates on the same setter path.
`LiquidAlphaDisabled` fires when the feature toggle is off. `AlphaLowOutOfRange` fires only after
liquid alpha is enabled, when alpha low is below the minimum or above alpha high
([Subtensor Standard Errors: AlphaLowOutOfRange](https://docs.learnbittensor.org/subtensor-api/errors#alphalowoutofrange)).

- **LiquidAlphaDisabled** — liquid alpha is not enabled on the subnet.
- **AlphaLowOutOfRange** — alpha low is outside the allowed range.

## Reader Boundary

This page defines the meaning of the error label and the `LiquidAlphaEnabled` gate on
`sudo_set_alpha_values`. It does not describe how to enable liquid alpha, how live alpha bounds are
chosen for a subnet, or how bond smoothing runs during consensus; those are documented separately
([Subnet Hyperparameters: LiquidAlphaEnabled](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#liquidalphaenabled),
[Consensus-based Weights](https://docs.learnbittensor.org/concepts/consensus-based-weights)).
