# Register

Register is the Bittensor subnet-entry process for miners and validators. The glossary describes it
as entering a subnet by purchasing a subnet position through a dynamic burn in TAO
([Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register)).

The term is useful because it separates subnet entry from later performance. Register explains how
an entrant gets into the subnet context; it does not say that the entrant is active, highly ranked,
or earning rewards.

## Subnet Entry Context

The mining documentation uses register as the entry step before a miner can participate in subnet
work. Validator documentation uses the same general subnet-entry idea for validators
([Miners](https://docs.learnbittensor.org/miners),
[Validators](https://docs.learnbittensor.org/validators),
[Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register)).

That makes register a role-neutral term at the article level. A miner-specific page or
validator-specific page can add role details, but the general concept is subnet entry.

## Dynamic Burn Context

Register has a dynamic burn context. The glossary describes the burn as changing over time within
subnet parameter bounds, so a static article should describe the concept rather than quote a current
value ([Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

This keeps register separate from ordinary fee or price language. The important reference point is
that subnet entry has a dynamic burn component, not that a particular amount is stable across time
or subnets.

## Capacity Boundary

Register is related to deregistration because subnets have limited capacity. Miner documentation
describes the removal path that can occur when a full subnet accepts a new entrant and a
low-performing eligible entrant is displaced
([Mining: Miner deregistration](https://docs.learnbittensor.org/miners#miner-deregistration),
[Glossary: Deregistration](https://docs.learnbittensor.org/resources/glossary#deregistration)).

That relationship does not mean every entry removes someone else. It means register should be read
with the subnet's capacity and replacement rules in mind.

## Immunity Boundary

Subsequent subnet status is interpreted with timing context. The immunity period gives a new entrant
temporary protection from ordinary low-performance removal after subnet entry
([Glossary: Immunity Period](https://docs.learnbittensor.org/resources/glossary#immunity-period),
[Miners](https://docs.learnbittensor.org/miners)).

For readers, register names entry. Immunity period names the temporary protection window that can
follow entry. Later performance and reward outcomes still depend on the subnet's evaluation rules.

## Evidence Boundary

Register references support claims about subnet entry and dynamic burn context. They do not by
themselves prove current cost, current capacity, later reward outcomes, or a specific entrant's
status in a subnet.

For readers, the safe use of register is as a reference label for entering subnet participation
([Glossary: Register](https://docs.learnbittensor.org/resources/glossary#register)).
