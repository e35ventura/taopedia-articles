# Max Delegate Dependencies Reached

`MaxDelegateDependenciesReached` is a contracts pallet error raised when a contract has reached its
maximum number of delegate dependencies. The API errors reference summarizes it as "The contract has
reached its maximum number of delegate dependencies"
([Subtensor API Errors: MaxDelegateDependenciesReached](https://docs.learnbittensor.org/subtensor-api/errors#maxdelegatedependenciesreached)).

## What It Means

Bittensor runs an Ethereum-compatible execution layer on Subtensor for smart contracts
([Bittensor EVM Smart Contracts](https://docs.learnbittensor.org/evm-tutorials)). The contracts
pallet lets a contract record delegate dependencies on other code hashes it may call through
delegation. `MaxDelegateDependenciesReached` means the contract already has as many delegate
dependencies as the runtime allows, so another dependency cannot be added
([Subtensor API Errors: MaxDelegateDependenciesReached](https://docs.learnbittensor.org/subtensor-api/errors#maxdelegatedependenciesreached)).

This is a delegate-dependency count ceiling rejection. It does not, by itself, mean the contract
already depends on the specific code hash being submitted, that a dependency was missing when one
was removed, or that nested call depth reached the schedule limit.

## Why It Appears

This error appears when a contracts operation would add another delegate dependency after the
contract has already reached its maximum allowed count
([Subtensor API Errors: MaxDelegateDependenciesReached](https://docs.learnbittensor.org/subtensor-api/errors#maxdelegatedependenciesreached)).

## Distinction from Delegate Dependency Already Exists

`MaxDelegateDependenciesReached` and `DelegateDependencyAlreadyExists` both block adding a delegate
dependency, but on different checks. `MaxDelegateDependenciesReached` is summarized as "The contract
has reached its maximum number of delegate dependencies." `DelegateDependencyAlreadyExists` is
summarized as "The contract already depends on the given delegate dependency."
([Subtensor API Errors: MaxDelegateDependenciesReached](https://docs.learnbittensor.org/subtensor-api/errors#maxdelegatedependenciesreached),
[Subtensor API Errors: DelegateDependencyAlreadyExists](https://docs.learnbittensor.org/subtensor-api/errors#delegatedependencyalreadyexists)).

- **MaxDelegateDependenciesReached** — the contract already has the maximum number of delegate
  dependencies.
- **DelegateDependencyAlreadyExists** — the contract already depends on the given delegate
  dependency.

## Distinction from Delegate Dependency Not Found

`MaxDelegateDependenciesReached` and `DelegateDependencyNotFound` involve delegate dependencies at
opposite ends of the dependency list. `MaxDelegateDependenciesReached` blocks adding another
dependency because the count ceiling is full. `DelegateDependencyNotFound` is summarized as "The
dependency was not found in the contract's delegate dependencies."
([Subtensor API Errors: MaxDelegateDependenciesReached](https://docs.learnbittensor.org/subtensor-api/errors#maxdelegatedependenciesreached),
[Subtensor API Errors: DelegateDependencyNotFound](https://docs.learnbittensor.org/subtensor-api/errors#delegatedependencynotfound)).

- **MaxDelegateDependenciesReached** — the contract already has the maximum number of delegate
  dependencies.
- **DelegateDependencyNotFound** — the requested dependency was not found in the contract's delegate
  dependencies.

## Reader Boundary

This page defines the meaning of the error label from the API reference. It does not report the live
delegate-dependency limit configured on a network or redesign a contract's dependency set
([Subtensor API Errors: MaxDelegateDependenciesReached](https://docs.learnbittensor.org/subtensor-api/errors#maxdelegatedependenciesreached),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
