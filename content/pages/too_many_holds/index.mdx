# Too Many Holds

`TooManyHolds` is a balances pallet error raised when placing a new hold on an account would exceed
the maximum number of holds the runtime permits. The API docs describe it as "Number of holds exceed
`VariantCountOf<T::RuntimeHoldReason>`"
([Subtensor API Errors: TooManyHolds](https://docs.learnbittensor.org/subtensor-api/errors#toomanyholds)).

## What It Means

Each account may have a limited number of balance holds active at the same time. `TooManyHolds`
fires when a pallet attempts to place a new hold on an account that already has the maximum number
of holds
([Subtensor API Errors: TooManyHolds](https://docs.learnbittensor.org/subtensor-api/errors#toomanyholds)).

## Why It Appears

This error appears when a pallet tries to hold balance on an account and the insertion fails because
the account's hold list is full
([Subtensor API Errors: TooManyHolds](https://docs.learnbittensor.org/subtensor-api/errors#toomanyholds)).

## Distinction from Too Many Reserves

`TooManyHolds` and `TooManyReserves` both block pallet-initiated balance operations, but they apply
to different balance mechanisms. `TooManyReserves` fires when the named-reserve count is exceeded.
`TooManyHolds` fires when the holds count is exceeded
([Subtensor API Errors: TooManyReserves](https://docs.learnbittensor.org/subtensor-api/errors#toomanyreserves)).

- **TooManyReserves** — named-reserve count is at the limit.
- **TooManyHolds** — holds count is at the limit.

## Distinction from Too Many Freezes

`TooManyHolds` and `TooManyFreezes` both fire when a per-account balance tracking list is full, but
they track different things. `TooManyFreezes` fires when the freeze list is full. `TooManyHolds`
fires when the hold list is full
([Subtensor API Errors: TooManyFreezes](https://docs.learnbittensor.org/subtensor-api/errors#toomanyfreezes)).

- **TooManyHolds** — hold list is full; new hold cannot be placed.
- **TooManyFreezes** — freeze list is full; new freeze cannot be placed.

## Reader Boundary

This page defines the meaning of the error label and the hold-count check that raises it. It does
not report the current number of active holds on any account; that is live chain state
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
