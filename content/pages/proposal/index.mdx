# Proposal

A proposal is a Bittensor governance item put forward by the Triumvirate for Senate review. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#proposal) defines it as a suggestion
or plan put forward by the Triumvirate for the Senate to vote on.

## Governance Context

The [Governance Overview](https://docs.learnbittensor.org/governance) describes the same separation
of roles: the Triumvirate creates proposals, and the Senate approves or rejects them. In Taopedia,
the useful boundary is that a proposal is the item being reviewed, while the Triumvirate and Senate
are the governance bodies around it.

## Governance Review Context

A proposal moves through Bittensor governance in stages. The governance overview describes a
bicameral structure in which the Triumvirate creates proposals for Senate approval. A proposal must
obtain Senate majority approval and then be closed by a Triumvirate member before it is executed.
Creation, approval, and closure are therefore separate parts of the same review path.

Proposal records can be visible before that path is complete. The Senate documentation says anyone
can view proposals currently before the Senate, while voting is limited to senators. Visibility
therefore does not imply approval, and Senate approval does not remove the closing step described in
the governance overview.

The proposal hash is the identifier used during voting. It identifies the proposal under review; it
is not the proposal body, the vote result, or a separate governance actor. This is why proposal
claims should distinguish the submitted proposal from the hash used to refer to it.

The governance overview also frames proposals as part of Bittensor's move away from single-key
administration for privileged changes. Before governance, administrative changes depended on sudo
authority. In the documented governance path, privileged changes are reviewed through proposal
creation, Senate approval, and Triumvirate closure.

## Proposal Status Boundaries

Proposal status language should separate existence, approval, and completion. The governance
overview describes proposals as reviewable governance items, not automatic changes. A proposal that
has been created still needs Senate approval, and an approved proposal still needs the closing step
documented in the governance flow.

The same boundary applies to proposal hashes. A proposal hash can identify which proposal is being
discussed during voting, but it does not state whether the proposal was approved or completed.
Approval and completion should be checked against the governance record rather than inferred from
the presence of a hash.

## Relationship to Proposal Hash

A proposal is referenced on chain by its proposal hash. The
[Glossary](https://docs.learnbittensor.org/resources/glossary#proposal-hash) defines the proposal
hash as the unique identifier for a proposal used in the voting process, so it is the reference for
the proposal rather than the proposal body itself. For readers, the proposal is the governance item
being reviewed, while the proposal hash is the identifier used to point at it during Senate voting.

References: [Proposal](https://docs.learnbittensor.org/resources/glossary#proposal),
[Proposal Hash](https://docs.learnbittensor.org/resources/glossary#proposal-hash)
