# User Liquidity Enabled

User liquidity enabled is a per-subnet hyperparameter, listed in the documentation as
`UserLiquidityEnabled`, that determines whether the user liquidity feature is enabled on a subnet.
The reference describes it as the toggle that decides whether participants can use the user
liquidity flow on that subnet, with a documented default of `false`
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).

## What It Controls

The setting gates whether the user liquidity feature is active on a subnet. When
`UserLiquidityEnabled` is `true`, the liquidity flow is available to participants interacting with
the subnet's pools; when it is `false`, that flow is closed and participants use only the ordinary
stake and alpha token paths
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#userliquidityenabled),
[Glossary: Liquidity](https://docs.learnbittensor.org/resources/glossary#liquidity)).

The toggle is a per-subnet setting controlled by the subnet owner, so the same network can carry
subnets with the user liquidity feature enabled alongside subnets where it is disabled. It does not
change the underlying stake, alpha token, or pool mechanics on its own; it opens or closes the
user-facing liquidity path on top of those mechanics
([Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Documented Type, Default, and Setter

The reference lists `UserLiquidityEnabled` as a `Boolean` with a documented default of `false`. It
is changed through the `sudo_set_user_liquidity_enabled` extrinsic. The reference does not expose a
`btcli` setter for this hyperparameter, so updates happen through the sudo extrinsic rather than
through the subnet-owner `btcli sudo set` workflow
([Subnet Hyperparameters: UserLiquidityEnabled](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#userliquidityenabled),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

The live value on a subnet can differ from the documented default after a sudo update has changed it
on chain. A reader verifying whether the user liquidity feature is currently active on a specific
subnet should read the current storage value rather than rely on the default alone
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters)).

## Reading the Live Value for netuid 1

For a specific parseable netuid such as netuid 1 on Finney mainnet, the live toggle can be read
directly with the standard hyperparameter query:
`btcli subnet hyperparameters --netuid 1 --network finney`. The returned row for
`UserLiquidityEnabled` reflects whether the subnet owner has opened the user liquidity feature on
that subnet
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters),
[Subnet Hyperparameters: UserLiquidityEnabled](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#userliquidityenabled)).

That per-netuid query keeps the liquidity-toggle claim tied to a reproducible live value on a named
subnet rather than to the documented default alone. A reader checking whether the documented example
subnet netuid 1 currently exposes user liquidity should run the hyperparameter query for that netuid
and read the boolean rather than assume the default holds on mainnet
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Reader Boundary

User liquidity enabled should not be read as a network-global setting, as a toggle on the dynamic
stake or alpha token mechanics, or as a guarantee that the user liquidity feature is currently
active. It names only the per-subnet flag that the subnet owner uses to open or close the user
liquidity feature on a single subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Understanding Subnets](https://docs.learnbittensor.org/subnets/understanding-subnets)).
