# User Liquidity Enabled

User liquidity enabled is a per-subnet hyperparameter, listed in the documentation as
`UserLiquidityEnabled`, that determines whether the user liquidity feature is turned on for a subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## What It Controls

The setting is a boolean switch owned by the subnet, not a network-wide flag. When it is on, the
user liquidity feature is enabled for that subnet; when it is off, the feature is not available
there. It governs whether the feature is offered on the subnet, not who has stake or how emissions
are shared
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Because it is a per-subnet flag, one subnet can have the feature enabled while another has it
disabled at the same time. The value is part of a subnet's own hyperparameter set rather than a
single global toggle
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Documented Type, Default, and Setter

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `UserLiquidityEnabled` as a `Bool` with a default of `false`, described as
"Determines whether or not the user liquidity feature is enabled on the subnet." It is changed
through the `toggle_user_liquidity` extrinsic, exposed in tooling as
`btcli sudo set --param user_liquidity_enabled`, and the reference marks the permission required to
set it as subnet owner
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Because the default is `false`, the feature is off on a subnet until its owner turns it on for that
subnet ([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Distinction from Subtoken Enabled

User liquidity enabled and `SubtokenEnabled` are both per-subnet boolean switches, but they toggle
different features and are set by different roles. User liquidity enabled turns the user liquidity
feature on or off and is set by the subnet owner. Subtoken enabled turns subtoken trading on or off
for the subnet and is set by root
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **User liquidity enabled** — whether the user liquidity feature is on, set by the subnet owner.
- **Subtoken enabled** — whether subtoken trading is on, set by root.

## Distinction from Serving Rate Limit

Both are per-subnet hyperparameters set by the subnet owner, but they are different kinds of
setting. User liquidity enabled is a boolean that turns a feature on or off. Serving rate limit is a
numeric block gap that paces how often a miner may update its serving metadata
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **User liquidity enabled** — an on/off switch for the user liquidity feature.
- **Serving rate limit** — a block-count cap on how often miner endpoint records update.

## Chain Reads for netuid 1

Readers can verify the live value for a subnet with
`btcli subnet hyperparameters --netuid 1 --network finney`, which lists the per-subnet
hyperparameter values, including this flag, for the documented example netuid
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters)).

That read path keeps the live value claim tied to a parseable netuid rather than to any single
network-wide setting
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Per-Subnet Live Value Boundary

User liquidity enabled is per-subnet chain state. The flag read for one netuid applies only to that
subnet and can differ from another subnet's setting, which may still be at the default of `false`
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

This article uses netuid 1 as an example label for reading one subnet's hyperparameter table on
Finney mainnet. That example helps a reader verify one row; it is not proof that every subnet shares
the same live value
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Reader Boundary

This page defines the user liquidity enabled hyperparameter and what its switch turns on for a
subnet. It does not document the internals of the user liquidity feature itself or the live value
set on any particular subnet; each subnet stores its own flag
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).
