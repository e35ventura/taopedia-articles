# User Liquidity Enabled

User liquidity enabled is a per-subnet hyperparameter, listed in the documentation as
`UserLiquidityEnabled`, that gates whether the user liquidity feature is active on a subnet. The
reference describes it as determining whether user liquidity is enabled, with a default of false
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## What It Controls

The hyperparameter is the on-off switch for user liquidity on a subnet, not pool pricing rules or
emission splits. When enabled, participants can use the user-liquidity paths the protocol exposes on
that netuid; when disabled, those paths are unavailable
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Subnet Liquidity Pools](https://docs.learnbittensor.org/subnets/subnet-liquidity-pools)).

It does not replace dynamic TAO staking, validator weights, or Yuma Consensus settlement. It only
decides whether user-provided liquidity features are available on the selected subnet
([Dynamic TAO](https://docs.learnbittensor.org/learn/dynamic-tao),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

The flag is owner-tunable per subnet, so netuid 1 can keep the default while another netuid enables
user liquidity, and the live value is chain state rather than a network constant
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Documented Type and Default

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `UserLiquidityEnabled` as a `Bool` with a default of false and marks the permission
required to change it as subnet owner
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Because each subnet carries its own hyperparameters, the user-liquidity gate on one netuid can
differ from the documented default and from the flag on another subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Reading the Live Value for netuid 1

User liquidity enabled is per-subnet chain state, so any live claim is tied to a specific netuid.
For the documented example netuid 1 on Finney mainnet, the flag appears in that subnet's
hyperparameter table, which the reference describes under viewing a subnet's hyperparameters
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters)).
The infobox uses netuid 1 only as an example label; other subnets expose their own values
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

## Distinction from Subtoken Enabled

Subtoken enabled gates whether subtoken trading is active for a subnet's alpha token. User liquidity
enabled gates whether user-provided liquidity features are available on the subnet
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Subtoken enabled** — whether alpha subtoken trading is active.
- **User liquidity enabled** — whether user liquidity features are active.
