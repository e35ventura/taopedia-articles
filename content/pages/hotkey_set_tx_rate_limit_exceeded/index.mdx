# Hotkey Set Tx Rate Limit Exceeded

`HotKeySetTxRateLimitExceeded` means a hotkey swap call was retried before the swap cooldown had
cleared for that coldkey. The standard-errors reference describes it as "Rate limit exceeded for
setting/swapping hotkey," and the API errors reference lists the same runtime label
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#hotkeysettxratelimitexceeded),
[Subtensor API Errors: HotKeySetTxRateLimitExceeded](https://docs.learnbittensor.org/subtensor-api/errors#hotkeysettxratelimitexceeded)).

The chain rate-limits reference makes the scope explicit: the current general transaction rate limit
applies to hotkey swaps, with a documented cooldown of one block, about 12 seconds
([Chain Rate Limits: General transaction rate limit](https://docs.learnbittensor.org/learn/chain-rate-limits#general-transaction-rate-limit)).

## What It Means

This error is a pacing rejection on the hotkey swap path, not a statement that the old hotkey is
wrong, that the new hotkey is invalid, or that the caller lacks ownership of the hotkey being
replaced. In `do_swap_hotkey`, the runtime reads the coldkey's last transaction block and returns
`HotKeySetTxRateLimitExceeded` when the swap is submitted again before that short cooldown clears
([Subtensor source: swap_hotkey.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/swap/swap_hotkey.rs#L66-L70)).

The practical meaning is narrow: the same coldkey needs to wait for the swap cooldown to expire
before trying another hotkey set or swap transaction
([Chain Rate Limits: General transaction rate limit](https://docs.learnbittensor.org/learn/chain-rate-limits#general-transaction-rate-limit)).

## Why It Appears

This error appears on the hotkey swap path after signature and ownership checks pass, but before the
runtime evaluates whether the replacement hotkey is already registered or whether a root-touching
swap is otherwise allowed
([Subtensor source: swap_hotkey.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/swap/swap_hotkey.rs#L24-L30),
[Subtensor source: swap_hotkey.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/swap/swap_hotkey.rs#L66-L88)).

So when this label appears, the immediate issue is timing. The coldkey retried a hotkey set or swap
operation too soon.

## Distinction from Tx Rate Limit Exceeded

`HotKeySetTxRateLimitExceeded` and `TxRateLimitExceeded` both describe pacing failures, but they are
not the same article topic. `HotKeySetTxRateLimitExceeded` is the dedicated hotkey-swap label on the
general transaction cooldown. `TxRateLimitExceeded` is the broader default label used on other
rate-limited extrinsic families
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#hotkeysettxratelimitexceeded),
[Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#txratelimitexceeded),
[Chain Rate Limits](https://docs.learnbittensor.org/learn/chain-rate-limits)).

- **HotKeySetTxRateLimitExceeded** — hotkey set or swap retried before the short swap cooldown
  clears.
- **TxRateLimitExceeded** — another transaction family hit its own documented pacing rule.

## Distinction from Hotkey Swap On Subnet Interval Not Passed

`HotKeySetTxRateLimitExceeded` and `HotKeySwapOnSubnetIntervalNotPassed` can both block hotkey-swap
activity, but they guard different timing rules. `HotKeySetTxRateLimitExceeded` is the short general
transaction cooldown for the coldkey submitting the swap. `HotKeySwapOnSubnetIntervalNotPassed` is
the separate rule for attempting a hotkey swap on the same subnet too frequently
([Chain Rate Limits: General transaction rate limit](https://docs.learnbittensor.org/learn/chain-rate-limits#general-transaction-rate-limit),
[Subtensor Standard Errors: HotKeySwapOnSubnetIntervalNotPassed](https://docs.learnbittensor.org/errors/subtensor#hotkeyswaponsubnetintervalnotpassed)).

- **HotKeySetTxRateLimitExceeded** — the coldkey retried the swap transaction too soon.
- **HotKeySwapOnSubnetIntervalNotPassed** — the subnet-specific hotkey-swap interval has not cleared
  yet.

## Distinction from New Hotkey Is Same With Old

`HotKeySetTxRateLimitExceeded` and `NewHotKeyIsSameWithOld` both appear on `do_swap_hotkey`, but
they fail for different reasons. `HotKeySetTxRateLimitExceeded` is a timing rejection after the
runtime reads the last transaction block. `NewHotKeyIsSameWithOld` means the submitted replacement
key is identical to the current one, so there is no real swap to perform
([Subtensor source: swap_hotkey.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/swap/swap_hotkey.rs#L60-L70),
[Subtensor Standard Errors: NewHotKeyIsSameWithOld](https://docs.learnbittensor.org/errors/subtensor#newhotkeyissamewithold)).

- **HotKeySetTxRateLimitExceeded** — retry happened before the cooldown cleared.
- **NewHotKeyIsSameWithOld** — the proposed replacement hotkey is the same key.

## Reader Boundary

This page defines the meaning of the error label and the cooldown gate it represents on hotkey swap.
It does not tell a reader which new hotkey to choose, whether a root-touching swap is allowed, or
the live last-transaction block for a specific coldkey
([Subtensor source: swap_hotkey.rs](https://github.com/opentensor/subtensor/blob/main/pallets/subtensor/src/swap/swap_hotkey.rs#L66-L88),
[Chain Rate Limits](https://docs.learnbittensor.org/learn/chain-rate-limits)).
