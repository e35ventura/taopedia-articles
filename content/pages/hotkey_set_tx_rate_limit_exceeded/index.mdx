# Hotkey Set Tx Rate Limit Exceeded

HotKeySetTxRateLimitExceeded means a coldkey retried a hotkey swap before the short general
transaction rate limit had cleared. The standard-errors reference describes it as "Rate limit
exceeded for setting/swapping hotkey"
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#hotkeysettxratelimitexceeded),
[Chain Rate Limits](https://docs.learnbittensor.org/learn/chain-rate-limits)).

## What It Means

Hotkey swap moves subnet participation from one hotkey to another owned by the same coldkey
([Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

Bittensor paces hotkey swap through a short, coldkey-level transaction cooldown documented in the
chain rate limits reference. HotKeySetTxRateLimitExceeded is the dedicated error label when that
short cooldown has not cleared for the calling coldkey
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#hotkeysettxratelimitexceeded),
[Chain Rate Limits: General transaction rate limit](https://docs.learnbittensor.org/learn/chain-rate-limits#general-transaction-rate-limit)).

The rate-limits reference documents that general transaction cooldown as a short wait, currently one
block on Finney, separate from the longer per-subnet hotkey swap interval
([Chain Rate Limits](https://docs.learnbittensor.org/learn/chain-rate-limits),
[Hotkey Swap On Subnet Interval](https://docs.learnbittensor.org/learn/chain-rate-limits)).

This is a coldkey-level pacing failure on hotkey swap. It does not, by itself, mean the longer
per-subnet hotkey swap interval has failed to clear, that the destination hotkey is already
registered, or that the coldkey lacks balance for swap fees.

## Why It Appears

This error appears when a coldkey submits another hotkey swap before the short general transaction
rate limit has elapsed since its last rate-limited transaction on this path. That can happen when
automation retries a swap immediately after another wallet transaction, or when a client replays the
swap without checking the last successful block for the coldkey
([Chain Rate Limits: General transaction rate limit](https://docs.learnbittensor.org/learn/chain-rate-limits#general-transaction-rate-limit),
[Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security)).

The practical meaning is narrow: wait for the short coldkey cooldown, then retry the swap.

## Distinction from Hotkey Swap On Subnet Interval Not Passed

HotKeySetTxRateLimitExceeded and HotKeySwapOnSubnetIntervalNotPassed both gate hotkey swaps, but at
different scopes. HotKeySetTxRateLimitExceeded is the short, coldkey-level transaction cooldown.
HotKeySwapOnSubnetIntervalNotPassed is the separate, longer per-subnet cooldown for each subnet the
swap would touch
([Subtensor Standard Errors: HotKeySetTxRateLimitExceeded](https://docs.learnbittensor.org/errors/subtensor#hotkeysettxratelimitexceeded),
[Subtensor Standard Errors: HotKeySwapOnSubnetIntervalNotPassed](https://docs.learnbittensor.org/errors/subtensor#hotkeyswaponsubnetintervalnotpassed),
[Hotkey Swap On Subnet Interval](https://docs.learnbittensor.org/learn/chain-rate-limits)).

## Distinction from Tx Rate Limit Exceeded

HotKeySetTxRateLimitExceeded and TxRateLimitExceeded both involve transaction pacing, but on
different paths. HotKeySetTxRateLimitExceeded is the dedicated label on hotkey swap when the short
general transaction cooldown has not cleared. TxRateLimitExceeded is the default label on other
rate-limited extrinsics such as child-hotkey updates and several subnet-admin paths
([Subtensor Standard Errors: HotKeySetTxRateLimitExceeded](https://docs.learnbittensor.org/errors/subtensor#hotkeysettxratelimitexceeded),
[Subtensor Standard Errors: TxRateLimitExceeded](https://docs.learnbittensor.org/errors/subtensor#txratelimitexceeded),
[Chain Rate Limits](https://docs.learnbittensor.org/learn/chain-rate-limits)).

## Reader Boundary

This page defines the meaning of the error label and the coldkey-level cooldown it represents on
hotkey swap. It does not describe swap fees, registration conflicts on the destination hotkey, or
the live per-subnet swap interval on a network; those depend on chain parameters at submission time
([Coldkey and Hotkey Workstation Security](https://docs.learnbittensor.org/keys/coldkey-hotkey-security),
[Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
