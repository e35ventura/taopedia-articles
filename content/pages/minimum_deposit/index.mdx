# Minimum Deposit

Minimum deposit is a crowdloan pallet runtime constant, listed in the chain's constants metadata as
minimumDeposit, with the value 10000000000 and the summary "The minimum deposit required to create a
crowdloan"
([Subtensor API Constants: minimumDeposit](https://docs.learnbittensor.org/subtensor-api/constants#minimumdeposit-u64)).
The value is denominated in rao, the base unit where one TAO is 1,000,000,000 rao, so the minimum
deposit is 10 TAO.

## What It Means

A crowdloan is a way to pool TAO from many contributors toward a shared funding goal
([Crowdloans](https://docs.learnbittensor.org/subnets/crowdloans)). Minimum deposit is the smallest
amount the creator must put up to open a crowdloan in the first place. An attempt to create a
crowdloan with less than this deposit does not meet the requirement
([Subtensor API Constants: minimumDeposit](https://docs.learnbittensor.org/subtensor-api/constants#minimumdeposit-u64)).
The deposit is a threshold on starting a crowdloan, not the funding target the crowdloan goes on to
raise.

## Distinction from the Contribution Minimum

Minimum deposit applies to the account that creates a crowdloan, while a separate floor applies to
each account that later contributes. The absolute minimum contribution, valued at 100000000 rao, or
0.1 TAO, is the smallest amount a contributor may add to an existing crowdloan
([Subtensor API Constants: absoluteMinimumContribution](https://docs.learnbittensor.org/subtensor-api/constants#absoluteminimumcontribution-u64)).
One threshold governs opening a crowdloan; the other governs joining one. The creator's minimum
deposit is the larger of the two.

## Why a Creation Deposit Exists

Requiring a deposit to create a crowdloan means opening one carries a real up-front commitment
rather than being cost-free. The creator's minimum deposit sets how large that commitment must be at
the low end, so a crowdloan begins only once its creator has put up at least this amount. It is a
gate on starting a crowdloan, applied once at creation, and it is the same fixed figure for every
creator rather than a value that scales with the size of the crowdloan being opened.

## Distinction from the Crowdloan Duration Bounds

Minimum deposit governs the cost of opening a crowdloan, while separate constants bound how long it
may run. The minimum block duration, valued at 50400 blocks, and the maximum block duration, valued
at 432000 blocks, set the shortest and longest a crowdloan may last
([Subtensor API Constants: minimumBlockDuration](https://docs.learnbittensor.org/subtensor-api/constants#minimumblockduration-u32),
[Subtensor API Constants: maximumBlockDuration](https://docs.learnbittensor.org/subtensor-api/constants#maximumblockduration-u32)).
At twelve seconds per block those spans are about seven and sixty days. The deposit is a one-time
threshold to start; the duration bounds constrain the window over which contributions are collected.

## Reader Boundary

Minimum deposit is a single network-wide constant expressed in rao, not a per-subnet value, and it
reflects the current runtime configuration rather than a fixed protocol rule; the value could change
in a future runtime upgrade. It names the floor for creating a crowdloan and does not describe how
much a crowdloan ultimately raises or how contributions are returned
([Subtensor API Constants: minimumDeposit](https://docs.learnbittensor.org/subtensor-api/constants#minimumdeposit-u64)).
