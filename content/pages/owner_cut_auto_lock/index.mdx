# Owner Cut Auto Lock

Owner cut auto lock is a per-subnet hyperparameter, listed in the documentation as
`OwnerCutAutoLockEnabled`, that controls whether the subnet owner's cut of
[emissions](https://docs.learnbittensor.org/resources/glossary#emission) is automatically locked
each epoch. The
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters) reference
describes it as controlling whether the subnet owner's cut of emissions is automatically locked each
epoch.

## What It Controls

The hyperparameter governs the handling of the owner's emission cut after it is paid. The subnet
owner receives a documented share of subnet emissions as stake; owner cut auto lock decides whether
that share is automatically locked each epoch rather than left immediately available
([Emission](https://docs.learnbittensor.org/learn/emissions)).

It does not set the size of the owner's share or whether the owner receives a cut at all. It only
affects whether the already-allocated cut is auto-locked on a per-epoch basis
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Documented Type, Default, and Setter

The [Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)
reference lists `OwnerCutAutoLockEnabled` as a Boolean with a default of `False`, so the owner's cut
is not auto-locked unless the subnet enables it. Because each subnet carries its own
hyperparameters, the setting is defined per subnet and applies only within that subnet.

The value in force is per-subnet chain state and can differ from the documented default, so a
subnet's real auto-lock behavior should be read for that subnet rather than assumed.

## Distinction from Subnet Owner Take

Subnet owner take, which the documentation also calls the owner cut, is the share of a subnet's
emissions that goes to the owner. Owner cut auto lock does not change that share; it only governs
whether the received cut is automatically locked each epoch
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Emission](https://docs.learnbittensor.org/learn/emissions)).

- **Subnet owner take** — the size of the owner's emission share.
- **Owner cut auto lock** — whether that received share is auto-locked each epoch.

## Distinction from Owner Cut Enabled

Whether the owner receives a cut at all is a separate enable setting. Owner cut auto lock assumes a
cut is being paid and only decides how it is held afterward, so the two answer different questions
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

- **Owner cut enabled** — whether the owner receives a cut at all.
- **Owner cut auto lock** — whether a received cut is auto-locked each epoch.

## BTCLI Reads the Live Value

Any user can read subnet hyperparameters for a selected netuid with
`btcli subnet hyperparameters --netuid 1`. The output includes the live owner-cut hyperparameter
values for that subnet at query time
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

Live values are network- and subnet-specific and can differ from the documented default, so an auto-
lock claim should be checked against the hyperparameter table for the relevant netuid rather than
assumed from the reference default alone.

## Why an Auto-Lock Option Exists

Auto-locking the owner's cut each epoch is a way to keep that share staked rather than immediately
liquid. Leaving the default in place keeps the cut unlocked, while enabling auto-lock commits the
owner's emission share on an ongoing per-epoch basis
([Emission](https://docs.learnbittensor.org/learn/emissions)).

For readers, owner cut auto lock is a handling rule for an already-allocated reward, not a control
on how much the owner earns. It answers what happens to the owner's cut after payment, not how large
that cut is
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).
