# Public Key

A public key is the shareable side of a cryptographic key pair. The official
[Public Key glossary](https://docs.learnbittensor.org/resources/glossary#public-key) describes it as
a publicly available cryptographic key used for verifying signatures, encrypting messages, and
identifying accounts in the Bittensor network. In that glossary context, public keys are associated
with both coldkey and hotkey key pairs.

## Key Pair Context

Public keys belong to key pairs. The public side can be used for identification and verification,
while the private side is the protected component. The official
[Private Key glossary](https://docs.learnbittensor.org/resources/glossary#private-key) supports this
contrast by describing the private key as the component used to authorize transactions and
operations.

This distinction is the core reading boundary: public key describes shareable cryptographic
material, while private key describes protected authorization material.

## EdDSA Context

Bittensor glossary terminology also connects public and private key pairs to EdDSA. The official
[EdDSA Cryptographic Keypairs glossary](https://docs.learnbittensor.org/resources/glossary#eddsa-cryptographic-keypairs)
describes EdDSA as the cryptographic algorithm used to generate public and private key pairs for
Bittensor coldkeys and hotkeys.

For Taopedia readers, EdDSA names the algorithm context, public key names one side of the resulting
pair, and private key names the protected side of that same pair.

## Account Reference Context

The public-key concept is useful because it helps separate public account reference from protected
authorization material. The official Public Key glossary includes identifying accounts among the
public key's uses, while the Private Key glossary places authorization on the protected side of the
pair.

This does not make a public key a private authorization component or an operational instruction. It
is one part of the keypair vocabulary used to talk about account identification and verification.

## Reader Boundary

Public key should not be read as a private key or secret. It is also not a recommendation about how
to create, store, rotate, import, or recover keys.

Claims about a specific account, address, wallet, or key file need a direct source for that account
or file. This article only explains the general public-key concept in Bittensor terminology.
