# Public Key

A public key is the shareable side of a cryptographic keypair in Bittensor wallet-key terminology.
The official [Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key)
describes it as publicly available key material used for verifying signatures, encrypting messages,
and identifying accounts in the Bittensor network.

## Keypair Context

Public keys are read together with private keys. The public side can be shared for account reference
or verification, while the
[Glossary: Private Key](https://docs.learnbittensor.org/resources/glossary#private-key) describes
the private side as the protected component used to authorize transactions and operations.

This distinction keeps public key from being treated as a secret. It is still part of the same
cryptographic keypair vocabulary, but it has a different role from private signing material.

## Wallet-Key Context

In Bittensor, public keys belong to wallet-key terminology rather than naming a separate network
role or token. The
[Glossary: EdDSA Cryptographic Keypairs](https://docs.learnbittensor.org/resources/glossary#eddsa-cryptographic-keypairs)
connects public and private key pairs with coldkeys and hotkeys, which are Bittensor wallet-key
roles.

For readers, the useful point is structural: a public key is part of the wallet-key system used to
identify and verify, not a staking position, subnet role, or balance.

## Verification Without Signing Authority

A public key can verify signatures and support account reference, but it is not the protected
authorization material that signs transactions. The
[Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key) describes the
public side as shareable material used for verification and identification, while the
[Glossary: Private Key](https://docs.learnbittensor.org/resources/glossary#private-key) describes
the private side as protected authorization material.

Readers should not treat a public key as something safe to mishandle because it is "public." It
identifies an account and supports verification, but possession of the public material alone does
not replace control of the private key.

## Shareable Material in Wallet Workflows

Wallet workflows often display or exchange public key material when identifying destinations,
verifying signatures, or comparing accounts. That shareability is intentional: the public side
exists so verification and reference can happen without exposing signing secrets. Bittensor wallet
documentation still treats the paired private material as the protected component.

For readers, public key names what can be referenced or verified in open workflow steps, not what
should be stored casually instead of proper wallet backup discipline.

## EdDSA Output Versus Network Roles

Bittensor coldkeys and hotkeys are generated from EdDSA keypairs described in official glossary
material. Public key names the shareable output of that pair, while coldkey and hotkey name wallet
roles with different authority in Bittensor operations. A public key therefore belongs to keypair
vocabulary before it belongs to miner, validator, or staking role vocabulary.

Readers comparing terms should keep the layers separate: algorithm and keypair output first, wallet
role and on-chain participation second.

## Relationship to Wallet Addresses

Wallet addresses are related but not identical. The
[Glossary: Wallet Address](https://docs.learnbittensor.org/resources/glossary#wallet-address)
describes a wallet address as a public-key-derived identifier used as a TAO destination. The
[Glossary: SS58 Encoded](https://docs.learnbittensor.org/resources/glossary#ss58-encoded) describes
SS58 encoded values as compact representations of those public-key-derived addresses.

This means public key is the cryptographic keypair concept, while wallet address and SS58 encoded
describe address representation and destination context.

## Relationship to Address Poisoning Scams

Public keys are the keypair material that wallet addresses are derived from, which is why two
different addresses can share display characteristics. The
[Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key) describes a
public key as shareable material used for account reference, and the
[Bittensor address-poisoning guide](https://docs.learnbittensor.org/keys/address-poisoning-scams)
warns that similar-looking addresses can appear familiar during routine wallet use.

For readers, a public key names the shareable keypair material, while address poisoning names the
risk that a lookalike derived address gets treated as the intended destination. Each public key
produces its own address, but those addresses can still look similar enough in abbreviated form to
mislead a user.

References: [Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key),
[Address Poisoning Scams guide](https://docs.learnbittensor.org/keys/address-poisoning-scams)

## Reader Boundary

Public key should not be read as a recovery phrase, a private key, or a complete wallet by itself.
It is a shareable public component used in identification and verification context. This article
does not describe how to create, store, recover, rotate, or use wallet keys.

## Relationship to Private Key

Public key and private key are related but different sides of Bittensor cryptographic keypair
vocabulary. A public key is shareable material used for verification and account reference, while a
private key is the protected component used to authorize transactions and operations. The
[Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key) describes the
public side of the pair, and the
[Glossary: Private Key](https://docs.learnbittensor.org/resources/glossary#private-key) describes
the private side as protected authorization material.

For readers, public key names the shareable pair side, while private key names the protected side
that must remain secret because it authorizes activity.

References: [Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key),
[Glossary: Private Key](https://docs.learnbittensor.org/resources/glossary#private-key)

## Relationship to Coldkeys

Public key and coldkey are related but different scopes in Bittensor wallet-key vocabulary. Public
key names the shareable side of a cryptographic keypair, while coldkey names the security-sensitive
wallet key that controls TAO and stake. The
[Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key) describes
public key as shareable key material, and the
[Glossary: Coldkey](https://docs.learnbittensor.org/resources/glossary#coldkey) describes the
coldkey as the key that controls TAO and stake.

For readers, public key names the keypair reference concept, while coldkey names the specific wallet
role that uses protected key material to control funds and stake.

References: [Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key),
[Glossary: Coldkey](https://docs.learnbittensor.org/resources/glossary#coldkey)

## Relationship to Hotkeys

Public key and hotkey are related but different scopes in Bittensor wallet-key vocabulary. Public
key names the shareable side of a cryptographic keypair, while hotkey names the operational wallet
key used for routine on-chain actions such as registration and weight submission. The
[Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key) describes
public key as shareable key material, and the
[Glossary: Hotkey](https://docs.learnbittensor.org/resources/glossary#hotkey) describes the hotkey
as the operational key used by miners, validators, and subnet actors.

For readers, public key names the shareable reference concept, while hotkey names the operational
wallet role derived under coldkey control for subnet actions.

References: [Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key),
[Glossary: Hotkey](https://docs.learnbittensor.org/resources/glossary#hotkey)

## Relationship to Extrinsics

Public key and extrinsics are related but different parts of Bittensor chain action vocabulary.
Extrinsics name signed transactions and calls submitted to Subtensor, while public key names the
shareable key material used to identify accounts referenced in those submissions. The
[Glossary: Extrinsics](https://docs.learnbittensor.org/resources/glossary#extrinsics) describes
signed transactions submitted to the chain, and the
[Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key) describes
public key as shareable material used for verifying signatures and identifying accounts.

For readers, extrinsics name submitted chain actions, while public key names the shareable account
reference material associated with those actions.

References: [Glossary: Extrinsics](https://docs.learnbittensor.org/resources/glossary#extrinsics),
[Glossary: Public Key](https://docs.learnbittensor.org/resources/glossary#public-key)
