Claims is Bittensor Subnet 111. Its on-chain identity registers the subnet for turning scientific
literature into a structured claim-evidence graph.

## What Claims Provides

The registered identity describes Claims as a subnet "turning scientific literature into a
structured claim-evidence graph." Miners produce that structured output, and the network rewards the
strongest results. The codebase is the
[oneoneone-io/subnet-111](https://github.com/oneoneone-io/subnet-111) repository, which defines the
task in more detail than the on-chain identity alone.

## Public Source Context

Subnet 111 has two public descriptions. The live on-chain identity names the subnet Claims and uses
the claim-evidence graph description, while the
[public repository README](https://raw.githubusercontent.com/oneoneone-io/subnet-111/main/README.md)
identifies the codebase as oneoneone, a decentralized protocol for accessing user-generated content.
The project website at [oneoneone.io](https://oneoneone.io) uses the same oneoneone branding for the
public-facing platform.

The README describes the repository scope as collecting, validating, and serving high-quality
user-generated content from platforms across the web. It gives examples such as reviews, discussion
posts, comments, social media content, blog entries, and other authentic digital expression by
users. That repository description is broader than the live identity phrase, so the on-chain label
and the repository's product description should be read as two public views of the same netuid.

## Data Flow Context

The README describes three participant groups: miners, validators, and API consumers. Miners
collect, clean, and format data from public sources. Validators assess data quality through
synthetic challenges and organic requests. API consumers access the structured content through the
oneoneone platform.

This makes Subnet 111 a content-access and validation subnet rather than a model-hosting subnet. The
work product is not a trained model or a single answer; it is structured external content that can
be checked, enriched, and served to downstream users. The README also describes AI-enhanced analysis
around authenticity, intent, emotion, sentiment, and translation, which explains why the subnet's
value depends on both collection coverage and quality checks.

At the incentive level, validator work is tied to whether miners return complete, timely, and useful
structured content for the requested source. That turns user-generated content into a Bittensor
task: miners compete to supply usable data, validators judge the returned data, and the resulting
weights flow through [[Yuma Consensus]].

## Miner and Validator Roles

Subnet 111 operates under the standard Bittensor two-role structure. Miners supply a capability —
here structured content collection and extraction, with the live identity emphasizing claim-evidence
graphs and the repository emphasizing user-generated content — and validators evaluate those
contributions and set weights. Reward distribution follows [[Yuma Consensus]].

## On-Chain Identity

The live Finney identity for netuid 111 registers the subnet name as Claims, with the description
"Turning scientific literature into a structured claim-evidence graph." The GitHub repository is
[oneoneone-io/subnet-111](https://github.com/oneoneone-io/subnet-111); no project website URL or
Discord is set in the identity. Live subnet data is available on
[TaoStats](https://taostats.io/subnets/111).
