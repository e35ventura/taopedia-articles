# Max Signatories

The `maxSignatories` runtime constant sets the maximum number of signatories allowed in a single
multisig operation at 100
([Subtensor API Constants: maxSignatories](https://docs.learnbittensor.org/subtensor-api/constants#maxsignatories)).

When a multisig call submits a signatory list longer than this limit, the runtime rejects it with
`TooManySignatories` before any approval logic runs
([Subtensor API Errors: TooManySignatories](https://docs.learnbittensor.org/subtensor-api/errors#toomanysignatories)).

## Distinction from Max Freezes

`maxSignatories` caps the number of signatories in a multisig wallet. `maxFreezes` caps the number
of individual freeze locks an account can hold. Both are per-account numeric limits, but they apply
to different pallets and mechanisms
([Subtensor API Constants: maxSignatories](https://docs.learnbittensor.org/subtensor-api/constants#maxsignatories),
[Subtensor API Constants: maxFreezes](https://docs.learnbittensor.org/subtensor-api/constants#maxfreezes)).

- **maxSignatories** — limits signatories in a multisig (multisig pallet, value 100).
- **maxFreezes** — limits freeze locks on an account (balances pallet, value 50).

## Distinction from Max Reserves

`maxSignatories` caps multisig signatories. `maxReserves` caps the number of named reserves an
account can hold. Both are per-account numeric limits enforced at submission time, but on different
pallets
([Subtensor API Constants: maxSignatories](https://docs.learnbittensor.org/subtensor-api/constants#maxsignatories),
[Subtensor API Constants: maxReserves](https://docs.learnbittensor.org/subtensor-api/constants#maxreserves)).

- **maxSignatories** — limits signatories in a multisig (multisig pallet, value 100).
- **maxReserves** — limits named reserves on an account (balances pallet, value 50).
