# Initial Serving Rate Limit

Initial Serving Rate Limit is a subtensorModule runtime constant, listed in the chain's constants
metadata as initialServingRateLimit, with the value 50 and the summary "Initial serving rate limit"
([Subtensor API Constants: initialServingRateLimit](https://docs.learnbittensor.org/subtensor-api/constants#initialservingratelimit-u64)).
It supplies the default value a subnet's ServingRateLimit uses.

## What It Means

ServingRateLimit is held per subnet and sets the rate limit, in blocks, on how often a miner may
call the serve_axon and serve_prometheus extrinsics. Initial Serving Rate Limit is the default this
per-subnet value falls back to before a different value applies for a subnet
([Subtensor API Constants: initialServingRateLimit](https://docs.learnbittensor.org/subtensor-api/constants#initialservingratelimit-u64)).
The ServingRateLimit in force on a subnet such as netuid 1 is that subnet's own chain state and can
differ from this default.

## Distinction from Registration Rate Defaults

Initial Serving Rate Limit is the default serving rate limit, while initialMaxRegistrationsPerBlock,
valued at 1, is the per-block registration cap; initialTargetRegistrationsPerInterval, valued at 2,
is the target registrations per interval
([Subtensor API Constants: initialMaxRegistrationsPerBlock](https://docs.learnbittensor.org/subtensor-api/constants#initialmaxregistrationsperblock-u16),
[Subtensor API Constants: initialTargetRegistrationsPerInterval](https://docs.learnbittensor.org/subtensor-api/constants#initialtargetregistrationsperinterval-u16)).

## Reader Boundary

Initial Serving Rate Limit is a default constant, not the live per-subnet ServingRateLimit, and it
reflects the current runtime configuration rather than a fixed protocol rule
([Subtensor API Constants: initialServingRateLimit](https://docs.learnbittensor.org/subtensor-api/constants#initialservingratelimit-u64)).
