ForeverMoney is Bittensor Subnet 98. Public ForeverMoney materials describe a decentralized
automated liquidity-management subnet for Uniswap V3 and Aerodrome strategies on Bittensor.

## What ForeverMoney Provides

The ForeverMoney README describes the subnet as decentralized automated liquidity management on
Bittensor. It optimizes concentrated-liquidity provision on Uniswap V3 and Aerodrome through
competitive strategies: miners propose dynamic rebalancing decisions, validators evaluate
performance through forward simulations, and the winning strategies are executed on-chain on Base.

According to the README, validators run multiple liquidity-management jobs concurrently, each tied
to a specific pool. Rounds operate in two modes: evaluation rounds, in which all miners compete in
forward simulations from the current chain state, and live rounds, in which winning miners execute
strategies on-chain after an eligible participation period. Miners build per-job reputation for
specific trading pairs, and the README notes a participation requirement before a miner becomes
eligible for live execution.

## Miner and Validator Roles

The README describes miners as implementing a rebalance handler that responds to a validator's
rebalance queries: a miner accepts or refuses a job and returns its desired positions, choosing when
and how to adjust a position or to keep the current one. Miners are scored on protecting inventory
and growing the managed position's value, with reputation accumulated through exponential moving
averages.

Validators evaluate miner strategies through forward simulations, score miners per job, and execute
the winning strategies on-chain. Operators should treat the repository as the source of truth for
current participant guidance.

## Job and Round Context

The
[ForeverMoney README](https://raw.githubusercontent.com/SN98-ForeverMoney/forever-money/main/README.md)
describes a jobs-based architecture where multiple liquidity-management tasks can run concurrently.
Each job is tied to a specific pool or vault context, and miners build reputation for the jobs they
participate in rather than earning one undifferentiated subnet-wide score.

The
[architecture documentation](https://raw.githubusercontent.com/SN98-ForeverMoney/forever-money/main/ARCHITECTURE.md)
separates evaluation rounds from live rounds. In evaluation mode, miners compete through forward
simulations from current blockchain state. In live mode, an eligible winner can have its strategy
executed on chain. The architecture document also describes exponential moving averages for
evaluation and live scores, which keeps recent performance important while preserving continuity
across rounds.

For readers, this means ForeverMoney should be understood as repeated strategy selection for
specific liquidity jobs, not as a one-time backtest. A miner can specialize in certain pools or
strategies, and a validator can evaluate several jobs in parallel before any live execution happens.

## Rebalance Query Context

The
[miner guide](https://raw.githubusercontent.com/SN98-ForeverMoney/forever-money/main/MINER_GUIDE.md)
describes the miner interaction as a `RebalanceQuery`. Validators start from current chainhead, send
job context and current position state, and ask miners whether to accept the job and what positions
they want. A miner can refuse a job, keep the current positions, or propose a rebalance to new
positions.

That protocol keeps the miner contribution focused on dynamic liquidity decisions. The miner is not
merely predicting a price direction; it is deciding how the managed liquidity position should change
given the current pool state and job context. The same guide describes current scoring around value
growth and inventory protection, with penalties for losing token inventory.

This also explains the participation requirement in the README. Live execution is reserved for
miners that have built enough consistent performance history, while evaluation rounds let all active
miners continue competing in simulation. The reward signal is therefore tied to both strategy
quality and sustained participation in the relevant jobs.
