# UID Trimming

UID trimming is a Bittensor subnet management mechanism for reducing the number of active UIDs in a
subnet while keeping the remaining UID set consecutively indexed. The official
[UID Trimming](https://docs.learnbittensor.org/subnets/uid-trimming) documentation describes it as a
way to remove lower-performing UIDs while preserving protected participants.

## Subnet UID Sets

A [[uid_slot|UID Slot]] identifies a participant position inside a subnet. When trimming changes the
size of the active UID set, the remaining UIDs are compressed so the subnet keeps consecutive
numbering. This keeps the subnet's participant index compact after some UIDs are removed.

This article describes the concept only. It does not list live subnet sizes, recommend a target
number of UIDs, or act as subnet-change instructions.

## Selection Boundary

The official UID trimming documentation frames trimming around lower-performing UIDs while skipping
protected ones. Recently registered participants can be protected by an
[[immunity_period|Immunity Period]], and the same source describes owner-controlled UIDs as
protected within the relevant subnet rules.

For readers, the important boundary is that trimming is not just arbitrary deletion. It is a subnet
management operation constrained by protection rules and by the need to preserve a valid UID order
for the remaining participants.

## Relationship to Deregistration

UID trimming and [[deregistration|Deregistration]] both concern removal in Bittensor, but they are
not the same reader concept. UID trimming is specifically about reducing a subnet's active UID set
and then compacting the remaining index.

Both concepts are easiest to read through the lens of [[subnet|Subnet]] capacity, participant
performance, and temporary protections for newly registered participants.
