# Expired Weight Commit

`ExpiredWeightCommit` means a reveal matched a stored commit that had already aged past the subnet's
reveal window. The standard-errors reference describes it as "Attempted to reveal weights that are
expired"
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#expiredweightcommit)).

Each pending commit carries the epoch it was made in. The subnet's `CommitRevealPeriod` sets how
long that commit stays eligible before the chain treats it as expired
([Commit-Reveal](https://docs.learnbittensor.org/concepts/commit-reveal),
[Commit Reveal Period](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#commitrevealperiod)).

## What It Means

[Commit-reveal](https://docs.learnbittensor.org/concepts/commit-reveal) weight submission happens in
two steps: a hash commitment first, then the actual weights and salt later. `ExpiredWeightCommit`
means the reveal step recomputed a hash that matched a stored commitment, but that commitment had
already exceeded the subnet's reveal period and was no longer eligible, so the chain rejected the
reveal instead of applying weights
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#expiredweightcommit)).

This is a late-reveal failure: the commit existed and the hash paired correctly, but the validator
waited too long to reveal within the subnet's allowed window.

## Why It Appears

This error appears on the reveal side after commit-reveal is enabled for the target netuid. It fires
when automation or a client submits a reveal after the matching commit has aged out of the active
pending queue
([Subtensor Standard Errors](https://docs.learnbittensor.org/errors/subtensor#expiredweightcommit)).

When debugging, compare timing and lookup errors before assuming a bad hash. `RevealTooEarly` means
the matching commit is still active but the eligible reveal epoch has not arrived yet.
`NoWeightsCommitFound` means no matching active stored commit exists for that hotkey and netuid
([Subtensor Standard Errors: RevealTooEarly](https://docs.learnbittensor.org/errors/subtensor#revealtooearly),
[Subtensor Standard Errors: NoWeightsCommitFound](https://docs.learnbittensor.org/errors/subtensor#noweightscommitfound)).

The practical meaning is narrow: the validator is trying to reveal against a commitment that was
made too long ago for the subnet to honor. The problem is not that commit-reveal is disabled or that
the reveal simply arrived before its window opened.

## Distinction from Invalid Reveal Commit Hash Not Match

`ExpiredWeightCommit` and `InvalidRevealCommitHashNotMatch` both appear when a reveal hash fails to
match any remaining active commit, but they reject different causes. `ExpiredWeightCommit` means the
hash matched a stored commit that had just been pruned as expired. `InvalidRevealCommitHashNotMatch`
means the hash matched no stored commit at all — for example because the reveal used the wrong salt,
weight vector, or version key
([Subtensor Standard Errors: InvalidRevealCommitHashNotMatch](https://docs.learnbittensor.org/errors/subtensor#invalidrevealcommithashnotmatch)).

- **ExpiredWeightCommit** — the hash matched a stored commit, but that commit had already expired.
- **InvalidRevealCommitHashNotMatch** — the hash matched no stored commit at all.

## Distinction from Reveal Too Early

`ExpiredWeightCommit` and `RevealTooEarly` are opposite timing failures on the reveal side.
`RevealTooEarly` means a matching commit is still active, but the current epoch is before its
eligible reveal epoch. `ExpiredWeightCommit` means the matching commit existed but has already aged
out
([Subtensor Standard Errors: RevealTooEarly](https://docs.learnbittensor.org/errors/subtensor#revealtooearly)).

- **RevealTooEarly** — the commit is still active, but its eligible epoch hasn't arrived.
- **ExpiredWeightCommit** — the matching commit aged out before the reveal was processed.

## Reader Boundary

This page defines the meaning of the error label and the expired-commit condition that raises it. It
does not describe the full commit-reveal lifecycle, how reveal timing windows are computed, or how
expired commits are pruned; those are separate topics
([Commit-Reveal](https://docs.learnbittensor.org/concepts/commit-reveal),
[Commit Reveal Period](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#commitrevealperiod)).
