# Initial Tempo

Initial Tempo is a subtensorModule runtime constant, listed in the chain's constants metadata as
initialTempo, with the value 360 and the summary "Tempo for each network"
([Subtensor API Constants: initialTempo](https://docs.learnbittensor.org/subtensor-api/constants#initialtempo-u16)).
It supplies the default value a subnet's Tempo uses.

## What It Means

Tempo is held per subnet and sets the number of blocks between a subnet's Yuma Consensus epoch
transitions. Initial Tempo is the default this per-subnet value falls back to before a different
value applies for a subnet
([Subtensor API Constants: initialTempo](https://docs.learnbittensor.org/subtensor-api/constants#initialtempo-u16)).
The Tempo in force on a subnet such as netuid 1 is that subnet's own chain state and can differ from
this default.

## Distinction from Min and Max Tempo

Initial Tempo is the default tempo a subnet starts with, while minTempo, valued at 360, is the
smallest tempo a subnet owner may set; maxTempo, valued at 50400, is the largest tempo a subnet
owner may set
([Subtensor API Constants: minTempo](https://docs.learnbittensor.org/subtensor-api/constants#mintempo-u16),
[Subtensor API Constants: maxTempo](https://docs.learnbittensor.org/subtensor-api/constants#maxtempo-u16)).

## Reader Boundary

Initial Tempo is a default constant, not the live per-subnet Tempo, and it reflects the current
runtime configuration rather than a fixed protocol rule
([Subtensor API Constants: initialTempo](https://docs.learnbittensor.org/subtensor-api/constants#initialtempo-u16)).
