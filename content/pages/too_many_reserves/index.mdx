# Too Many Reserves

`TooManyReserves` is a balances pallet error raised when placing a new named reserve on an account
would exceed the runtime maximum. The API errors reference documents this error on the named-reserve
insertion path
([Subtensor API Errors: TooManyReserves](https://docs.learnbittensor.org/subtensor-api/errors#toomanyreserves)).

## What It Means

Each account may hold a limited number of named reserves at the same time. `TooManyReserves` fires
when a pallet attempts to place a new named reserve on an account that already has the maximum
number of reserves
([Subtensor API Errors: TooManyReserves](https://docs.learnbittensor.org/subtensor-api/errors#toomanyreserves)).

This is a named-reserve count rejection, not proof that the account lacks balance, that holds are
exhausted, or that freezes are at their limit.

## Why It Appears

This error appears when a pallet tries to add a named reserve to an account and the insertion fails
because the account's named-reserve list has reached its maximum
([Subtensor API Errors: TooManyReserves](https://docs.learnbittensor.org/subtensor-api/errors#toomanyreserves)).

## Distinction from Too Many Holds

`TooManyReserves` and `TooManyHolds` both fire when a per-account balance tracking list is full, but
they apply to different balance mechanisms. `TooManyHolds` fires when the hold list is full.
`TooManyReserves` fires when the named-reserve list is full
([Subtensor API Errors: TooManyHolds](https://docs.learnbittensor.org/subtensor-api/errors#toomanyholds),
[Subtensor API Errors: TooManyReserves](https://docs.learnbittensor.org/subtensor-api/errors#toomanyreserves)).

- **TooManyReserves** — named-reserve list is full; new reserve cannot be placed.
- **TooManyHolds** — hold list is full; new hold cannot be placed.

## Distinction from Too Many Freezes

`TooManyReserves` and `TooManyFreezes` both block balance operations when per-account tracking lists
are full, but for different mechanisms. `TooManyFreezes` fires when the freeze list is full.
`TooManyReserves` fires when the named-reserve list is full
([Subtensor API Errors: TooManyFreezes](https://docs.learnbittensor.org/subtensor-api/errors#toomanyfreezes),
[Subtensor API Errors: TooManyReserves](https://docs.learnbittensor.org/subtensor-api/errors#toomanyreserves)).

- **TooManyReserves** — named-reserve list is full; new reserve cannot be placed.
- **TooManyFreezes** — freeze list is full; new freeze cannot be placed.

## Reader Boundary

This page defines the meaning of the error label and the named-reserve count check that raises it.
It does not report the current number of active named reserves on any account; that is live chain
state ([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).
