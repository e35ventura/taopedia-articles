# Nominate

To nominate is to stake TAO with a validator or delegate in Bittensor. The
[Nominate glossary](https://docs.learnbittensor.org/resources/glossary#nominate) describes
nomination as the staking process by which TAO holders participate through validators.

## Delegation Context

Nominate is the action side of the nominator relationship. A nominator is the account role, while
nomination names the act of staking TAO with the validating side of a delegation relationship
([Glossary: Delegation](https://docs.learnbittensor.org/resources/glossary#delegation),
[Glossary: Nominator](https://docs.learnbittensor.org/resources/glossary#nominator)).

## Staking Context

The
[staking and delegation documentation](https://docs.learnbittensor.org/staking-and-delegation/delegation)
uses delegation to describe staking TAO with validators. In Taopedia prose, nominate should be read
as delegation vocabulary rather than as a subnet role, account count, or chain-state claim.

## Validator Hotkey Context

The [Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate) describes
nomination as staking TAO on a validator's hotkey so token holders can participate in subnet
emissions through active validators. The term names the delegation action and its validator-side
target in staking vocabulary, distinct from the nominator account role
([Glossary: Nominator](https://docs.learnbittensor.org/resources/glossary#nominator)).

Nomination prose should name the validator hotkey or delegation context being supported rather than
a generic account label.

## The Nominating Coldkey Can Later Lock That Stake for Conviction

Nominate attaches a coldkey's stake to a validator hotkey on a subnet. The conviction and locked
stake feature works at that same coldkey level: locked staking documentation describes locked
staking as letting coldkey holders lock alpha stake to a specific hotkey on a subnet
([Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate),
[Conviction and locked stake](https://docs.learnbittensor.org/staking-and-delegation/conviction-staking)).

A coldkey that nominates a validator hotkey is therefore the same coldkey that can subsequently lock
that staked position to build a conviction signal on that hotkey. Nominate names the staking action
that creates the position; locking is a separate, later action available to the same coldkey on a
position that already exists
([Staking and delegation overview](https://docs.learnbittensor.org/staking-and-delegation/delegation)).

## Staking Documentation Covers Procedures, Not This Label

This article is a concept boundary. It does not provide staking procedures, CLI commands, or live
chain data. Staking and delegation documentation covers how nomination is submitted on chain
([Staking and delegation documentation](https://docs.learnbittensor.org/staking-and-delegation/delegation)).

Readers should keep procedural claims tied to those references rather than to nominate vocabulary
alone.

## Nomination Applies Within a Subnet Context

A netuid identifies which subnet is in scope, while nominate names the delegation action that
supports a validator participating in that context
([Glossary: Netuid](https://docs.learnbittensor.org/resources/glossary#netuid),
[Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate)).

A precise claim should name both the subnet context and the validator hotkey receiving delegated
support.

## Nomination Is a Chosen Staking Action

Nomination names a deliberate delegation act by a TAO holder. The
[Glossary: Nominator](https://docs.learnbittensor.org/resources/glossary#nominator) describes a
nominator as an account that stakes TAO with validators, while nominate names the act of making that
delegation choice.

That keeps the action separate from automatic routing mechanisms. A holder chooses nomination; it is
not the same vocabulary as autostaking or miner emission routing.

The [Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate) also ties
nomination to staking TAO on a validator hotkey so token holders can participate through active
validators.

## Development Stage Context

The
[Introduction to Bittensor](https://docs.learnbittensor.org/learn/introduction#subnet-development)
describes subnet development as moving from localnet to testnet and then mainnet. For nominate on a
subnet such as netuid 1, that sequence changes how readers should interpret evidence about TAO
delegation and validator stake relationships.

In localnet, nomination can be tested in an isolated environment. Stake delegated to validators in
localnet reflects local chain configuration and does not represent production validator associations
or real TAO.

On testnet, nomination can be observed in a shared, non-production network. Testnet nomination on a
selected netuid affects testnet validator stake but remains separate from mainnet delegation state
and real nominator relationships.

On mainnet, nominating is a live Subtensor staking action that changes real TAO positions and
validator stake on the production network. The
[Staking and delegation documentation](https://docs.learnbittensor.org/staking-and-delegation/delegation)
describes the delegation mechanics that apply on mainnet.

The [Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks) reference
separates mainnet, testnet, and localnet. A nomination example from one environment should not be
read as representing validator stake or delegation associations in another environment.

## Delegation Names the Support Relationship

Nominate names the staking action that attaches TAO to a validator hotkey, while
[delegation](https://docs.learnbittensor.org/resources/glossary#delegation) names the support
relationship that action establishes
([Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate),
[Glossary: Nominator](https://docs.learnbittensor.org/resources/glossary#nominator)).

A nominator performs nomination to attach support; delegation describes the resulting support link
to the validator receiving that stake
([Staking and delegation overview](https://docs.learnbittensor.org/staking-and-delegation/delegation)).

Use nominate when the article covers the staking action and delegation when it covers the support
relationship that action creates on the validator hotkey being supported
([Glossary: Delegate](https://docs.learnbittensor.org/resources/glossary#delegate)).

## Stake Is the Amount After Support Exists

[Stake](https://docs.learnbittensor.org/resources/glossary#stake) names the amount associated with a
validator position after support exists. Nomination is one path by which that support becomes
attached ([Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate),
[Staking and delegation overview](https://docs.learnbittensor.org/staking-and-delegation/delegation)).

Nominate names the action; stake names the resulting amount context behind the validator hotkey.

## Effective Stake Combines Self-Stake and Nomination

Nomination attaches a TAO holder's stake to a validator hotkey.
[Effective stake](https://docs.learnbittensor.org/resources/glossary#effective-stake) is the total
staked amount associated with the receiving validator after both the delegate's own stake and
nominated TAO are counted
([Glossary: Delegate Stake](https://docs.learnbittensor.org/resources/glossary#delegate-stake)).

Nominate names the supplying action; effective stake names the combined backing behind the validator
after nomination is included.

## Validator Dividends Follow Nomination Support

Nomination increases a validator's effective stake, which Yuma Consensus uses to weight that
validator's influence during coinbase-triggered epoch rounds
([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

[Coinbase](https://docs.learnbittensor.org/navigating-subtensor/emissions-coinbase) distributes
validator dividends from each epoch's emissions, and a share of those dividends flows back to
nominators in proportion to the stake they delegated
([Emission: Distribution](https://docs.learnbittensor.org/learn/emissions#distribution)).

Nominate is the action that positions stake behind a validator; validator dividends describe the
emission share that can follow from that support relationship. Validator take vocabulary names the
validator-kept portion before the remainder flows toward nominators
([Glossary: Validator Take %](https://docs.learnbittensor.org/resources/glossary#validator-take-)).

## Nomination Versus Unstaking

Nomination adds or adjusts delegated support for a validator. Unstaking removes stake from the
delegation model. The
[Glossary: Unstake](https://docs.learnbittensor.org/resources/glossary#unstaking) describes
unstaking as withdrawing delegated stake
([Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate)).

Using the right verb keeps staking prose precise. Nominate is not a synonym for unstake or transfer.
Unstaking ends or reduces delegated exposure, while nomination establishes or changes which
validator hotkey receives that delegated support.

## Moving Stake Repoints Delegation

Moving stake rearranges an existing delegated position between hotkeys or subnets without treating
the action as a fresh nomination from scratch. The
[Staking and delegation overview](https://docs.learnbittensor.org/staking-and-delegation/delegation#moving-stake)
lists moving stake alongside other stake-management operations separate from the initial delegation
choice ([Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate)).

Nominate belongs with first-time or adjusted delegation support, while moving stake belongs with
rearranging where an existing staked position already sits. Both verbs concern stake management, but
they name different kinds of delegation changes.

## Nominator Is the Supplying Account Role

Nominator names the TAO-holder account role that supplies delegated stake, while nominate names the
staking action that attaches TAO to a validator hotkey
([Glossary: Nominator](https://docs.learnbittensor.org/resources/glossary#nominator),
[Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate)).

Nominator names the account role; nominate names the delegation action carried out by that role.

## Delegate Is the Receiving Validator Role

Nominate names the action of staking TAO with a validator hotkey, while
[delegate](https://docs.learnbittensor.org/resources/glossary#delegate) names the subnet validator
role that receives that staked TAO and performs validation work
([Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate)).

Nominate names the supplying action; delegate names the receiving validator role on the other side
of that relationship.

## Netuid Selects the Subnet Context

A [netuid](https://docs.learnbittensor.org/resources/glossary#netuid) identifies a subnet on the
network, while nominate names the action of staking TAO with a validator participating in that
subnet context ([Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate)).

Netuid selects which subnet context is in scope; nominate names the delegation action that supports
a validator in that context.

## Autostaking Routes Miner Emissions Automatically

Nominate and autostaking both result in staked TAO on a validator, but they describe different
things. Nominate is the act of staking TAO with a validator or delegate — a staking action a TAO
holder chooses to take
([Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate)). Autostaking is
a mechanism that automatically routes a miner's emission proceeds into a staking position on a
chosen validator ([Autostaking](https://docs.learnbittensor.org/miners/autostaking)).

Nominate names a deliberate staking action by a token holder, while autostaking names an automatic
routing of a miner's emissions into stake. Both place stake on a validator, but one is a holder's
chosen action and the other is an ongoing automatic mechanism.

## Subtensor Records the Delegation Action

[Subtensor](https://docs.learnbittensor.org/resources/glossary#subtensor) names Bittensor's layer 1
blockchain and system of record, while nominate names the staking action of attaching TAO to a
validator hotkey recorded through chain-layer delegation state
([Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate)).

Subtensor names the chain layer; nominate names the delegation action recorded on that layer.

## Multiple Mechanisms Share the Same Nomination Action

Nomination attaches TAO support to a validator inside a subnet. The
[Glossary: Incentive Mechanism](https://docs.learnbittensor.org/resources/glossary#incentive-mechanism)
notes that each subnet has one or more incentive mechanisms
([Multiple Incentive Mechanisms Within Subnets](https://docs.learnbittensor.org/subnets/understanding-multiple-mech-subnets)).

Nominate still names the delegation action in staking vocabulary. That action supports a validator
position in one subnet, which may run more than one incentive mechanism.

## Governance Nomination Is Separate Vocabulary

Nominate language should keep governance nomination separate from staking nomination when both
appear near each other. Governance sources separate proposal flow, Senate participation, and
role-specific authority, so governance nomination claims should identify the body or process they
affect ([Governance Overview](https://docs.learnbittensor.org/governance),
[Senate](https://docs.learnbittensor.org/governance/senate)).

A governance nomination can be part of selecting or authorizing a role, while voting, approval,
closure, and execution remain separate steps. Staking nominate prose should not be mixed with
governance nomination without naming that context.

## Reader Boundary

Nominate should not be read as a subnet role, a completed governance appointment, or proof that
emissions were received. In staking vocabulary it names the delegation action of attaching TAO to a
validator hotkey ([Glossary: Nominate](https://docs.learnbittensor.org/resources/glossary#nominate),
[Staking and delegation documentation](https://docs.learnbittensor.org/staking-and-delegation/delegation)).

Current chain values, wallet state, validator-specific outcomes, or production measurements belong
to the relevant network, block, account, or tool output at the time of observation.
