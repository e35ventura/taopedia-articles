# Kappa

Kappa is a per-subnet hyperparameter that sets the consensus majority ratio used by Yuma Consensus.
Documentation describes it as the consensus majority ratio and states that the weights set by
validators with lower normalized stake than kappa are not used in calculating consensus
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## What It Controls

Kappa marks the stake-weighted majority point used when validator weights are combined into a
consensus result. Per the documentation, weights coming from validators whose normalized stake falls
below kappa do not enter the consensus calculation. In effect, kappa sets how much of the
stake-weighted agreement forms consensus and where lower-stake input stops counting
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Subnet Hyperparameters: Kappa](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#kappa)).

## Default and Representation

The documentation lists kappa as a `u16` value with a default of 32767, which is approximately 0.5
once normalized against the maximum of that type. That places the default near the halfway point of
stake-weighted agreement. The value actually in force is per-subnet chain state and can differ from
the documented default
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Distinction from Clipping

Kappa is the stake fraction that sets which validator weights count toward the consensus majority.
Clipping is the Yuma step that trims individual weights above the stake-weighted agreement benchmark
([Subnet Hyperparameters: Kappa](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#kappa),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

Kappa filters which validator rows participate in the majority calculation. Clipping then punishes
inflated ratings that still outlie the resulting agreement.

- **Kappa** — stake fraction that sets which validator weights count toward consensus.
- **Clipping** — trimming weights that exceed the stake-weighted agreement benchmark.

## Distinction from Consensus Score

Kappa is the subnet hyperparameter that sets the consensus majority ratio. Consensus score is the
stake-weighted median benchmark that clipping compares individual weight values against
([Subnet Hyperparameters: Kappa](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#kappa),
[Glossary: Consensus Score](https://docs.learnbittensor.org/resources/glossary#consensus-score),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Kappa** — stake fraction that sets the consensus clipping ceiling input.
- **Consensus score** — stake-weighted median benchmark clipping compares weights against.

## Distinction from Bonds Penalty

Kappa sets the stake fraction used to derive the consensus clipping ceiling. Bonds penalty sets how
costly it is to post weights above that benchmark during bonding
([Subnet Hyperparameters: Kappa](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#kappa),
[Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Kappa** — stake fraction for the consensus clipping ceiling.
- **Bonds penalty** — penalty magnitude on weights above that benchmark.

## Distinction from Validator Permit

Kappa is the root-level stake fraction that sets the consensus clipping ceiling in Yuma Consensus. A
validator permit is the per-subnet permission flag that records whether a UID may submit counting
weights
([Subnet Hyperparameters: Kappa](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#kappa),
[Glossary: Validator Permit](https://docs.learnbittensor.org/resources/glossary#validator-permit),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Kappa** — stake-weighted majority threshold for consensus clipping.
- **Validator permit** — subnet-level right to submit weights that can enter aggregation.

A validator can hold a permit yet still fall below the stake-weighted majority kappa defines
([Understanding Incentive Mechanisms](https://docs.learnbittensor.org/learn/anatomy-of-incentive-mechanism)).

## Chain Reads for netuid 1

Readers can verify live hyperparameter values for the documented example netuid with
`btcli subnet hyperparameters --netuid 1 --network finney`
([Subnet Hyperparameters: View hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#view-hyperparameters)).

That read path keeps live hyperparameter claims tied to a parseable netuid.

## Per-Subnet Live Value Boundary

Kappa is per-subnet chain state. The consensus majority ratio configured on one netuid governs which
validator weights count toward consensus on that subnet, but the live value can differ from
reference defaults and from kappa on another netuid
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Subnet Hyperparameters: Kappa](https://docs.learnbittensor.org/subnets/subnet-hyperparameters#kappa)).

This article's infobox uses netuid 1 as an example label when reading one subnet's hyperparameter
table. That example helps readers verify one row; it is not proof that every subnet exposes the same
live kappa value
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks)).

Kappa governs weight inclusion in consensus; Yuma Consensus still converts eligible weights into
emission shares each epoch ([Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus)).

- **Kappa** — consensus majority ratio for weight inclusion on a subnet.
- **Per-subnet boundary** — live value is chain state on one netuid.

## Distinction from Yuma Consensus

Kappa is a per-subnet hyperparameter that sets the consensus majority ratio Yuma Consensus uses when
deciding which validator weights count. Yuma Consensus is the broader tempo process that applies
that threshold while converting validator weight submissions into emission shares
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters),
[Yuma Consensus](https://docs.learnbittensor.org/learn/yuma-consensus),
[Emission](https://docs.learnbittensor.org/learn/emissions)).

- **Kappa** — consensus majority ratio hyperparameter for weight inclusion.
- **Yuma Consensus** — mechanism that turns validator weights into emission shares.

- **Root-level setting** — documentation marks kappa as governed at the root level rather than by
  subnet owners
  ([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).
- **Documented default** — reference default is 32767, about 0.5 normalized
  ([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).

## Reader Boundary

This page defines the concept at a high level. It does not report the kappa value set on any
particular subnet or the current consensus outcome of an epoch. Those are live chain state and
should be checked for the relevant netuid. The 32767 figure, about 0.5 normalized, is the documented
default, and the parameter is governed at the root level
([Subnet Hyperparameters](https://docs.learnbittensor.org/subnets/subnet-hyperparameters)).
