# Invalid Spec Name

`InvalidSpecName` is a system pallet error raised when a runtime upgrade submission's `spec_name`
field does not match the chain's currently configured `spec_name`. The API errors reference
summarizes it as "The name of specification does not match between the current runtime and the new
runtime."
([Subtensor API Errors: InvalidSpecName](https://docs.learnbittensor.org/subtensor-api/errors#invalidspecname)).

## What It Means

Subtensor runs a Substrate-style runtime that identifies each compiled runtime build by a
`spec_name` field in its embedded `RuntimeVersion`. Submitting a replacement runtime with the same
`spec_name` signals a same-chain upgrade; submitting one with a different `spec_name` signals a
different chain. `InvalidSpecName` means the runtime upgrade check compared the submitted
`spec_name` against the current one and the comparison failed, so the upgrade path stops before the
new runtime is applied
([Subtensor API Errors: InvalidSpecName](https://docs.learnbittensor.org/subtensor-api/errors#invalidspecname)).

This is the spec_name equality check on the runtime upgrade validation path. It does not, by itself,
mean the new runtime's `spec_version` was lower than the current one, that the runtime was
unreadable, or that the runtime upgrade was blocked by the dispatch filter.

## Why It Appears

This error appears when a runtime upgrade submission is processed with `check_version: true` and the
embedded `spec_name` does not equal the current chain's `spec_name`. The pinned frame-system source
describes the check inside the `can_set_code` helper: after decoding the new `RuntimeVersion`, the
helper compares `new_version.spec_name` against `current_version.spec_name` and returns
`CanSetCodeResult::InvalidVersion(Error::<T>::InvalidSpecName)` when the names differ
([opentensor/polkadot-sdk: substrate/frame/system/src/lib.rs#L2338](https://github.com/opentensor/polkadot-sdk/blob/7cc54bf2d50ae3921d718736dfeb0de9468539c7/substrate/frame/system/src/lib.rs#L2338)).

The `can_set_code` helper performs three sequential upgrade-version checks against the embedded
`RuntimeVersion`: decode failure first
([`FailedToExtractRuntimeVersion`](https://docs.learnbittensor.org/subtensor-api/errors#failedtoextractruntimeversion),
[opentensor/polkadot-sdk: lib.rs#L2329](https://github.com/opentensor/polkadot-sdk/blob/7cc54bf2d50ae3921d718736dfeb0de9468539c7/substrate/frame/system/src/lib.rs#L2329)),
then spec_name equality (this error), then `spec_version` monotonicity
([`SpecVersionNeedsToIncrease`](https://docs.learnbittensor.org/subtensor-api/errors#specversionneedstoincrease),
[opentensor/polkadot-sdk: lib.rs#L2342](https://github.com/opentensor/polkadot-sdk/blob/7cc54bf2d50ae3921d718736dfeb0de9468539c7/substrate/frame/system/src/lib.rs#L2342)).

## Distinction from Failed To Extract Runtime Version

`InvalidSpecName` and `FailedToExtractRuntimeVersion` both surface as `InvalidVersion` results from
`can_set_code`, but they fire at different stages. `InvalidSpecName` is the spec_name equality check
against the decoded new runtime's `spec_name`. `FailedToExtractRuntimeVersion` is reached earlier
when the embedded `RuntimeVersion` could not be decoded at all
([Subtensor API Errors: InvalidSpecName](https://docs.learnbittensor.org/subtensor-api/errors#invalidspecname),
[Subtensor API Errors: FailedToExtractRuntimeVersion](https://docs.learnbittensor.org/subtensor-api/errors#failedtoextractruntimeversion)).

- **InvalidSpecName** — the new runtime's `spec_name` differs from the current one.
- **FailedToExtractRuntimeVersion** — the new runtime's `RuntimeVersion` could not be decoded.

## Distinction from Spec Version Needs To Increase

`InvalidSpecName` and `SpecVersionNeedsToIncrease` both appear inside the same `can_set_code`
helper's version validation, but they check different fields. `InvalidSpecName` rejects the
submission when the submitted `spec_name` does not match the current `spec_name`.
`SpecVersionNeedsToIncrease` rejects the submission when the submitted `spec_version` is not greater
than the current `spec_version`
([Subtensor API Errors: InvalidSpecName](https://docs.learnbittensor.org/subtensor-api/errors#invalidspecname),
[Subtensor API Errors: SpecVersionNeedsToIncrease](https://docs.learnbittensor.org/subtensor-api/errors#specversionneedstoincrease)).

- **InvalidSpecName** — the submitted runtime's `spec_name` differs.
- **SpecVersionNeedsToIncrease** — the submitted runtime's `spec_version` did not increase.

## Reader Boundary

This page defines the meaning of the error label and the spec_name equality check it represents on
the runtime upgrade path. It does not report which `spec_name` the chain is currently running, list
the runtime upgrade extrinsic that submits the new bytes, or describe how the upgrade is authorized
on a given network
([Bittensor Networks](https://docs.learnbittensor.org/concepts/bittensor-networks),
[Subtensor API Errors: InvalidSpecName](https://docs.learnbittensor.org/subtensor-api/errors#invalidspecname)).
